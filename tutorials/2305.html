Advanced Crew Patterns

Learn about advanced crew patterns.

Understanding Advanced Crew Patterns

Welcome back! In this lesson, we'll explore advanced patterns for building AI agent crews that can handle complex, multi-step tasks. You've already learned the basics of creating single agents and simple crews — now it's time to level up.

By the end of this lesson, you'll understand how to design agent crews with sophisticated coordination, conditional workflows, and error recovery strategies that make your AI systems more reliable and powerful.

The Need for Advanced Patterns

When you start building real-world AI agent systems, you quickly discover that simple linear workflows aren't enough. Real tasks require:

  • Decision points — where the crew needs to choose between different paths
  • Fallback behavior — what happens when an agent fails
  • Information routing — passing context between agents intelligently
  • Parallel execution — having multiple agents work simultaneously

Let's explore each of these patterns in detail.

Pattern 1: Conditional Branching

Sometimes your crew needs to make decisions based on the output of a previous agent. A researcher agent might find that data is unavailable, and the crew should pivot to a different data source rather than blindly continuing.

Building a Decision Router

The decision router is an agent that evaluates outputs and determines which agent should handle the task next. Here's how you can implement one using CrewAI:

from crewai import Agent, Task, Crew

# Agent that decides the next step based on results
decision_router = Agent(
    role="Decision Router",
    goal="Analyze task results and determine the optimal next agent",
    backstory="""You are an expert at analyzing outputs and routing tasks
    to the most appropriate specialist agent. You evaluate quality, completeness,
    and relevance to decide the next step.""",
    allow_delegation=True,
    verbose=True
)

# The routing task dynamically evaluates the situation
routing_task = Task(
    description="""Review the research output: {research_output}.
    If the data is complete and high quality, route to 'writer'.
    If data is incomplete or uncertain, route back to 'researcher'
    with additional context. If the topic is off-track, route to
    'researcher' with corrected instructions.""",
    expected_output="A routing decision: either 'route_to_writer', 
    'route_back_to_researcher', or 'route_with_correction'.",
    agent=decision_router
)

# Build the crew with the router
crew = Crew(
    agents=[researcher, writer, decision_router],
    tasks=[research_task, routing_task, writing_task],
    verbose=True
)
Key Concept: Conditional branching means your crew isn't just a straight line — it's a graph where the path depends on what happens at each step.

Pattern 2: Fallback and Error Recovery

Things go wrong. APIs return errors, agents produce low-quality output, and unexpected inputs appear. A robust crew handles these situations gracefully.

Implementing Retry Logic

The simplest form of error recovery is retrying. But smart retries include additional context about what went wrong:

from crewai import Agent, Task, Crew
import time

def execute_with_retry(crew, max_retries=3, backoff_factor=2):
    """Execute a crew with intelligent retry logic."""
    last_exception = None
    
    for attempt in range(max_retries):
        try:
            result = crew.kickoff()
            
            # Validate the result meets quality standards
            if validate_output(result):
                return result
            else:
                raise ValueError(
                    f"Output quality check failed on attempt {attempt + 1}"
                )
                
        except Exception as e:
            last_exception = e
            wait_time = backoff_factor ** attempt
            
            print(f"Attempt {attempt + 1} failed: {e}")
            print(f"Retrying in {wait_time} seconds...")
            time.sleep(wait_time)
    
    raise RuntimeError(
        f"All {max_retries} attempts failed. Last error: {last_exception}"
    )

def validate_output(result):
    """Check if the crew output meets minimum standards."""
    if result is None:
        return False
    if hasattr(result, 'raw') and len(result.raw.strip()) < 50:
        return False
    return True

# Usage
crew = Crew(agents=[researcher, writer], tasks=[research_task, writing_task])

try:
    final_result = execute_with_retry(crew, max_retries=3)
    print("Success:", final_result)
except RuntimeError as e:
    print("Crew failed after all retries:", e)

Fallback Agent Pattern

When your primary agent fails, you can have a simpler fallback agent take over:

from crewai import Agent, Task, Crew

# Primary agent — sophisticated but may fail on edge cases
primary_researcher = Agent(
    role="Senior Research Analyst",
    goal="Conduct thorough, nuanced research on complex topics",
    backstory="""You are a senior analyst with deep expertise.
    You handle complex, multi-faceted research questions.""",
    allow_delegation=False,
    verbose=True
)

# Fallback agent — simpler but more reliable
fallback_researcher = Agent(
    role="Research Assistant",
    goal="Provide basic, reliable research summaries",
    backstory="""You are a straightforward research assistant.
    You may not handle complex analysis, but you reliably
    produce usable summaries for common topics.""",
    allow_delegation=False,
    verbose=True
)

def create_robust_crew(topic):
    """Create a crew that falls back to a simpler agent on failure."""
    
    primary_task = Task(
        description=f"Research the topic: {topic}. Provide a comprehensive analysis.",
        expected_output="A detailed research report with sources and analysis.",
        agent=primary_researcher
    )
    
    fallback_task = Task(
        description=f"Provide a basic summary about: {topic}",
        expected_output="A clear, basic summary of the topic.",
        agent=fallback_researcher
    )
    
    return Crew(
        agents=[primary_researcher, fallback_researcher],
        tasks=[primary_task, fallback_task],
        verbose=True
    )

# Execute with fallback logic
topic = "Quantum computing applications in drug discovery"
crew = create_robust_crew(topic)

try:
    # Try primary agent first
    result = crew.kickoff(inputs={"active_task": "primary"})
    if not validate_output(result):
        raise ValueError("Primary agent output insufficient")
    print("Primary agent succeeded:", result)
except Exception as e:
    print(f"Primary agent failed ({e}). Using fallback...")
    result = crew.kickoff(inputs={"active_task": "fallback"})
    print("Fallback agent result:", result)
Common Mistake: Don't catch all exceptions silently. Always log failures so you can improve your agents over time. Silent failures make debugging nearly impossible.

Pattern 3: Parallel Execution with Aggregation

Some tasks can be split into independent subtasks that run simultaneously. This dramatically reduces total execution time for research-heavy workflows.

Splitting and Merging Work

from crewai import Agent, Task, Crew
from concurrent.futures import ThreadPoolExecutor, as_completed

# Create specialist agents for different aspects
market_analyst = Agent(
    role="Market Analyst",
    goal="Analyze market size, trends, and competition",
    backstory="You specialize in market research and competitive analysis.",
    verbose=True
)

tech_analyst = Agent(
    role="Technical Analyst",
    goal="Evaluate technical feasibility and requirements",
    backtitle="You assess whether ideas are technically achievable.",
    verbose=True
)

financial_analyst = Agent(
    role="Financial Analyst",
    goal="Assess financial viability and projected returns",
    backstory="You build financial models and evaluate ROI.",
    verbose=True
)

def run_parallel_analysis(idea):
    """Run all three analyses in parallel, then aggregate results."""
    
    # Define independent tasks
    tasks = {
        "market": Task(
            description=f"Analyze the market for: {idea}",
            expected_output="Market size, growth rate, and key competitors.",
            agent=market_analyst
        ),
        "technical": Task(
            description=f"Assess technical feasibility of: {idea}",
            expected_output="Technical requirements, risks, and timeline estimate.",
            agent=tech_analyst
        ),
        "financial": Task(
            description=f"Evaluate financial viability of: {idea}",
            expected_output="Projected costs, revenue, and break-even analysis.",
            agent=financial_analyst
        )
    }
    
    results = {}
    
    # Execute tasks in parallel using threads
    with ThreadPoolExecutor(max_workers=3) as executor:
        futures = {}
        
        for name, task in tasks.items():
            single_crew = Crew(
                agents=[task.agent],
                tasks=[task],
                verbose=True
            )
            futures[executor.submit(single_crew.kickoff)] = name
        
        for future in as_completed(futures):
            name = futures[future]
            try:
                results[name] = future.result()
                print(f"✓ {name.capitalize()} analysis complete")
            except Exception as e:
                print(f"✗ {name.capitalize()} analysis failed: {e}")
                results[name] = f"Analysis failed: {e}"
    
    return results

# Aggregate results with a synthesis agent
synthesizer = Agent(
    role="Synthesis Expert",
    goal="Combine multiple analyses into a unified recommendation",
    backstory="""You take inputs from multiple analysts and create
    a coherent, actionable recommendation.""",
    verbose=True
)

def aggregate_and_recommend(idea, parallel_results):
    """Feed all parallel results into a synthesis agent."""
    
    combined_context = "\n\n".join(
        f"--- {name.upper()} ANALYSIS ---\n{result}"
        for name, result in parallel_results.items()
    )
    
    synthesis_task = Task(
        description=f"""Based on the following analyses for '{idea}',
        provide a unified recommendation:
        
        {combined_context}
        
        Your recommendation should weigh all factors and provide
        a clear go/no-go decision with reasoning.""",
        expected_output="A unified recommendation with go/no-go decision 
        and supporting reasoning from all three analyses.",
        agent=synthesizer
    )
    
    synthesis_crew = Crew(
        agents=[synthesizer],
        tasks=[synthesis_task],
        verbose=True
    )
    
    return synthesis_crew.kickoff()

# Full workflow
idea = "AI-powered meal planning app for diabetics"

print("Starting parallel analysis...")
parallel_results = run_parallel_analysis(idea)

print("\nAggregating results...")
final_recommendation = aggregate_and_recommend(idea, parallel_results)

print("\n=== FINAL RECOMMENDATION ===")
print(final_recommendation)
Performance Tip: Parallel execution works best when tasks are truly independent. If one agent's output feeds another's input, keep them sequential. Don't parallelize what should be sequential — it adds complexity without speed benefits.

Comparing Crew Patterns

Here's a quick reference to help you choose the right pattern for your use case:

Pattern Best For Complexity Speed Reliability
Sequential Simple, linear workflows Low Slow (one step at a time) Medium
Conditional Branching Tasks with decision points Medium Medium High
Fallback/Retry Critical tasks that must succeed Medium Variable Very High
Parallel + Aggregate Independent subtasks High Fast High
Hierarchical Large, complex projects Very High Medium Very High

Pattern 4: Hierarchical Crews

In a hierarchical pattern, a manager agent oversees worker agents, delegating tasks and synthesizing results. This mirrors how human teams operate and scales well to complex projects.

from crewai import Agent, Task, Crew

# Manager agent coordinates the team
manager = Agent(
    role="Project Manager",
    goal="Coordinate research and writing efforts to produce excellent content",
    backstory="""You are an experienced project manager who excels at
    breaking down complex projects into tasks, delegating to the right
    people, and synthesizing their work into cohesive deliverables.""",
    allow_delegation=True,
    verbose=True
)

# Worker agents handle specific tasks
researcher = Agent(
    role="Researcher",
    goal="Find accurate, relevant information on assigned topics",
    backstory="You are a meticulous researcher who always cites sources.",
    verbose=True
)

fact_checker = Agent(
    role="Fact Checker",
    goal="Verify all claims and data in the research",
    backstory="""You carefully verify every factual claim against
    reliable sources and flag anything uncertain.""",
    verbose=True
)

writer = Agent(
    role="Technical Writer",
    goal="Transform research into clear, engaging content",
    backstory="""You write clear, well-structured content that
    makes complex topics accessible.""",
    verbose=True
)

# Define tasks with clear dependencies
research_task = Task(
    description="""Research the latest developments in AI agent frameworks.
    Focus on CrewAI, AutoGen, and LangGraph. Include release dates,
    key features, and community adoption metrics.""",
    expected_output="A structured research document with sources.",
    agent=researcher
)

fact_check_task = Task(
    description="""Review the research output and verify all factual claims.
    Flag any unverified statements and note confidence levels.""",
    expected_output="A fact-check report with verified, unverified, 
    and corrected claims.",
    agent=fact_checker,
    context=[research_task]  # Depends on research
)

writing_task = Task(
    description="""Using the verified research, write a comprehensive
    comparison article about AI agent frameworks. Make it engaging
    for intermediate developers.""",
    expected_output="A polished article ready for publication.",
    agent=writer,
    context=[research_task, fact_check_task]  # Depends on both
)

# Build the hierarchical crew
hierarchical_crew = Crew(
    agents=[manager, researcher, fact_checker, writer],
    tasks=[research_task, fact_check_task, writing_task],
    manager_llm=manager,  # Manager coordinates delegation
    verbose=True
)

result = hierarchical_crew.kickoff()
print(result)

Putting It All Together

In practice, you'll often combine multiple patterns. A real-world crew might use parallel execution for research, conditional branching to handle different result types, and fallback agents for reliability.

The key is to start simple and add complexity only when needed. A sequential crew that works reliably is better than a parallel crew that's hard to debug.

Design Principle: Add complexity only when the simpler pattern fails to meet your requirements. Each additional pattern increases debugging surface area and cognitive load.
Exercise: Build a Resilient Research Crew

Create a crew that:

  1. Has a researcher agent that investigates a topic
  2. Has a fallback researcher with simpler instructions
  3. Uses a decision router to check if the research quality is sufficient
  4. If quality is insufficient, routes back to the researcher with feedback
  5. If quality is sufficient, routes to a writer agent
  6. Includes retry logic with a maximum of 2 retries

Use any topic you'd like — try "renewable energy trends in 2024" or something that interests you.

from crewai import Agent, Task, Crew

# === AGENTS ===

researcher = Agent(
    role="Senior Researcher",
    goal="Conduct thorough research on assigned topics with citations",
    backstory="""You are an expert researcher who provides detailed,
    well-sourced information. You always include specific data points
    and cite your sources.""",
    verbose=True
)

fallback_researcher = Agent(
    role="Research Assistant",
    goal="Provide clear, basic information on topics",
    backstory="""You provide straightforward summaries. You may lack
    depth but you are reliable and clear.""",
    verbose=True
)

quality_checker = Agent(
    role="Quality Checker",
    goal="Evaluate research quality and determine if it meets standards",
    backstory="""You evaluate research based on: completeness,
    specificity of data, source quality, and clarity. You output
    either 'PASS' or 'FAIL' with specific feedback.""",
    verbose=True
)

writer = Agent(
    role="Content Writer",
    goal="Transform quality research into engaging content",
    backstory="""You write clear, engaging articles based on
    provided research. You maintain accuracy while making
    content accessible.""",
    verbose=True
)

# === TASKS ===

research_task = Task(
    description="""Research: {topic}. Include specific statistics,
    recent developments, and at least 3 credible sources.
    Previous feedback (if any): {feedback}""",
    expected_output="Detailed research with data, trends, and sources.",
    agent=researcher
)

quality_task = Task(
    description="""Rate the following research as PASS or FAIL.
    Criteria: (1) Has specific data/stats, (2) Has 3+ sources,
    (3) Addresses the topic directly, (4) Is 200+ words.
    
    Research to evaluate: {research_output}""",
    expected_output="'PASS' or 'FAIL' with 2-3 sentences of feedback.",
    agent=quality_checker,
    context=[research_task]
)

writing_task = Task(
    description="""Write a 400-word article based on this research:
    {research_output}
    
    Make it engaging for a general audience while maintaining accuracy.""",
    expected_output="A polished 400-word article.",
    agent=writer,
    context=[research_task]
)

# === EXECUTION WITH RETRY ===

def run_resilient_crew(topic, max_retries=2):
    feedback = "None — this is the first attempt."
    
    for attempt in range(max_retries + 1):
        print(f"\n=== Attempt {attempt + 1} ===")
        
        # Update research task with feedback
        research_task.description = f"""Research: {topic}. Include 
        specific statistics, recent developments, and at least 3 
        credible sources. Previous feedback (if any): {feedback}"""
        
        crew = Crew(
            agents=[researcher, quality_checker, writer],
            tasks=[research_task, quality_task],
            verbose=True
        )
        
        result = crew.kickoff(inputs={"topic": topic})
        
        # Check if quality passed
        if "PASS" in str(result).upper():
            print("✓ Quality check passed! Proceeding to writing...")
            
            # Run the writing crew
            write_crew = Crew(
                agents=[writer],
                tasks=[writing_task],
                verbose=True
            )
            return write_crew.kickoff(inputs={
                "research_output": result,
                "topic": topic
            })
        else:
            feedback = f"Attempt {attempt + 1} failed. Improve: {result}"
            print(f"✗ Quality check failed. Feedback: {feedback}")
    
    print("Max retries reached. Using fallback researcher...")
    # Fallback: use simpler agent
    fallback_crew = Crew(
        agents=[fallback_researcher, writer],
        tasks=[
            Task(
                description=f"Provide a clear summary about: {topic}",
                expected_output="A clear, basic summary.",
                agent=fallback_researcher
            ),
            writing_task
        ],
        verbose=True
    )
    return fallback_crew.kickoff(inputs={"topic": topic})

# Run it
topic = "renewable energy trends in 2024"
final_article = run_resilient_crew(topic)
print("\n=== FINAL ARTICLE ===")
print(final_article)

Key Takeaways

  • Conditional branching lets your crew make decisions at runtime, routing tasks to the right agent based on intermediate results.
  • Fallback patterns ensure your crew produces output even when primary agents fail — always have a plan B.
  • Parallel execution dramatically speeds up workflows where subtasks are independent, but adds complexity.
  • Hierarchical crews use a manager agent to coordinate workers, mirroring real team structures for complex projects.
  • Retry logic with feedback is more effective than blind retries — tell the agent what went wrong so it can improve.
  • Start simple and add complexity only when your current pattern can't meet requirements.
  • Always validate outputs — don't assume agents produced good work just because they didn't crash.
  • Combine patterns thoughtfully — real crews often mix sequential, parallel, and conditional elements.
