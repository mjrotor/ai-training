External Memory Storage

Learn about external memory storage.

What Is External Memory Storage?

So far, we've seen that AI agents can reason, plan, and use tools. But there's a big limitation: they forget everything once a conversation ends. Every time you start a new chat, the agent has no idea what happened before. That's like trying to write a novel by only remembering one page at a time.

External memory storage solves this problem. It gives your AI agent a place to save information outside of its conversation — in files, databases, or cloud storage — so it can remember things across sessions, build knowledge over time, and even share information between different agents.

Think of it this way: an AI agent's built-in memory is like your short-term memory (what you're thinking about right now). External memory is like a notebook you carry everywhere — you can write things down, flip back to them later, and even share pages with a friend.

Key Idea: External memory storage lets an AI agent persist information beyond a single conversation, enabling long-term learning, context continuity, and collaboration between agents.

Types of External Memory

There are several common ways to store external memory for an AI agent. Each has different strengths depending on what you need.

1. Flat Files (TXT, JSON, CSV)

The simplest form of external memory. You write data to a file on disk, and the agent reads it back later. This is great for small projects, configuration data, or simple logs.

import json

# Saving agent memory to a JSON file
agent_memory = {
    "user_name": "Alice",
    "preferences": {"language": "Python", "style": "concise"},
    "conversation_count": 42,
    "last_topic": "memory storage"
}

with open("agent_memory.json", "w") as f:
    json.dump(agent_memory, f, indent=2)

# Loading it back in a future session
with open("agent_memory.json", "r") as f:
    restored_memory = json.load(f)

print(f"Welcome back, {restored_memory['user_name']}!")
print(f"We've chatted {restored_memory['conversation_count']} times.")

2. Vector Databases (Embedding Stores)

When your agent needs to store and search through large amounts of information — like documents, past conversations, or knowledge bases — a vector database is the right tool. It stores data as embeddings (numerical representations of meaning) so the agent can find relevant information using semantic search.

from sentence_transformers import SentenceTransformer
import chromadb

# Initialize embedding model and vector database
model = SentenceTransformer("all-MiniLM-L6-v2")
client = chromadb.Client()
collection = client.create_collection("agent_knowledge")

# Store knowledge as embeddings
documents = [
    "Python uses indentation to define code blocks.",
    "External memory allows agents to persist data across sessions.",
    "Vector databases enable semantic search over stored knowledge."
]

embeddings = model.encode(documents).tolist()

collection.add(
    documents=documents,
    embeddings=embeddings,
    ids=["doc1", "doc2", "doc3"]
)

# Later: search for relevant knowledge
query = "How do agents remember things?"
query_embedding = model.encode([query]).tolist()

results = collection.query(query_embeddings=query_embedding, n_results=2)
print("Relevant knowledge found:")
for doc in results["documents"][0]:
    print(f"  → {doc}")

3. Relational Databases (SQLite, PostgreSQL)

When your agent needs to store structured data — user records, transaction logs, task histories — a relational database gives you powerful querying capabilities with SQL.

import sqlite3

# Create a database for the agent's task history
conn = sqlite3.connect("agent_history.db")
cursor = conn.cursor()

cursor.execute("""
    CREATE TABLE IF NOT EXISTS tasks (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        task_name TEXT NOT NULL,
        status TEXT DEFAULT 'pending',
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        result TEXT
    )
""")

# The agent records a completed task
cursor.execute(
    "INSERT INTO tasks (task_name, status, result) VALUES (?, ?, ?)",
    ("Summarize report", "completed", "Report summarized in 3 paragraphs.")
)
conn.commit()

# Later: query past tasks
cursor.execute("SELECT * FROM tasks WHERE status = 'completed'")
completed = cursor.fetchall()
print(f"Agent has completed {len(completed)} task(s).")

conn.close()

4. Cloud Storage (S3, Google Cloud Storage)

For production agents that need to store large files — images, audio, large datasets, or shared knowledge bases — cloud storage provides durability, scalability, and accessibility from anywhere.

Tip: Start with flat files (JSON) for prototyping. Move to a vector database when you need semantic search, and a relational database when you need structured queries. Use cloud storage when files get large or need to be shared.

Comparing Memory Storage Options

Storage Type Best For Query Style Complexity Scalability
Flat Files (JSON, TXT) Simple state, configs, small logs Read/write entire file Low Low
Vector Database Semantic search, document retrieval Similarity search Medium High
Relational Database Structured records, task logs SQL queries Medium High

How External Memory Fits Into the Agent Loop

Remember the agent loop from earlier lessons? External memory adds two new steps to the cycle:

  1. READ — Before reasoning, the agent loads relevant memory from storage.
  2. REASON & ACT — The agent thinks and uses tools (as before).
  3. WRITE — After acting, the agent saves new information to storage.
  4. REPEAT — The loop continues, now with richer context each time.
class AgentWithMemory:
    def __init__(self, memory_file="agent_memory.json"):
        self.memory_file = memory_file
        self.memory = self._load_memory()

    def _load_memory(self):
        """READ: Load memory from external storage."""
        try:
            with open(self.memory_file, "r") as f:
                return json.load(f)
        except FileNotFoundError:
            return {"interactions": [], "facts": {}}

    def _save_memory(self):
        """WRITE: Persist memory to external storage."""
        with open(self.memory_file, "w") as f:
            json.dump(self.memory, f, indent=2)

    def remember(self, key, value):
        """Store a fact in memory."""
        self.memory["facts"][key] = value
        self._save_memory()

    def recall(self, key):
        """Retrieve a fact from memory."""
        return self.memory["facts"].get(key, None)

    def interact(self, user_input):
        """Main agent loop with memory."""
        # READ relevant context
        context = self._build_context()

        # REASON (simplified)
        response = f"Based on what I know: {context}\nYou said: {user_input}"

        # WRITE new interaction to memory
        self.memory["interactions"].append({
            "input": user_input,
            "response": response
        })
        self._save_memory()

        return response

    def _build_context(self):
        """Build context string from stored facts."""
        if not self.memory["facts"]:
            return "I don't know much yet."
        return ", ".join(
            f"{k}={v}" for k, v in self.memory["facts"].items()
        )


# Usage
agent = AgentWithMemory()
agent.remember("user_name", "Alice")
agent.remember("favorite_language", "Python")

print(agent.What's my favorite language?"))
# Output: Based on what I know: user_name=Alice, favorite_language=Python
#         You said: What's my favorite language?
Warning: Always handle file I/O errors gracefully. If your memory file gets corrupted or is missing, your agent should fall back to a clean state rather than crashing. Use try/except blocks around all storage operations.

Memory Management Best Practices

Storing data is easy. Storing it well requires some thought. Here are key practices for managing your agent's external memory:

Keep Memory Focused

Don't store everything. An agent that remembers every single word of every conversation will become slow and confused. Instead, extract and store only what's useful:

  • User preferences and profile information
  • Important facts discovered during conversations
  • Task states and progress
  • Learned patterns or corrections

Set Expiration and Cleanup

Old information can become outdated or irrelevant. Build in a cleanup mechanism:

from datetime import datetime, timedelta

def cleanup_old_entries(memory, max_age_days=30):
    """Remove memory entries older than max_age_days."""
    cutoff = datetime.now() - timedelta(days=max_age_days)
    cleaned = []
    for entry in memory.get("interactions", []):
        entry_date = datetime.fromisoformat(entry.get("timestamp", ""))
        if entry_date > cutoff:
            cleaned.append(entry)
    memory["interactions"] = cleaned
    return memory

Separate Memory by Purpose

Use different storage for different types of memory, just like humans use different parts of the brain:

  • Working memory — Current session context (in-memory, temporary)
  • Short-term memory — Recent interactions (JSON file, last 7 days)
  • Long-term memory — Important facts and knowledge (database or vector store)

Coding Exercise

Exercise: Build a Note-Taking Memory System

Create a MemoryNotebook class that lets an AI agent take notes, search through them, and forget old ones. Your class should support:

  1. add_note(topic, content) — Store a note with a topic tag and timestamp.
  2. search_notes(keyword) — Return all notes whose topic or content contains the keyword (case-insensitive).
  3. forget_before(date_string) — Remove all notes before a given date (format: "YYYY-MM-DD").
  4. save(filename) and load(filename) — Persist and restore notes to/from a JSON file.

Test it by adding 3 notes on different topics, searching for one, and saving/loading the notebook.

import json
from datetime import datetime

class MemoryNotebook:
    def __init__(self):
        self.notes = []

    def add_note(self, topic, content):
        note = {
            "topic": topic,
            "content": content,
            "timestamp": datetime.now().isoformat()
        }
        self.notes.append(note)
        print(f"Note added: '{topic}'")

    def search_notes(self, keyword):
        keyword_lower = keyword.lower()
        results = [
            note for note in self.notes
            if keyword_lower in note["topic"].lower()
            or keyword_lower in note["content"].lower()
        ]
        return results

    def forget_before(self, date_string):
        cutoff = datetime.fromisoformat(date_string)
        original_count = len(self.notes)
        self.notes = [
            note for note in self.notes
            if datetime.fromisoformat(note["timestamp"]) >= cutoff
        ]
        removed = original_count - len(self.notes)
        print(f"Forgot {removed} note(s) before {date_string}")

    def save(self, filename):
        with open(filename, "w") as f:
            json.dump(self.notes, f, indent=2)
        print(f"Saved {len(self.notes)} note(s) to {filename}")

    def load(self, filename):
        try:
            with open(filename, "r") as f:
                self.notes = json.load(f)
            print(f"Loaded {len(self.notes)} note(s) from {filename}")
        except FileNotFoundError:
            print(f"No file found: {filename}. Starting fresh.")
            self.notes = []


# --- Testing the notebook ---
notebook = MemoryNotebook()

notebook.add_note("Python", "Python uses indentation for code blocks.")
notebook.add_note("Memory", "External memory helps agents persist knowledge.")
notebook.add_note("Agents", "AI agents use tools, memory, and reasoning loops.")

# Search
results = notebook.search_notes("memory")
print(f"\nSearch results for 'memory':")
for r in results:
    print(f"  [{r['topic']}] {r['content']}")

# Save and load
notebook.save("my_notes.json")

new_notebook = MemoryNotebook()
new_notebook.load("my_notes.json")
print(f"\nReloaded notebook has {len(new_notebook.notes)} note(s).")

Key Takeaways

  • External memory lets AI agents persist information beyond a single conversation, enabling long-term learning and continuity.
  • Four main storage types — flat files, vector databases, relational databases, and cloud storage — each serve different needs.
  • The agent loop expands to READ → REASON → WRITE, with memory operations before and after the core reasoning step.
  • Good memory management means storing only what's useful, cleaning up old data, and separating memory by purpose (working, short-term, long-term).
  • Always handle errors gracefully when reading from or writing to external storage — your agent should never crash because of a missing file.
  • Start simple (JSON files) and scale up to databases and vector stores as your agent's needs grow.
