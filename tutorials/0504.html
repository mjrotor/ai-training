Parallel Tool Calls

Learn about parallel tool calls.

What Are Parallel Tool Calls?

In earlier lessons, you learned how AI agents can call tools one at a time — asking each tool in sequence, waiting for the result, and then deciding what to do next. This works perfectly fine when your agent only needs a single piece of information. But what happens when your agent needs to gather multiple independent pieces of information at the same time?

Imagine you're planning a trip and need the weather in three different cities. If you check them one by one, you wait three times. But if you could check all three at the same time, you'd only wait once — as long as the slowest request takes.

This is exactly what parallel tool calls allow an AI agent to do: invoke multiple independent tools simultaneously, collect all the results, and then reason over them together.

Key Idea: Parallel tool calls let an AI agent execute multiple independent tool invocations at the same time, dramatically reducing total wait time when tools involve network requests, file I/O, or other slow operations.

Sequential vs. Parallel Execution

Let's compare how an agent behaves when it needs results from two tools: a get_weather tool and a search_web tool.

Sequential Tool Calls (What You've Seen So Far)

In sequential execution, the agent calls one tool, waits for the result, then calls the second tool and waits again. The total time is roughly the sum of both tool execution times.

# Sequential approach — tools called one after another
import time

def get_weather(city):
    time.sleep(2)  # Simulates a slow network request
    return f"Weather in {city}: Sunny, 75°F"

def search_web(query):
    time.sleep(2)  # Simulates a slow search API call
    return f"Top result for '{query}': Travel guide available"

# Sequential execution
start = time.time()

weather = get_weather("Paris")        # Waits 2 seconds
result = search_web("Paris travel")   # Waits another 2 seconds

elapsed = time.time() - start
print(f"Sequential time: {elapsed:.2f}s")  # ~4.00 seconds
print(weather)
print(result)

Here, the total wait is about 4 seconds — 2 seconds for the weather check plus 2 seconds for the web search.

Parallel Tool Calls (Today's Topic)

With parallel execution, both tools are called at the same time. The total time is roughly the maximum of the individual execution times, not the sum.

# Parallel approach — tools called simultaneously
import asyncio

async def get_weather(city):
    await asyncio.sleep(2)  # Simulates an async network request
    return f"Weather in {city}: Sunny, 75°F"

async def search_web(query):
    await asyncio.sleep(2)  # Simulates an async search API call
    return f"Top result for '{query}': Travel guide available"

async def main():
    start = time.time()
    
    # Both tools start at the same time!
    weather, result = await asyncio.gather(
        get_weather("Paris"),
        search_web("Paris travel")
    )
    
    elapsed = time.time() - start
    print(f"Parallel time: {elapsed:.2f}s")  # ~2.00 seconds
    print(weather)
    print(result)

asyncio.run(main())

Now the total wait is only about 2 seconds — both tools run at the same time, so you're only waiting for the slowest one.

Rule of Thumb: Use parallel tool calls when the tools are independent — meaning one tool's result doesn't affect what the other tool needs. If Tool B needs Tool A's output as input, you must call them sequentially.

When to Use Parallel Tool Calls

Not every situation calls for parallel execution. Here's a simple decision framework:

Scenario Use Parallel? Why?
Fetching weather for 3 cities ✅ Yes Each city lookup is independent
Searching the web + checking weather ✅ Yes No dependency between the two
Looking up a user ID, then fetching their profile ❌ No Step 2 depends on Step 1's result
Reading 5 different files from disk ✅ Yes Files are independent of each other
Calling an API, then parsing its response with another tool ❌ No Parsing depends on the API response

How Agents Decide What to Call in Parallel

When an AI agent is equipped with tools, it doesn't just call them blindly. The agent's underlying language model reasons about which tools it needs and which ones can run at the same time. In modern agent frameworks, the model outputs a structured list of tool calls in a single response, and the framework handles executing them concurrently.

Agent Framework Parallelism

Here's a simplified example of how an agent framework might handle parallel tool calls under the hood:

from concurrent.futures import ThreadPoolExecutor, as_completed

class Agent:
    def __init__(self):
        self.tools = {}
    
    def register_tool(self, name, func):
        self.tools[name] = func
    
    def execute_parallel(self, tool_calls):
        """
        Execute multiple tool calls in parallel.
        
        tool_calls: list of dicts, e.g. [
            {"name": "get_weather", "args": {"city": "Paris"}},
            {"name": "search_web", "args": {"query": "Paris travel"}}
        ]
        """
        results = {}
        
        with ThreadPoolExecutor() as executor:
            # Submit all tool calls at once
            future_to_call = {}
            for call in tool_calls:
                tool_func = self.tools[call["name"]]
                future = executor.submit(tool_func, **call["args"])
                future_to_call[future] = call["name"]
            
            # Collect results as they complete
            for future in as_completed(future_to_call):
                tool_name = future_to_call[future]
                results[tool_name] = future.result()
        
        return results

# --- Usage ---
def get_weather(city):
    return f"Weather in {city}: Sunny, 75°F"

def search_web(query):
    return f"Top result for '{query}': Travel guide available"

def get_exchange_rate(currency):
    return f"USD to {currency}: 0.92"

agent = Agent()
agent.register_tool("get_weather", get_weather)
agent.register_tool("search_web", search_web)
agent.register_tool("get_exchange_rate", get_exchange_rate)

# Agent decides to call all three tools in parallel
tool_calls = [
    {"name": "get_weather", "args": {"city": "Paris"}},
    {"name": "search_web", "args": {"query": "Paris travel"}},
    {"name": "get_exchange_rate", "args": {"currency": "EUR"}},
]

results = agent.execute_parallel(tool_calls)
for tool_name, result in results.items():
    print(f"[{tool_name}] {result}")

In this example, the agent's language model would have decided that all three tools are needed and independent. The framework then uses a ThreadPoolExecutor to run them all at once, collecting results as each one finishes.

Async/Await: The Foundation of Parallelism

Under the hood, most modern agent frameworks use async/await (asynchronous programming) to achieve parallelism. Let's understand the basics.

The asyncio.gather() Function

The most common way to run multiple async tasks in parallel is asyncio.gather(). It takes multiple coroutines and runs them concurrently, returning all results in order.

import asyncio

async def fetch_data(source, delay):
    """Simulates fetching data from a source."""
    print(f"Fetching from {source}...")
    await asyncio.sleep(delay)  # Simulates network delay
    print(f"Done fetching from {source}!")
    return f"Data from {source}"

async def main():
    # Run three fetches in parallel
    results = await asyncio.gather(
        fetch_data("API_A", delay=3),
        fetch_data("API_B", delay=1),
        fetch_data("API_C", delay=2),
    )
    
    # Results are in the SAME ORDER as the calls,
    # regardless of which finished first
    for result in results:
        print(result)

asyncio.run(main())

# Output:
# Fetching from API_A...
# Fetching from API_B...
# Fetching from API_C...
# Done fetching from API_B!     (finished first, after 1s)
# Done fetching from API_C!     (finished second, after 2s)
# Done fetching from API_A!     (finished last, after 3s)
# Data from API_A               (results still in original order)
# Data from API_B
# Data from API_C
Important: asyncio.gather() preserves the order of results, matching the order you passed the tasks in, even if they finish in a different order. This is critical for agents that need to match results back to the correct tool call.

Handling Failures Gracefully

When running tools in parallel, what happens if one of them fails? By default, asyncio.gather() will raise an exception if any task fails. But for agents, you often want to handle partial failures gracefully — getting results from the tools that succeeded while logging the ones that didn't.

import asyncio

async def reliable_tool(name):
    await asyncio.sleep(1)
    return f"{name}: Success ✓"

async def failing_tool(name):
    await asyncio.sleep(1)
    raise ValueError(f"{name}: Something went wrong!")

async def main():
    results = await asyncio.gather(
        reliable_tool("Weather API"),
        failing_tool("Broken Search Tool"),
        reliable_tool("Exchange Rate API"),
        return_exceptions=True  # Don't crash on failures
    )
    
    for i, result in enumerate(results):
        if isinstance(result, Exception):
            print(f"Task {i} FAILED: {result}")
        else:
            print(f"Task {i} succeeded: {result}")

asyncio.run(main())

# Output:
# Task 0 succeeded: Weather API: Success ✓
# Task 1 FAILED: Broken Search Tool: Something went wrong!
# Task 2 succeeded: Exchange Rate API: Success ✓

The return_exceptions=True parameter tells gather() to return exceptions as results instead of raising them. This lets the agent continue working with whatever results it did get.

Real-World Example: A Travel Planning Agent

Let's build a more complete example — a travel planning agent that gathers information from multiple sources in parallel before giving you a recommendation.

import asyncio
import json

# --- Tool Definitions ---

async def get_weather(city: str) -> dict:
    """Get current weather for a city."""
    await asyncio.sleep(1.5)  # Simulates API delay
    weather_data = {
        "Paris": {"temp_f": 72, "condition": "Sunny"},
        "Tokyo": {"temp_f": 68, "condition": "Cloudy"},
        "New York": {"temp_f": 55, "condition": "Rainy"},
    }
    return weather_data.get(city, {"temp_f": "N/A", "condition": "Unknown"})

async def get_attractions(city: str) -> list:
    """Get top attractions for a city."""
    await asyncio.sleep(1.0)
    attractions = {
        "Paris": ["Eiffel Tower", "Louvre Museum", "Notre-Dame"],
        "Tokyo": ["Shibuya Crossing", "Senso-ji", "Tokyo Tower"],
        "New York": ["Central Park", "Statue of Liberty", "Times Square"],
    }
    return attractions.get(city, [])

async def get_flight_price(origin: str, destination: str) -> dict:
    """Get estimated flight price."""
    await asyncio.sleep(2.0)
    return {
        "route": f"{origin} → {destination}",
        "price_usd": 850,
        "duration_hours": 8.5,
    }

async def get_exchange_rate(base: str, target: str) -> float:
    """Get currency exchange rate."""
    await asyncio.sleep(0.8)
    rates = {"USD_EUR": 0.92, "USD_JPY": 149.5, "USD_GBP": 0.79}
    return rates.get(f"{base}_{target}", 1.0)

# --- Agent Logic ---

async def plan_trip(city: str):
    print(f"🌍 Planning a trip to {city}...\n")
    
    # Agent decides: "I need weather, attractions, flight price, 
    # and exchange rate — all independent, so I'll call them in parallel!"
    
    weather, attractions, flight, rate = await asyncio.gather(
        get_weather(city),
        get_attractions(city),
        get_flight_price("San Francisco", city),
        get_exchange_rate("USD", "EUR" if city == "Paris" else "JPY"),
    )
    
    # Agent now reasons over ALL results together
    print(f"📍 Weather in {city}: {weather['temp_f']}°F, {weather['condition']}")
    print(f"🏛️ Top attractions: {', '.join(attractions)}")
    print(f"✈️  Flight: {flight['route']} — ${flight['price_usd']} ({flight['duration_hours']}h)")
    print(f"💱 Exchange rate: 1 USD = {rate}")
    
    # Simple recommendation logic
    score = 0
    if weather["condition"] == "Sunny":
        score += 2
    elif weather["condition"] == "Cloudy":
        score += 1
    if flight["price_usd"] < 1000:
        score += 1
    if len(attractions) >= 3:
        score += 1
    
    print(f"\n⭐ Trip Score: {score}/4")
    if score >= 3:
        print("🎉 Great choice! Highly recommended.")
    elif score >= 2:
        print("👍 Decent option. Worth considering.")
    else:
        print("🤔 Might want to reconsider or check other dates.")

# Run the agent
asyncio.run(plan_trip("Paris"))

Notice how the agent calls all four tools with a single asyncio.gather() call. Even though the flight price tool takes 2 seconds (the longest), the total wait is only about 2 seconds — not the sum of all four delays (which would be 5.3 seconds).

Performance Insight: In the sequential version, the total wait would be 1.5 + 1.0 + 2.0 + 0.8 = 5.3 seconds. In the parallel version, it's only ~2.0 seconds (the slowest tool). That's a 62% speedup — and the more tools you call, the bigger the savings!

Limiting Concurrency with Semaphores

Sometimes you can't run all tools in parallel. Maybe you're calling an API with a rate limit, or you don't want to overwhelm a server with 50 simultaneous requests. In these cases, you use a semaphore to limit how many tasks run at the same time.

import asyncio

async def call_api(tool_name: str, semaphore: asyncio.Semaphore):
    async with semaphore:  # Only N tasks can enter this block at once
        print(f"  → {tool_name}: Starting...")
        await asyncio.sleep(1)  # Simulates API call
        print(f"  ✓ {tool_name}: Done!")
        return f"Result from {tool_name}"

async def main():
    # Allow at most 3 concurrent tool calls
    semaphore = asyncio.Semaphore(3)
    
    tools = [f"Tool_{i}" for i in range(8)]
    
    tasks = [call_api(name, semaphore) for name in tools]
    results = await asyncio.gather(*tasks)
    
    print(f"\nAll {len(results)} tools completed.")

asyncio.run(main())

# Output:
#   → Tool_0: Starting...
#   → Tool_1: Starting...
#   → Tool_2: Starting...
#   ✓ Tool_0: Done!     (Tools 3-7 wait because semaphore is full)
#   ✓ Tool_1: Done!
#   ✓ Tool_2: Done!
#   → Tool_3: Starting...  (Now a slot opened up)
#   → Tool_4: Starting...
#   → Tool_5: Starting...
#   ✓ Tool_3: Done!
#   ✓ Tool_4: Done!
#   ✓ Tool_5: Done!
#   → Tool_6: Starting...
#   → Tool_7: Starting...
#   ✓ Tool_6: Done!
#   ✓ Tool_7: Done!
# 
# All 8 tools completed.

Even though we had 8 tools, only 3 ran at any given moment. This is essential for real-world agents that interact with rate-limited APIs.

Common Pitfalls

Parallel tool calls are powerful, but there are some common mistakes to watch out for:

  1. Calling dependent tools in parallel. If Tool B needs Tool A's output, you must call them sequentially. Running them in parallel means Tool B might execute before Tool A finishes, leading to errors or missing data.
  2. Forgetting error handling. When one tool in a parallel batch fails, it can crash the entire batch unless you use return_exceptions=True or wrap individual calls in try/except blocks.
  3. Ignoring rate limits. Firing off 100 API calls at once might get you blocked. Always consider using semaphores or batching strategies.
  4. Mixing sync and async code incorrectly. You can't call a blocking (synchronous) function inside an async context without using loop.run_in_executor(), or it will block the entire event loop and defeat the purpose of parallelism.
Watch Out: A common beginner mistake is wrapping synchronous (blocking) functions in async def without actually making them non-blocking. If your tool calls time.sleep() instead of asyncio.sleep(), or makes a blocking HTTP request, it will block the entire event loop and your "parallel" calls will run sequentially anyway!

Key Takeaways

  • Parallel tool calls allow an AI agent to execute multiple independent tools simultaneously, reducing total wait time from the sum of all tool durations to roughly the maximum.
  • Use parallel calls when tools are independent — one tool's input doesn't depend on another tool's output.
  • Python's asyncio.gather() is the primary mechanism for running async tasks concurrently. It preserves result order regardless of completion order.
  • Use return_exceptions=True with gather() to handle partial failures gracefully — critical for robust agents.
  • Semaphores (asyncio.Semaphore) let you limit the number of concurrent tool calls, which is essential for respecting API rate limits.
  • Be careful not to mix blocking synchronous code with async code — it can silently defeat your parallelism.
  • Parallel tool calls are one of the key features that make modern AI agents fast and responsive, especially when they need to gather information from multiple external sources.
