Choosing an LLM Provider

Welcome to Day 2! Now that you understand what AI agents are, it's time to choose the brain behind your agent: the Large Language Model (LLM). The LLM provider you select will shape your agent's capabilities, cost, and performance.

What Is an LLM Provider?

An LLM provider is a company that offers access to large language models through an API (Application Programming Interface). Instead of running a model on your own computer, you send requests to their servers and get responses back.

Think of it like this: An LLM provider is like a utility company. You don't build your own power plant—you plug into the grid and pay for what you use. Similarly, you don't need to train your own AI model—you connect to a provider and pay per request.

Major LLM Providers Compared

Here's a comparison of the most popular LLM providers for building AI agents:

Provider Popular Models Strengths Pricing Model Best For
OpenAI GPT-4o, GPT-4o-mini, o1 Strong reasoning, large ecosystem, function calling Per token (input/output) General-purpose agents, complex reasoning
Anthropic Claude 3.5 Sonnet, Claude 3 Haiku Excellent instruction following, long context, safety-focused Per token (input/output) Agents requiring careful instruction adherence
Google Gemini 1.5 Pro, Gemini 1.5 Flash Multimodal (text, images, audio), very long context Per token (input/output) Multimodal agents, large document processing
Groq Llama 3.1, Mixtral Extremely fast inference speeds Per token Real-time agents needing low latency
Ollama (Local) Llama, Mistral, Phi, and many more Free, runs locally, full privacy Free (uses your hardware) Learning, prototyping, privacy-sensitive apps

Key Factors to Consider

1. Cost

LLM APIs charge based on tokens. A token is roughly 3/4 of a word. Both your input (the prompt you send) and output (the response you receive) count toward your bill.

# Example: Estimating token usage with tiktoken (OpenAI's tokenizer)
import tiktoken

encoding = tiktoken.encoding_for_model("gpt-4o")

prompt = "You are a helpful assistant that summarizes articles."
text = "The quick brown fox jumps over the lazy dog."

prompt_tokens = len(encoding.encode(prompt))
text_tokens = len(encoding.encode(text))

print(f"Prompt tokens: {prompt_tokens}")  # ~12 tokens
print(f"Text tokens: {text_tokens}")      # ~10 tokens
print(f"Total input tokens: {prompt_tokens + text_tokens}")

# GPT-4o pricing (as of 2024):
# Input:  $2.50 per 1M tokens
# Output: $10.00 per 1M tokens
cost_per_request = ((prompt_tokens + text_tokens) / 1_000_000) * 2.50
print(f"Estimated input cost: ${cost_per_request:.6f}")

2. Latency

Latency is how long it takes to get a response. For interactive agents (like chatbots), low latency matters. For background tasks (like document processing), it matters less.

Pro tip: If you're building a real-time agent, test response times from different providers before committing. Groq and Google's Flash models are known for speed, while OpenAI's o1 model is slower but more thorough.

3. Context Window

The context window is how much text the model can process in a single request. If your agent needs to analyze long documents or maintain long conversations, you need a large context window.

  • OpenAI GPT-4o: 128K tokens (~96,000 words)
  • Anthropic Claude 3.5: 200K tokens (~150,000 words)
  • Google Gemini 1.5: 1M tokens (~750,000 words)

4. Function Calling & Tool Use

AI agents need to take actions—search the web, run code, query databases. This requires the LLM to support structured function calling.

# Example: Defining tools for an agent with OpenAI
from openai import OpenAI

client = OpenAI()

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "The city name, e.g. San Francisco"
                    }
                },
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "search_web",
            "description": "Search the web for information",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {
                        "type": "string",
                        "description": "The search query"
                    }
                },
                "required": ["query"]
            }
        }
    }
]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "What's the weather in Tokyo?"}
    ],
    tools=tools,
    tool_choice="auto"
)

# Check if the model wants to call a function
if response.choices[0].message.tool_calls:
    tool_call = response.choices[0].message.tool_calls[0]
    print(f"Function to call: {tool_call.function.name}")
    print(f"Arguments: {tool_call.function.arguments}")

Setting Up Your First LLM Connection

Let's write a simple script that connects to an LLM provider and sends a message. We'll use OpenAI as the example, but the pattern is similar for all providers.

# Install the OpenAI library first:
# pip install openai

from openai import OpenAI

# Initialize the client with your API key
# Store your API key in an environment variable, never hardcode it!
import os
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

def ask_llm(prompt: str, model: str = "gpt-4o-mini") -> str:
    """Send a prompt to the LLM and return the response."""
    response = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": "You are a helpful AI assistant."},
            {"role": "user", "content": prompt}
        ],
        temperature=0.7,  # Controls randomness (0 = deterministic, 1 = creative)
        max_tokens=500    # Limits response length
    )
    return response.choices[0].message.content

# Try it out!
answer = ask_llm("Explain what an AI agent is in one sentence.")
print(answer)
Security warning: Never hardcode API keys in your code. Always use environment variables or a secrets manager. If you accidentally commit a key to GitHub, revoke it immediately and generate a new one.

Using Other Providers

The good news is that most LLM providers follow a similar pattern. Here's how the same call looks with different providers:

# --- Anthropic (Claude) ---
# pip install anthropic
import anthropic

anthropic_client = anthropic.Anthropic(
    api_key=os.environ.get("ANTHROPIC_API_KEY")
)

response = anthropic_client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=500,
    system="You are a helpful AI assistant.",
    messages=[{"role": "user", "content": "Explain what an AI agent is in one sentence."}]
)
print(response.content[0].text)


# --- Google Gemini ---
# pip install google-generativeai
import google.generativeai as genai

genai.configure(api_key=os.environ.get("GOOGLE_API_KEY"))
model = genai.GenerativeModel("gemini-1.5-flash")
response = model.generate_content("Explain what an AI agent is in one sentence.")
print(response.text)


# --- Ollama (Local, Free) ---
# pip install ollama
import ollama

response = ollama.chat(
    model="llama3.1",
    messages=[{"role": "user", "content": "Explain what an AI agent is in one sentence."}]
)
print(response["message"]["content"])

Making Your Code Provider-Agnostic

As you build agents, you might want to switch between providers. A common pattern is to create a simple wrapper:

from enum import Enum

class Provider(Enum):
    OPENAI = "openai"
    ANTHROPIC = "anthropic"
    GOOGLE = "google"
    OLLAMA = "ollama"

def create_client(provider: Provider):
    """Factory function to create the right client for each provider."""
    if provider == Provider.OPENAI:
        from openai import OpenAI
        return OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))
    elif provider == Provider.ANTHROPIC:
        import anthropic
        return anthropic.Anthropic(api_key=os.environ.get("ANTHROPIC_API_KEY"))
    elif provider == Provider.GOOGLE:
        import google.generativeai as genai
        genai.configure(api_key=os.environ.get("GOOGLE_API_KEY"))
        return genai
    elif provider == Provider.OLLAMA:
        import ollama
        return ollama
    else:
        raise ValueError(f"Unknown provider: {provider}")

# Now you can switch providers with one line:
provider = Provider.OPENAI  # Change this to switch providers
client = create_client(provider)
print(f"Connected to {provider.value}")
Note: In a real project, you'd use libraries like LangChain or LlamaIndex that handle provider abstraction for you. We'll cover these in later lessons!

Key Takeaways

  • LLM providers give you access to powerful language models through APIs—you don't need to train your own.
  • Cost is based on tokens (roughly 3/4 of a word), charged for both input and output.
  • Latency matters for real-time agents; consider Groq or Flash models for speed.
  • Context window determines how much text the model can process at once—important for long documents or conversations.
  • Function calling is essential for agents that need to take actions (search, calculate, query databases).
  • Never hardcode API keys—always use environment variables.
  • You can make your code provider-agnostic by using factory patterns or libraries like LangChain.
  • For learning and prototyping, Ollama lets you run models locally for free.
