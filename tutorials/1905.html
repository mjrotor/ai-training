Building the Full Support Agent

Learn about building the full support agent.

What Is a Full Support Agent?

So far, you have built individual pieces of an AI system — a classifier, a knowledge base, and a response generator. Now it is time to connect everything into a single, working support agent that can handle real user queries from start to finish.

A full support agent is an AI system that can:

  • Receive a user message
  • Understand what the user needs (intent classification)
  • Retrieve relevant information (knowledge base lookup)
  • Generate a helpful, accurate response
  • Escalate to a human when necessary

Think of it like assembling a factory line. Each station does one job, and the product moves from station to station until it is complete.

Why build a full agent? In real-world applications, isolated components are useful for testing, but users interact with a single system. Combining them teaches you how to manage data flow between modules — a critical skill for any AI engineer.

Designing the Agent Architecture

Before writing code, let's map out how data flows through the system. A well-designed architecture makes debugging and extending your agent much easier.

The Pipeline Stages

  1. Input Layer: Receives the raw user message and cleans it.
  2. Classification Layer: Determines the intent (billing, technical, general).
  3. Retrieval Layer: Searches the knowledge base for relevant context.
  4. Response Layer: Generates a reply using the classified intent and retrieved context.
  5. Output Layer: Formats and returns the response, or escalates if confidence is low.
# High-level pipeline pseudocode
def support_agent_pipeline(user_message):
    # Stage 1: Clean input
    cleaned = preprocess(user_message)

    # Stage 2: Classify intent
    intent = classify_intent(cleaned)

    # Stage 3: Retrieve context
    context = search_knowledge_base(cleaned, intent)

    # Stage 4: Generate response
    response = generate_response(intent, context)

    # Stage 5: Decide output or escalation
    if response.confidence < 0.5:
        return escalate_to_human(user_message)
    return response
Design tip: Keep each layer independent. If you later swap out your classifier for a better model, the rest of the pipeline should not break. This principle is called separation of concerns.

Building the Support Agent Class

Let's create a Python class that brings all the pieces together. This class will be the single entry point for your support system.

Defining the Class Structure

import re

class SupportAgent:
    def __init__(self, knowledge_base, classifier, responder):
        self.kb = knowledge_base
        self.classifier = classifier
        self.responder = responder
        self.conversation_log = []

    def preprocess(self, text):
        """Clean and normalize user input."""
        text = text.strip()
        text = re.sub(r'\s+', ' ', text)
        text = text.lower()
        return text

    def classify(self, text):
        """Determine the intent of the message."""
        return self.classifier.predict(text)

    def retrieve(self, text, intent):
        """Search knowledge base for relevant context."""
        results = self.kb.search(text, top_k=3)
        return results

    def respond(self, text, intent, context):
        """Generate a response based on intent and context."""
        return self.responder.generate(intent, context)

    def log_interaction(self, user_msg, agent_msg):
        """Store the conversation for review."""
        self.conversation_log.append({
            "user": user_msg,
            "agent": agent_msg
        })

    def handle(self, user_message):
        """Main entry point — runs the full pipeline."""
        cleaned = self.preprocess(user_message)
        intent = self.classify(cleaned)
        context = self.retrieve(cleaned, intent)
        response = self.respond(cleaned, intent, context)
        self.log_interaction(user_message, response)
        return response

Notice how the handle() method orchestrates every stage. A caller only needs to pass a user message and receive a response — the complexity is hidden inside the class.

Adding Escalation Logic

Not every query can be answered by an AI. A production support agent must know when to hand off to a human. This is called escalation.

When Should the Agent Escalate?

  • Low confidence: The classifier or responder is unsure.
  • Out-of-scope: The query falls outside the knowledge base.
  • Sentiment threshold: The user is frustrated or angry.
  • Repetitive failures: The same question was asked multiple times without resolution.
def should_escalate(self, intent, context, response):
    """Decide whether to escalate to a human agent."""
    # Low confidence from classifier
    if intent.get("confidence", 1.0) < 0.4:
        return True

    # No relevant context found
    if not context or len(context) == 0:
        return True

    # Repeated unresolved queries
    recent = self.conversation_log[-3:]
    if len(recent) == 3:
        user_msgs = [r["user"] for r in recent]
        if len(set(user_msgs)) == 1:
            return True  # Same message sent 3 times

    return False

def handle_with_escalation(self, user_message):
    """Pipeline with escalation check."""
    cleaned = self.preprocess(user_message)
    intent = self.classify(cleaned)
    context = self.retrieve(cleaned, intent)
    response = self.respond(cleaned, intent, context)

    if self.should_escalate(intent, context, response):
        return {
            "type": "escalation",
            "message": "Connecting you to a human agent...",
            "original_query": user_message
        }

    self.log_interaction(user_message, response)
    return {"type": "response", "message": response}
Important: Always log escalated queries. These logs are gold mines for improving your knowledge base and training data. Every escalation is a signal that your agent has a gap.

Comparing Agent Architectures

There are several ways to structure a support agent. Here is a comparison of the most common approaches:

Architecture Pros Cons Best For
Pipeline (Sequential) Simple, easy to debug Rigid, no backtracking Small support teams
Router-Based Flexible routing per intent More complex setup Multi-department teams
LLM-Orchestrated Handles open-ended queries Higher cost, slower Complex, varied queries
Hybrid Best of both worlds Hardest to maintain Enterprise applications

In this lesson, we use the Pipeline architecture because it is the easiest to understand and extend. As you gain experience, you can migrate to a hybrid approach.

Handling Conversation State

Real conversations have context. A user might say "What about refunds?" — but "refunds" only makes sense if you know what was discussed before. Your agent needs to track conversation state.

class ConversationManager:
    def __init__(self):
        self.sessions = {}

    def get_session(self, session_id):
        if session_id not in self.sessions:
            self.sessions[session_id] = {
                "history": [],
                "context": {},
                "turn_count": 0
            }
        return self.sessions[session_id]

    def add_message(self, session_id, role, text):
        session = self.get_session(session_id)
        session["history"].append({"role": role, "text": text})
        session["turn_count"] += 1

    def get_context_window(self, session_id, max_turns=5):
        """Return the last N turns for context."""
        session = self.get_session(session_id)
        return session["history"][-max_turns:]

# Integrating with SupportAgent
class StatefulSupportAgent(SupportAgent):
    def __init__(self, knowledge_base, classifier, responder):
        super().__init__(knowledge_base, classifier, responder)
        self.conversations = ConversationManager()

    def handle(self, session_id, user_message):
        self.conversations.add_message(session_id, "user", user_message)

        # Include conversation history in context
        history = self.conversations.get_context_window(session_id)
        cleaned = self.preprocess(user_message)
        intent = self.classify(cleaned)
        context = self.retrieve(cleaned, intent)
        response = self.respond(cleaned, intent, context)

        self.conversations.add_message(session_id, "agent", response)
        self.log_interaction(user_message, response)
        return response
Context window: The get_context_window method limits how much history is included. Without this limit, your agent would become slow and expensive as conversations grow longer.

Testing Your Full Agent

Now let's put everything together and test the agent with a few sample queries.

# Mock components for testing
class MockClassifier:
    def predict(self, text):
        if "refund" in text or "money" in text:
            return {"intent": "billing", "confidence": 0.9}
        elif "error" in text or "broken" in text:
            return {"intent": "technical", "confidence": 0.85}
        return {"intent": "general", "confidence": 0.7}

class MockKnowledgeBase:
    def search(self, text, top_k=3):
        return ["Relevant article about: " + text[:30]]

class MockResponder:
    def generate(self, intent, context):
        return f"Here is help regarding your {intent} question."

# Create and test the agent
agent = StatefulSupportAgent(
    knowledge_base=MockKnowledgeBase(),
    classifier=MockClassifier(),
    responder=MockResponder()
)

# Simulate a conversation
session = "user-123"
print(agent.handle(session, "I need a refund for my last order"))
print(agent.handle(session, "Never mind, the system is broken now"))
print(agent.handle(session, "This is urgent, I need help ASAP"))

You should see three responses. The third one should trigger escalation because it contains the keyword "urgent".

Testing tip: Always test with edge cases — empty messages, very long messages, messages in different languages, and messages with special characters. Real users will surprise you.

Key Takeaways

  • A full support agent connects classification, retrieval, and response generation into a single pipeline.
  • Use a class-based architecture to encapsulate logic and keep components modular and testable.
  • Escalation logic is essential — your agent must know when it cannot help and hand off to a human.
  • Conversation state tracking allows your agent to understand context across multiple turns.
  • The Pipeline architecture is the simplest starting point; you can evolve to hybrid architectures as your needs grow.
  • Always log interactions — they are your primary source of improvement data.
  • Test with edge cases early and often to build a robust agent.
