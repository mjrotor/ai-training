Types of Agent Failures

Learn about types of agent failures.

Understanding Agent Failures

As you begin building AI agents, it's important to understand that agents don't always behave perfectly. Just like humans make mistakes, agents can fail in predictable and unpredictable ways. In this lesson, we'll explore the most common types of agent failures, why they happen, and how to recognize them early.

By understanding failure modes, you'll be better equipped to design robust agents, debug issues when they arise, and set realistic expectations for what your agent can and cannot do reliably.

What Is an Agent Failure?

An agent failure occurs when an AI agent does not achieve its intended goal. This can range from a minor hiccup — like choosing the wrong tool — to a complete breakdown where the agent gets stuck in a loop or produces harmful output.

Key Concept: An agent failure is not the same as a model hallucination. A hallucination is one type of failure, but failures also include planning errors, tool misuse, and goal drift.

Categories of Agent Failures

Agent failures generally fall into four major categories. Understanding these categories will help you diagnose problems quickly when building and testing your own agents.

1. Planning Failures

Planning failures happen when the agent creates an incorrect or inefficient sequence of steps to reach its goal. The agent might skip essential steps, repeat unnecessary ones, or choose a strategy that cannot possibly work.

Common symptoms of planning failures include:

  • The agent jumps to a conclusion without gathering enough information
  • The agent repeats the same action multiple times expecting a different result
  • The agent chooses an impossible or contradictory sequence of steps
# Example: A planning failure in a simple agent loop
# The agent keeps calling the same tool without updating its plan

def broken_agent_loop(goal, max_steps=10):
    steps_taken = []
    for i in range(max_steps):
        # BUG: The agent always picks the same action
        # regardless of what it has already done
        action = "search_web"  # Hardcoded — never adapts!
        result = execute_tool(action, goal)
        steps_taken.append(action)
        if goal_achieved(result):
            return steps_taken
    return steps_taken  # Exhausted steps without reaching goal

# This agent will call "search_web" every single time,
# even if it already has the information it needs.
# That's a planning failure.

2. Tool-Use Failures

Tool-use failures occur when an agent selects the wrong tool, passes incorrect arguments to a tool, or misinterprets the output a tool returns. Since agents rely on tools to interact with the outside world, these failures can have cascading effects.

# Example: A tool-use failure with incorrect arguments

def agent_calculate(agent, query):
    # The agent decides to use a calculator tool
    # but passes the wrong argument format
    if "calculate" in query.lower():
        # BUG: Passing the entire query string instead of
        # extracting just the mathematical expression
        result = calculator_tool(query)  # Should be: calculator_tool("5 + 3")
        return result
    return "I don't understand."

# If query is "Can you calculate 5 + 3 for me?",
# the calculator tool receives the full sentence
# instead of just "5 + 3", causing an error.
Warning: Tool-use failures are among the hardest to debug because the agent may not realize it made an error. It might confidently report a wrong answer derived from a tool that received bad input.

3. Reasoning Failures

Reasoning failures happen when the agent's internal logic breaks down. The agent might draw incorrect conclusions from valid data, fail to recognize contradictions, or apply rules incorrectly.

These failures are particularly tricky because the agent often thinks it is being logical. The steps may look reasonable in isolation, but the overall chain of reasoning leads to a wrong answer.

# Example: A reasoning failure with flawed logic

def agent_discount_calculator(agent, items):
    total = sum(item.price for item in items)
    
    # BUG: The agent applies a discount incorrectly
    # It checks if total > 100 and applies 10% off,
    # but then ALSO applies a "bulk" discount on top
    # without checking if the conditions are mutually exclusive
    
    if total > 100:
        total = total * 0.90  # 10% off
    
    if len(items) > 5:
        total = total * 0.95  # Additional 5% off
    
    # The agent doesn't realize that for orders over $100
    # with more than 5 items, it's applying a stacked discount
    # that the business rules don't allow.
    
    return total

4. Goal Drift

Goal drift occurs when an agent gradually loses sight of its original objective. This commonly happens in long-running tasks where the agent gets sidetracked by intermediate steps and forgets what it was originally asked to do.

Tip: One effective way to combat goal drift is to include the original goal in every step of the agent's reasoning loop. Think of it as giving the agent a "north star" to refer back to. 
# Example: Goal drift in a multi-step agent

def agent_with_goal_drift(goal, context):
    current_task = goal
    history = []
    
    for step in range(20):
        # BUG: The agent updates current_task based on
        # intermediate results, losing the original goal
        current_task = agent.reason(f"Given this context: {context}, "
                                     f"what should I do next for: {current_task}?")
        history.append(current_task)
        
        # After several iterations, current_task may have
        # drifted far from the original goal
        
    return history

# Fix: Keep the original goal accessible at every step
def agent_with_goal_anchor(original_goal, context):
    current_task = original_goal
    history = []
    
    for step in range(20):
        current_task = agent.reason(
            f"Original goal: {original_goal}\n"
            f"Current progress: {history}\n"
            f"What should I do next?"
        )
        history.append(current_task)
        
    return history

Comparing Failure Types

The table below summarizes the four main failure categories, their common causes, and strategies for prevention.

Failure Type Common Cause Symptom Prevention Strategy
Planning Rigid or missing step logic Repeats actions or skips steps Use adaptive planning with step validation
Tool-Use Wrong tool or bad arguments Tool errors or nonsensical results Validate tool inputs before calling
Reasoning Flawed logic or missing context Confident but incorrect answers Add self-verification steps
Goal Drift Long tasks without goal reference Agent pursues wrong objective Anchor the original goal in every step

Detecting Failures in Practice

Now that you understand the types of failures, let's look at how you can detect them when running your own agents. A good practice is to build guardrails — checks that run alongside your agent to catch failures early.

# Example: Simple failure detection guardrails

class AgentGuardrails:
    def __init__(self, max_repeated_actions=3, max_steps=50):
        self.max_repeated_actions = max_repeated_actions
        self.max_steps = max_steps
    
    def check_repeated_actions(self, action_history):
        """Detect planning failures from repeated actions."""
        if len(action_history) < 2:
            return False
        last_action = action_history[-1]
        recent = action_history[-self.max_repeated_actions:]
        return all(a == last_action for a in recent)
    
    def check_step_limit(self, step_count):
        """Detect runaway agents."""
        return step_count >= self.max_steps
    
    def check_goal_relevance(self, original_goal, current_action, llm):
        """Detect goal drift using the LLM itself."""
        prompt = (
            f"Original goal: {original_goal}\n"
            f"Current action: {current_action}\n"
            f"Is this action relevant to the original goal? "
            f"Answer yes or no."
        )
        response = llm.generate(prompt)
        return "no" in response.lower()

# Usage
guardrails = AgentGuardrails(max_repeated_actions=3, max_steps=50)

Exercise: Identify the Failure

Read the following agent scenario and identify which type of failure is occurring. Then propose a fix.

Exercise

An agent is asked to "Find the population of France and compare it to Germany." The agent does the following:

  1. Calls search("population of France") → gets 68 million
  2. Calls search("population of France") → gets 68 million
  3. Calls search("population of France") → gets 68 million
  4. Calls search("population of France") → gets 68 million
  5. Returns: "The population of France is 68 million. I could not find Germany's population."

Questions:

  1. What type(s) of failure is the agent exhibiting?
  2. What is the root cause?
  3. How would you fix this agent?

1. Failure types: The agent exhibits a planning failure (it repeats the same search instead of moving to the next step) and a goal drift (it forgets that the task also requires finding Germany's population).

2. Root cause: The agent's loop does not track which sub-tasks have been completed. It keeps searching for France because it has no mechanism to recognize it already has that data and should move on.

3. Fix: Add a task checklist that the agent updates as it completes each sub-task:

task_plan = {
    "find_france_population": "pending",
    "find_germany_population": "pending",
    "compare_populations": "pending"
}

# After each successful tool call, update the status:
task_plan["find_france_population"] = "done"

# Only proceed to the next pending task
next_task = next(
    (t for t, status in task_plan.items() if status == "pending"),
    None
)

Key Takeaways

  • Agent failures fall into four main categories: planning, tool-use, reasoning, and goal drift.
  • Planning failures occur when the agent cannot create or follow a valid sequence of steps to reach its goal.
  • Tool-use failures happen when the agent selects the wrong tool, passes bad arguments, or misinterprets tool output.
  • Reasoning failures involve flawed logic that leads to confident but incorrect conclusions.
  • Goal drift happens when an agent loses sight of its original objective during long or complex tasks.
  • You can detect and prevent many failures by building guardrails — automated checks that monitor agent behavior during execution.
  • Including the original goal at every step of the agent's reasoning is one of the simplest and most effective ways to prevent goal drift.
