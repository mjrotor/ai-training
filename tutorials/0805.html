Building a Resilient Agent

Learn about building a resilient agent.

What Is a Resilient Agent?

As you build more complex AI agents, you'll encounter situations where things go wrong: APIs fail, tools return unexpected results, or the agent gets stuck in a loop. A resilient agent is one that can handle these failures gracefully, recover when possible, and provide useful feedback when it can't.

Think of resilience like a GPS navigation system. When you miss a turn, it doesn't give up — it recalculates. Your agents should do the same.

Common Failure Points

Before we can build resilience, we need to understand where agents typically fail:

  • Tool failures: External APIs go down, return errors, or timeout
  • Invalid outputs: The LLM produces malformed tool calls or unexpected formats
  • Infinite loops: The agent keeps calling the same tool repeatedly
  • Context overflow: The conversation history grows too large
  • Hallucinations: The agent makes up information or tool names
Warning: In production, unhandled failures can lead to poor user experiences, wasted API costs, and even security vulnerabilities. Always plan for failure from the start.

Error Handling Patterns

Let's explore practical patterns you can implement today.

1. Try-Except Wrappers

The simplest resilience pattern is wrapping tool calls in try-except blocks:

def safe_tool_call(tool_func, *args, max_retries=3):
    """Call a tool with automatic retry logic."""
    for attempt in range(max_retries):
        try:
            result = tool_func(*args)
            return {"success": True, "result": result}
        except ConnectionError:
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)  # Exponential backoff
                continue
            return {"success": False, "error": "Connection failed after retries"}
        except Exception as e:
            return {"success": False, "error": str(e)}
    return {"success": False, "error": "Max retries exceeded"}

2. Circuit Breaker Pattern

When a tool fails repeatedly, stop calling it temporarily to avoid wasting resources:

class CircuitBreaker:
    def __init__(self, failure_threshold=3, recovery_time=30):
        self.failure_count = 0
        self.failure_threshold = failure_threshold
        self.recovery_time = recovery_time
        self.last_failure_time = None
        self.state = "CLOSED"  # CLOSED, OPEN, HALF_OPEN
    
    def call(self, func, *args):
        if self.state == "OPEN":
            if time.time() - self.last_failure_time > self.recovery_time:
                self.state = "HALF_OPEN"
            else:
                raise Exception("Circuit is OPEN - tool unavailable")
        
        try:
            result = func(*args)
            self.failure_count = 0
            self.state = "CLOSED"
            return result
        except Exception as e:
            self.failure_count += 1
            self.last_failure_time = time.time()
            if self.failure_count >= self.failure_threshold:
                self.state = "OPEN"
            raise e
Tip: The circuit breaker is especially useful for external APIs that might be down for extended periods. It prevents your agent from hammering a broken service.

3. Fallback Chains

When your primary tool fails, have a backup plan:

def get_weather_with_fallbacks(location):
    """Try multiple weather services in order."""
    services = [
        ("primary", call_weather_api_v2),
        ("fallback", call_weather_api_v1),
        ("cache", get_cached_weather),
    ]
    
    for name, service in services:
        try:
            result = service(location)
            if result:
                return {"source": name, "data": result}
        except Exception as e:
            print(f"{name} failed: {e}")
            continue
    
    return {"source": "none", "error": "All services unavailable"}

Loop Detection and Prevention

One of the most common agent failures is getting stuck in a loop. Here's how to prevent it:

class LoopDetector:
    def __init__(self, max_repeats=3):
        self.call_history = []
        self.max_repeats = max_repeats
    
    def check_loop(self, tool_name, args):
        """Check if we're repeating the same call too often."""
        call_signature = f"{tool_name}:{str(args)}"
        self.call_history.append(call_signature)
        
        # Check last N calls
        recent = self.call_history[-self.max_repeats:]
        if len(recent) == self.max_repeats and len(set(recent)) == 1:
            return True  # Loop detected!
        return False
    
    def reset(self):
        self.call_history = []
Info: Loop detection is crucial for agents that use tools iteratively. Without it, an agent might call the same failing tool hundreds of times, burning through your API budget.

Graceful Degradation

When all else fails, your agent should degrade gracefully rather than crashing:

def resilient_agent_step(agent, user_input):
    try:
        # Normal agent execution
        response = agent.run(user_input)
        return response
    except ToolExecutionError as e:
        # Tool failed but agent can continue
        return f"I encountered an issue with one of my tools: {e}. Let me try a different approach."
    except ContextOverflowError:
        # Summarize and continue
        agent.summarize_history()
        return "Let me summarize our conversation and continue..."
    except Exception as e:
        # Unknown error - log and inform user
        log_error(e)
        return "I'm having trouble processing your request. Please try again or rephrase."

Comparison: Resilience Strategies

Strategy Best For Complexity When to Use
Try-Except Simple tool calls Low Always implement first
Circuit Breaker External APIs Medium When tools fail frequently
Fallback Chains Critical features Medium When uptime matters
Loop Detection Iterative agents Low Any agent with loops
Graceful Degradation User-facing agents High Production systems

Putting It All Together

Here's a complete resilient agent wrapper that combines these patterns:

class ResilientAgent:
    def __init__(self, agent):
        self.agent = agent
        self.loop_detector = LoopDetector()
        self.circuit_breakers = {}
    
    def run(self, user_input):
        try:
            # Check for loops before executing
            if self.loop_detector.check_loop("main", user_input):
                return "I notice we're going in circles. Let me try something different."
            
            # Execute with circuit breaker protection
            response = self._execute_with_protection(user_input)
            self.loop_detector.reset()
            return response
            
        except Exception as e:
            return self._handle_error(e)
    
    def _execute_with_protection(self, input):
        # Apply circuit breakers to each tool
        for tool in self.agent.tools:
            if tool.name not in self.circuit_breakers:
                self.circuit_breakers[tool.name] = CircuitBreaker()
        return self.agent.run(input)
    
    def _handle_error(self, error):
        # Log and return user-friendly message
        print(f"Agent error: {error}")
        return "I encountered an issue. Please try again."
Exercise: Add Resilience to Your Agent

Take the simple agent you built in the previous lesson and add the following resilience features:

  1. Wrap all tool calls in try-except blocks
  2. Add a loop detector that stops after 3 repeated calls
  3. Implement a fallback for your primary tool
  4. Add a graceful error message for users

Test your agent by simulating a tool failure. Does it handle the error gracefully?

import time

class ResilientSimpleAgent:
    def __init__(self):
        self.call_count = {}
        self.max_repeats = 3
    
    def run(self, user_input):
        # Check for loops
        if self._is_looping(user_input):
            return "I'm going in circles. Let's try something else."
        
        try:
            # Try primary tool
            result = self._call_primary_tool(user_input)
            return result
        except Exception as primary_error:
            print(f"Primary failed: {primary_error}")
            try:
                # Fallback tool
                return self._call_fallback_tool(user_input)
            except Exception as fallback_error:
                return f"I'm having trouble: {fallback_error}. Please try again."
    
    def _is_looping(self, input):
        self.call_count[input] = self.call_count.get(input, 0) + 1
        return self.call_count[input] > self.max_repeats
    
    def _call_primary_tool(self, input):
        # Simulate tool that might fail
        if "fail" in input.lower():
            raise Exception("Tool unavailable")
        return f"Result from primary: {input}"
    
    def _call_fallback_tool(self, input):
        return f"Result from fallback: {input}"

# Test it
agent = ResilientSimpleAgent()
print(agent.run("Hello"))  # Normal
print(agent.run("fail test"))  # Triggers fallback
print(agent.run("Hello"))  # Loop detection kicks in after 3 calls

Key Takeaways

  • Always expect failure: External tools will fail, APIs will timeout, and LLMs will hallucinate
  • Start simple: Begin with try-except wrappers before adding complex patterns
  • Prevent loops: Track repeated calls and set maximum limits
  • Have fallbacks: Critical features should have backup options
  • Fail gracefully: Users should never see raw error messages
  • Log everything: Even when handling errors silently, log them for debugging
