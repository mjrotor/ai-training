Choosing the Right Pattern

Learn about choosing the right pattern.

What Are AI Agent Patterns?

As you build more AI agents, you'll quickly notice that certain problems keep appearing. Maybe your agent needs to reason through a complex task step by step. Maybe it needs to call external tools. Or maybe it needs to collaborate with other agents. Over time, researchers and engineers have developed reusable design patterns to solve these recurring problems.

Think of agent patterns like recipes in cooking. You don't invent a new way to make pasta every time — you follow a proven recipe. Similarly, agent patterns give you a proven structure for building reliable, maintainable AI agents.

What you'll learn today: We'll cover the most important agent patterns, when to use each one, and how to choose the right pattern for your specific use case.

The Five Core Agent Patterns

There are five foundational patterns that cover the vast majority of agent architectures. Let's walk through each one.

1. The ReAct Pattern (Reason + Act)

The ReAct pattern is the most widely used agent pattern. The agent alternates between reasoning (thinking about what to do next) and acting (calling a tool or performing an action). After each action, it observes the result and decides what to do next.

from openai import OpenAI

client = OpenAI()

def react_agent(user_question, tools):
    messages = [
        {"role": "system", "content": "You are a helpful assistant. Think step by step, then use tools when needed."},
        {"role": "user", "content": user_question}
    ]
    
    while True:
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools
        )
        
        reply = response.choices[0].message
        messages.append(reply)
        
        if reply.tool_calls:
            for call in reply.tool_calls:
                result = execute_tool(call)
                messages.append({
                    "role": "tool",
                    "tool_call_id": call.id,
                    "content": result
                })
        else:
            return reply.content  # Final answer

def execute_tool(tool_call):
    # Route to the appropriate tool
    if tool_call.function.name == "search_web":
        return search_web(json.loads(tool_call.function.arguments))
    elif tool_call.function.name == "calculate":
        return calculate(json.loads(tool_call.function.arguments))

This pattern is great when your agent needs to interact with external tools and make decisions based on what it finds.

2. The Plan-and-Execute Pattern

Sometimes a task is too complex to figure out on the fly. The Plan-and-Execute pattern has the agent first create a full plan, then execute each step one by one. This is especially useful for multi-step tasks where the order of operations matters.

def plan_and_execute(user_task):
    # Step 1: Generate a plan
    plan_response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "Break the user's task into a numbered list of steps. Be specific."},
            {"role": "user", "content": user_task}
        ]
    )
    plan = plan_response.choices[0].message.content
    steps = parse_steps(plan)  # Parse into a list
    
    # Step 2: Execute each step
    results = []
    for i, step in enumerate(steps):
        result = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": f"Complete this step. Previous results: {results}"},
                {"role": "user", "content": step}
            ]
        )
        results.append(result.choices[0].message.content)
    
    return results[-1]  # Return final result

3. The Chain-of-Thought Pattern

The Chain-of-Thought (CoT) pattern encourages the model to reason through problems step by step before giving a final answer. This dramatically improves performance on complex reasoning tasks.

def chain_of_thought(question):
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "Think through this problem step by step. Show your reasoning before giving the final answer."},
            {"role": "user", "content": question}
        ]
    )
    return response.choices[0].message.content

# Example usage
answer = chain_of_thought("If a store has 120 apples and sells 35, then receives a shipment of 50, how many apples are left?")
print(answer)
# Output: "Step 1: Start with 120 apples. Step 2: Subtract 35 sold apples = 85. Step 3: Add 50 from shipment = 135. Final answer: 135 apples."

4. The Multi-Agent Pattern

When tasks become highly complex, a single agent may not be enough. The Multi-Agent pattern uses multiple specialized agents working together, each responsible for a different part of the task.

class MultiAgentSystem:
    def __init__(self):
        self.researcher = Agent(role="researcher")
        self.writer = Agent(role="writer")
        self.reviewer = Agent(role="reviewer")
    
    def run(self, topic):
        # Agent 1: Research
        research = self.researcher.run(f"Research everything about: {topic}")
        
        # Agent 2: Write based on research
        draft = self.writer.run(f"Write an article using this research: {research}")
        
        # Agent 3: Review and improve
        final = self.reviewer.run(f"Review and improve this draft: {draft}")
        
        return final

class Agent:
    def __init__(self, role):
        self.role = role
    
    def run(self, task):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": f"You are a {self.role}. Do your best work."},
                {"role": "user", "content": task}
            ]
        )
        return response.choices[0].message.content

5. The Tool-Use / Function-Calling Pattern

The Tool-Use pattern focuses on an agent that can call specific functions (APIs, databases, calculators) to accomplish tasks. The model decides when to call a tool and what arguments to pass.

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "The city name"}
                },
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "book_flight",
            "description": "Book a flight from origin to destination",
            "parameters": {
                "type": "object",
                "properties": {
                    "origin": {"type": "string"},
                    "destination": {"type": "string"},
                    "date": {"type": "string", "format": "date"}
                },
                "required": ["origin", "destination", "date"]
            }
        }
    }
]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "What's the weather in Tokyo?"}],
    tools=tools
)
# The model will automatically call get_weather with city="Tokyo"

Comparing the Patterns

Here's a side-by-side comparison to help you choose the right pattern for your use case:

Pattern Best For Complexity Tools Required Example Use Case
ReAct Dynamic tasks with tool calls Low–Medium External APIs Web search assistant
Plan-and-Execute Multi-step sequential tasks Medium Task planner Report generation
Chain-of-Thought Complex reasoning problems Low None Math/logic problems
Multi-Agent Large, complex workflows High Multiple agents Research + writing pipeline
Tool-Use API-driven automation Low–Medium Defined functions Booking systems, data queries

How to Choose the Right Pattern

Choosing the right pattern depends on several factors. Here's a decision framework:

  1. What is the task complexity? Simple tasks may only need Tool-Use or Chain-of-Thought. Complex workflows may need Plan-and-Execute or Multi-Agent.
  2. Does the agent need external data? If yes, ReAct or Tool-Use are strong candidates.
  3. Is the task sequential? If steps depend on each other, Plan-and-Execute keeps things organized.
  4. Do you need specialized expertise? Multi-Agent lets you assign different roles to different agents.
  5. What are your latency and cost constraints? Multi-Agent and Plan-and-Execute use more API calls, which increases cost and latency.
Pro tip: Start with the simplest pattern that solves your problem. You can always refactor to a more complex pattern later. Most production agents use a combination of patterns — for example, a ReAct agent that uses Chain-of-Thought reasoning internally.

Coding Exercise: Pick the Pattern

Exercise

You're building an AI agent that helps users plan a vacation. The agent needs to:

  • Search for flights based on user preferences
  • Find hotels at the destination
  • Create a day-by-day itinerary
  • Send the final plan to the user via email

Which pattern (or combination of patterns) would you choose? Write a brief explanation and a skeleton Python function that implements your chosen approach.

Recommended approach: A combination of Plan-and-Execute and Tool-Use. Plan-and-Execute handles the sequential nature of vacation planning (flights → hotels → itinerary → email), while Tool-Use handles the individual API calls.

def vacation_planner(destination, dates, preferences):
    # PLAN phase
    plan = generate_plan(destination, dates, preferences)
    # e.g., ["search_flights", "search_hotels", "create_itinerary", "send_email"]
    
    # EXECUTE phase
    context = {}
    for step in plan:
        if step == "search_flights":
            context["flights"] = search_flights(destination, dates)
        elif step == "search_hotels":
            context["hotels"] = search_hotels(destination, preferences)
        elif step == "create_itinerary":
            context["itinerary"] = create_itinerary(context, preferences)
        elif step == "send_email":
            send_email(context)
    
    return context

This keeps the workflow organized and makes it easy to add or remove steps later.

Common mistake: Don't jump to Multi-Agent for everything. It adds complexity and cost. If a single agent with ReAct or Plan-and-Execute can handle your task, that's usually the better choice.

Combining Patterns in Practice

In real-world applications, you'll rarely use just one pattern. Here are some common combinations:

  • ReAct + Chain-of-Thought: The agent reasons through each step before taking action. Great for research assistants.
  • Plan-and-Execute + Tool-Use: Each step in the plan involves calling a specific tool. Great for automation workflows.
  • Multi-Agent + ReAct: Each agent in the multi-agent system uses ReAct internally. Great for complex collaborative tasks.

The key is to start simple and add complexity only when you need it. A well-designed single-agent system with ReAct is often more reliable than a poorly designed multi-agent system.

Key Takeaways

  • ReAct is the go-to pattern for agents that need to reason and use tools dynamically.
  • Plan-and-Execute works best for tasks with clear, sequential steps.
  • Chain-of-Thought improves reasoning quality by making the model think step by step.
  • Multi-Agent systems divide complex work among specialized agents but add overhead.
  • Tool-Use is essential whenever your agent needs to interact with external systems.
  • Always start with the simplest pattern that meets your needs, then refactor as requirements grow.
  • Combining patterns is common in production — ReAct + CoT and Plan-and-Execute + Tool-Use are popular pairings.
  • Use the comparison table and decision framework above as a quick reference when architecting new agents.
