Message Passing

Learn about message passing.

What Is Message Passing?

In multi-agent systems, message passing is the primary mechanism by which agents communicate with each other. Think of it like sending letters between coworkers — each agent can send, receive, and act on messages to coordinate tasks, share information, or delegate work.

Today, we'll explore how message passing works in practice and build a simple two-agent system that communicates via messages.

Why Message Passing Matters

  • Agents can work in parallel without shared memory
  • Communication is explicit and traceable
  • Enables modular, decoupled agent design
  • Supports both synchronous and asynchronous workflows
Note: Message passing is the backbone of most multi-agent frameworks, including LangGraph, AutoGen, and CrewAI. Understanding it deeply will help you design robust agent architectures.

Basic Message Structure

A message typically contains:

  • Sender: Who sent the message
  • Receiver: Who should receive it
  • Content: The actual data or instruction
  • Type: Optional category (e.g., "request", "response", "error")
class Message:
    def __init__(self, sender, receiver, content, msg_type="info"):
        self.sender = sender
        self.receiver = receiver
        self.content = content
        self.msg_type = msg_type

    def __repr__(self):
        return f"[{self.msg_type.upper()}] {self.sender} → {self.receiver}: {self.content}"

Building a Simple Message Bus

A message bus (or broker) routes messages between agents. Here's a minimal implementation:

class MessageBus:
    def __init__(self):
        self.agents = {}
        self.log = []

    def register(self, agent):
        self.agents[agent.name] = agent

    def send(self, message):
        self.log.append(message)
        if message.receiver in self.agents:
            self.agents[message.receiver].receive(message)
        else:
            print(f"Warning: No agent named '{message.receiver}' found.")

Connecting Agents to the Bus

class Agent:
    def __init__(self, name, bus):
        self.name = name
        self.bus = bus
        self.inbox = []

    def send(self, receiver, content, msg_type="info"):
        msg = Message(self.name, receiver, content, msg_type)
        self.bus.send(msg)

    def receive(self, message):
        self.inbox.append(message)
        print(f"{self.name} received: {message}")

Putting It All Together

# Setup
bus = MessageBus()
agent_a = Agent("Planner", bus)
agent_b = Agent("Executor", bus)

bus.register(agent_a)
bus.register(agent_b)

# Communication
agent_a.send("Executor", "Please fetch user data for ID 42", "request")
agent_b.send("Planner", "Data retrieved successfully", "response")
Tip: Always validate receiver names before sending. Silent failures in message passing can lead to hard-to-debug issues in complex systems.

Synchronous vs. Asynchronous Messaging

Feature Synchronous Asynchronous
Blocking? Yes — sender waits No — sender continues
Complexity Lower Higher
Use Case Simple request-response Parallel task coordination

Exercise: Build a Three-Agent Pipeline

Exercise

Create three agents: Collector, Processor, and Reporter. The Collector sends raw data to the Processor, which transforms it and sends the result to the Reporter. Implement the full pipeline using the MessageBus and Agent classes above.

bus = MessageBus()

collector = Agent("Collector", bus)
processor = Agent("Processor", bus)
reporter = Agent("Reporter", bus)

bus.register(collector)
bus.register(processor)
bus.register(reporter)

# Simulate pipeline
collector.send("Processor", "[1, 2, 3, 4, 5]", "data")
processor.send("Reporter", "Sum: 15", "result")
Warning: In production systems, always handle message serialization (e.g., JSON) and network failures. This example assumes in-memory communication only.

Key Takeaways

  • Message passing enables decoupled, scalable agent communication
  • A message should include sender, receiver, content, and type
  • A message bus centralizes routing and logging
  • Synchronous messaging is simpler; asynchronous enables parallelism
  • Always validate receivers and handle failures gracefully
