Defining Your First Tool

Learn about defining your first tool.

What Is a Tool, Really?

In the world of AI agents, a tool is a function that the agent can call to interact with the outside world. Think of it as giving your agent a superpower — the ability to do something beyond just generating text. Without tools, an AI agent is like a brilliant person locked in a room with no phone, no computer, and no way to affect anything. Tools are how agents break out of that room.

At its core, a tool is just a function with three things:

  • A name — so the agent knows what to call it
  • A description — so the agent knows when and why to use it
  • A function body — the actual code that runs when the tool is invoked

Why Tools Matter

Imagine you ask an AI agent, "What's the weather in Tokyo?" Without a tool, the agent can only guess based on its training data — and it might give you outdated or completely wrong information. With a weather tool, the agent can call a real API and return accurate, live data.

Tools transform an AI from a knowledge engine into an action engine. Here are some common categories of tools:

Category Example What It Does
Data Retrieval Web Search API Fetches real-time information from the internet
Computation Calculator Function Performs math the agent shouldn't trust itself with
External Actions Email Sender Sends a message on the agent's behalf
Database SQL Query Runner Reads or writes to a database
Key Insight: The agent doesn't "know" what a tool does internally. It only sees the name, description, and parameters. The description is your contract with the agent — write it carefully!

Anatomy of a Tool Definition

Let's break down every part of a well-defined tool. In most agent frameworks, you define a tool by providing metadata and a function. Here's the structure:

The Four Essential Parts

  1. Tool Name — A short, descriptive identifier (e.g., get_weather)
  2. Description — A natural language explanation of what the tool does, when to use it, and what it returns
  3. Parameters — The inputs the tool needs, including types and descriptions
  4. Function Implementation — The actual code that executes when the tool is called

Writing Your First Tool in Python

Let's build a real tool from scratch. We'll create a simple get_weather tool that fetches weather data for a given city. We'll use a mock API call for simplicity, but the pattern is identical to real integrations.

def get_weather(city: str) -> dict:
    """
    Get the current weather for a given city.

    Args:
        city: The name of the city to look up.

    Returns:
        A dictionary with temperature, condition, and humidity.
    """
    # In a real implementation, you'd call an API like:
    # response = requests.get(f"https://api.weather.com/v1/{city}")
    # return response.json()

    # For now, we return mock data:
    mock_data = {
        "Tokyo": {"temperature": 22, "condition": "Sunny", "humidity": 45},
        "London": {"temperature": 14, "condition": "Cloudy", "humidity": 78},
        "New York": {"temperature": 18, "condition": "Partly Cloudy", "humidity": 60},
    }

    if city in mock_data:
        return mock_data[city]
    else:
        return {"error": f"Weather data not available for {city}"}


# Let's test it:
result = get_weather("Tokyo")
print(result)
# Output: {'temperature': 22, 'condition': 'Sunny', 'humidity': 45}
Pro Tip: The docstring (the triple-quoted string right after the function definition) is arguably the most important part. The agent reads this to decide when to use the tool. Be specific! Instead of "Gets weather," write "Get the current temperature, sky condition, and humidity for a specified city. Use this when the user asks about weather, temperature, or outdoor conditions."

Registering a Tool with Your Agent

Having a function isn't enough — you need to register it with your agent so the agent knows it exists. Different frameworks handle this differently, but the concept is the same: you provide metadata alongside the function.

# Example: Registering a tool with an agent framework
# (Pseudo-code that works across most agent libraries)

tool_definition = {
    "name": "get_weather",
    "description": (
        "Get the current weather for a given city. "
        "Returns temperature (Celsius), sky condition, and humidity. "
        "Use this when the user asks about weather, temperature, "
        "or whether it's a good day to go outside."
    ),
    "parameters": {
        "type": "object",
        "properties": {
            "city": {
                "type": "string",
                "description": "The name of the city, e.g. 'Tokyo', 'London'"
            }
        },
        "required": ["city"]
    },
    "function": get_weather  # Reference to our function above
}

# Register it with the agent
agent.register_tool(tool_definition)

What Happens Behind the Scenes

When you register a tool, the agent framework typically does the following:

  1. Stores the metadata (name, description, parameters) in a format the LLM can see
  2. Injects it into the system prompt so the model knows the tool is available
  3. Listens for tool calls in the model's output — when the model decides to use a tool, it outputs a structured request
  4. Executes the function and feeds the result back to the model as context
Common Mistake: Don't confuse the tool's description with its implementation. The description is for the agent (natural language, persuasive, clear). The implementation is for the computer (code, logic, error handling). Both matter, but they serve different purposes.

Handling Errors Gracefully

Tools fail. APIs go down, inputs are malformed, and networks timeout. A well-designed tool handles errors gracefully and returns useful information to the agent so it can decide what to do next.

import requests

def get_weather(city: str) -> dict:
    """
    Get the current weather for a given city.
    Returns temperature (Celsius), sky condition, and humidity.
    """
    try:
        response = requests.get(
            f"https://api.weather.example.com/v1/{city}",
            timeout=5  # Don't wait forever
        )
        response.raise_for_status()  # Raise exception for 4xx/5xx
        data = response.json()
        return {
            "temperature": data["temp_c"],
            "condition": data["condition"],
            "humidity": data["humidity"]
        }
    except requests.Timeout:
        return {"error": "Weather service timed out. Try again later."}
    except requests.HTTPError as e:
        return {"error": f"Weather service returned an error: {e}"}
    except Exception as e:
        return {"error": f"Unexpected error: {e}"}

Notice how every error path returns a dictionary with an "error" key. This consistency lets the agent understand that something went wrong and respond to the user appropriately, rather than crashing or producing nonsense.

Tool Design Best Practices

Before we jump into the exercise, let's establish some principles for writing good tools:

Principle Bad Example Good Example
Be specific in descriptions "Does stuff with data" "Retrieves the latest stock price for a given ticker symbol"
Validate inputs Assume the caller always passes a string Check type and format, return clear errors
Keep tools focused One tool that searches, filters, sorts, and formats Separate tools for each concern
Handle failures Let exceptions propagate Catch errors, return structured error messages
Use clear parameter names q, p, x query, page_number, max_results
Remember: The agent is a language model, not a programmer. It can't read your code — it only sees the name, description, and parameter schema. Invest your effort in writing crystal-clear descriptions.

Exercise: Build a Tool

Exercise

Create a tool called convert_currency that takes three parameters:

  • amount (float) — the amount to convert
  • from_currency (string) — the source currency code, e.g. "USD"
  • to_currency (string) — the target currency code, e.g. "EUR"

The tool should include a proper docstring (description), input validation (check that amount is positive, and currencies are 3-letter codes), and error handling. Use the following hardcoded exchange rates for simplicity:

exchange_rates = {
    "USD": 1.0,
    "EUR": 0.92,
    "GBP": 0.79,
    "JPY": 149.50,
    "CAD": 1.36
}

Return a dictionary with the converted amount and the target currency, or an error message if something goes wrong.

def convert_currency(amount: float, from_currency: str, to_currency: str) -> dict:
    """
    Convert an amount from one currency to another.

    Args:
        amount: The monetary amount to convert. Must be positive.
        from_currency: The source currency code (3-letter ISO code, e.g. 'USD').
        to_currency: The target currency code (3-letter ISO code, e.g. 'EUR').

    Returns:
        A dictionary with the converted amount and target currency,
        or an error message if the conversion cannot be performed.
    """
    exchange_rates = {
        "USD": 1.0,
        "EUR": 0.92,
        "GBP": 0.79,
        "JPY": 149.50,
        "CAD": 1.36
    }

    # Input validation
    if not isinstance(amount, (int, float)) or amount <= 0:
        return {"error": "Amount must be a positive number."}

    from_currency = from_currency.upper().strip()
    to_currency = to_currency.upper().strip()

    if len(from_currency) != 3 or len(to_currency) != 3:
        return {"error": "Currency codes must be 3-letter ISO codes (e.g. 'USD', 'EUR')."}

    if from_currency not in exchange_rates:
        return {"error": f"Unknown currency: {from_currency}"}
    if to_currency not in exchange_rates:
        return {"error": f"Unknown currency: {to_currency}"}

    # Convert: first to USD, then to target
    amount_in_usd = amount / exchange_rates[from_currency]
    converted = amount_in_usd * exchange_rates[to_currency]

    return {
        "original_amount": amount,
        "from_currency": from_currency,
        "converted_amount": round(converted, 2),
        "to_currency": to_currency
    }


# Test it:
print(convert_currency(100, "USD", "EUR"))
# Output: {'original_amount': 100, 'from_currency': 'USD', 'converted_amount': 92.0, 'to_currency': 'EUR'}

print(convert_currency(-5, "USD", "EUR"))
# Output: {'error': 'Amount must be a positive number.'}

print(convert_currency(100, "USD", "XYZ"))
# Output: {'error': 'Unknown currency: XYZ}'}

Key Takeaways

  • A tool is a function that gives an AI agent the ability to interact with the outside world — fetching data, performing calculations, or taking actions.
  • Every tool needs four things: a name, a description, parameters, and an implementation.
  • The description is the most important part — the agent uses it to decide when and how to use the tool. Write it clearly and specifically.
  • Always validate inputs and handle errors gracefully. Return structured error messages so the agent can respond intelligently.
  • Keep tools focused on a single task. It's better to have five small, well-defined tools than one giant multi-purpose tool.
  • Register your tools with the agent framework so the model knows they're available and understands their schemas.
