Embeddings Explained

Learn about embeddings explained.

What Are Embeddings?

Imagine you have a library with millions of books. How would you organize them so that similar books are near each other? You might group them by topic, author, or genre. In the world of AI, embeddings do something similar — but for words, sentences, or even entire documents.

An embedding is a way to represent text as a list of numbers (a vector) so that similar meanings are close together in a mathematical space. Think of it like giving every piece of text a unique "address" on a giant map, where nearby addresses mean similar things.

💡 Analogy: Think of embeddings like GPS coordinates for words. The words "dog" and "puppy" would have very close coordinates, while "dog" and "airplane" would be far apart.

Why Do We Need Embeddings?

Computers don't understand words the way humans do. They only understand numbers. When we want an AI to work with text — like searching documents, recommending articles, or powering a chatbot — we need a way to turn text into numbers that preserve meaning.

Here's why embeddings are essential:

  • Semantic similarity: Embeddings capture meaning, so "king" and "queen" are close together, while "king" and "banana" are far apart.
  • Efficient search: Instead of matching exact words, embeddings let us find semantically similar content.
  • Foundation for AI agents: Agents use embeddings to understand user queries, retrieve relevant information, and make decisions.
  • Cross-language understanding: Good embeddings can map words from different languages into the same space, enabling translation and multilingual search.

How Embeddings Work

At a high level, an embedding model takes a piece of text and outputs a vector — a list of numbers. The length of this list is called the dimension. Common embedding models produce vectors with 384, 768, or even 1,536 dimensions.

The Embedding Process

  1. Input text: You provide a word, sentence, or document.
  2. Tokenization: The text is broken into smaller pieces (tokens).
  3. Neural network processing: A pre-trained model processes the tokens through multiple layers.
  4. Output vector: The model produces a fixed-length list of numbers representing the meaning of the input.
from sentence_transformers import SentenceTransformer

# Load a pre-trained embedding model
model = SentenceTransformer('all-MiniLM-L6-v2')

# Embed a single sentence
sentence = "Artificial intelligence is transforming the world."
embedding = model.encode(sentence)

print(f"Embedding shape: {embedding.shape}")
print(f"First 5 values: {embedding[:5]}")
🔧 Tip: The all-MiniLM-L6-v2 model is a great starting point — it's fast, lightweight, and produces 384-dimensional vectors. Perfect for learning and prototyping!

Comparing Embeddings: Cosine Similarity

Once we have embeddings, the most common way to compare them is using cosine similarity. This measures the angle between two vectors — the smaller the angle, the more similar the meanings.

Cosine Similarity Meaning Example
1.0 Identical meaning "cat" vs "cat"
0.8 – 0.99 Very similar "dog" vs "puppy"
0.5 – 0.79 Somewhat related "car" vs "road"
0.0 – 0.49 Weakly related "music" vs "weather"
Negative values Opposite meanings "hot" vs "cold" (in some models) 
from sentence_transformers import SentenceTransformer, util
import torch

model = SentenceTransformer('all-MiniLM-L6-v2')

# Define sentences to compare
sentences = [
    "The cat sat on the mat.",
    "A feline rested on the rug.",
    "The stock market crashed today.",
    "I love eating pizza."
]

# Generate embeddings
embeddings = model.encode(sentences, convert_to_tensor=True)

# Compare sentence 0 with all others
for i in range(1, len(sentences)):
    similarity = util.cos_sim(embeddings[0], embeddings[i])
    print(f'"{sentences[0]}" vs "{sentences[i]}"')
    print(f"  Similarity: {similarity.item():.4f}\n")

Embeddings in AI Agents

Embeddings are the backbone of how AI agents understand and retrieve information. Here's how they fit into the agent workflow:

Retrieval-Augmented Generation (RAG)

When an AI agent needs to answer a question, it often uses a vector database — a special database that stores embeddings. The process works like this:

  1. The user asks a question.
  2. The agent converts the question into an embedding.
  3. The agent searches the vector database for the most similar stored embeddings.
  4. The agent retrieves the original text associated with those embeddings.
  5. The agent uses the retrieved text as context to generate an answer.
⚠️ Important: The quality of your embeddings directly affects your agent's performance. A poor embedding model will retrieve irrelevant information, leading to bad answers. Always test different models for your use case!

Building a Simple Vector Store

from sentence_transformers import SentenceTransformer
import numpy as np

class SimpleVectorStore:
    def __init__(self, model_name='all-MiniLM-L6-v2'):
        self.model = SentenceTransformer(model_name)
        self.documents = []
        self.embeddings = None

    def add_documents(self, texts):
        """Add documents and compute their embeddings."""
        new_embeddings = self.model.encode(texts)
        self.documents.extend(texts)

        if self.embeddings is None:
            self.embeddings = new_embeddings
        else:
            self.embeddings = np.vstack([self.embeddings, new_embeddings])

    def search(self, query, top_k=3):
        """Find the most similar documents to the query."""
        query_embedding = self.model.encode([query])

        # Compute cosine similarities
        similarities = np.dot(self.embeddings, query_embedding.T).flatten()
        similarities = similarities / (
            np.linalg.norm(self.embeddings, axis=1) *
            np.linalg.norm(query_embedding)
        )

        # Get top-k results
        top_indices = np.argsort(similarities)[::-1][:top_k]
        results = [
            {
                "document": self.documents[i],
                "score": float(similarities[i])
            }
            for i in top_indices
        ]
        return results

# Example usage
store = SimpleVectorStore()

# Add some documents
documents = [
    "Python is a popular programming language for data science.",
    "Machine learning models learn patterns from data.",
    "The Eiffel Tower is located in Paris, France.",
    "Neural networks are inspired by the human brain.",
    "France is known for its wine and cheese."
]
store.add_documents(documents)

# Search
results = store.search("What is deep learning?", top_k=3)
for r in results:
    print(f"Score: {r['score']:.4f} | {r['document']}")

Popular Embedding Models

Not all embedding models are created equal. Here's a comparison of some popular options:

Model Dimensions Speed Best For
all-MiniLM-L6-v2 384 ⚡ Very Fast General purpose, prototyping
text-embedding-3-small 1,536 ⚡ Fast OpenAI ecosystem, production
text-embedding-3-large 3,072 🐢 Slower High accuracy, complex tasks
BGE-large-en-v1.5 1,024 🐢 Moderate English retrieval, RAG systems
💡 Choosing a Model: Start with a smaller, faster model like all-MiniLM-L6-v2 for experimentation. Move to larger models only when you need higher accuracy and can afford the computational cost.

Common Pitfalls

When working with embeddings, watch out for these common mistakes:

  • Using the wrong model for your language: Many models are English-only. For multilingual tasks, use models like paraphrase-multilingual-MiniLM-L12-v2.
  • Ignoring chunk size: When embedding long documents, split them into meaningful chunks (e.g., paragraphs). Embedding an entire book as one vector loses too much detail.
  • Not normalizing vectors: If you're computing cosine similarity manually, always normalize your vectors first.
  • Mixing embedding models: Never compare embeddings from different models — they live in different mathematical spaces!
Exercise: Build a FAQ Matcher

Create a simple FAQ matcher using embeddings. Given a list of frequently asked questions and their answers, write a function that takes a user's question and returns the most relevant FAQ answer.

Your FAQ data:

  • Q: "How do I reset my password?" → A: "Go to Settings → Security → Reset Password."
  • Q: "What payment methods do you accept?" → A: "We accept credit cards, PayPal, and bank transfers."
  • Q: "How can I contact support?" → A: "Email us at support@example.com or use the live chat."
  • Q: "Where can I find my invoice?" → A: "Invoices are available under Account → Billing History."

Write code that embeds the FAQ questions, then finds the best match for the user query: "I forgot my login credentials, what should I do?"

from sentence_transformers import SentenceTransformer, util
import torch

# Initialize model
model = SentenceTransformer('all-MiniLM-L6-v2')

# FAQ data
faq_questions = [
    "How do I reset my password?",
    "What payment methods do you accept?",
    "How can I contact support?",
    "Where can I find my invoice?"
]

faq_answers = [
    "Go to Settings → Security → Reset Password.",
    "We accept credit cards, PayPal, and bank transfers.",
    "Email us at support@example.com or use the live chat.",
    "Invoices are available under Account → Billing History."
]

# Pre-compute FAQ embeddings
faq_embeddings = model.encode(faq_questions, convert_to_tensor=True)

def find_best_answer(user_query, threshold=0.4):
    """Find the best matching FAQ answer for a user query."""
    # Embed the user query
    query_embedding = model.encode(user_query, convert_to_tensor=True)

    # Compute similarities with all FAQ questions
    similarities = util.cos_sim(query_embedding, faq_embeddings)[0]

    # Find the best match
    best_idx = torch.argmax(similarities).item()
    best_score = similarities[best_idx].item()

    if best_score >= threshold:
        return {
            "question": faq_questions[best_idx],
            "answer": faq_answers[best_idx],
            "confidence": best_score
        }
    else:
        return {
            "question": None,
            "answer": "Sorry, I couldn't find a relevant answer. Please contact support.",
            "confidence": best_score
        }

# Test with the user query
user_query = "I forgot my login credentials, what should I do?"
result = find_best_answer(user_query)

print(f"User Query: {user_query}")
print(f"Best Match: {result['question']}")
print(f"Confidence: {result['confidence']:.4f}")
print(f"Answer: {result['answer']}")

Key Takeaways

  • Embeddings convert text into numerical vectors that capture semantic meaning.
  • Similar texts have embeddings that are close together in vector space.
  • Cosine similarity is the standard way to compare two embeddings.
  • Embeddings power RAG systems, search engines, recommendation systems, and AI agents.
  • Always use the same embedding model for both storage and querying — never mix models.
  • Choose your embedding model based on your needs: speed vs. accuracy, language support, and dimensionality.
  • When working with long documents, chunk them into smaller pieces before embedding.
