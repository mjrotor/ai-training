Escalation & Handoff

Learn about escalation & handoff.

What Is Escalation and Handoff?

As your AI agent grows more complex, it will inevitably encounter situations it cannot handle on its own. Maybe a user asks a question outside the agent's expertise, or perhaps a task requires a human to approve a critical decision. Escalation is the process by which an agent recognizes it needs help and routes the situation to the right resource. Handoff is the mechanism of transferring control from one agent (or system) to another — or to a human — without losing context.

Together, escalation and handoff patterns make your agents more reliable, transparent, and safe. Instead of guessing or failing silently, a well-designed agent knows when to say, "I think a human should take it from here."

Why Escalation Matters

Without escalation logic, an AI agent will either:

  • Hallucinate — confidently produce a wrong answer
  • Loop endlessly — keep retrying the same failing action
  • Break trust — the user loses confidence when the agent clearly doesn't understand

Escalation is not a sign of failure. It is a design feature. Production-grade agents escalate for several reasons:

  1. Confidence threshold — the agent's response falls below a confidence score
  2. Policy boundary — the request involves sensitive actions (payments, deletions, legal)
  3. Domain gap — the question is outside the agent's trained scope
  4. User request — the human explicitly asks for a real person
Key Idea: Escalation is a first-class behavior in agent design. Plan for it from the start, not as an afterthought.

Types of Handoff

There are three primary handoff patterns you will use in agent systems:

1. Agent-to-Human Handoff

The agent transfers the full conversation context to a human operator. This is common in customer support, healthcare, and financial advisory agents. The agent summarizes what it has gathered so the human can pick up seamlessly.

2. Agent-to-Agent Handoff

One specialized agent delegates to another. For example, a triage agent might determine that a billing question should go to a billing specialist agent. The triage agent passes along the user's information so the user does not have to repeat themselves.

3. Agent-to-Tool / Agent-to-System Handoff

The agent invokes an external system to complete a task — for instance, creating a ticket in a CRM, sending an email, or triggering a workflow in another service. This is not a handoff of conversation, but a handoff of action.

Designing an Escalation Policy

An escalation policy defines the rules for when and how an agent escalates. A good policy answers these questions:

  • Trigger: What condition causes escalation?
  • Context: What information is passed along?
  • Destination: Where does the issue go?
  • Fallback: What happens if the escalation target is unavailable?

Here is a simple Python implementation of an escalation policy:

from dataclasses import dataclass, field
from enum import Enum
from typing import Optional

class EscalationReason(Enum):
    LOW_CONFIDENCE = "low_confidence"
    POLICY_VIOLATION = "policy_violation"
    USER_REQUEST = "user_request"
    DOMAIN_GAP = "domain_gap"

@dataclass
class EscalationPolicy:
    confidence_threshold: float = 0.6
    sensitive_keywords: list = field(default_factory=lambda: [
        "refund", "cancel account", "legal", "lawsuit", "medical"
    ])
    human_agent_available: bool = True

    def should_escalate(self, user_input: str, confidence: float) -> Optional[EscalationReason]:
        # Check confidence
        if confidence < self.confidence_threshold:
            return EscalationReason.LOW_CONFIDENCE

        # Check policy boundaries
        lower_input = user_input.lower()
        for keyword in self.sensitive_keywords:
            if keyword in lower_input:
                return EscalationReason.POLICY_VIOLATION

        # Check for explicit human request
        human_phrases = ["talk to a human", "speak to someone", "real person", "agent please"]
        for phrase in human_phrases:
            if phrase in lower_input:
                return EscalationReason.USER_REQUEST

        return None

    def escalate(self, reason: EscalationReason, conversation_context: dict) -> dict:
        if not self.human_agent_available:
            return {
                "status": "escalation_failed",
                "reason": reason.value,
                "message": "No human agent available. Please try again later."
            }

        return {
            "status": "escalated",
            "reason": reason.value,
            "context_summary": conversation_context.get("summary", "No summary available."),
            "handoff_id": "HO-20240119-001"
        }

# Usage
policy = EscalationPolicy(confidence_threshold=0.7)

# Simulate a low-confidence response
result = policy.should_escalate("How do I fix my router?", confidence=0.45)
print(f"Escalation needed: {result}")  # Escalation needed: EscalationReason.LOW_CONFIDENCE

if result:
    outcome = policy.escalate(result, {"summary": "User having router connectivity issues"})
    print(outcome)
Pro Tip: Always include a context summary in your handoff payload. The receiving agent or human should never have to ask the user to repeat information.

Implementing Agent-to-Agent Handoff

Agent-to-agent handoff requires a shared context format so the receiving agent understands the full state of the conversation. Here is a practical example with a triage agent that routes to specialist agents:

from dataclasses import dataclass, field
from typing import Callable
from enum import Enum

class AgentType(Enum):
    TRIAGE = "triage"
    BILLING = "billing"
    TECHNICAL = "technical"
    GENERAL = "general"

@dataclass
class ConversationContext:
    user_id: str
    messages: list = field(default_factory=list)
    metadata: dict = field(default_factory=dict)
    current_agent: AgentType = AgentType.TRIAGE

    def add_message(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})

    def summary(self) -> str:
        last_user_msg = next(
            (m["content"] for m in reversed(self.messages) if m["role"] == "user"),
            "No user message found."
        )
        return f"User ({self.user_id}) said: {last_user_msg}"

def triage_agent(context: ConversationContext) -> dict:
    """Routes the conversation to the appropriate specialist agent."""
    last_message = context.messages[-1]["content"].lower()

    routing_rules = {
        AgentType.BILLING: ["charge", "invoice", "payment", "refund", "subscription"],
        AgentType.TECHNICAL: ["error", "bug", "crash", "not working", "broken", "setup"],
    }

    for agent_type, keywords in routing_rules.items():
        if any(kw in last_message for kw in keywords):
            return {
                "action": "handoff",
                "target_agent": agent_type,
                "context": context.summary(),
                "reason": f"Detected {agent_type.value} intent."
            }

    return {
        "action": "respond",
        "target_agent": AgentType.GENERAL,
        "context": context.summary(),
        "reason": "No specialist match; routing to general agent."
    }

def specialist_agent(agent_type: AgentType, context: ConversationContext) -> str:
    """Simulates a specialist agent generating a response."""
    responses = {
        AgentType.BILLING: "I'm the billing specialist. Let me look into your account charges.",
        AgentType.TECHNICAL: "I'm the technical support agent. Let me help troubleshoot the issue.",
        AgentType.GENERAL: "I'm a general assistant. How can I help you today?",
    }
    return responses[agent_type]

# Simulate a conversation
ctx = ConversationContext(user_id="USR-4421")
ctx.add_message("user", "I was charged twice for my subscription last month")

routing = triage_agent(ctx)
print(f"Routing decision: {routing['action']} → {routing['target_agent'].value}")
print(f"Reason: {routing['reason']}")
print(f"Context passed: {routing['context']}")

if routing["action"] == "handoff":
    response = specialist_agent(routing["target_agent"], ctx)
    print(f"\nAgent response: {response}")

Comparing Handoff Strategies

Different situations call for different handoff approaches. Here is a comparison to help you choose:

Strategy Best For Latency Complexity User Experience
Immediate Handoff Clear domain gaps, sensitive topics Low Low Seamless if context is passed well
Confirm-Then-Handoff Expensive or irreversible actions Medium Medium User feels in control
Graceful Degradation Non-critical queries Low Medium Can frustrate if overused
Parallel Agent + Escalation Complex multi-step workflows High High Most flexible, hardest to debug
Warning: Never silently hand off without informing the user. Always let the user know they are being transferred and why. Transparency builds trust.

Building a Confidence-Based Escalation Trigger

One of the most practical escalation patterns is confidence-based routing. The agent evaluates its own certainty about a response and escalates when it falls below a threshold. Here is a more advanced example that combines confidence scoring with conversation history:

import time
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class EscalationEngine:
    confidence_threshold: float = 0.65
    max_retries: int = 2
    escalation_log: list = field(default_factory=list)

    def evaluate_and_respond(
        self,
        user_input: str,
        generate_response: Callable[[str], dict],
        escalate_fn: Callable[[dict], dict]
    ) -> dict:
        """
        Attempts to generate a response. Escalates if confidence is too low
        after max_retries attempts.
        """
        attempts = 0
        last_result = None

        while attempts < self.max_retries:
            result = generate_response(user_input)
            last_result = result
            confidence = result.get("confidence", 0.0)

            if confidence >= self.confidence_threshold:
                self._log_event("responded", user_input, confidence)
                return {
                    "status": "success",
                    "response": result["text"],
                    "confidence": confidence,
                    "attempts": attempts + 1
                }

            attempts += 1
            print(f"  Attempt {attempts}: confidence {confidence:.2f} below threshold. Retrying...")

        # Max retries reached — escalate
        self._log_event("escalated", user_input, last_result.get("confidence", 0.0))
        escalation_result = escalate_fn({
            "user_input": user_input,
            "last_attempt": last_result,
            "total_attries": attempts
        })

        return {
            "status": "escalated",
            "escalation_result": escalation_result,
            "attempts": attempts
        }

    def _log_event(self, event_type: str, user_input: str, confidence: float):
        self.escalation_log.append({
            "timestamp": time.time(),
            "type": event_type,
            "input_preview": user_input[:50] + "..." if len(user_input) > 50 else user_input,
            "confidence": confidence
        })

# Simulated response generator (replace with your actual LLM call)
def mock_generate(user_input: str) -> dict:
    """Simulates an LLM returning a response with confidence."""
    # In reality, you'd get confidence from model logits or a separate classifier
    ambiguous_queries = ["thing", "stuff", "it", "that one"]
    if any(word in user_input.lower() for word in ambiguous_queries):
        return {"text": "I'm not sure what you mean.", "confidence": 0.3}
    return {"text": f"Here's help with: {user_input}", "confidence": 0.92}

def mock_escalate(context: dict) -> dict:
    """Simulates handing off to a human agent."""
    return {
        "handoff_id": f"HO-{int(time.time())}",
        "message": "Connecting you with a human agent...",
        "context": context
    }

# Run the engine
engine = EscalationEngine(confidence_threshold=0.65, max_retries=2)

# Test 1: High confidence — should respond directly
print("=== Test 1: Clear query ===")
result = engine.evaluate_and_respond(
    "How do I reset my password?",
    mock_generate,
    mock_escalate
)
print(f"Result: {result}\n")

# Test 2: Low confidence — should escalate after retries
print("=== Test 2: Ambiguous query ===")
result = engine.evaluate_and_respond(
    "help with that thing",
    mock_generate,
    mock_escalate
)
print(f"Result: {result}\n")

# Review escalation log
print("=== Escalation Log ===")
for entry in engine.escalation_log:
    print(f"  [{entry['type']}] confidence={entry['confidence']:.2f} | {entry['input_preview']}")

Context Preservation During Handoff

The biggest challenge in handoff is making sure nothing gets lost. When control transfers, the next agent or human needs:

  • Conversation history — what has been discussed so far
  • User intent — what the user is trying to accomplish
  • Collected entities — names, IDs, dates, preferences already gathered
  • Agent state — what steps have been completed, what is pending

A good handoff payload looks like this:

handoff_payload = {
    "handoff_id": "HO-20240119-001",
    "source_agent": "triage_agent_v2",
    "target_agent": "billing_specialist_v1",
    "reason": "User has a billing dispute requiring human review",
    "timestamp": "2024-01-19T14:32:00Z",
    "user": {
        "id": "USR-4421",
        "name": "Jane Doe",
        "tier": "premium"
    },
    "conversation_summary": "User was charged twice for subscription in December. Already verified account. Needs manual refund approval.",
    "collected_entities": {
        "account_id": "ACC-9912",
        "disputed_amount": 29.99,
        "dispute_date": "2024-12-15"
    },
    "pending_actions": [
        "Process refund of $29.99",
        "Send confirmation email"
    ],
    "conversation_history": [
        {"role": "user", "content": "I was charged twice last month"},
        {"role": "agent", "content": "I'm sorry about that. Let me look into your account."},
        {"role": "agent", "content": "I can see the duplicate charge of $29.99 on Dec 15."},
        {"role": "user", "content": "Yes, can you refund it?"}
    ]
}
Best Practice: Keep your handoff payload schema consistent across all agents in your system. Use a shared data class or JSON schema so every agent produces and consumes the same format.

Coding Exercise

Exercise: Build a Two-Stage Escalation Pipeline

Create a two-stage escalation pipeline with the following requirements:

  1. A Stage 1 function that checks if the user's message contains any crisis keywords (e.g., "suicide", "harm myself", "emergency"). If found, immediately escalate to a crisis response.
  2. A Stage 2 function that checks if the agent's confidence is below 0.5. If so, escalate to a human agent with a full context summary.
  3. If neither stage triggers, the agent responds normally.
  4. Each escalation should return a structured dict with status, stage, action, and message fields.

Write your solution below and then check the answer.

from dataclasses import dataclass, field
from typing import Optional

CRISIS_KEYWORDS = ["suicide", "harm myself", "kill myself", "emergency", "urgent help"]

@dataclass
class TwoStageEscalationPipeline:
    confidence_threshold: float = 0.5

    def stage1_crisis_check(self, user_input: str) -> Optional[dict]:
        """Stage 1: Check for crisis keywords. Immediate escalation."""
        lower_input = user_input.lower()
        matched = [kw for kw in CRISIS_KEYWORDS if kw in lower_input]
        if matched:
            return {
                "status": "escalated",
                "stage": 1,
                "action": "crisis_response",
                "message": "This sounds like it may be an emergency. If you are in crisis, please contact 988 Suicide & Crisis Lifeline by calling or texting 988.",
                "matched_keywords": matched
            }
        return None

    def stage2_confidence_check(self, confidence: float, context: dict) -> Optional[dict]:
        """Stage 2: Check if confidence is too low. Escalate to human."""
        if confidence < self.confidence_threshold:
            return {
                "status": "escalated",
                "stage": 2,
                "action": "human_handoff",
                "message": "I'm having trouble with this request. Let me connect you with a human agent.",
                "context_summary": context.get("summary", "No summary"),
                "confidence": confidence
            }
        return None

    def process(self, user_input: str, confidence: float, context: dict) -> dict:
        """Run both stages in order."""
        # Stage 1: Crisis check (highest priority)
        crisis_result = self.stage1_crisis_check(user_input)
        if crisis_result:
            return crisis_result

        # Stage 2: Confidence check
        confidence_result = self.stage2_confidence_check(confidence, context)
        if confidence_result:
            return confidence_result

        # No escalation needed
        return {
            "status": "success",
            "stage": 0,
            "action": "respond",
            "message": f"Here's help with your request about: {user_input}"
        }

# Test the pipeline
pipeline = TwoStageEscalationPipeline(confidence_threshold=0.5)

# Test 1: Crisis keyword
result1 = pipeline.process("I want to harm myself", confidence=0.8, context={"summary": "User expressing distress"})
print(f"Test 1: {result1}\n")

# Test 2: Low confidence
result2 = pipeline.process("help with quantum computing", confidence=0.3, context={"summary": "User asking about quantum computing"})
print(f"Test 2: {result2}\n")

# Test 3: Normal response
result3 = pipeline.process("What's the weather today?", confidence=0.95, context={"summary": "User asking about weather"})
print(f"Test 3: {result3}")

Key Takeaways

  • Escalation is a feature, not a bug. Design your agents to recognize their limits and hand off gracefully.
  • There are three main handoff types: agent-to-human, agent-to-agent, and agent-to-tool/system.
  • An escalation policy defines triggers, context to pass, destinations, and fallback behavior.
  • Confidence-based escalation uses a threshold to decide when the agent should stop trying and escalate.
  • Context preservation is critical. Always pass conversation history, user intent, collected entities, and pending actions in your handoff payload.
  • Multi-stage escalation lets you prioritize — for example, checking for crisis keywords before checking confidence.
  • Always be transparent with users. Never silently hand off; tell the user what is happening and why.
  • Use a consistent handoff schema across all agents in your system so every component speaks the same language.
