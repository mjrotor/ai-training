Writing Review Comments

Learn about writing review comments.

What Are Review Comments?

When you're working with AI agents, one of the most powerful ways to guide their behavior is through review comments. Review comments are structured notes or annotations that you attach to specific parts of your code or output. Think of them as leaving sticky notes for your AI agent — they help the agent understand what went well, what needs improvement, and what to do differently next time.

In the context of AI agents, review comments serve as a feedback loop. The agent reads your comments, adjusts its reasoning, and produces better results. This is the foundation of effective human-AI collaboration.

Why Review Comments Matter

Without review comments, an AI agent has no way to know whether its output met your expectations. Review comments bridge the gap between what you wanted and what the agent delivered. They turn a one-way output into a conversation.

Did you know? In professional software development, code review comments are considered essential for maintaining code quality. The same principle applies to AI agents — the quality of your feedback directly shapes the quality of the agent's future responses.

Anatomy of a Good Review Comment

A well-written review comment has three key components:

  1. Location — Where exactly is the comment referring to? Be specific about the line, section, or output.
  2. Observation — What did you notice? Describe what the agent did or didn't do.
  3. Suggestion — What should the agent do instead? Offer a clear, actionable path forward.
# REVIEW COMMENT
# Location: Line 12, function calculate_total()
# Observation: The function does not handle negative prices,
# which could lead to incorrect totals.
# Suggestion: Add a validation check to reject negative
# values before performing the calculation.

def calculate_total(prices):
    return sum(prices)

Types of Review Comments for AI Agents

Not all review comments serve the same purpose. Here are the main categories you'll use when working with AI agents:

Comment Type Purpose Example
Correction Fix an error or mistake "The agent used the wrong variable name on line 5."
Enhancement Suggest an improvement "Consider adding error handling here."
Clarification Ask for more detail "The output is missing the summary section."
Praise Reinforce good behavior "Great job structuring the data this way."

Writing Corrections Effectively

When you correct an AI agent, be specific and constructive. Instead of saying "this is wrong," point to the exact issue and explain the correct approach. The agent learns best when feedback is precise.

# ❌ Vague feedback:
# "This code is bad."

# ✅ Specific and constructive feedback:
# "The loop on line 8 iterates over the wrong range."
# "It should iterate from 0 to len(data), not 1 to len(data)."
# "This causes the first element to be skipped."
Pro Tip: Always include the exact line number or section name in your review comment. AI agents parse structured feedback much more effectively than vague statements.

Structuring Review Comments for Maximum Impact

When you write review comments for an AI agent, structure matters. Here's a recommended format:

## Review Comment
**Section:** [Name or line reference]
**Issue:** [What's wrong or could be better]
**Severity:** [Low / Medium / High]
**Suggested Fix:** [What to change]

This format gives the agent a clear, machine-readable structure to parse and act upon. You can use this format whether you're reviewing code, text output, or any other agent deliverable.

Common Mistakes to Avoid

Even with good intentions, review comments can go wrong. Here are pitfalls to watch out for:

  • Being too vague — "Fix this" tells the agent nothing about what to fix.
  • Overloading with comments — Too many comments at once can confuse the agent about priorities.
  • Ignoring what went well — Positive feedback helps the agent repeat good patterns.
  • Using emotional language — "This is terrible" is less useful than "Line 15 has an off-by-one error."
Warning: Avoid writing review comments in a frustrated or emotional tone. AI agents respond best to neutral, structured, and specific feedback. Emotional language can introduce noise without providing actionable information.

Putting It All Together

Let's look at a complete example. Suppose an AI agent generated a Python function, and you want to leave a review comment:

# Original agent output:
def get_average(numbers):
    total = sum(numbers)
    return total / len(numbers)

# Your review comment might look like this:
# ## Review Comment
# **Section:** get_average(), line 3
# **Issue:** No handling for empty list input.
# **Severity:** High
# **Suggested Fix:** Add a guard clause to return 0
# or raise a ValueError if the list is empty.

# Improved version after applying the review:
def get_average(numbers):
    if not numbers:
        raise ValueError("List cannot be empty")
    return sum(numbers) / len(numbers)
Exercise

Write a structured review comment for the following AI-generated code. Use the format we discussed (Section, Issue, Severity, Suggested Fix). The code is supposed to filter out all even numbers from a list, but it has a bug.

def filter_evens(numbers):
    result = []
    for n in numbers:
        if n % 2 == 0:
            result.append(n)
    return result

Can you identify the bug and write a proper review comment for the agent?

Bug: The function is named filter_evens but it actually keeps even numbers instead of removing them. The logic is inverted.

Review Comment:

## Review Comment
**Section:** filter_evens(), line 3
**Issue:** The condition keeps even numbers instead of filtering them out.
**Severity:** High
**Suggested Fix:** Change the condition from
`n % 2 == 0` to `n % 2 != 0` if the goal is to
keep only odd numbers, or rename the function to
`keep_evens` if the current logic is intended.

Key Takeaways

  • Review comments are structured feedback that guide AI agents toward better outputs.
  • Every good review comment includes a location, observation, and suggestion.
  • Use the four types of comments — Correction, Enhancement, Clarification, and Praise — to cover all feedback scenarios.
  • Structure your comments with clear headers (Section, Issue, Severity, Suggested Fix) for maximum agent comprehension.
  • Avoid vague, emotional, or overloaded feedback — be specific, neutral, and focused.
  • Positive reinforcement is just as important as corrections; it helps agents repeat successful patterns.
