Retry Patterns

Learn about retry patterns.

Understanding Retry Patterns in AI Agents

When building AI agents, things don't always go as planned. Network requests fail, APIs return errors, and models sometimes produce unexpected outputs. Retry patterns are strategies that help your agent handle these failures gracefully by automatically attempting an operation again when it fails.

Think of it like this: if you call a friend and they don't answer, you might try again in a few minutes. Retry patterns do the same thing for your code — they give your agent a second (or third, or fourth) chance to succeed.

Why Do We Need Retry Patterns?

AI agents interact with many external systems:

  • Language model APIs (like OpenAI, Anthropic, etc.)
  • Web scraping and HTTP requests
  • Database connections
  • File system operations

Any of these can fail temporarily due to:

  • Rate limiting — the API says "too many requests, try again later"
  • Network issues — a brief connection drop
  • Server errors — the service is temporarily unavailable
  • Timeouts — the request took too long
💡 Key Insight: Most failures in distributed systems are temporary. A well-designed retry pattern can turn a failed operation into a successful one without any human intervention.

Basic Retry: The Simple Loop

The simplest retry pattern is a loop that tries an operation multiple times before giving up:

import time
import random

def call_api_with_retry(prompt, max_retries=3):
    """Call an API with basic retry logic."""
    for attempt in range(1, max_retries + 1):
        try:
            print(f"Attempt {attempt} of {max_retries}...")
            # Simulate an API call that might fail
            if random.random() < 0.6:  # 60% chance of failure
                raise ConnectionError("API temporarily unavailable")
            return "Success! Here is your response."
        except ConnectionError as e:
            print(f"  Failed: {e}")
            if attempt == max_retries:
                print("  All retries exhausted. Giving up.")
                raise
            print("  Retrying...")

# Try it out
try:
    result = call_api_with_retry("Hello, world!")
    print(f"Result: {result}")
except ConnectionError:
    print("Operation failed after all retries.")

This works, but it has a problem: it retries immediately after each failure. If the API is overwhelmed, hammering it with instant retries can make things worse!

Exponential Backoff

Exponential backoff is a strategy where you wait longer and longer between each retry. This gives the failing service time to recover.

Attempt Wait Time (base=1s) Total Elapsed
1 0s (immediate) 0s
2 1s 1s
3 2s 3s
4 4s 7s
5 8s 15s

The formula is simple: wait_time = base_delay × 2^(attempt - 1)

import time
import random

def call_api_with_backoff(prompt, max_retries=5, base_delay=1.0):
    """Call an API with exponential backoff."""
    for attempt in range(1, max_retries + 1):
        try:
            print(f"Attempt {attempt} of {max_retries}...")
            # Simulate an API call
            if random.random() < 0.5:
                raise ConnectionError("API temporarily unavailable")
            return "Success! Here is your response."
        except ConnectionError as e:
            print(f"  Failed: {e}")
            if attempt == max_retries:
                print("  All retries exhausted.")
                raise
            # Calculate wait time with exponential backoff
            wait_time = base_delay * (2 ** (attempt - 1))
            print(f"  Waiting {wait_time:.1f}s before retrying...")
            time.sleep(wait_time)

# Try it out
try:
    result = call_api_with_backoff("Hello, world!")
    print(f"Result: {result}")
except ConnectionError:
    print("Operation failed after all retries.")
🌟 Pro Tip: Always add a small random "jitter" to your wait times. If many clients retry at exactly the same time, they can create a "thundering herd" that overwhelms the server again. Adding randomness spreads out the retries.

Adding Jitter

import time
import random

def call_api_with_backoff_and_jitter(prompt, max_retries=5, base_delay=1.0):
    """Call an API with exponential backoff and jitter."""
    for attempt in range(1, max_retries + 1):
        try:
            print(f"Attempt {attempt} of {max_retries}...")
            if random.random() < 0.5:
                raise ConnectionError("API temporarily unavailable")
            return "Success! Here is your response."
        except ConnectionError as e:
            print(f"  Failed: {e}")
            if attempt == max_retries:
                print("  All retries exhausted.")
                raise
            # Exponential backoff with jitter
            wait_time = base_delay * (2 ** (attempt - 1))
            jitter = random.uniform(0, wait_time * 0.5)  # Up to 50% jitter
            total_wait = wait_time + jitter
            print(f"  Waiting {total_wait:.2f}s (base: {wait_time:.1f}s + jitter: {jitter:.2f}s)...")
            time.sleep(total_wait)

Retrying Only on Specific Errors

Not all errors should trigger a retry. If you send invalid data to an API, retrying won't help — you'll just get the same error again. You should only retry on transient (temporary) errors.

Error Type Retry? Reason
ConnectionError ✅ Yes Network issues are usually temporary
TimeoutError ✅ Yes Server might recover after a moment
HTTP 429 (Rate Limited) ✅ Yes Wait and try again
HTTP 500 (Server Error) ✅ Yes Server-side issue, may resolve
HTTP 400 (Bad Request) ❌ No Your request is invalid — fix the code
HTTP 401 (Unauthorized) ❌ No Your credentials are wrong — fix them
HTTP 404 (Not Found) ❌ No The resource doesn't exist 
import time
import random

class APIError(Exception):
    """Custom exception with status code."""
    def __init__(self, message, status_code):
        super().__init__(message)
        self.status_code = status_code

RETRYABLE_STATUS_CODES = {429, 500, 502, 503, 504}

def call_api_smart_retry(prompt, max_retries=3, base_delay=1.0):
    """Only retry on transient errors."""
    for attempt in range(1, max_retries + 1):
        try:
            print(f"Attempt {attempt} of {max_retries}...")
            # Simulate different types of errors
            error_roll = random.random()
            if error_roll < 0.2:
                raise APIError("Rate limited", 429)  # Retryable
            elif error_roll < 0.4:
                raise APIError("Server error", 500)  # Retryable
            elif error_roll < 0.5:
                raise APIError("Bad request", 400)   # NOT retryable
            return "Success!"
        except APIError as e:
            print(f"  Error {e.status_code}: {e}")
            # Don't retry on non-retryable errors
            if e.status_code not in RETRYABLE_STATUS_CODES:
                print(f"  Non-retryable error. Stopping immediately.")
                raise
            if attempt == max_retries:
                print("  All retries exhausted.")
                raise
            wait_time = base_delay * (2 ** (attempt - 1))
            jitter = random.uniform(0, wait_time * 0.5)
            print(f"  Retryable error. Waiting {wait_time + jitter:.2f}s...")
            time.sleep(wait_time + jitter)
⚠️ Warning: Never retry non-idempotent operations without caution. If an operation charges a credit card or sends an email, retrying could result in duplicate charges or duplicate messages. Always check if an operation is safe to repeat!

Building a Reusable Retry Decorator

Instead of writing retry logic inside every function, you can create a decorator that adds retry behavior to any function:

import time
import random
from functools import wraps

def retry(max_retries=3, base_delay=1.0, retryable_exceptions=(Exception,)):
    """A reusable retry decorator with exponential backoff and jitter."""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_exception = None
            for attempt in range(1, max_retries + 1):
                try:
                    return func(*args, **kwargs)
                except retryable_exceptions as e:
                    last_exception = e
                    if attempt == max_retries:
                        print(f"  [{func.__name__}] All {max_retries} retries exhausted.")
                        raise
                    wait_time = base_delay * (2 ** (attempt - 1))
                    jitter = random.uniform(0, wait_time * 0.5)
                    print(f"  [{func.__name__}] Attempt {attempt} failed: {e}")
                    print(f"  [{func.__name__}] Retrying in {wait_time + jitter:.2f}s...")
                    time.sleep(wait_time + jitter)
            raise last_exception
        return wrapper
    return decorator

# Now you can add retry logic to ANY function with a simple decorator!

@retry(max_retries=4, base_delay=0.5, retryable_exceptions=(ConnectionError, TimeoutError))
def fetch_data(url):
    """Simulate fetching data from a URL."""
    print(f"Fetching {url}...")
    if random.random() < 0.6:
        raise ConnectionError("Connection refused")
    return f"Data from {url}"

@retry(max_retries=3, base_delay=1.0, retryable_exceptions=(ValueError,))
def parse_response(text):
    """Simulate parsing a response."""
    print(f"Parsing: {text}")
    if random.random() < 0.5:
        raise ValueError("Malformed response")
    return {"parsed": text.upper()}

# Use them!
try:
    data = fetch_data("https://api.example.com/data")
    print(f"Got: {data}")
except ConnectionError:
    print("Could not fetch data after all retries.")

try:
    parsed = parse_response("hello world")
    print(f"Parsed: {parsed}")
except ValueError:
    print("Could not parse response after all retries.")

Retry Patterns in AI Agent Workflows

In a real AI agent, retry patterns are essential at multiple points:

  1. LLM API calls — The model provider might be rate-limited or temporarily down
  2. Tool execution — External tools (search, calculators, databases) can fail
  3. Output parsing — The model's response might not be in the expected format
  4. Validation — Generated code might have syntax errors that need re-generation
import time
import random

class AIAgent:
    """A simple AI agent with retry patterns at every step."""
    
    def __init__(self):
        self.max_retries = 3
        self.base_delay = 1.0
    
    def _backoff_wait(self, attempt):
        """Wait with exponential backoff and jitter."""
        wait = self.base_delay * (2 ** (attempt - 1))
        jitter = random.uniform(0, wait * 0.5)
        time.sleep(wait + jitter)
    
    def call_llm(self, prompt):
        """Call the language model with retries."""
        for attempt in range(1, self.max_retries + 1):
            try:
                print(f"  [LLM] Attempt {attempt}...")
                # Simulate LLM call
                if random.random() < 0.4:
                    raise ConnectionError("LLM API unavailable")
                return f"Response to: {prompt}"
            except ConnectionError as e:
                print(f"  [LLM] Failed: {e}")
                if attempt == self.max_retries:
                    raise
                self._backoff_wait(attempt)
    
    def use_tool(self, tool_name, input_data):
        """Use a tool with retries."""
        for attempt in range(1, self.max_retries + 1):
            try:
                print(f"  [Tool: {tool_name}] Attempt {attempt}...")
                # Simulate tool execution
                if random.random() < 0.3:
                    raise RuntimeError(f"{tool_name} crashed")
                return f"{tool_name} result for: {input_data}"
            except RuntimeError as e:
                print(f"  [Tool: {tool_name}] Failed: {e}")
                if attempt == self.max_retries:
                    raise
                self._backoff_wait(attempt)
    
    def run(self, user_input):
        """Run the agent with full retry protection."""
        print(f"\n🤖 Agent processing: '{user_input}'")
        print("=" * 50)
        
        # Step 1: Call LLM
        print("\n📡 Step 1: Calling LLM...")
        llm_response = self.call_llm(user_input)
        print(f"  ✅ LLM responded: {llm_response}")
        
        # Step 2: Use a tool
        print("\n🔧 Step 2: Using search tool...")
        tool_result = self.use_tool("search", llm_response)
        print(f"  ✅ Tool returned: {tool_result}")
        
        # Step 3: Generate final answer
        print("\n📝 Step 3: Generating final answer...")
        final_answer = f"Based on {tool_result}, here is my answer."
        print(f"  ✅ Done!")
        
        return final_answer

# Run the agent
agent = AIAgent()
try:
    answer = agent.run("What is the weather today?")
    print(f"\n🎉 Final Answer: {answer}")
except Exception as e:
    print(f"\n❌ Agent failed: {e}")
💡 Design Principle: Each step in your agent's workflow should have its own retry logic. This way, if the LLM call succeeds but the tool fails, you don't waste the LLM call — you only retry the tool.

Common Retry Strategies Compared

Strategy Description Best For Downside
Immediate Retry Retry right away, no delay Very rare, fast-recovering errors Can overwhelm the service
Fixed Delay Wait the same amount between retries Predictable recovery times May wait too long or not long enough
Exponential Backoff Double the wait time each attempt Most network/API failures Can take a long time for many retries
Exponential + Jitter Backoff with random variation Distributed systems with many clients Slightly more complex to implement
🌟 Best Practice: For AI agents, use exponential backoff with jitter as your default strategy. It handles the widest range of failure scenarios and plays nicely with shared APIs.

Circuit Breaker: When to Stop Trying

Sometimes, retrying over and over just wastes resources. A circuit breaker pattern stops retries after a threshold and "opens the circuit" — meaning no more requests are sent for a cooldown period.

import time
import random

class CircuitBreaker:
    """Stop retrying when failures exceed a threshold."""
    
    CLOSED = "CLOSED"      # Normal operation
    OPEN = "OPEN"          # Blocking all requests
    HALF_OPEN = "HALF_OPEN"  # Testing if service recovered
    
    def __init__(self, failure_threshold=5, recovery_timeout=30):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.state = self.CLOSED
        self.failure_count = 0
        self.last_failure_time = None
    
    def can_execute(self):
        """Check if a request should be allowed."""
        if self.state == self.CLOSED:
            return True
        elif self.state == self.OPEN:
            # Check if recovery timeout has passed
            if time.time() - self.last_failure_time >= self.recovery_timeout:
                print("  [CircuitBreaker] Timeout passed. Trying HALF_OPEN...")
                self.state = self.HALF_OPEN
                return True
            print("  [CircuitBreaker] Circuit is OPEN. Request blocked.")
            return False
        elif self.state == self.HALF_OPEN:
            return True  # Allow one test request
    
    def record_success(self):
        """Record a successful request."""
        self.failure_count = 0
        if self.state == self.HALF_OPEN:
            print("  [CircuitBreaker] Recovery confirmed! Circuit CLOSED.")
        self.state = self.CLOSED
    
    def record_failure(self):
        """Record a failed request."""
        self.failure_count += 1
        self.last_failure_time = time.time()
        print(f"  [CircuitBreaker] Failure {self.failure_count}/{self.failure_threshold}")
        if self.failure_count >= self.failure_threshold:
            print("  [CircuitBreaker] Threshold reached! Circuit OPEN.")
            self.state = self.OPEN

# Example usage
breaker = CircuitBreaker(failure_threshold=3, recovery_timeout=5)

@retry(max_retries=2, base_delay=0.1, retryable_exceptions=(ConnectionError,))
def api_call_with_circuit_breaker(url):
    """Make an API call protected by a circuit breaker."""
    if not breaker.can_execute():
        raise ConnectionError("Circuit breaker is OPEN")
    
    print(f"  Calling {url}...")
    if random.random() < 0.7:
        breaker.record_failure()
        raise ConnectionError("API failed")
    
    breaker.record_success()
    return f"Data from {url}"

# Simulate multiple requests
for i in range(10):
    print(f"\n--- Request {i+1} ---")
    try:
        result = api_call_with_circuit_breaker("https://api.example.com")
        print(f"  ✅ {result}")
    except ConnectionError as e:
        print(f"  ❌ {e}")
    time.sleep(0.5)
⚠️ Important: Circuit breakers are essential for production AI agents. Without them, a failing service can cause your agent to hang indefinitely, wasting compute and blocking users.

Practical Guidelines for AI Agents

  1. Set reasonable retry limits: 3–5 retries is usually enough. If it doesn't work by then, it likely won't.
  2. Use exponential backoff with jitter: This is the gold standard for most scenarios.
  3. Only retry transient errors: Don't retry authentication errors, validation errors, or "not found" errors.
  4. Log every retry: When debugging agent failures, retry logs are invaluable.
  5. Set a maximum total timeout: Don't let retries go on forever. Cap the total time spent retrying.
  6. Use circuit breakers for external services: Protect your agent from getting stuck on a broken dependency.
  7. Make retries configurable: Different tools and APIs may need different retry settings.
🧪 Exercise: Build a Resilient API Client

Create a function resilient_api_call() that combines all the retry patterns you've learned:

  • Accepts a URL and optional max_retries parameter (default: 4)
  • Uses exponential backoff with jitter (base delay: 0.5s)
  • Only retries on ConnectionError and TimeoutError
  • Logs each attempt with its number and wait time
  • Returns the result on success, or raises the last exception after all retries

Then write a second function agent_workflow() that calls resilient_api_call() three times in sequence (simulating a 3-step agent workflow), where each step depends on the previous step's output.

import time
import random
from functools import wraps

def resilient_api_call(url, max_retries=4):
    """
    Make an API call with exponential backoff, jitter,
    and selective retry on transient errors only.
    """
    base_delay = 0.5
    last_exception = None
    
    for attempt in range(1, max_retries + 1):
        try:
            print(f"  [API] Attempt {max_retries} for {url}...")
            # Simulate API behavior
            roll = random.random()
            if roll < 0.3:
                raise ConnectionError(f"Cannot connect to {url}")
            elif roll < 0.5:
                raise TimeoutError(f"Request to {url} timed out")
            elif roll < 0.55:
                raise ValueError("Invalid request format")  # NOT retryable
            
            result = f"Data from {url}"
            print(f"  [API] ✅ Success on attempt {attempt}")
            return result
            
        except (ConnectionError, TimeoutError) as e:
            last_exception = e
            print(f"  [API] ⚠️ Transient error: {e}")
            
            if attempt == max_retries:
                print(f"  [API] ❌ All {max_retries} retries exhausted for {url}")
                raise
            
            wait_time = base_delay * (2 ** (attempt - 1))
            jitter = random.uniform(0, wait_time * 0.5)
            total_wait = wait_time + jitter
            print(f"  [API] Waiting {total_wait:.2f}s before retry...")
            time.sleep(total_wait)
            
        except ValueError as e:
            # Non-retryable error — fail immediately
            print(f"  [API] ❌ Non-retryable error: {e}")
            raise
    
    raise last_exception


def agent_workflow(start_url):
    """
    A 3-step agent workflow where each step depends on the previous.
    Each step uses resilient retry logic.
    """
    print(f"\n🤖 Starting agent workflow with: {start_url}")
    print("=" * 55)
    
    # Step 1: Fetch initial data
    print("\n📡 Step 1: Fetching initial data...")
    data = resilient_api_call(start_url)
    
    # Step 2: Process the data (depends on step 1)
    print(f"\n🔧 Step 2: Processing '{data}'...")
    processed = resilient_api_call(f"process.api/transform?input={data}")
    
    # Step 3: Store the result (depends on step 2)
    print(f"\n💾 Step 3: Storing '{processed}'...")
    confirmation = resilient_api_call(f"store.api/save?result={processed}")
    
    print(f"\n🎉 Workflow complete! Confirmation: {confirmation}")
    return confirmation


# Run the workflow
try:
    agent_workflow("https://api.example.com/start")
except Exception as e:
    print(f"\n💥 Workflow failed: {e}")

Key Takeaways

  • Retry patterns automatically re-attempt failed operations, making AI agents more resilient to temporary failures.
  • Exponential backoff progressively increases wait times between retries, giving services time to recover.
  • Jitter adds randomness to wait times, preventing many clients from retrying simultaneously (the "thundering herd" problem).
  • Only retry transient errors like connection failures and timeouts — never retry logic errors like bad requests or authentication failures.
  • Circuit breakers stop all requests to a failing service after a threshold, preventing resource waste and enabling recovery.
  • Decorators let you add retry logic to any function cleanly and reusable, keeping your agent code clean.
  • In AI agent workflows, apply retry logic at each independent step so that a failure in one step doesn't waste the work of previous steps.
  • Always log retries and set reasonable limits (3–5 retries, with a maximum total timeout) to prevent infinite loops.
