Indexing & Searching

Learn about indexing & searching.

What Is Indexing and Why Does It Matter?

Imagine you have a massive library with millions of books, but there's no catalog, no labels, and no organization. Finding a specific piece of information would take forever. That's exactly the problem AI agents face when working with large amounts of data. Indexing is the process of organizing data so that it can be searched and retrieved quickly and efficiently.

In the context of AI agents, indexing is one of the most important concepts you'll learn. It's the backbone of a technique called Retrieval-Augmented Generation (RAG), which allows AI agents to look up relevant information from a knowledge base before generating a response. Instead of relying solely on what the model was trained on, the agent can search through your specific documents, databases, or files to find exactly the right information.

What is RAG? Retrieval-Augmented Generation (RAG) is a technique where an AI agent first retrieves relevant information from a data source, then uses that information to generate a more accurate and contextually relevant response. Think of it as giving the AI an open-book exam instead of a closed-book one.

How Indexing Works: The Core Concepts

Before we dive into code, let's understand the key building blocks of indexing and search. There are three main steps involved in making your data searchable:

  1. Chunking — Breaking large documents into smaller, manageable pieces.
  2. Embedding — Converting each chunk into a numerical vector that captures its meaning.
  3. Storing — Saving those vectors in a special database optimized for fast similarity searches.

Step 1: Chunking Your Data

Raw data comes in all shapes and sizes — long PDFs, web pages, database records, chat logs. Before you can index anything, you need to break it down into smaller pieces called chunks. The size of your chunks matters a lot:

  • Too small — The chunk may lack enough context to be meaningful.
  • Too large — The chunk may contain too much irrelevant information, diluting the search results.
  • Just right — Typically 200–500 tokens, with some overlap between chunks to preserve context at boundaries.
from langchain.text_splitter import RecursiveCharacterTextSplitter

# Sample document
document = """
Artificial intelligence (AI) is transforming industries across the globe. 
Machine learning, a subset of AI, enables systems to learn from data. 
Deep learning uses neural networks with many layers to model complex patterns. 
Natural language processing allows machines to understand human language. 
Computer vision enables machines to interpret visual information from the world.
"""

# Create a text splitter with chunk size and overlap
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=100,
    chunk_overlap=20,
    length_function=len,
)

# Split the document into chunks
chunks = text_splitter.split_text(document)

for i, chunk in enumerate(chunks):
    print(f"Chunk {i + 1}: {chunk}")
    print("-" * 50)
Pro Tip: The RecursiveCharacterTextSplitter is one of the most popular chunking strategies. It tries to split on paragraphs first, then sentences, then words — recursively — to keep related content together. Always experiment with chunk_size and chunk_overlap to find the best settings for your specific data.

Step 2: Creating Embeddings

Once your data is chunked, each piece needs to be converted into a vector embedding — a list of numbers that represents the semantic meaning of the text. Texts with similar meanings will have vectors that are close together in vector space.

from langchain_openai import OpenAIEmbeddings

# Initialize the embedding model
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# Sample chunks from our document
chunks = [
    "Artificial intelligence (AI) is transforming industries across the globe.",
    "Machine learning, a subset of AI, enables systems to learn from data.",
    "Deep learning uses neural networks with many layers to model complex patterns.",
]

# Generate embeddings for each chunk
for i, chunk in enumerate(chunks):
    vector = embeddings.embed_query(chunk)
    print(f"Chunk {i + 1} embedding (first 5 values): {vector[:5]}")
    print(f"Vector length: {len(vector)}")
    print("-" * 50)

Each embedding is typically a vector of 1,536 numbers (for OpenAI's text-embedding-3-small model). These numbers don't mean anything individually, but together they create a unique "fingerprint" of the text's meaning. When you search, the system converts your query into a vector too, then finds the stored vectors that are most similar.

Step 3: Storing in a Vector Database

Now that we have our embeddings, we need a place to store them. A regular database isn't optimized for finding similar vectors. Instead, we use a vector database — a specialized database designed for fast similarity searches.

Vector Database Best For Deployment Open Source?
Chroma Prototyping, small projects, local development Local / In-memory Yes
Pinecone Production apps, managed service Cloud No
Weaviate Hybrid search, enterprise applications Cloud / Self-hosted Yes
FAISS Large-scale similarity search, research Local Yes
Qdrant Production-grade, filtering + search Cloud / Self-hosted Yes

For this lesson, we'll use Chroma because it's easy to set up locally and perfect for learning.

from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain.text_splitter import RecursiveCharacterTextSplitter

# Sample documents
documents = [
    "Python is a versatile programming language used in web development, data science, and AI.",
    "JavaScript is the primary language for web development, running in browsers and on servers.",
    "Machine learning algorithms can classify images, predict trends, and generate text.",
    "Vector databases store embeddings and enable fast similarity search for AI applications.",
    "LangChain is a framework for building applications powered by language models.",
]

# Split documents into chunks
text_splitter = RecursiveCharacterTextSplitter(chunk_size=200, chunk_overlap=20)
chunks = text_splitter.create_documents(documents)

# Create embeddings
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# Store in Chroma vector database
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db"
)

print(f"Indexed {len(chunks)} chunks into the vector database.")

Searching Your Index

With your data indexed, you can now perform similarity searches. This is where the magic happens — you ask a question, and the system finds the most relevant chunks from your data.

Basic Similarity Search

# Load the existing vector store
vectorstore = Chroma(
    persist_directory="./chroma_db",
    embedding_function=OpenAIEmbeddings(model="text-embedding-3-small")
)

# Search for relevant documents
query = "What is used for building AI applications?"
results = vectorstore.similarity_search(query, k=3)

print(f"Query: {query}\n")
for i, doc in enumerate(results):
    print(f"Result {i + 1}:")
    print(f"  Content: {doc.page_content}")
    print(f"  Source: {doc.metadata.get('source', 'unknown')}")
    print("-" * 50)

Similarity Search with Scores

Sometimes you want to know how relevant each result is. You can get similarity scores alongside the results:

query = "Tell me about programming languages for the web"
results_with_scores = vectorstore.similarity_search_with_score(query, k=3)

print(f"Query: {query}\n")
for i, (doc, score) in enumerate(results_with_scores):
    print(f"Result {i + 1} (Score: {score:.4f}):")
    print(f"  Content: {doc.page_content}")
    print("-" * 50)
Understanding Scores: In Chroma, the score represents the distance between vectors — lower scores mean higher similarity. A score of 0.0 would be a perfect match. Don't confuse this with cosine similarity where higher is better. Always check the documentation for your specific vector database to understand how scores work.

Maximum Marginal Relevance (MMR) Search

Regular similarity search can return results that are all very similar to each other. MMR search balances relevance with diversity, ensuring you get a broader range of useful results:

query = "How do AI systems work?"
results = vectorstore.max_marginal_relevance_search(query, k=3, fetch_k=10)

print(f"Query: {query}\n")
for i, doc in enumerate(results):
    print(f"Result {i + 1}:")
    print(f"  Content: {doc.page_content}")
    print("-" * 50)

The fetch_k parameter tells the system to first fetch 10 candidates, then select the 3 most diverse and relevant ones. This gives you better coverage of your data.

Building a Complete RAG Pipeline

Now let's put it all together into a complete RAG pipeline — the foundation of most AI agent knowledge systems:

from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.chains import RetrievalQA
from langchain_core.documents import Document

# Step 1: Prepare your documents
raw_documents = [
    Document(
        page_content="OWL is an AI assistant developed by ZOO company. It helps developers build AI applications.",
        source="about_owl.txt"
    ),
    Document(
        page_content="RAG stands for Retrieval-Augmented Generation. It combines search with language model generation.",
        source="rag_guide.txt"
    ),
    Document(
        page_content="Vector databases like Chroma, Pinecone, and Weaviate store embeddings for fast similarity search.",
        source="vector_db_guide.txt"
    ),
    Document(
        page_content="Chunking strategies include fixed-size splitting, recursive character splitting, and semantic splitting.",
        source="chunking_guide.txt"
    ),
]

# Step 2: Split into chunks
splitter = RecursiveCharacterTextSplitter(chunk_size=150, chunk_overlap=15)
chunks = splitter.split_documents(raw_documents)

# Step 3: Create embeddings and store in vector database
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(documents=chunks, embedding=embeddings)

# Step 4: Create a retriever
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# Step 5: Create the RAG chain
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    retriever=retriever,
    return_source_documents=True
)

# Step 6: Ask questions!
query = "What is RAG and how does it work?"
result = qa_chain.invoke({"query": query})

print(f"Question: {query}")
print(f"\nAnswer: {result['result']}")
print(f"\nSources used:")
for doc in result["source_documents"]:
    print(f"  - {doc.metadata.get('source', 'unknown')}: {doc.page_content[:80]}...")

Metadata and Filtering

One of the most powerful features of vector databases is the ability to attach metadata to your documents and use it to filter search results. This is critical for real-world AI agents that need to search within specific categories, date ranges, or user permissions.

from langchain_core.documents import Document

# Documents with rich metadata
documents = [
    Document(
        page_content="Python 3.12 introduced improved error messages and performance optimizations.",
        metadata={"category": "programming", "language": "python", "year": 2023, "difficulty": "intermediate"}
    ),
    Document(
        page_content="React 18 introduced concurrent rendering and automatic batching.",
        metadata={"category": "programming", "language": "javascript", "year": 2022, "difficulty": "intermediate"}
    ),
    Document(
        page_content="GPT-4 Turbo supports a 128K context window and knowledge up to April 2024.",
        metadata={"category": "ai", "language": "general", "year": 2024, "difficulty": "advanced"}
    ),
    Document(
        page_content="Chroma is an open-source embedding database for AI applications.",
        metadata={"category": "ai", "language": "python", "year": 2023, "difficulty": "beginner"}
    ),
]

# Store with metadata
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(documents=documents, embedding=embeddings)

# Search with metadata filter — only AI-related documents
results = vectorstore.similarity_search(
    query="What are the latest AI tools?",
    k=2,
    filter={"category": "ai"}
)

print("Filtered results (AI category only):")
for doc in results:
    print(f"  [{doc.metadata['language']}] {doc.page_content}")
    print(f"  Year: {doc.metadata['year']}, Difficulty: {doc.metadata['difficulty']}")
    print("-" * 50)
Best Practice: Always add metadata to your documents during indexing. At minimum, include a source field so your AI agent can cite its sources. Additional metadata like category, date, author, or access_level enables powerful filtering that makes your agent much more useful.

Common Pitfalls and How to Avoid Them

Indexing and search might seem straightforward, but there are several common mistakes that can seriously degrade your AI agent's performance:

  • Wrong chunk size: If chunks are too small, the agent loses context. If too large, it gets noise. Start with 200–500 tokens and adjust based on your data.
  • No chunk overlap: Without overlap (typically 10–20% of chunk size), important information at chunk boundaries gets lost.
  • Ignoring metadata: Documents without metadata are like books without titles. Always tag your data.
  • Not updating the index: When your source data changes, your index becomes stale. Build a re-indexing strategy from day one.
  • Using the wrong embedding model: Different models have different strengths. text-embedding-3-small is great for general use, but domain-specific data may benefit from fine-tuned models.
Performance Warning: Indexing large datasets can be slow and expensive. Each chunk requires an API call to generate embeddings. For a 100-page document split into 500 chunks, that's 500 API calls. Always test with a small subset first, and consider batching your embedding requests to avoid rate limits.

Key Takeaways

  • Indexing is the process of organizing data (chunking → embedding → storing) so AI agents can search it efficiently.
  • Chunking breaks large documents into smaller pieces. Use RecursiveCharacterTextSplitter with 200–500 token chunks and 10–20% overlap for best results.
  • Embeddings convert text into numerical vectors that capture semantic meaning. Similar texts have similar vectors.
  • Vector databases like Chroma, Pinecone, and Weaviate are optimized for fast similarity searches across millions of embeddings.
  • RAG (Retrieval-Augmented Generation) combines search with language model generation to give AI agents access to specific, up-to-date knowledge.
  • Metadata filtering lets you narrow search results by category, date, or any custom field — essential for production AI agents.
  • MMR search provides more diverse results than basic similarity search by balancing relevance with variety.
  • Always add source metadata to your documents so your agent can cite where information came from.
