How RAG Works

Learn about how rag works.

What Is Retrieval-Augmented Generation?

Retrieval-Augmented Generation (RAG) is a technique that enhances AI language models by giving them access to external knowledge sources. Instead of relying solely on what the model learned during training, RAG allows the model to "look up" relevant information before generating a response.

Why RAG matters: Large language models have a knowledge cutoff date. RAG lets them access current, specific, or private information they weren't trained on.

The RAG Pipeline

A typical RAG system works in three stages:

  1. Indexing: Documents are processed and stored in a searchable format (usually as vector embeddings)
  2. Retrieval: When a question is asked, the system finds the most relevant document chunks
  3. Generation: The retrieved context is combined with the user's question and sent to the language model

Understanding Vector Embeddings

Before documents can be searched semantically, they need to be converted into numerical representations called embeddings. These are vectors (lists of numbers) that capture the meaning of text.

from sentence_transformers import SentenceTransformer

# Load a pre-trained embedding model
model = SentenceTransformer('all-MiniLM-L6-v2')

# Convert text to embeddings
documents = [
    "Python is a programming language",
    "JavaScript runs in web browsers",
    "Machine learning uses statistical methods"
]

embeddings = model.encode(documents)

print(f"Embedding dimension: {embeddings.shape[1]}")
print(f"First 5 values of first embedding: {embeddings[0][:5]}")
Tip: The 'all-MiniLM-L6-v2' model produces 384-dimensional vectors. Larger models produce higher-dimensional embeddings but are slower.

Why Embeddings Enable Semantic Search

Traditional keyword search looks for exact matches. Semantic search using embeddings finds conceptually similar content even when the words are different.

Query Keyword Match Semantic Match
"How to code in Python" Only finds docs with "Python" and "code" Finds docs about programming, scripting, development

Building a Simple RAG System

Let's build a basic RAG pipeline using Python. We'll use a vector store to hold our document embeddings and retrieve relevant context for questions.

import numpy as np
from sentence_transformers import SentenceTransformer

class SimpleRAG:
    def __init__(self):
        self.model = SentenceTransformer('all-MiniLM-L6-v2')
        self.documents = []
        self.embeddings = None
    
    def add_documents(self, docs):
        """Add documents and compute their embeddings"""
        self.documents.extend(docs)
        self.embeddings = self.model.encode(self.documents)
    
    def retrieve(self, query, top_k=2):
        """Find the most relevant documents for a query"""
        query_embedding = self.model.encode([query])
        
        # Compute cosine similarity
        similarities = np.dot(self.embeddings, query_embedding.T).flatten()
        similarities = similarities / (np.linalg.norm(self.embeddings, axis=1) * np.linalg.norm(query_embedding))
        
        # Get top-k indices
        top_indices = np.argsort(similarities)[-top_k:][::-1]
        
        return [(self.documents[i], similarities[i]) for i in top_indices]

# Usage
rag = SimpleRAG()
rag.add_documents([
    "RAG combines retrieval with generation",
    "Vector databases store document embeddings",
    "Python is used for AI development"
])

results = rag.retrieve("How does RAG work?")
for doc, score in results:
    print(f"Score: {score:.3f} | {doc}")
Warning: This is a simplified example. Production RAG systems use dedicated vector databases like Pinecone, Weaviate, or ChromaDB for efficient similarity search at scale.

Integrating with a Language Model

Once we retrieve relevant context, we combine it with the user's question to create an enriched prompt for the language model.

def generate_response(query, retrieved_docs, llm_client):
    """Generate a response using retrieved context"""
    context = "\n".join([doc for doc, _ in retrieved_docs])
    
    prompt = f"""Based on the following context, answer the question.

Context:
{context}

Question: {query}

Answer:"""
    
    response = llm_client.generate(prompt)
    return response

Evaluating RAG Systems

Not all RAG systems perform equally. Key metrics help us measure quality:

  • Retrieval Accuracy: Are the right documents being found?
  • Answer Relevance: Does the generated answer address the question?
  • Faithfulness: Is the answer supported by the retrieved context?
  • Latency: How long does the full pipeline take?

def chunk_document(text, chunk_size=100, overlap=20):
    """
    Split text into overlapping chunks.
    """
    words = text.split()
    chunks = []
    step = chunk_size - overlap
    
    for i in range(0, len(words), step):
        chunk = " ".join(words[i:i + chunk_size])
        chunks.append(chunk)
        
        # Stop if we've reached the end
        if i + chunk_size >= len(words):
            break
    
    return chunks

Key Takeaways

  • RAG enhances language models by providing access to external, up-to-date information
  • Vector embeddings enable semantic search, finding conceptually similar content beyond keyword matching
  • The RAG pipeline consists of indexing, retrieval, and generation stages
  • Document chunking is crucial—too large and you lose precision, too small and you lose context
  • Production systems use dedicated vector databases for efficient similarity search at scale
  • Evaluating RAG requires measuring both retrieval quality and generation faithfulness
