Shared State

Learn about shared state.

What Is Shared State?

In multi-agent systems, shared state refers to data that multiple agents can access, read from, and write to during their operation. Think of it like a communal whiteboard in a team meeting — everyone can see what's written there, and anyone can add or update information.

Shared state is essential when agents need to coordinate, avoid duplicating work, or build on each other's progress. Without it, agents operate in isolation and can't collaborate effectively.

Why Shared State Matters

Imagine two agents working on a research task. One agent gathers data while the other analyzes it. Without shared state, the analyst agent has no way to know when the data is ready or where to find it. Shared state solves this by providing a common reference point.

Key Insight: Shared state enables agents to communicate indirectly. Instead of sending messages directly to each other, agents read and write to a shared data structure.

Types of Shared State

There are several common patterns for implementing shared state in agent systems:

Type Description Best For
Shared Dictionary A simple key-value store accessible by all agents Small-scale coordination, flags, counters
Shared List/Queue Ordered collection where agents add or consume items Task distribution, work queues
Shared Object A structured object with methods and properties Complex state with validation or logic
Database/File Persistent storage accessible across agents Large datasets, long-running tasks

Implementing Shared State in Python

Let's look at a basic example using a shared dictionary to coordinate two agents: one that produces data and one that consumes it.

import threading
import time

# Shared state: a dictionary accessible by all agents
shared_state = {
    "data_ready": False,
    "data": None,
    "processed": False
}

# Lock to prevent race conditions
lock = threading.Lock()

def producer_agent():
    """Simulates an agent that gathers data."""
    print("Producer: Starting data collection...")
    time.sleep(2)  # Simulate work
    
    with lock:
        shared_state["data"] = [10, 20, 30, 40, 50]
        shared_state["data_ready"] = True
        print("Producer: Data is ready!")

def consumer_agent():
    """Simulates an agent that processes data."""
    print("Consumer: Waiting for data...")
    
    while True:
        with lock:
            if shared_state["data_ready"]:
                data = shared_state["data"]
                total = sum(data)
                shared_state["processed"] = True
                print(f"Consumer: Processed data. Sum = {total}")
                break
        time.sleep(0.5)  # Check periodically

# Run both agents in parallel
t1 = threading.Thread(target=producer_agent)
t2 = threading.Thread(target=consumer_agent)

t1.start()
t2.start()

t1.join()
t2.join()

print("Final shared state:", shared_state)
Warning: Always use locks or other synchronization mechanisms when multiple agents write to shared state simultaneously. Without them, you risk race conditions — where the outcome depends on unpredictable timing.

Using Queues for Task Distribution

A more robust pattern uses a queue to distribute work among agents. This avoids busy-waiting and scales better.

import queue
import threading
import time

# Shared queue for tasks
task_queue = queue.Queue()
results = []

def worker_agent(agent_id):
    """An agent that processes tasks from the queue."""
    while True:
        try:
            task = task_queue.get(timeout=2)  # Wait up to 2 seconds
            result = task * task  # Example: square the number
            results.append((agent_id, task, result))
            print(f"Agent {agent_id}: Processed {task} → {result}")
            task_queue.task_done()
        except queue.Empty:
            print(f"Agent {agent_id}: No more tasks. Exiting.")
            break

# Add tasks to the queue
for i in range(1, 11):
    task_queue.put(i)

# Start multiple worker agents
agents = []
for i in range(3):
    t = threading.Thread(target=worker_agent, args=(i,))
    agents.append(t)
    t.start()

# Wait for all tasks to complete
task_queue.join()

# Wait for all agents to finish
for t in agents:
    t.join()

print("\nAll results:", results)

Best Practices for Shared State

When designing shared state for your agent systems, keep these principles in mind:

  • Minimize shared state: Only share what's necessary. The less shared data, the fewer synchronization issues you'll face.
  • Use immutable data when possible: If agents only read data (never modify it), you avoid many concurrency problems.
  • Prefer message passing over shared memory: In some architectures, passing messages between agents is cleaner than shared state.
  • Document ownership: Clearly define which agent is responsible for writing to each piece of shared state.
  • Handle failures gracefully: What happens if an agent crashes while updating shared state? Plan for it.
Pro Tip: Start simple. Use a shared dictionary for prototyping, then move to more robust solutions like databases or message brokers as your system grows.

Common Pitfalls

Here are mistakes to avoid when working with shared state:

  1. Race conditions: Two agents modify the same data at the same time, causing corruption.
  2. Deadlocks: Two agents each wait for the other to release a lock, freezing the system.
  3. Stale data: An agent reads outdated information because another agent hasn't finished updating it yet.
  4. Over-sharing: Making too much data shared increases complexity and slows down your system.
Exercise: Build a Shared Counter

Create a program where three agents increment a shared counter from 0 to 30. Each agent should increment the counter by 1, ten times. Use a lock to ensure the final value is exactly 30.

Your program should:

  • Initialize a shared counter at 0
  • Create three threads, each incrementing the counter 10 times
  • Use a lock to protect the increment operation
  • Print the final counter value
import threading

counter = 0
lock = threading.Lock()

def increment_counter(agent_id):
    global counter
    for _ in range(10):
        with lock:
            current = counter
            # Simulate some work
            counter = current + 1
    print(f"Agent {agent_id} finished.")

# Create and start three agents
threads = []
for i in range(3):
    t = threading.Thread(target=increment_counter, args=(i,))
    threads.append(t)
    t.start()

# Wait for all threads to complete
for t in threads:
    t.join()

print(f"Final counter value: {counter}")  # Should be 30

Key Takeaways

  • Shared state allows multiple agents to coordinate by reading and writing to common data structures.
  • Use locks or other synchronization to prevent race conditions when multiple agents write simultaneously.
  • Queues are an excellent pattern for distributing work among agents without busy-waiting.
  • Minimize shared state and prefer immutable data when possible to reduce complexity.
  • Always plan for failure — what happens if an agent crashes mid-update?
