RAG as an Agent Tool

Learn about rag as an agent tool.

What Is RAG and Why Does It Matter for Agents?

Retrieval-Augmented Generation (RAG) is a technique that enhances large language models (LLMs) by giving them access to external knowledge sources. Instead of relying solely on what the model learned during training, RAG allows the model to "look up" relevant information before generating a response. This is especially powerful for AI agents, which often need to reason about specific, up-to-date, or domain-specific data that wasn't part of the model's original training set.

In this lesson, we'll explore how RAG can be used as a tool within an agent framework, enabling your agents to retrieve and reason over external documents, databases, or APIs before taking action.

How RAG Works: A Quick Overview

At a high level, RAG involves three main steps:

  1. Retrieve: Given a user query, the system searches a knowledge base (e.g., a vector database) to find relevant documents or passages.
  2. Augment: The retrieved context is combined with the original query to form an enriched prompt.
  3. Generate: The LLM uses this augmented prompt to produce a more accurate, context-aware response.

This process helps reduce hallucinations and keeps responses grounded in real data.

Note: RAG does not require fine-tuning the model. It works by dynamically injecting relevant context at inference time, making it flexible and cost-effective.

Using RAG as an Agent Tool

In an agent architecture, tools are functions or services the agent can call to gather information or perform actions. RAG fits naturally as a retrieval tool — the agent decides when it needs external knowledge and invokes the RAG pipeline accordingly.

For example, imagine a customer support agent. When a user asks, "What's your return policy?", the agent doesn't guess — it uses a RAG tool to fetch the latest policy document and generates a precise answer.

Designing a RAG Tool for Agents

To integrate RAG as a tool, you need to:

  • Preprocess and index your documents into a searchable format (e.g., using embeddings and a vector store).
  • Define a function that takes a query, retrieves relevant chunks, and returns them as context.
  • Register this function as a tool in your agent framework.

Here’s a simplified example using Python and LangChain:

from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings
from langchain_core.tools import tool

# Assume documents are already loaded and split
embeddings = OpenAIEmbeddings()
vectorstore = FAISS.from_documents(documents, embeddings)

@tool
def retrieve_policy(query: str) -> str:
    """Retrieve relevant policy documents based on the query."""
    docs = vectorstore.similarity_search(query, k=3)
    return "\n\n".join([doc.page_content for doc in docs])

This retrieve_policy function can now be passed to an agent as a tool. The agent will call it whenever it needs policy-related information.

Tip: Always include a clear description in your tool’s docstring. Agents use this to decide when to invoke the tool.

RAG vs. Other Knowledge Strategies

Let’s compare RAG with other common approaches to handling external knowledge:

Strategy Pros Cons Best For
RAG Dynamic, up-to-date, no retraining Latency from retrieval step, depends on index quality Factual Q&A, document-heavy domains
Fine-tuning Fast inference, deep domain adaptation Expensive, static knowledge, risk of catastrophic forgetting Style transfer, narrow tasks with stable data
Prompt Engineering Simple, no infrastructure needed Limited context window, manual curation Small, static knowledge bases

Building a Simple RAG-Enabled Agent

Let’s build a minimal agent that uses our RAG tool. We’ll use LangChain’s agent framework for this example.

from langchain_openai import ChatOpenAI
from langchain.agents import AgentExecutor, create_tool_calling_agent
from langchain_core.prompts import ChatPromptTemplate

llm = ChatOpenAI(model="gpt-4")
tools = [retrieve_policy]

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant. Use the retrieve_policy tool when asked about company policies."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}")
])

agent = create_tool_calling_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

response = agent_executor.invoke({"input": "What is the return policy for electronics?"})
print(response["output"])

When run, the agent will automatically call retrieve_policy if it determines the question relates to policies, then generate a grounded response.

Warning: Always validate retrieved content. Poorly indexed or outdated documents can lead to incorrect answers, even with RAG.

Exercise: Create Your Own RAG Tool

Exercise

Create a RAG tool called search_faq that retrieves answers from a list of frequently asked questions. Use the following sample FAQ data:

faq_documents = [
    "Q: How do I reset my password? A: Go to Settings > Security > Reset Password.",
    "Q: Where can I view my order history? A: Navigate to Account > Orders.",
    "Q: How do I contact support? A: Email support@example.com or use the in-app chat."
]

Write the Python function decorated with @tool that performs a simple keyword match (for simplicity, no vector store needed). Return the best-matching FAQ entry.

from langchain_core.tools import tool

faq_documents = [
    "Q: How do I reset my password? A: Go to Settings > Security > Reset Password.",
    "Q: Where can I view my order history? A: Navigate to Account > Orders.",
    "Q: How do I contact support? A: Email support@example.com or use the in-app chat."
]

@tool
def search_faq(query: str) -> str:
    """Search FAQ documents for relevant answers based on keyword matching."""
    query_lower = query.lower()
    best_match = None
    best_score = 0
    
    for doc in faq_documents:
        score = sum(1 for word in query_lower.split() if word in doc.lower())
        if score > best_score:
            best_score = score
            best_match = doc
    
    return best_match if best_match else "No relevant FAQ found."

Key Takeaways

  • RAG enhances LLMs by retrieving external knowledge at inference time, reducing hallucinations.
  • RAG can be implemented as a reusable tool within an agent architecture.
  • Agents use tool descriptions to decide when to invoke RAG — clear docstrings are essential.
  • RAG is dynamic and doesn’t require model retraining, making it ideal for evolving knowledge bases.
  • Always validate your retrieval pipeline — garbage in, garbage out.
