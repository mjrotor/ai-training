Vector DB Overview

Learn about vector db overview.

What Is a Vector Database?

A vector database is a specialized type of database designed to store, index, and query vector embeddings — numerical representations of data (like text, images, or audio) that capture semantic meaning. Unlike traditional databases that match exact values, vector databases find similar items based on their mathematical proximity in a high-dimensional space.

Think of it this way: if you search for "happy" in a traditional database, you only get results containing the exact word "happy." But in a vector database, you also get results with "joyful," "cheerful," or "elated" — because their vector representations are close together in meaning-space.

💡 Key Concept: A vector embedding is a list of numbers (e.g., [0.23, -0.87, 0.45, ...]) that represents the meaning of a piece of data. Models like OpenAI's text-embedding-ada-002 or open-source alternatives like sentence-transformers generate these embeddings.

Why Do AI Agents Need Vector Databases?

AI agents often need to remember and retrieve relevant information from large knowledge bases. This is the core of Retrieval-Augmented Generation (RAG) — a pattern where an agent:

  1. Receives a user query
  2. Searches a vector database for semantically similar documents
  3. Feeds those documents as context to an LLM
  4. Generates an accurate, grounded response

Without a vector database, an agent would either need to feed all its knowledge into the LLM's context window (expensive and limited) or rely solely on the LLM's training data (which may be outdated or incomplete).

🎯 Pro Tip: Vector databases are the backbone of almost every production RAG system. Mastering them is essential for building reliable AI agents that can reason over private or domain-specific data.

How Vector Search Works

When you store a document in a vector database, the following happens:

  1. Embedding: The document is converted into a vector using an embedding model.
  2. Indexing: The vector is stored in a specialized index structure optimized for fast similarity search.
  3. Querying: When you search, your query is also embedded, and the database finds the nearest vectors using a distance metric.

Distance Metrics

The most common ways to measure "closeness" between vectors:

Metric Description Best For
Cosine Similarity Measures the angle between two vectors (ignores magnitude) Text embeddings (most common)
Euclidean (L2) Distance Straight-line distance between two points Image embeddings, spatial data
Dot Product Measures both angle and magnitude When magnitude carries meaning
⚠️ Important: Always use the same embedding model for both storing and querying. Mixing models will produce meaningless results because each model maps data to different vector spaces.

Popular Vector Databases

Here are the most widely used vector databases in production today:

  • ChromaDB — Lightweight, Python-native, great for prototyping and local development
  • Pinecone — Fully managed cloud service, excellent for production at scale
  • Weaviate — Open-source with built-in vectorization and GraphQL API
  • Qdrant — Open-source, written in Rust, high performance with filtering support
  • pgvector — PostgreSQL extension, ideal if you already use Postgres
  • FAISS (Facebook) — A library (not a full DB) for fast similarity search, often used as a building block

Hands-On: Storing and Querying with ChromaDB

Let's walk through a complete example using ChromaDB, one of the easiest vector databases to get started with.

Step 1: Install Dependencies

pip install chromadb openai

Step 2: Create a Collection and Add Documents

import chromadb
from chromadb.utils import embedding_functions

# Initialize a persistent ChromaDB client
client = chromadb.PersistentClient(path="./my_vector_db")

# Use OpenAI's embedding function (or use a free alternative)
openai_ef = embedding_functions.OpenAIEmbeddingFunction(
    api_key="your-api-key",
    model_name="text-embedding-ada-002"
)

# Create a collection
collection = client.get_or_create_collection(
    name="agent_knowledge",
    embedding_function=openai_ef
)

# Add documents with metadata
collection.add(
    documents=[
        "Python is a versatile programming language used for web development, data science, and AI.",
        "Vector databases store embeddings for semantic search in AI applications.",
        "Retrieval-Augmented Generation combines LLMs with external knowledge sources.",
        "ChromaDB is an open-source vector database designed for AI applications."
    ],
    metadatas=[
        {"source": "python_intro", "category": "programming"},
        {"source": "vector_db_guide", "category": "databases"},
        {"source": "rag_explained", "category": "ai"},
        {"source": "chromadb_docs", "category": "databases"}
    ],
    ids=["doc1", "doc2", "doc3", "doc4"]
)

print(f"Collection now has {collection.count()} documents.")

Step 3: Query for Similar Documents

# Search for documents related to "How do AI systems find information?"
results = collection.query(
    query_texts=["How do AI systems find information?"],
    n_results=2,  # Return top 2 matches
    where={"category": "databases"}  # Optional: filter by metadata
)

for i, (doc, distance) in enumerate(zip(
    results["documents"][0],
    results["distances"][0]
)):
    print(f"Result {i+1} (distance: {distance:.4f}):")
    print(f"  {doc}")
    print()

Expected output:

Result 1 (distance: 0.3521):
  Vector databases store embeddings for semantic search in AI applications.
Result 2 (distance: 0.4892):
  ChromaDB is an open-source vector database designed for AI applications.

Step 4: Updating and Deleting Documents

# Update a document
collection.update(
    ids=["doc1"],
    documents=["Python is a powerful language for AI, machine learning, and web development."]
)

# Delete a document
collection.delete(ids=["doc4"])

print(f"Collection now has {collection.count()} documents.")
💡 Note: ChromaDB automatically re-embeds documents when you use update(). If you're using a paid embedding API, be mindful of API call costs when updating large collections.

Indexing Strategies for Large Datasets

When your vector database grows to millions of documents, brute-force search (comparing your query to every vector) becomes too slow. Vector databases use Approximate Nearest Neighbor (ANN) algorithms to speed things up:

Algorithm How It Works Trade-off
HNSW (Hierarchical Navigable Small World) Builds a multi-layer graph for fast traversal Fast queries, higher memory usage
IVF (Inverted File Index) Partitions vectors into clusters, searches only nearby clusters Good balance of speed and memory
PQ (Product Quantization) Compresses vectors to reduce memory footprint Lower memory, slight accuracy loss
🎯 Pro Tip: For most applications, the default indexing strategy works well. Only tune ANN parameters when you're working with 100K+ vectors and notice latency issues.

Metadata Filtering

One of the most powerful features of vector databases is the ability to combine semantic search with metadata filtering. This lets you narrow results before or after the vector search:

# Find documents about databases, but only from the "databases" category
results = collection.query(
    query_texts=["What tools help with data storage?"],
    n_results=3,
    where={"category": "databases"}  # Pre-filter: only search within this category
)

# You can also use complex filters
results = collection.query(
    query_texts=["programming languages"],
    n_results=3,
    where={
        "$and": [
            {"category": "programming"},
            {"source": "python_intro"}
        ]
    }
)

Coding Exercise

Exercise: Build a Mini Knowledge Base

Create a ChromaDB collection called space_facts and add at least 5 facts about space exploration (you can make them up or use real ones). Each document should have metadata with a topic field (e.g., "planets," "missions," "astronauts").

Then, write a query that searches for information about "traveling to other worlds" and filters to only return results where the topic is "missions."

Print the top result and its distance score.

import chromadb
from chromadb.utils import embedding_functions

# Initialize client
client = chromadb.Client()

# Use the default free embedding function
default_ef = embedding_functions.DefaultEmbeddingFunction()

# Create collection
collection = client.get_or_create_collection(
    name="space_facts",
    embedding_function=default_ef
)

# Add space facts with metadata
collection.add(
    documents=[
        "The Apollo 11 mission landed the first humans on the Moon in 1969.",
        "Mars is often called the Red Planet due to iron oxide on its surface.",
        "The Voyager 1 spacecraft is the farthest human-made object from Earth.",
        "NASA's Artemis program aims to return humans to the Moon by 2025.",
        "Jupiter is the largest planet in our solar system with 95 known moons.",
        "The International Space Station orbits Earth at approximately 400 kilometers altitude."
    ],
    metadatas=[
        {"topic": "missions"},
        {"topic": "planets"},
        {"topic": "missions"},
        {"topic": "missions"},
        {"topic": "planets"},
        {"topic": "missions"}
    ],
    ids=["fact1", "fact2", "fact3", "fact4", "fact5", "fact6"]
)

# Query with metadata filter
results = collection.query(
    query_texts=["traveling to other worlds"],
    n_results=1,
    where={"topic": "missions"}
)

top_doc = results["documents"][0][0]
top_distance = results["distances"][0][0]

print(f"Top result (distance: {top_distance:.4f}):")
print(f"  {top_doc}")

Key Takeaways

  • Vector databases store embeddings — numerical representations that capture the meaning of data.
  • They enable semantic search: finding similar content based on meaning, not exact keyword matches.
  • Vector databases are essential for RAG (Retrieval-Augmented Generation), the most common pattern for giving AI agents access to external knowledge.
  • Always use the same embedding model for both indexing and querying.
  • Metadata filtering lets you combine semantic search with traditional database-style filters for precise results.
  • For large datasets, ANN algorithms like HNSW and IVF provide fast approximate search with minimal accuracy loss.
  • ChromaDB is an excellent starting point for learning; Pinecone, Weaviate, and Qdrant are popular for production deployments.
