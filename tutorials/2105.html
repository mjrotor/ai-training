LangChain RAG Agent

Learn about langchain rag agent.

What is a RAG Agent?

So far, you've built agents that use tools to search the web or query databases. But what if you want your AI to answer questions about your own documents — your company's internal wiki, a set of PDFs, or a collection of research papers? That's where RAG (Retrieval-Augmented Generation) comes in.

A RAG Agent combines two powerful ideas:

  • Retrieval: Finding relevant information from a knowledge base (your documents) based on the user's question.
  • Generation: Using an LLM to synthesize a natural-language answer from the retrieved information.

LangChain makes this incredibly easy with built-in utilities for loading documents, splitting them into chunks, embedding them into vector stores, and retrieving them at query time — all wired up as tools your agent can call.

💡 What's the difference between RAG and a regular chatbot?
A regular chatbot only knows what it was trained on. A RAG agent can "look things up" in your documents before answering, which means it can reference up-to-date, domain-specific, or private information it was never trained on.

How RAG Works Under the Hood

Before we write any code, let's understand the pipeline. A RAG system has four main stages:

  1. Load — Read your documents (PDFs, text files, web pages, etc.).
  2. Split — Break large documents into smaller chunks that fit within embedding and context window limits.
  3. Embed & Store — Convert each chunk into a numerical vector (embedding) and store them in a vector database.
  4. Retrieve & Generate — When a user asks a question, find the most relevant chunks and pass them to the LLM along with the question.

The Vector Store

A vector store is a database optimized for storing and searching vectors. When you embed a question, the vector store finds the document chunks whose vectors are most similar (using cosine similarity or other distance metrics). Popular options include Chroma, FAISS, Pinecone, and Weaviate.

For this lesson, we'll use Chroma because it's lightweight, runs locally, and integrates seamlessly with LangChain.

Setting Up Your Environment

Install the required packages:

pip install langchain langchain-openai chromadb tiktoken

Set your OpenAI API key:

import os
os.environ["OPENAI_API_KEY"] = "sk-your-api-key-here"

Step 1: Load and Split Documents

LangChain provides document loaders for many file types and text splitters for breaking documents into chunks. Let's load a text file and split it:

from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

# Load a document
loader = TextLoader("company_handbook.txt")
documents = loader.load()

# Split into chunks
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    length_function=len,
)

chunks = text_splitter.split_documents(documents)

print(f"Created {len(chunks)} chunks from {len(documents)} document(s)")
# Output: Created 47 chunks from 1 document(s)
💡 Tip: Choosing chunk size
A chunk size of 300–1000 characters works well for most use cases. Smaller chunks are more precise but may miss context. Larger chunks capture more context but may include irrelevant information. The chunk_overlap ensures that text at the boundary of two chunks isn't lost.

Loading Other File Types

LangChain supports many formats out of the box:

from langchain_community.document_loaders import (
    PyPDFLoader,
    UnstructuredWordDocumentLoader,
    WebBaseLoader,
    CSVLoader,
)

# PDF
pdf_loader = PyPDFLoader("report.pdf")
pdf_docs = pdf_loader.load()

# Web page
web_loader = WebBaseLoader("https://example.com/article")
web_docs = web_loader.load()

# CSV
csv_loader = CSVLoader("data.csv")
csv_docs = csv_loader.load()

Step 2: Create Embeddings and Store in a Vector Database

Now we'll convert our chunks into embeddings and store them in Chroma:

from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Chroma

# Create embedding model
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# Create vector store from chunks
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db",  # Save to disk
)

print(f"Vector store created with {vectorstore._collection.count()} entries")

Loading a Persisted Vector Store

Once saved, you can reload the vector store without re-embedding everything:

# Load from disk on a future run
vectorstore = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings,
)

Step 3: Create a Retrieval Tool

We'll wrap our vector store as a LangChain tool so the agent can call it:

from langchain_core.tools import Tool

# Create a retriever from the vector store
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 3},  # Return top 3 results
)

# Wrap it as a LangChain Tool
retrieval_tool = Tool(
    name="company_handbook_search",
    func=retriever.invoke,
    description=(
        "Search the company handbook for information about policies, "
        "benefits, procedures, and guidelines. Use this when the user "
        "asks questions about company rules, HR policies, or workplace "
        "procedures."
    ),
)
⚠️ Important: The description field is critical! The agent uses it to decide when to call this tool. Make it specific and descriptive so the agent knows exactly when retrieval is relevant.

Step 4: Build the RAG Agent

Now let's put it all together. We'll create an agent that can use our retrieval tool alongside other tools:

from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

# Initialize the LLM
llm = ChatOpenAI(model="gpt-4o", temperature=0)

# Define the prompt
prompt = ChatPromptTemplate.from_messages([
    ("system", (
        "You are a helpful assistant for Acme Corp employees. "
        "Use the company_handbook_search tool to find relevant information "
        "from the company handbook before answering questions about "
        "company policies, benefits, or procedures. Always cite the "
        "source when you find information in the handbook."
    )),
    MessagesPlaceholder(variable_name="chat_history", optional=True),
    ("human", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

# Define tools
tools = [retrieval_tool]

# Create the agent
agent = create_tool_calling_agent(llm, tools, prompt)

# Create the agent executor
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,  # Set to False in production
)

# Run a query
response = agent_executor.invoke({
    "input": "What is the company's remote work policy?",
    "chat_history": [],
})

print(response["output"])

When you run this with verbose=True, you'll see the agent's thought process:

Thought: The user is asking about the remote work policy. I should search the company handbook.
Action: company_handbook_search
Action Input: "remote work policy"
Observation: [Document 1: Remote Work Policy - Employees may work remotely up to 3 days per week...] [Document 2: Hybrid Schedule Guidelines...]
Thought: I found relevant information about the remote work policy. Let me summarize it.
Final Answer: According to the company handbook, employees may work remotely up to 3 days per week...

Adding Memory to Your RAG Agent

A great RAG agent remembers the conversation. Let's add memory:

from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

# Create a session store
store = {}

def get_session_history(session_id: str):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

# Wrap the agent with memory
agent_with_memory = RunnableWithMessageHistory(
    agent_executor,
    get_session_history,
    input_messages_key="input",
    history_messages_key="chat_history",
    output_messages_key="output",
)

# First query
response1 = agent_with_memory.invoke(
    {"input": "What's the PTO policy?"},
    config={"configurable": {"session_id": "user-123"}},
)

# Follow-up query — the agent remembers the previous conversation
response2 = agent_with_memory.invoke(
    {"input": "How does that apply to part-time employees?"},
    config={"configurable": {"session_id": "user-123"}},
)

RAG Agent vs. Simple RAG Pipeline

You might be wondering: why use an agent at all? Can't I just do retrieval + generation directly? Here's a comparison:

Feature Simple RAG Pipeline RAG Agent
Multi-step reasoning Single retrieval + single answer Can retrieve, reason, retrieve again
Multiple tools Only retrieval Retrieval + web search + calculators + APIs
Follow-up questions Needs full context each time Maintains conversation memory
Conditional retrieval Always retrieves Decides whether retrieval is needed
Complexity Simple, predictable More flexible, harder to debug
Best for FAQ bots, simple Q&A Complex assistants, research tools
💡 When to use which?
If your use case is straightforward — "answer questions from this document set" — a simple RAG pipeline is faster and more predictable. If your agent needs to combine document retrieval with other tools, handle multi-turn conversations, or make decisions about when to retrieve, go with a RAG agent.

Advanced: Multi-Document RAG with Multiple Retrievers

In real applications, you often have multiple knowledge sources. You can create separate retrievers for each and let the agent choose:

# Create separate vector stores for different document types
policy_vectorstore = Chroma.from_documents(
    documents=policy_chunks,
    embedding=embeddings,
    collection_name="policies",
)

technical_vectorstore = Chroma.from_documents(
    documents=tech_chunks,
    embedding=embeddings,
    collection_name="technical",
)

# Create separate tools
policy_tool = Tool(
    name="policy_search",
    func=policy_vectorstore.as_retriever(search_kwargs={"k": 3}).invoke,
    description="Search company policies, HR guidelines, and employee handbook.",
)

technical_tool = Tool(
    name="technical_search",
    func=technical_vectorstore.as_retriever(search_kwargs={"k": 3}).invoke,
    description="Search technical documentation, API references, and architecture guides.",
)

# Agent with both tools
tools = [policy_tool, technical_tool]
agent = create_tool_calling_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

Common Pitfalls and How to Avoid Them

1. Retrieving Irrelevant Chunks

If your chunks are too large or your embedding model isn't well-suited to your domain, you'll get noisy results. Solutions:

  • Reduce chunk size and increase overlap
  • Use search_type="mmr" (Maximum Marginal Relevance) for more diverse results
  • Add a re-ranking step after retrieval
# Using MMR for more diverse results
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 5, "lambda_mult": 0.7},
)

2. Losing Context at Chunk Boundaries

When a sentence is split across two chunks, the agent may miss important context. Use chunk_overlap and consider adding metadata to each chunk:

# Add metadata to chunks
for i, chunk in enumerate(chunks):
    chunk.metadata["chunk_id"] = i
    chunk.metadata["source"] = "company_handbook.txt"
    chunk.metadata["section"] = "remote_work"  # Manual or auto-tagged

3. The Agent Ignoring Retrieved Context

Sometimes the LLM will answer from its own knowledge instead of the retrieved documents. Fix this with a strong system prompt:

system_prompt = """
You are a company policy assistant. You MUST answer ONLY based on the 
information retrieved from the company handbook. If the retrieved documents 
do not contain enough information to answer the question, say so honestly. 
Do NOT use your general knowledge to fill in gaps.

When you find relevant information, cite which document it came from.
"""
⚠️ Hallucination Risk: Even with good prompts, LLMs can hallucinate. For production systems, consider adding a verification step or using a smaller, fine-tuned model for the generation step.

Exercise: Build a Research Assistant Agent

Exercise

Create a RAG agent that can answer questions about a set of your own documents. Your agent should:

  1. Load at least two different text files (you can create sample files with any content you like).
  2. Split the documents into appropriate chunks.
  3. Create a Chroma vector store with embeddings.
  4. Build a retrieval tool with a clear, descriptive name and description.
  5. Create an agent that uses the retrieval tool and can answer questions about the documents.
  6. Add conversation memory so the agent can handle follow-up questions.

import os
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain_core.tools import Tool
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

os.environ["OPENAI_API_KEY"] = "sk-your-api-key-here"

# Step 1: Load documents
loader1 = TextLoader("product_faq.txt")
loader2 = TextLoader("onboarding_guide.txt")
docs1 = loader1.load()
docs2 = loader2.load()
all_docs = docs1 + docs2

# Step 2: Split
splitter = RecursiveCharacterTextSplitter(chunk_size=400, chunk_overlap=40)
chunks = splitter.split_documents(all_docs)

# Step 3: Embed and store
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./research_db",
)

# Step 4: Create retrieval tool
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 4},
)

retrieval_tool = Tool(
    name="knowledge_base_search",
    func=retriever.invoke,
    description=(
        "Search the knowledge base containing product FAQs and onboarding "
        "guides. Use this when the user asks questions about product features, "
        "troubleshooting, or the employee onboarding process."
    ),
)

# Step 5: Create agent
llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", (
        "You are a research assistant. Use the knowledge_base_search tool "
        "to find relevant information before answering. Always cite your sources "
        "and be honest if you can't find the answer in the documents."
    )),
    MessagesPlaceholder(variable_name="chat_history", optional=True),
    ("human", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

tools = [retrieval_tool]
agent = create_tool_calling_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# Step 6: Add memory
store = {}

def get_history(session_id):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

agent_with_memory = RunnableWithMessageHistory(
    agent_executor,
    get_history,
    input_messages_key="input",
    history_messages_key="chat_history",
    output_messages_key="output",
)

# Test it
response = agent_with_memory.invoke(
    {"input": "What are the most common product issues reported?"},
    config={"configurable": {"session_id": "exercise-session"}},
)
print(response["output"])

Key Takeaways

  • RAG (Retrieval-Augmented Generation) combines document retrieval with LLM generation to answer questions about your own data.
  • The RAG pipeline has four stages: Load → Split → Embed & Store → Retrieve & Generate.
  • Chunk size and overlap are critical hyperparameters — too large and you get noise, too small and you lose context.
  • The tool description is the most important part of a retrieval tool — it tells the agent when to use it.
  • A RAG agent is more powerful than a simple RAG pipeline because it can combine retrieval with other tools, handle multi-step reasoning, and maintain conversation memory.
  • Use MMR (Maximum Marginal Relevance) search for more diverse retrieval results when similarity search returns redundant chunks.
  • Always instruct the agent to answer only from retrieved documents and to admit when information is missing — this reduces hallucinations.
  • You can create multiple retrievers for different document collections and let the agent choose the right one.
  • LangChain's RunnableWithMessageHistory makes it straightforward to add persistent memory to any agent.
