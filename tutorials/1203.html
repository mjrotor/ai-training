Embedding & Storage

Learn about embedding & storage.

What Is Embedding and Why Do AI Agents Need It?

So far, your AI agents have relied on tools like web searches and APIs to retrieve information. But what if you want your agent to search through your own documents, past conversations, or a company knowledge base? That's where embeddings and storage come in — they form the backbone of what's often called Retrieval-Augmented Generation (RAG).

Think of embeddings as a way to convert text into numbers — specifically, into long lists of numbers called vectors. These vectors capture the meaning of the text, not just the exact words. This means that "I love dogs" and "Canines are my favorite animals" will have similar vectors, even though they share no common words.

Analogy: Imagine every piece of text gets dropped onto a giant map. Similar meanings land close together; different meanings land far apart. An embedding model is the tool that figures out where each piece of text should be placed on that map.

How Embeddings Work Under the Hood

An embedding model (like OpenAI's text-embedding-3-small or open-source models like all-MiniLM-L6-v2) takes a string of text and outputs a vector — typically a list of 384, 1,536, or more floating-point numbers. The magic is that the distance between two vectors tells you how semantically similar the original texts are.

The most common way to measure similarity between two vectors is cosine similarity, which looks at the angle between them. A cosine similarity of 1.0 means the vectors point in exactly the same direction (identical meaning), 0.0 means they're orthogonal (unrelated), and -1.0 means they point in opposite directions (opposite meaning).

Pro tip: You don't need to build your own embedding model. Services like OpenAI, Google, Cohere, and open-source libraries like sentence-transformers provide excellent models out of the box.

Storing Embeddings: Vector Databases

Once you've converted your documents into vectors, you need somewhere to store them. A regular database isn't great at finding "similar" vectors quickly. That's why we use vector databases — specialized storage systems optimized for Approximate Nearest Neighbor (ANN) search.

Popular Vector Database Options

Database Type Best For
Chroma Local / Embedded Development, prototyping, small projects
Pinecone Managed Cloud Production apps needing zero infrastructure
Weaviate Self-hosted / Cloud Hybrid search (vector + keyword)
FAISS Library (in-memory / disk) Research, high-performance local search
pgvector PostgreSQL extension Teams already using PostgreSQL
Important: For this lesson, we'll use Chroma because it runs locally with zero setup. In production, you'll likely want a managed solution like Pinecone or Weaviate for better scalability and reliability.

Building a Document Embedding Pipeline with Chroma

Let's build a complete pipeline: we'll take a collection of text documents, embed them, store them in Chroma, and then query them to find relevant information.

Step 1: Install the Required Libraries

pip install chromadb openai

Step 2: Embed and Store Documents

import chromadb
from openai import OpenAI

# Initialize the Chroma client (persistent, saves to disk)
client = chromadb.PersistentClient(path="./my_vector_db")

# Create or get a collection
collection = client.get_or_create_collection(
    name="knowledge_base",
    metadata={"hnsw:space": "cosine"}  # Use cosine similarity
)

# Sample documents to embed
documents = [
    "Dogs are loyal companions and great family pets.",
    "Cats are independent animals that enjoy solitude.",
    "Python is a versatile programming language used in AI.",
    "JavaScript is essential for web development and front-end interfaces.",
    "Machine learning models require large datasets for training.",
    "Vector databases enable semantic search over documents.",
]

# Generate embeddings using OpenAI's embedding API
openai_client = OpenAI()
embeddings = []

for doc in documents:
    response = openai_client.embeddings.create(
        input=doc,
        model="text-embedding-3-small"
    )
    embeddings.append(response.data[0].embedding)

# Store documents with their embeddings
collection.add(
    documents=documents,
    embeddings=embeddings,
    ids=[f"doc_{i}" for i in range(len(documents))]
)

print(f"Stored {collection.count()} documents in the knowledge base.")

Step 3: Query the Knowledge Base

def search_knowledge_base(query: str, n_results: int = 3):
    """Search for documents semantically similar to the query."""
    
    # Embed the query using the same model
    response = openai_client.embeddings.create(
        input=query,
        model="text-embedding-3-small"
    )
    query_embedding = response.data[0].embedding

    # Search for the most similar documents
    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=n_results
    )

    # Display results
    for i, (doc, distance) in enumerate(
        zip(results["documents"][0], results["distances"][0])
    ):
        print(f"Result {i+1} (distance: {distance:.4f}):")
        print(f"  {doc}\n")

# Try different queries
search_knowledge_base("What pets are good for families?")
search_knowledge_base("How do I build a website?")
search_knowledge_base("Tell me about AI training")
What just happened? We converted text into vectors, stored them in a vector database, and then used the database to find documents that are semantically similar to our query — even when the exact words don't match. "What pets are good for families?" matched "Dogs are loyal companions and great family pets" because their vectors are close together in meaning-space.

Chunking: Breaking Documents into Pieces

In the real world, your documents might be hundreds or thousands of pages long. You can't embed an entire book as a single vector — it would lose too much detail. Instead, you chunk the document into smaller, meaningful pieces before embedding.

Common Chunking Strategies

  • Fixed-size chunking: Split text every N characters or tokens. Simple but may cut sentences in half.
  • Recursive chunking: Try to split on paragraphs first, then sentences, then words — respecting natural boundaries.
  • Semantic chunking: Use an LLM or heuristic to identify topic boundaries and split there.
  • Sliding window: Create overlapping chunks so no information is lost at boundaries.
from langchain.text_splitter import RecursiveCharacterTextSplitter

# A more realistic chunking setup
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # Each chunk is ~500 characters
    chunk_overlap=50,      # 50 characters of overlap between chunks
    length_function=len,
    separators=["\n\n", "\n", ". ", " "]  # Split in this order of priority
)

long_document = """
Artificial intelligence has transformed many industries. In healthcare, 
AI assists doctors in diagnosing diseases from medical images. In 
finance, algorithms detect fraudulent transactions in real time. 
Self-driving cars use AI to navigate roads safely. Natural language 
processing powers chatbots and virtual assistants. The future of AI 
holds even more promise, with advances in reasoning, creativity, 
and autonomous decision-making.
"""

chunks = text_splitter.split_text(long_document)
for i, chunk in enumerate(chunks):
    print(f"Chunk {i+1}: {chunk[:80]}...")
Watch out! Chunk size matters a lot. Too small, and you lose context. Too large, and the embedding becomes unfocused. Start with 200–500 tokens and experiment based on your use case. Always include some overlap to preserve information at chunk boundaries.

Integrating RAG into an AI Agent

Now let's put it all together. We'll build a simple agent that uses embeddings to retrieve relevant knowledge before answering a question.

import chromadb
from openai import OpenAI

class KnowledgeAgent:
    def __init__(self, db_path="./agent_kb"):
        self.chroma_client = chromadb.PersistentClient(path=db_path)
        self.collection = self.chroma_client.get_or_create_collection(
            name="agent_knowledge",
            metadata={"hnsw:space": "cosine"}
        )
        self.openai_client = OpenAI()

    def add_document(self, text: str, doc_id: str = None):
        """Add a single document to the knowledge base."""
        if doc_id is None:
            doc_id = f"doc_{self.collection.count()}"
        
        response = self.openai_client.embeddings.create(
            input=text,
            model="text-embedding-3-small"
        )
        
        self.collection.add(
            documents=[text],
            embeddings=[response.data[0].embedding],
            ids=[doc_id]
        )

    def query(self, question: str) -> str:
        """Retrieve relevant context and generate an answer."""
        
        # Step 1: Embed the question
        response = self.openai_client.embeddings.create(
            input=question,
            model="text-embedding-3-small"
        )
        query_embedding = response.data[0].embedding

        # Step 2: Retrieve top 3 relevant documents
        results = self.collection.query(
            query_embeddings=[query_embedding],
            n_results=3
        )
        context = "\n\n".join(results["documents"][0])

        # Step 3: Generate answer using retrieved context
        system_prompt = f"""You are a helpful assistant. Use the following 
context to answer the question. If the context doesn't contain relevant 
information, say so.

Context:
{context}"""

        chat_response = self.openai_client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": question}
            ]
        )
        return chat_response.choices[0].message.content


# Usage
agent = KnowledgeAgent()

# Add some knowledge
agent.add_document("The company's refund policy allows returns within 30 days.", "policy_1")
agent.add_document("Our premium plan costs $29/month and includes priority support.", "pricing_1")
agent.add_document("Technical support is available Monday-Friday, 9 AM to 6 PM EST.", "support_1")

# Ask questions
answer = agent.query("How much does the premium plan cost?")
print(answer)

answer2 = agent.query("Can I get a refund after 45 days?")
print(answer2)
Architecture pattern: Notice the three-step flow: Embed → Retrieve → Generate. This is the core RAG pattern. The agent never "memorizes" the documents — it retrieves relevant pieces at query time and feeds them to the LLM as context.

Handling Updates and Metadata

Real-world knowledge bases change over time. Let's look at how to update, delete, and filter documents using metadata.

# Add documents with metadata for filtering
collection.add(
    documents=[
        "Python 3.12 introduced improved error messages.",
        "JavaScript ES2024 added the Array grouping proposal.",
    ],
    embeddings=[...],  # Your embeddings here
    ids=["py_update", "js_update"],
    metadatas=[
        {"language": "python", "version": "3.12", "category": "update"},
        {"language": "javascript", "version": "ES2024", "category": "update"},
    ]
)

# Query with metadata filter — only search Python documents
results = collection.query(
    query_embeddings=[query_embedding],
    n_results=5,
    where={"language": "python"}  # Filter by metadata

Performance Considerations

As your knowledge base grows, you'll need to think about performance:

  • Indexing speed: Batch your embedding API calls. Most providers support batching (e.g., OpenAI accepts up to 2,048 inputs per request).
  • Search speed: ANN indexes (like HNSW used by Chroma) trade a tiny bit of accuracy for dramatically faster search. For millions of vectors, this is essential.
  • Cost: Every embedding API call costs money. Cache embeddings for documents that don't change frequently.
  • Memory: A 1,536-dimension float32 vector uses ~6 KB. A million documents = ~6 GB of vector data alone.
Scaling tip: For production systems with millions of documents, consider using a managed vector database like Pinecone or Weaviate, which handle sharding, replication, and optimized indexing automatically.
Exercise: Build a FAQ Search System

Create a script that:

  1. Reads a list of FAQ question-answer pairs (at least 5).
  2. Embeds the questions and stores them in a Chroma collection along with the answers as metadata.
  3. Accepts a user's natural language query, embeds it, and finds the most similar FAQ question.
  4. Returns the corresponding answer from the metadata.

Test it with a query that uses different wording than any of your stored questions.

import chromadb
from openai import OpenAI

# FAQ data: list of (question, answer) pairs
faq_data = [
    ("How do I reset my password?", "Go to Settings > Security > Reset Password."),
    ("What is your return policy?", "Items can be returned within 30 days with a receipt."),
    ("How do I contact support?", "Email support@example.com or call 1-800-555-0123."),
    ("Where can I track my order?", "Log in and visit 'My Orders' in your account dashboard."),
    ("Do you offer international shipping?", "Yes, we ship to over 50 countries. See our shipping page for details."),
]

# Setup
client = chromadb.Client()  # In-memory for this exercise
collection = client.create_collection(name="faq", metadata={"hnsw:space": "cosine"})
openai_client = OpenAI()

# Embed and store questions
questions = [q for q, a in faq_data]
answers = [a for q, a in faq_data]

response = openai_client.embeddings.create(
    input=questions,
    model="text-embedding-3-small"
)
embeddings = [item.embedding for item in response.data]

collection.add(
    documents=questions,
    embeddings=embeddings,
    ids=[f"faq_{i}" for i in range(len(faq_data))],
    metadatas=[{"answer": a} for a in answers]
)

# Search function
def find_answer(user_query: str) -> str:
    response = openai_client.embeddings.create(
        input=user_query,
        model="text-embedding-3-small"
    )
    query_embedding = response.data[0].embedding

    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=1
    )

    best_match = results["documents"][0][0]
    best_answer = results["metadatas"][0][0]["answer"]
    distance = results["distances"][0][0]

    print(f"Matched FAQ: {best_match}")
    print(f"Similarity distance: {distance:.4f}")
    return best_answer

# Test with different wording
print(find_answer("I forgot my login credentials, what should I do?"))
# Output: Go to Settings > Security > Reset Password.

print(find_answer("Can I send something back to you?"))
# Output: Items can be returned within 30 days with a receipt.

Key Takeaways

  • Embeddings convert text into numerical vectors that capture semantic meaning, enabling similarity-based search.
  • Vector databases like Chroma, Pinecone, and Weaviate are optimized for fast nearest-neighbor search over millions of vectors.
  • The RAG pattern (Embed → Retrieve → Generate) lets AI agents ground their responses in specific, up-to-date knowledge rather than relying solely on training data.
  • Chunking is essential for processing large documents — split text into meaningful pieces before embedding, and use overlap to preserve context at boundaries.
  • Metadata filtering lets you narrow searches by category, date, source, or any custom attribute, making retrieval more precise.
  • Consider performance and cost early: batch embedding calls, cache results, and choose the right vector database for your scale.
