Building a Content Crew

Learn about building a content crew.

What Is a Content Crew?

Imagine you're running a media company. You need writers, editors, designers, and publishers — each with their own specialty. A Content Crew works the same way, but instead of humans, you deploy multiple AI agents that each handle a specific part of the content creation pipeline. One agent researches, another writes, a third edits, and a fourth publishes. Together, they form a coordinated team.

In AI agent terms, a "crew" is a multi-agent system where each agent has a defined role, goal, and backstory. They communicate through a shared workflow, passing outputs from one stage to the next. This lesson will teach you how to build one from scratch using Python.

Why a crew instead of one big agent? A single agent trying to research, write, edit, and publish often produces shallow results. Specialized agents produce higher-quality output because each one is fine-tuned for a narrow task — just like a real newsroom.

The Architecture of a Multi-Agent Crew

Before writing code, let's understand the three building blocks that every crew member needs:

Component What It Defines Example
Role The agent's job title and domain "SEO Content Writer"
Goal What the agent is trying to achieve "Write blog posts that rank on page one"
Backstory Context and personality that shapes responses "You are a veteran tech journalist with 10 years of experience covering AI and startups."

When you combine these three elements, you give the language model a clear persona. The model then generates responses that stay in character, which dramatically improves consistency and quality.

Setting Up Your Python Environment

We'll use the openai library to call a language model and a lightweight crew framework. Install the dependencies first:

pip install openai python-dotenv

Create a .env file to store your API key securely:

OPENAI_API_KEY=sk-your-key-here

Now let's build a base Agent class that every crew member will inherit from:

import os
import openai
from dotenv import load_dotenv

load_dotenv()

class Agent:
    """Base class for all crew members."""

    def __init__(self, role, goal, backstory, model="gpt-4o"):
        self.role = role
        self.goal = goal
        self.backstory = backstory
        self.model = model

    def run(self, prompt):
        """Send a prompt to the LLM and return the response."""
        response = openai.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": self._build_system_prompt()},
                {"role": "user", "content": prompt},
            ],
            temperature=0.7,
        )
        return response.choices[0].message.content

    def _build_system_prompt(self):
        return (
            f"You are {self.role}.\n"
            f"Your goal is: {self.goal}\n"
            f"Backstory: {self.backstory}\n"
            f"Stay in character at all times."
        )
Pro tip: Keep temperature between 0.5 and 0.8 for creative tasks like writing. Drop it to 0.1–0.3 for fact-checking agents where accuracy matters more than flair.

Building the Pipeline

The crew works in a sequential pipeline: each agent receives the output of the previous agent as its input. This is the simplest and most reliable orchestration pattern.

class ContentCrew:
    """Orchestrates a sequential content creation pipeline."""

    def __init__(self, agents):
        self.agents = agents

    def kickoff(self, topic):
        """Run the full pipeline on a given topic."""
        output = topic  # Start with the raw topic as input

        for agent in self.agents:
            print(f"\n{'='*50}")
            print(f"Running: {agent.role}")
            print(f"{'='*50}\n")
            output = agent.run(output)
            print(output)

        return output


# Assemble and run the crew
crew = ContentCrew(agents=[researcher, writer, editor, publisher])
final_article = crew.kickoff("How AI agents are changing software development")
Watch out for context limits! If the researcher's output is very long, the writer may hit the model's token limit. Consider summarizing or chunking outputs between stages, or use a model with a larger context window.

Passing Structured Data Between Agents

Raw text works, but structured outputs make the pipeline far more reliable. Let's modify our agents to return JSON that the next agent can parse cleanly.

import json

class StructuredAgent(Agent):
    """Agent that returns structured JSON output."""

    def run(self, prompt):
        response = openai.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": self._build_system_prompt()},
                {"role": "user", "content": prompt},
            ],
            temperature=0.7,
            response_format={"type": "json_object"},
        )
        return json.loads(response.choices[0].message.content)


# Example: Researcher returns structured data
structured_researcher = StructuredAgent(
    role="Senior Research Analyst",
    goal="Return a JSON object with 'facts', 'statistics', and 'sources' keys",
    backstory="You always respond in valid JSON format.",
)

# The writer can now consume it cleanly
topic = "AI agents in healthcare"
research = structured_researcher.run(
    f"Research the following topic and return JSON: {topic}"
)

# Pass structured data to the next agent
writer_prompt = (
    f"Using the following research, write a 500-word blog post:\n"
    f"{json.dumps(research, indent=2)}"
)

Adding Memory and Context

Agents that remember previous interactions produce more coherent output. Let's add a simple short-term memory buffer to each agent:

class AgentWithMemory(Agent):
    """Agent that retains a rolling window of past interactions."""

    def __init__(self, *args, memory_window=3, **kwargs):
        super().__init__(*args, **kwargs)
        self.memory = []
        self.memory_window = memory_window

    def run(self, prompt):
        # Build context from memory
        memory_text = ""
        if self.memory:
            memory_text = "\n\nPrevious context:\n"
            for i, entry in enumerate(self.memory, 1):
                memory_text += f"{i}. {entry}\n"

        full_prompt = f"{memory_text}\n\nCurrent task: {prompt}"
        result = super().run(full_prompt)

        # Store in memory buffer
        self.memory.append(f"Task: {prompt[:80]}... | Result: {result[:80]}...")
        if len(self.memory) > self.memory_window:
            self.memory.pop(0)

        return result


# Usage
writer_with_memory = AgentWithMemory(
    role="SEO Content Writer",
    goal="Write engaging blog posts",
    backstory="You are a veteran tech journalist.",
    memory_window=2,
)
Memory window controls how many past interactions the agent remembers. A window of 2–3 works well for most content pipelines. Larger windows increase token usage and cost.

Comparing Orchestration Patterns

Sequential pipelines are great for content crews, but other patterns exist. Here's when to use each:

Pattern How It Works Best For Complexity
Sequential Agent A → Agent B → Agent C Content pipelines, data ETL Low
Hierarchical A manager agent delegates to workers Complex projects with subtasks Medium
Parallel Multiple agents work simultaneously Research with multiple sources Medium
Iterative Output loops back for refinement Code review, quality assurance High

Key Takeaways

  • A Content Crew is a multi-agent system where each agent has a specialized role, goal, and backstory.
  • The three core components of any agent are role (what it does), goal (what it aims to achieve), and backstory (context that shapes its behavior).
  • Sequential pipelines are the simplest orchestration pattern: each agent passes its output to the next.
  • Structured outputs (like JSON) make inter-agent communication more reliable than raw text.
  • Short-term memory buffers help agents maintain context across multiple tasks within a session.
  • Choose your orchestration pattern — sequential, hierarchical, parallel, or iterative — based on the complexity of your project.
  • Always watch for context limits when passing large outputs between agents; summarize or chunk when necessary.
