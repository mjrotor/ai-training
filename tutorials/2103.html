LangChain Tools & Agents

Learn about langchain tools & agents.

What Are LangChain Tools?

In our previous lessons, we learned how to build basic chains in LangChain — sequential pipelines that process prompts through language models. But language models on their own can only generate text. They can't browse the web, query databases, or perform calculations. Tools bridge that gap by giving AI agents the ability to interact with external systems.

Think of a tool as a single, well-defined function that an agent can call when needed. Each tool has a name, a description, and a specific input format. The agent reads these descriptions and decides which tool to use based on the user's request.

Core Tool Concepts

Every LangChain tool wraps a Python function with additional metadata that helps the language model understand when and how to use it. The key components are:

  • Name: A short identifier for the tool (e.g., "search", "calculator")
  • Description: A detailed explanation of what the tool does — this is how the agent decides to use it
  • Function: The actual Python callable that executes when the tool is invoked
  • Arguments: The input schema defining what parameters the tool expects
from langchain.tools import Tool

def search_web(query: str) -> str:
    """Searches the web for the given query and returns top results."""
    # In a real implementation, this would call a search API
    return f"Search results for '{query}': Result 1, Result 2, Result 3"

search_tool = Tool(
    name="web_search",
    func=search_web,
    description="Useful for searching the web to find current information about recent events, facts, or data."
)

print(search_tool.name)
print(search_tool.description)
print(search_tool.run("LangChain agents"))
Why Descriptions Matter: The language model relies entirely on the tool's description to decide when to use it. A vague description like "searches things" will lead to poor tool selection. Be specific about when and why the agent should use each tool.

What Are Agents?

An agent is a system that uses a language model as a reasoning engine to decide what actions to take and in what order. Unlike a simple chain — where the path is predetermined — an agent dynamically decides which tools to call, in what sequence, and when it has enough information to provide a final answer.

The agent loop works like this:

  1. The user provides a question or task
  2. The language model receives the question along with tool descriptions
  3. The model decides whether to use a tool or respond directly
  4. If it chooses a tool, the agent executes it and feeds the result back to the model
  5. The model examines the tool output and decides the next step
  6. This repeats until the model determines it has enough information to answer

The ReAct Framework

The most common agent reasoning pattern is called ReAct (Reason + Act). In this pattern, the agent interleaves reasoning traces and actions:

  • Thought: The model reasons about what it needs to do next
  • Action: The model selects a tool and provides input
  • Observation: The tool returns its result
  • This cycle repeats until the model produces a Final Answer
Important: Agents should not be confused with chains. Chains have a fixed sequence of steps. Agents make dynamic decisions at each step. Use chains when the workflow is predictable, and agents when the model needs to reason about which steps to take.

Building Your First Agent

Let's build a complete agent that can search the web and perform calculations. We'll use LangChain's create_react_agent helper function.

from langchain import hub
from langchain.agents import AgentExecutor, create_react_agent
from langchain_community.tools import DuckDuckGoSearchRun
from langchain_openai import ChatOpenAI

# Initialize the language model
llm = ChatOpenAI(model="gpt-4", temperature=0)

# Define the tools available to the agent
tools = [
    DuckDuckGoSearchRun(name="web_search"),
]

# Pull the ReAct prompt from LangChain Hub
prompt = hub.pull("hwchase17/react")

# Create the agent
agent = create_react_agent(llm, tools, prompt)

# Create the agent executor to run the agent
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,  # This lets us see the agent's reasoning
    max_iterations=5
)

# Run the agent with a question
response = agent_executor.invoke({
    "input": "What is the current population of Tokyo, and what is that number divided by 3?"
})

print(response["output"])

With verbose=True, you'll see the agent's thought process in the console:

# Console output (simplified):
# Thought: I need to find the current population of Tokyo first.
# Action: web_search
# Action Input: current population of Tokyo 2024
# Observation: Tokyo has approximately 14 million residents...
# Thought: Now I need to divide 14,000,000 by 3.
# Action: calculator
# Action Input: 14000000 / 3
# Observation: 4666666.67
# Thought: I now have all the information needed to answer.
# Final Answer: Tokyo's population is approximately 14 million,
# and divided by 3 that is about 4,666,666.67.

Understanding the Agent Executor

The AgentExecutor is the runtime that drives the agent loop. Key parameters include:

  • max_iterations: Maximum number of steps the agent can take before stopping. Prevents infinite loops.
  • handle_parsing_errors: If True, the agent will try to recover from output parsing errors instead of crashing.
  • return_intermediate_steps: If True, returns every tool call and result for inspection.
Watch Out for Infinite Loops: Always set max_iterations to a reasonable number (3–10). Without this limit, an agent that can't find an answer might loop indefinitely, burning through API credits.

Creating Custom Tools

While built-in tools are useful, the real power comes from creating your own custom tools tailored to your application's needs. You can create custom tools in two ways:

Method 1: Using the @tool Decorator

from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """Get the current weather for a city. Use this when the user asks about weather conditions."""
    # In production, you'd call a weather API here
    weather_data = {
        "new york": "72°F, partly cloudy",
        "london": "55°F, rainy",
        "tokyo": "68°F, sunny"
    }
    return weather_data.get(city.lower(), f"Weather data not available for {city}")

@tool
def calculate_discount(price: float, discount_percent: float) -> str:
    """Calculate the final price after applying a discount percentage."""
    discount_amount = price * (discount_percent / 100)
    final_price = price - discount_amount
    return f"Original: ${price:.2f}, Discount: ${discount_amount:.2f}, Final: ${final_price:.2f}"

Method 2: Using the Tool Class for More Control

from langchain.tools import Tool
from typing import Optional

def convert_temperature(value: float, from_unit: str = "celsius", to_unit: str = "fahrenheit") -> str:
    """Convert temperature between Celsius and Fahrenheit."""
    if from_unit == "celsius" and to_unit == "fahrenheit":
        result = (value * 9/5) + 32
    elif from_unit == "fahrenheit" and to_unit == "celsius":
        result = (value - 32) * 5/9
    else:
        return "Conversion not supported"
    return f"{value}°{from_unit.capitalize()} = {result:.1f}°{to_unit.capitalize()}"

temp_tool = Tool(
    name="temperature_converter",
    func=convert_temperature,
    description="Convert temperature between Celsius and Fahrenheit. Input should include the numeric value, source unit, and target unit."
)
Best Practice: Always write detailed descriptions for your tools. The language model uses these descriptions to decide which tool to call. Include example inputs and clarify the expected format in the docstring.

Agent Types in LangChain

LangChain offers several agent types, each using different reasoning strategies:

Agent Type Reasoning Strategy Best Use Case
ReAct Thought → Action → Observation loop General-purpose tasks requiring multi-step reasoning
Self-Ask with Search Decomposes questions into sub-questions Complex factual questions needing intermediate answers
Conversational ReAct with conversation memory Chat-based applications needing context across turns
OpenAI Functions Uses OpenAI's function calling API When using OpenAI models with structured tool inputs
Tool Calling Agent Native tool calling with modern models GPT-4, Claude, and other models with built-in tool calling

Conversational Agent Example

For chat applications, you'll want an agent that remembers the conversation history:

from langchain.agents import create_react_agent, AgentExecutor
from langchain_community.chat_models import ChatOpenAI
from langchain.memory import ConversationBufferMemory
from langchain_core.prompts import MessagesPlaceholder

# Create memory that stores conversation history
memory = ConversationBufferMemory(
    memory_key="chat_history",
    return_messages=True
)

# The prompt needs a place for the conversation history
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant with access to tools."),
    MessagesPlaceholder(variable_name="chat_history"),
    ("user", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

from langchain.agents import create_tool_calling_agent
from langchain.agents.output_parsers import OpenAIFunctionsAgentOutputParser

llm = ChatOpenAI(model="gpt-4", temperature=0)

agent = create_tool_calling_agent(llm, tools, prompt)

agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    memory=memory,
    verbose=True
)

# First message
agent_executor.invoke({"input": "My name is Alex."})

# Second message — the agent remembers your name!
agent_executor.invoke({"input": "What's my name?"})

Handling Agent Errors Gracefully

Agents can fail in several ways. Building robust error handling is essential for production applications:

from langchain.agents import AgentExecutor, create_react_agent
from langchain_core.exceptions import OutputParserException

tools = [get_weather, calculate_discount]
agent = create_react_agent(llm, tools, prompt)

agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    max_iterations=5,
    handle_parsing_errors=True,
    return_intermediate_steps=True
)

try:
    response = agent_executor.invoke({
        "input": "What's the weather in Mars, and then calculate a 15% discount on $200?"
    })
    
    # Access the final answer
    print("Answer:", response["output"])
    
    # Inspect all the steps the agent took
    for step in response.get("intermediate_steps", []):
        action, observation = step
        print(f"Tool used: {action.tool}")
        print(f"Input: {action.tool_input}")
        print(f"Result: {observation}")
        print("---")

except OutputParserException as e:
    print(f"The agent had trouble parsing its output: {e}")
except Exception as e:
    print(f"An unexpected error occurred: {e}")
Why Inspect Intermediate Steps? Logging intermediate steps helps you debug agent behavior, understand why it chose certain tools, and improve your tool descriptions. In production, these logs are invaluable for identifying failure patterns.
Exercise

Build a Research Agent: Create a custom agent that can help with research tasks. Your agent should have at least two tools:

  1. A summarize_text tool that takes a long text string and returns a one-sentence summary (you can simulate this by returning the first sentence or a hardcoded response for now)
  2. A word_count tool that counts the number of words in a given text

Set up the agent with a ReAct prompt, configure it with max_iterations=4, and test it with the input: "How many words are in this text: 'The quick brown fox jumps over the lazy dog. This sentence contains exactly nine words and demonstrates a classic pangram used in typing exercises.'"

Make sure your tool descriptions are detailed enough that the agent knows when to use each one.

from langchain import hub
from langchain.agents import AgentExecutor, create_react_agent
from langchain.tools import tool
from langchain_openai import ChatOpenAI

@tool
def summarize_text(text: str) -> str:
    """Summarize the given text into a single sentence. Use this when the user wants a brief summary of a passage or document."""
    sentences = text.split(". ")
    if len(sentences) > 0:
        return f"Summary: {sentences[0]}."
    return "The text is empty and cannot be summarized."

@tool
def word_count(text: str) -> str:
    """Count the number of words in the given text. Use this when the user asks about word count, text length, or needs to know how many words are in a passage."""
    words = text.split()
    count = len(words)
    return f"The text contains {count} words."

# Set up the model and tools
llm = ChatOpenAI(model="gpt-4", temperature=0)
tools = [summarize_text, word_count]

# Get the ReAct prompt
prompt = hub.pull("hwchase17/react")

# Build the agent
agent = create_react_agent(llm, tools, prompt)
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    max_iterations=4,
    verbose=True
)

# Test the agent
test_text = ("The quick brown fox jumps over the lazy dog. "
             "This sentence contains exactly nine words and demonstrates "
             "a classic pangram used in typing exercises.")

response = agent_executor.invoke({
    "input": f"How many words are in this text: '{test_text}'"
})

print(response["output"])

Key Takeaways

  • Tools give language models the ability to interact with external systems — search engines, databases, calculators, APIs, and more.
  • Each tool needs a clear, detailed description so the language model can decide when to use it. Poor descriptions lead to poor agent decisions.
  • An agent uses a language model as a reasoning engine to dynamically decide which tools to call and in what order, unlike chains which follow a fixed sequence.
  • The ReAct pattern (Reason + Act) is the most common agent framework, where the model interleaves thoughts, tool calls, and observations.
  • You can create custom tools using the @tool decorator for simplicity or the Tool class for more control over configuration.
  • Always set max_iterations to prevent infinite loops, and use verbose=True during development to observe the agent's reasoning process.
  • Different agent types (ReAct, Conversational, Self-Ask, Tool Calling) are suited for different use cases — choose based on your application's needs.
  • Use ConversationBufferMemory when building chat-based agents that need to remember context across multiple interactions.
  • Robust error handling with try/except blocks and handle_parsing_errors=True is essential for production agent deployments.
  • Inspecting intermediate steps helps you debug agent behavior and continuously improve your tool descriptions and prompts.
