Reranking with Cross-Encoders

Learn about reranking with cross-encoders.

What Is Reranking?

After retrieving documents using a fast method like vector similarity search, you often end up with a list of candidates that might be relevant — but they’re not always in the best order. Reranking is the step where you take those top candidates and reorder them using a more accurate (but slower) model to improve precision. Think of it like this: retrieval finds the right neighborhood, reranking picks the best house on the block.

In today’s lesson, we’ll focus on one of the most effective reranking techniques: cross-encoders. Unlike bi-encoders (which embed queries and documents separately), cross-encoders process the query and document together, allowing for much richer interaction between them.

Bi-Encoders vs. Cross-Encoders

It’s important to understand the difference:

  • Bi-Encoders embed the query and each document independently into vectors. Fast for large-scale retrieval but limited in interaction depth.
  • Cross-Encoders take the full query-document pair as input and compute a relevance score through full attention. Slower, but far more accurate.
When to use which?
Use bi-encoders for initial retrieval over millions of documents. Then apply a cross-encoder to rerank only the top 20–100 candidates.

Why Cross-Encoders Are Better at Understanding Nuance

Because cross-encoders see both the query and document at once, they can detect subtle relationships like negation, context shifts, or domain-specific phrasing that bi-encoders might miss. For example:

  • Query: “How to prevent data loss”
  • Document A: “Best ways to cause data loss”
  • Document B: “Strategies to avoid data loss”

A bi-encoder might rank Document A highly due to shared keywords (“data loss”), but a cross-encoder will correctly prioritize Document B because it understands the semantic contrast between “prevent” and “cause.”

Implementing a Cross-Encoder Reranker

We’ll use the popular sentence-transformers library, which includes pre-trained cross-encoder models fine-tuned for reranking. Let’s walk through a practical example.

Step 1: Install and Import

pip install sentence-transformers

from sentence_transformers import CrossEncoder

Step 2: Load a Pretrained Model

# Load a cross-encoder model optimized for reranking
model = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')
Pro Tip: The ms-marco models are trained on real search queries and are excellent for general-purpose reranking tasks.

Step 3: Prepare Query-Document Pairs

query = "How does photosynthesis work?"
documents = [
    "Photosynthesis converts sunlight into chemical energy in plants.",
    "The history of the Roman Empire spans several centuries.",
    "Mitochondria are the powerhouse of the cell.",
    "Chlorophyll absorbs light to produce glucose in leaves."
]

Step 4: Score and Rerank

# Create pairs for the cross-encoder
pairs = [(query, doc) for doc in documents]

# Get relevance scores
scores = model.predict(pairs)

# Combine and sort by score (descending)
ranked = sorted(zip(documents, scores), key=lambda x: x[1], reverse=True)

for doc, score in ranked:
    print(f"Score: {score:.4f} | Doc: {doc}")

This will output documents in order of true relevance — notice how the plant/photosynthesis-related docs rank highest!

Performance vs. Accuracy Trade-offs

Cross-encoders are powerful, but they’re computationally expensive. Here’s how they compare to other approaches:

Method Speed Accuracy Best Use Case
Bi-Encoder (Dense Retrieval) ⚡ Fast ✅ Good Initial retrieval from large corpus
BM25 (Sparse Retrieval) ⚡ Fast ✅ Good for keywords Exact keyword matching
Cross-Encoder (Reranker) 🐢 Slow 🔥 Excellent Reranking top-k candidates
Caution: Never run a cross-encoder over your entire document corpus — it’s too slow. Always limit reranking to the top 20–100 candidates from your retriever.

Coding Exercise

Exercise

You have the following query and three candidate documents. Use a cross-encoder to rerank them and return only the top-2 documents.

Query: "Benefits of regular exercise"

Documents:

  • "Exercise improves cardiovascular health and mental well-being."
  • "The latest smartphone features include foldable screens."
  • "Running for 30 minutes daily reduces stress and boosts immunity."

Complete the code below to print only the top-2 reranked documents.

from sentence_transformers import CrossEncoder

model = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')
query = "Benefits of regular exercise"
docs = [
    "Exercise improves cardiovascular health and mental well-being.",
    "The latest smartphone features include foldable screens.",
    "Running for 30 minutes daily reduces stress and boosts immunity."
]

# Your code here: create pairs, score, sort, and print top 2

pairs = [(query, doc) for doc in docs]
scores = model.predict(pairs)
ranked = sorted(zip(docs, scores), key=lambda x: x[1], reverse=True)

for doc, score in ranked[:2]:
    print(f"Score: {score:.4f} | {doc}")

Expected output (scores may vary slightly):

Score: 8.2143 | Exercise improves cardiovascular health and mental well-being.
Score: 7.8921 | Running for 30 minutes daily reduces stress and boosts immunity.

Key Takeaways

  • Reranking improves retrieval accuracy by reordering candidates using a more precise model.
  • Cross-encoders process query-document pairs together, enabling deep semantic understanding.
  • Use cross-encoders only on a small set of top candidates (e.g., top 50) due to high computational cost.
  • Combine fast retrievers (like bi-encoders) with cross-encoders for optimal speed and accuracy.
  • Models like ms-marco are pre-trained for reranking and easy to use via sentence-transformers.
  • Always validate reranking quality with real user queries and domain-specific documents.
