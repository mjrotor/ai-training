Testing Your Assistant

Learn about testing your assistant.

Why Testing Matters for AI Assistants

You've built your AI assistant, and it seems to work when you try it out. But how do you know it will work reliably every time? That's where testing comes in. Testing your assistant helps you catch problems early, ensures consistent behavior, and gives you confidence that your code works as expected.

Think of testing like checking your car before a long trip. You wouldn't drive across the country without making sure the tires are inflated and the oil is changed. Similarly, you shouldn't deploy an assistant without verifying it handles different situations correctly.

What is testing? Testing is the process of running your code with specific inputs and checking if the outputs match what you expect. For AI assistants, this means verifying that your assistant responds correctly to different user messages.

Types of Tests for Your Assistant

There are several types of tests you can write. Let's look at the most important ones for your AI assistant.

Unit Tests

Unit tests check individual pieces of your code in isolation. For your assistant, this might mean testing a function that extracts information from a user's message.

import unittest

def extract_topic(message):
    """Extract the main topic from a user message."""
    words = message.lower().split()
    # Simple extraction: return the first meaningful word
    stop_words = ['what', 'is', 'the', 'a', 'an', 'tell', 'me', 'about']
    for word in words:
        if word not in stop_words:
            return word
    return None

class TestExtractTopic(unittest.TestCase):
    def test_simple_topic(self):
        result = extract_topic("What is Python?")
        self.assertEqual(result, 'python')
    
    def test_no_stop_words(self):
        result = extract_topic("Python programming")
        self.assertEqual(result, 'python')
    
    def test_empty_message(self):
        result = extract_topic("")
        self.assertIsNone(result)

if __name__ == '__main__':
    unittest.main()

Integration Tests

Integration tests check how different parts of your assistant work together. This is where you test the full flow from user input to assistant response.

import unittest
from unittest.mock import patch, MagicMock

class TestAssistantIntegration(unittest.TestCase):
    
    @patch('your_module.call_ai_api')
    def test_full_conversation_flow(self, mock_api):
        # Set up the mock to return a specific response
        mock_api.return_value = "Python is a programming language."
        
        # Simulate a user message
        user_message = "What is Python?"
        
        # Call your assistant's main function
        response = your_assistant.get_response(user_message)
        
        # Check that the response is what we expect
        self.assertIn("Python", response)
        self.assertIn("programming", response)
    
    @patch('your_module.call_ai_api')
    def test_error_handling(self, mock_api):
        # Simulate an API error
        mock_api.side_effect = Exception("API timeout")
        
        response = your_assistant.get_response("Hello")
        
        # Check that your assistant handles errors gracefully
        self.assertIn("sorry", response.lower())
Tip: Use @patch to mock external API calls in your tests. This makes your tests faster and more reliable, since they won't depend on the actual API being available.

Testing Different Scenarios

Your assistant needs to handle many different situations. Here are the key scenarios you should test:

Scenario What to Test Example Input
Normal questions Correct, helpful responses "What is machine learning?"
Empty input Graceful handling ""
Very long input Proper processing without errors A 500-word message
Off-topic questions Polite redirection "What's your favorite color?"
API failures Error messages, retry logic (forced timeout)
Special characters No crashes or weird behavior "Hello! @#$%^&*()"

Writing Scenario Tests

Let's write tests for some of these scenarios:

import unittest
from your_assistant import AIAssistant

class TestAssistantScenarios(unittest.TestCase):
    
    def setUp(self):
        """Create a fresh assistant for each test."""
        self.assistant = AIAssistant()
    
    def test_normal_question(self):
        response = self.assistant.get_response("What is AI?")
        self.assertIsNotNone(response)
        self.assertGreater(len(response), 0)
    
    def test_empty_input(self):
        response = self.assistant.get_response("")
        # Should return a helpful message, not crash
        self.assertIsNotNone(response)
        self.assertIn("question", response.lower())
    
    def test_very_long_input(self):
        long_message = "Tell me about " + "Python " * 100
        response = self.assistant.get_response(long_message)
        # Should still return a valid response
        self.assertIsNotNone(response)
    
    def test_special_characters(self):
        response = self.assistant.get_response("Hello! @#$%^&*()")
        self.assertIsNotNone(response)
    
    def test_off_topic_question(self):
        response = self.assistant.get_response("What's your favorite pizza?")
        # Should politely redirect or acknowledge
        self.assertIsNotNone(response)
Warning: Don't forget to test edge cases! Most bugs happen at the boundaries — empty strings, very long inputs, or unexpected characters. These are the inputs your users will eventually try.

Checking Response Quality

Testing isn't just about whether your code runs without errors. You also need to check that the responses are actually good. Here are some ways to do that:

Response Validation

You can write helper functions to check response quality:

def validate_response(response, expected_keywords=None, max_length=1000):
    """
    Check if a response meets quality standards.
    
    Args:
        response: The assistant's response string
        expected_keywords: List of words that should appear
        max_length: Maximum acceptable response length
    
    Returns:
        tuple: (is_valid, list_of_issues)
    """
    issues = []
    
    # Check if response exists
    if not response or response.strip() == "":
        issues.append("Response is empty")
        return False, issues
    
    # Check length
    if len(response) > max_length:
        issues.append(f"Response too long ({len(response)} chars)")
    
    # Check for expected keywords
    if expected_keywords:
        response_lower = response.lower()
        for keyword in expected_keywords:
            if keyword.lower() not in response_lower:
                issues.append(f"Missing keyword: '{keyword}'")
    
    # Check for common error phrases
    error_phrases = ["i don't know", "i cannot", "error occurred"]
    for phrase in error_phrases:
        if phrase in response.lower():
            issues.append(f"Contains error phrase: '{phrase}'")
    
    is_valid = len(issues) == 0
    return is_valid, issues

# Example usage in a test
def test_response_quality(self):
    response = self.assistant.get_response("What is Python?")
    is_valid, issues = validate_response(
        response, 
        expected_keywords=["python", "programming"]
    )
    
    if not is_valid:
        print(f"Response issues: {issues}")
    
    self.assertTrue(is_valid, f"Response had issues: {issues}")

Running Your Tests

Now that you've written tests, you need to run them. Here's how to run tests from the command line:

# Run all tests in a file
python -m unittest test_assistant.py

# Run with verbose output (shows each test name)
python -m unittest -v test_assistant.py

# Run a specific test class
python -m unittest test_assistant.TestAssistantScenarios

# Run a single test method
python -m unittest test_assistant.TestAssistantScenarios.test_normal_question

When you run your tests, you'll see output like this:

test_empty_input (__main__.TestAssistantScenarios) ... ok
test_normal_question (__main__.TestAssistantScenarios) ... ok
test_off_topic_question (__main__.TestAssistantScenarios) ... ok
test_special_characters (__main__.TestAssistantScenarios) ... ok
test_very_long_input (__main__.TestAssistantScenarios) ... ok

----------------------------------------------------------------------
Ran 5 tests in 0.045s

OK
Understanding test output: Each line shows a test name and whether it passed (ok) or failed (FAIL/ERROR). At the bottom, you see a summary. "OK" means all tests passed. If any fail, you'll see details about what went wrong.

Exercise: Test the Response Formatter

Your assistant has a function that formats responses. Write tests to make sure it works correctly.

Here's the function to test:

def format_response(raw_response, user_name="User"):
    """Format a raw response for display."""
    if not raw_response:
        return f"Sorry {user_name}, I couldn't generate a response."
    
    # Clean up whitespace
    cleaned = raw_response.strip()
    
    # Add greeting if not present
    if not cleaned.lower().startswith(("hello", "hi", "hey")):
        cleaned = f"Hello {user_name}! {cleaned}"
    
    return cleaned

Write tests that check:

  • Normal responses get formatted correctly
  • Empty responses return the error message
  • The user's name appears in the response
  • Responses that already start with a greeting don't get a double greeting
import unittest
from your_module import format_response

class TestFormatResponse(unittest.TestCase):
    
    def test_normal_response(self):
        result = format_response("Python is great.", "Alice")
        self.assertEqual(result, "Hello Alice! Python is great.")
    
    def test_empty_response(self):
        result = format_response("", "Bob")
        self.assertEqual(result, "Sorry Bob, I couldn't generate a response.")
    
    def test_none_response(self):
        result = format_response(None, "Charlie")
        self.assertEqual(result, "Sorry Charlie, I couldn't generate a response.")
    
    def test_user_name_appears(self):
        result = format_response("Here is info.", "Diana")
        self.assertIn("Diana", result)
    
    def test_already_greeted(self):
        result = format_response("Hello! I can help.", "Eve")
        # Should not add another greeting
        self.assertEqual(result, "Hello! I can help.")
    
    def test_whitespace_cleanup(self):
        result = format_response("  Some info.  ", "Frank")
        self.assertEqual(result, "Hello Frank! Some info.")

if __name__ == '__main__':
    unittest.main()

Key Takeaways

  • Testing catches bugs early — Find problems before your users do by writing tests for your assistant.
  • Unit tests check individual functions — Test each piece of your code separately to make sure it works on its own.
  • Integration tests check the full flow — Test how your assistant handles a complete conversation from start to finish.
  • Test edge cases — Empty inputs, very long messages, and special characters are where most bugs hide.
  • Mock external APIs — Use @patch to simulate API responses so your tests are fast and reliable.
  • Check response quality — It's not enough that your code runs; verify that responses are helpful and correct.
  • Run tests regularly — Make testing part of your development routine, not something you do only at the end.
