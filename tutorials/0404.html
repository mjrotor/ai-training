Multiple Tools & Tool Selection

Welcome to Day 4, Lesson 4! So far, you've learned how to give an AI agent a single tool and watch it use that tool to solve problems. But real-world agents rarely get by with just one tool. Imagine a personal assistant who can only check the weather but can't send emails, search the web, or do math. Not very useful, right?

In this lesson, you'll learn how to equip your agent with multiple tools and how the agent intelligently selects the right tool for each task. By the end, you'll be able to build agents that juggle several capabilities at once.

Why Multiple Tools?

Think of tools as the agent's superpowers. Each tool gives the agent a new ability:

  • A calculator tool lets it do math.
  • A web search tool lets it find current information.
  • A file reader tool lets it open and read documents.
  • A weather tool lets it check forecasts.

When you give an agent multiple tools, it can handle a much wider variety of questions. The key challenge becomes: how does the agent know which tool to use?

💡 Key Idea: The agent reads the description of each tool and uses its language understanding to match the user's request to the most appropriate tool. You don't have to write if/else logic for this — the agent figures it out!

Defining Multiple Tools

Let's start by defining several tools and registering them all with our agent. Each tool is a Python function with a clear docstring that describes what it does. The docstring is critical — it's how the agent decides when to use the tool.

# multiple_tools.py

def add_numbers(a: float, b: float) -> float:
    """Add two numbers together and return the sum.
    
    Args:
        a: The first number.
        b: The second number.
    
    Returns:
        The sum of a and b.
    """
    return a + b


def multiply_numbers(a: float, b: float) -> float:
    """Multiply two numbers together and return the product.
    
    Args:
        a: The first number.
        b: The second number.
    
    Returns:
        The product of a and b.
    """
    return a * b


def get_weather(city: str) -> str:
    """Get the current weather for a given city.
    
    Args:
        city: The name of the city to check weather for.
    
    Returns:
        A string describing the current weather.
    """
    # In a real app, this would call a weather API
    weather_data = {
        "New York": "Sunny, 72°F",
        "London": "Cloudy, 58°F",
        "Tokyo": "Rainy, 65°F",
        "Sydney": "Clear, 80°F",
    }
    return weather_data.get(city, f"Weather data not available for {city}")


def search_web(query: str) -> str:
    """Search the web for information about a topic.
    
    Args:
        query: The search query string.
    
    Returns:
        A summary of search results.
    """
    # In a real app, this would call a search API
    return f"Search results for '{query}': Found 10 relevant articles."

Notice how each function has a detailed docstring. The agent reads these descriptions to understand when to call each tool.

Registering Tools with the Agent

Now let's register all four tools with our agent. We'll use a list of tool definitions, where each definition includes the function name, description, and parameter schema.

# agent_with_multiple_tools.py

from typing import Callable

# Our tool functions (defined above)
tools = [add_numbers, multiply_numbers, get_weather, search_web]

# Build tool descriptions for the agent
tool_descriptions = []
for tool in tools:
    tool_descriptions.append({
        "name": tool.__name__,
        "description": tool.__doc__,
        "parameters": tool.__annotations__,
    })

# The agent's system prompt includes all tool descriptions
system_prompt = f"""You are a helpful assistant with access to the following tools:

{tool_descriptions}

When a user asks a question, determine which tool is most appropriate.
Call the tool with the correct parameters and return the result."""
✅ Best Practice: Always write clear, descriptive docstrings for your tools. The agent relies entirely on these descriptions to choose the right tool. A vague docstring like "does stuff" will confuse the agent!

How Tool Selection Works

When a user sends a message, the agent follows this process:

  1. Read the user's request. The agent analyzes the natural language input.
  2. Review all available tools. It reads the name and description of each registered tool.
  3. Match request to tool. It picks the tool whose description best matches what the user is asking for.
  4. Extract parameters. It pulls the necessary arguments from the user's message.
  5. Call the tool. It executes the function with the extracted parameters.
  6. Return the result. It sends the tool's output back to the user.

Here's a concrete example of what happens under the hood:

# Example: User asks "What's 15 times 23?"

# Step 1: Agent reads the request — it involves multiplication
# Step 2: Agent reviews tools:
#   - add_numbers: "Add two numbers together"
#   - multiply_numbers: "Multiply two numbers together"  ← MATCH!
#   - get_weather: "Get the current weather"
#   - search_web: "Search the web for information"

# Step 3: Agent selects multiply_numbers
# Step 4: Extracts a=15, b=23
# Step 5: Calls multiply_numbers(15, 23) → 345
# Step 6: Returns "15 × 23 = 345"

Building a Multi-Tool Agent

Let's put it all together into a complete agent that can handle math, weather, and web search queries.

# complete_agent.py

class MultiToolAgent:
    def __init__(self, tools: list[Callable]):
        self.tools = {tool.__name__: tool for tool in tools}
        self.history = []
    
    def _select_tool(self, user_message: str) -> tuple[str, dict]:
        """Select the best tool based on the user's message.
        
        In a real implementation, this would use an LLM to analyze
        the message and pick the right tool. Here we simulate it.
        """
        message_lower = user_message.lower()
        
        if "weather" in message_lower or "temperature" in message_lower:
            # Extract city name (simplified)
            for city in ["new york", "london", "tokyo", "sydney"]:
                if city in message_lower:
                    return "get_weather", {"city": city.title()}
        
        if "multiply" in message_lower or "times" in message_lower:
            # Extract numbers (simplified)
            import re
            numbers = re.findall(r'\d+', user_message)
            if len(numbers) >= 2:
                return "multiply_numbers", {
                    "a": float(numbers[0]),
                    "b": float(numbers[1])
                }
        
        if "add" in message_lower or "plus" in message_lower or "sum" in message_lower:
            import re
            numbers = re.findall(r'\d+', user_message)
            if len(numbers) >= 2:
                return "add_numbers", {
                    "a": float(numbers[0]),
                    "b": float(numbers[1])
                }
        
        if "search" in message_lower or "find" in message_lower or "look up" in message_lower:
            return "search_web", {"query": user_message}
        
        return None, {}
    
    def run(self, user_message: str) -> str:
        """Process a user message and return a response."""
        tool_name, params = self._select_tool(user_message)
        
        if tool_name is None:
            return ("I'm not sure which tool to use for that request. "
                    "I can help with math, weather, or web searches.")
        
        tool_func = self.tools[tool_name]
        result = tool_func(**params)
        
        self.history.append({
            "message": user_message,
            "tool_used": tool_name,
            "result": result
        })
        
        return f"[Used {tool_name}] {result}"


# --- Run the agent ---
agent = MultiToolAgent([add_numbers, multiply_numbers, get_weather, search_web])

# Test with different queries
queries = [
    "What's 12 plus 34?",
    "Multiply 7 by 8",
    "What's the weather in Tokyo?",
    "Search for latest AI news",
]

for query in queries:
    print(f"User: {query}")
    print(f"Agent: {agent.run(query)}")
    print()

When you run this code, you'll see output like:

User: What's 12 plus 34?
Agent: [Used add_numbers] 46.0

User: Multiply 7 by 8
Agent: [Used multiply_numbers] 56.0

User: What's the weather in Tokyo?
Agent: [Used get_weather] Rainy, 65°F

User: Search for latest AI news
Agent: [Used search_web] Search results for 'Search for latest AI news': Found 10 relevant articles.

Common Pitfalls with Multiple Tools

1. Vague Tool Descriptions

If two tools have similar descriptions, the agent may pick the wrong one. Be specific!

# BAD — too vague
def tool_one(data):
    """Process the data."""
    ...

def tool_two(data):
    """Process the data."""
    ...

# GOOD — specific and distinct
def calculate_average(numbers: list) -> float:
    """Calculate the arithmetic mean of a list of numbers."""
    ...

def calculate_median(numbers: list) -> float:
    """Find the middle value in a sorted list of numbers."""
    ...

2. Too Many Tools at Once

Giving an agent 50 tools can overwhelm it and lead to poor selection. Start with 3–5 tools and add more as needed.

⚠️ Warning: More tools ≠ better agent. Each additional tool increases the chance of misselection. Only add tools that serve distinct, clearly different purposes.

3. Overlapping Tool Responsibilities

If two tools can both handle the same request, the agent may become inconsistent. Make sure each tool has a clear, unique role.

Tool Selection Strategies

There are several approaches to how an agent selects tools:

  • LLM-based selection (most common): The language model reads all tool descriptions and picks the best match. This is how most production agents work.
  • Keyword matching: Simple pattern matching on keywords (like our example above). Fast but limited.
  • Routing classifier: A separate small model trained to classify which tool to use. More accurate for large tool sets.
  • Multi-step selection: The agent first picks a category (e.g., "math"), then picks a specific tool within that category.

Coding Exercise

🛠️ Exercise: Build a Three-Tool Agent

Create an agent with three tools:

  1. fahrenheit_to_celsius(f) — converts Fahrenheit to Celsius
  2. count_words(text) — counts the number of words in a string
  3. is_palindrome(text) — checks if a string is a palindrome

Write the tool functions with clear docstrings, then implement a simple keyword-based tool selector (like the one in our example). Test it with at least three different user queries.

# Exercise Solution: Three-Tool Agent

def fahrenheit_to_celsius(f: float) -> float:
    """Convert a temperature from Fahrenheit to Celsius.
    
    Args:
        f: Temperature in Fahrenheit.
    
    Returns:
        Temperature in Celsius.
    """
    return (f - 32) * 5 / 9


def count_words(text: str) -> int:
    """Count the number of words in a text string.
    
    Args:
        text: The input string to count words in.
    
    Returns:
        The number of words.
    """
    return len(text.split())


def is_palindrome(text: str) -> bool:
    """Check if a string is a palindrome (reads the same forwards and backwards).
    
    Args:
        text: The string to check.
    
    Returns:
        True if the string is a palindrome, False otherwise.
    """
    cleaned = text.lower().replace(" ", "")
    return cleaned == cleaned[::-1]


class ThreeToolAgent:
    def __init__(self):
        self.tools = {
            "fahrenheit_to_celsius": fahrenheit_to_celsius,
            "count_words": count_words,
            "is_palindrome": is_palindrome,
        }
    
    def select_and_run(self, message: str):
        message_lower = message.lower()
        
        if "fahrenheit" in message_lower or "celsius" in message_lower or "convert" in message_lower:
            import re
            numbers = re.findall(r'\d+', message)
            if numbers:
                result = fahrenheit_to_celsius(float(numbers[0]))
                return f"[fahrenheit_to_celsius] {numbers[0]}°F = {result:.1f}°C"
        
        if "word" in message_lower or "count" in message_lower:
            # Extract the text in quotes if present
            import re
            match = re.search(r'"([^"]*)"', message)
            text = match.group(1) if match else message
            result = count_words(text)
            return f"[count_words] '{text}' has {result} words"
        
        if "palindrome" in message_lower:
            import re
            match = re.search(r'"([^"]*)"', message)
            if match:
                text = match.group(1)
                result = is_palindrome(text)
                return f"[is_palindrome] '{text}' is {'a' if result else 'not a'} palindrome"
        
        return "I'm not sure which tool to use. Try asking about temperature, word count, or palindromes."


# Test the agent
agent = ThreeToolAgent()

test_queries = [
    'Convert 100 fahrenheit to celsius',
    'Count the words in "Hello world this is a test"',
    'Is "racecar" a palindrome?',
    'Is "hello world" a palindrome?',
]

for query in test_queries:
    print(f"User: {query}")
    print(f"Agent: {agent.select_and_run(query)}")
    print()

Key Takeaways

  • Multiple tools make an agent far more capable and versatile than a single-tool agent.
  • The agent selects tools by reading the docstring descriptions you provide — so write them clearly and specifically.
  • Tool selection is typically handled by the LLM itself, which matches the user's intent to the best tool description.
  • Avoid vague or overlapping tool descriptions — they lead to incorrect tool selection.
  • Start with 3–5 well-defined tools and expand as needed. More tools isn't always better.
  • Each tool should have a single, clear responsibility — just like good function design in general programming.
  • You can implement tool selection via LLM reasoning, keyword matching, or classifier models depending on your needs.
