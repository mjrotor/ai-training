Streaming with OpenAI API

Learn about streaming with openai api.

What Is Streaming?

When you make a request to the OpenAI API, the model doesn't generate its entire response all at once. Instead, it produces text piece by piece — word by word or token by token. Streaming is the technique of receiving and displaying these pieces as they're generated, rather than waiting for the complete response.

Think of it like watching someone type a message in real time versus waiting for them to finish typing and then seeing the whole message at once. Streaming gives your users a much more responsive and engaging experience.

Why it matters: Without streaming, a user might wait 5–10 seconds staring at a blank screen before seeing any output. With streaming, they see the first word appear almost immediately, making the interaction feel natural and fast.

How Streaming Works

Under the hood, streaming uses a protocol called Server-Sent Events (SSE). When you set stream=True in your API call, the server sends back a series of small data chunks instead of one large JSON response. Each chunk contains a piece of the generated text.

  1. You send a request to the OpenAI API with stream=True.
  2. The server begins generating the response token by token.
  3. Each token is sent back to your application as soon as it's ready.
  4. Your code processes each chunk and can display it immediately.
  5. The stream ends when the model finishes generating the full response.

Basic Streaming with the OpenAI Python SDK

Let's look at how to enable streaming using the official OpenAI Python library. The key difference from a normal call is simply adding the stream=True parameter.

from openai import OpenAI

client = OpenAI()

# Non-streaming call (waits for the full response)
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Explain what an API is in one sentence."}
    ]
)
print(response.choices[0].message.content)

Now here's the same call, but with streaming enabled:

from openai import OpenAI

client = OpenAI()

# Streaming call (receives chunks as they arrive)
stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Explain what an API is in one sentence."}
    ],
    stream=True  # ← This is the only change!
)

for chunk in stream:
    if chunk.choices[0].delta.content is not None:
        print(chunk.choices[0].delta.content, end="", flush=True)
Pro tip: Notice the end="" and flush=True in the print() call. The end="" prevents a newline after each chunk, and flush=True forces Python to output the text immediately instead of buffering it. Without these, the text might appear in large, delayed bursts.

Understanding the Chunk Structure

Each chunk in the stream is a ChatCompletionChunk object. It has a similar structure to a regular response, but the content arrives piece by piece inside chunk.choices[0].delta.content.

for chunk in stream:
    # Each chunk looks something like this:
    # ChatCompletionChunk(
    #   id='...',
    #   choices=[Choice(delta=ChoiceDelta(content='An'), index=0, ...)],
    #   ...
    # )
    
    content = chunk.choices[0].delta.content
    if content is not None:
        print(f"Received chunk: '{content}'")

Sometimes delta.content is None — this happens for the first chunk (which contains metadata) and the final chunk (which signals completion). That's why we always check if content is not None before using it.

Streaming vs. Non-Streaming: A Comparison

Feature Non-Streaming Streaming
User Experience User waits for full response Text appears in real time
Time to First Token Same (network latency) Same (network latency)
Total Response Time Same Same
Code Complexity Simple — one response object Slightly more — loop over chunks
Perceived Speed Feels slow Feels fast and responsive
Error Handling Straightforward Must handle mid-stream errors
Important: Streaming does not make the model generate text faster. The total time to produce the full response is the same. What changes is the perceived speed — users see output immediately, which makes the experience feel much more responsive.

Building a Simple Streaming Chat Loop

Let's put everything together into a complete, interactive chat loop that streams responses in real time. This is the kind of pattern you'd use in a real application.

from openai import OpenAI

client = OpenAI()

messages = [
    {"role": "system", "content": "You are a helpful assistant."}
]

print("Chat with the AI (type 'quit' to exit)\n")

while True:
    user_input = input("You: ")
    
    if user_input.lower() == "quit":
        break
    
    # Add user message to conversation history
    messages.append({"role": "user", "content": user_input})
    
    # Stream the response
    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        stream=True
    )
    
    print("AI: ", end="", flush=True)
    full_response = ""
    
    for chunk in stream:
        content = chunk.choices[0].delta.content
        if content is not None:
            print(content, end="", flush=True)
            full_response += content
    
    print()  # Newline after response is complete
    
    # Add assistant's full response to conversation history
    messages.append({"role": "assistant", "content": full_response})

Why Save the Full Response?

You might wonder why we collect full_response by concatenating each chunk. The reason is conversation history. The OpenAI API is stateless — it doesn't remember previous messages. To maintain a multi-turn conversation, you need to send the entire message history with each request. By saving the streamed response, we can append it to messages and the AI will "remember" what it said earlier.

Memory management tip: In a real application, you'll want to limit the length of your messages list. Old conversations can be summarized or trimmed to stay within the model's context window and reduce costs.

Handling Errors During Streaming

When streaming, errors can occur mid-response — the network might drop, or the API might return an error partway through. It's important to handle these gracefully.

from openai import OpenAI
from openai import APIError, APIConnectionError

client = OpenAI()

try:
    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Tell me a story."}],
        stream=True
    )
    
    for chunk in stream:
        content = chunk.choices[0].delta.content
        if content is not None:
            print(content, end="", flush=True)
    print()

except APIConnectionError:
    print("\n[Error] Could not connect to the API. Check your network.")
except APIError as e:
    print(f"\n[Error] API returned an error: {e}")
except Exception as e:
    print(f"\n[Error] Something went wrong: {e}")

Streaming with Additional Parameters

Streaming works with all the same parameters you'd use in a non-streaming call. Here are some common ones:

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    stream=True,
    temperature=0.7,          # Controls randomness (0 = deterministic, 2 = random)
    max_tokens=500,           # Limits response length
    top_p=1.0,                # Nucleus sampling parameter
    frequency_penalty=0.0,    # Reduces repetition
    presence_penalty=0.0      # Encourages new topics
)
Tip: When streaming, max_tokens is especially useful because it prevents the model from generating an extremely long response that keeps the stream open for a long time.

Practice Exercise

Exercise: Build a Streaming Word Counter

Write a Python script that streams a response from the OpenAI API and counts the number of words in the response as they arrive. After the stream finishes, print the total word count.

Requirements:

  • Use stream=True in your API call.
  • After each chunk, print the running word count.
  • After the stream ends, print the final word count.
  • Split words by whitespace using .split().

Starter code:

from openai import OpenAI

client = OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Write a short paragraph about Python."}
    ],
    stream=True
)

# Your code here:
# 1. Initialize a variable to track the full response text
# 2. Loop through chunks and accumulate text
# 3. After each chunk, print the current word count
# 4. After the loop, print the final word count
from openai import OpenAI

client = OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Write a short paragraph about Python."}
    ],
    stream=True
)

full_text = ""

for chunk in stream:
    content = chunk.choices[0].delta.content
    if content is not None:
        full_text += content
        word_count = len(full_text.split())
        print(f"Running word count: {word_count}")

print(f"\nFinal word count: {len(full_text.split())}")

How it works: We accumulate each chunk's content into full_text. After each chunk arrives, we split the accumulated text by whitespace and count the elements. This gives us a running word count that updates in real time as the model generates text.

Key Takeaways

  • Streaming delivers AI-generated text to users token by token, making interactions feel fast and responsive.
  • Enable streaming by adding stream=True to your client.chat.completions.create() call.
  • Loop over the stream object and read each chunk from chunk.choices[0].delta.content.
  • Always check if delta.content is not None — some chunks contain metadata instead of text.
  • Use end="" and flush=True in print() to display text smoothly without buffering delays.
  • Collect the full response during streaming if you need to maintain conversation history across turns.
  • Wrap streaming calls in try/except blocks to handle network errors and API failures gracefully.
  • Streaming improves perceived speed, not actual generation speed — the total response time is the same.
