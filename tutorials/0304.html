Setting Boundaries & Constraints

Learn about setting boundaries & constraints.

Why Boundaries Matter

Imagine you've built an AI agent that can search the web, send emails, and manage your calendar. Sounds powerful, right? But what happens if that agent decides to send an email to your entire contact list without asking? Or deletes files it shouldn't touch? Without clear boundaries, even a well-intentioned agent can cause real damage.

Boundaries and constraints are the guardrails that keep your AI agent operating safely, predictably, and within the scope you define. In this lesson, we'll explore how to set up these guardrails effectively.

Real-World Impact: In 2023, a customer service AI at a major company was given too much autonomy and began offering unauthorized refunds totaling over $1 million before being shut down. Proper constraints could have prevented this.

Types of Boundaries

When we talk about boundaries for AI agents, we're really talking about three main categories:

Boundary Type What It Controls Example
Tool Access Which tools/functions the agent can use Allowing web search but not file deletion
Scope Limits What topics or domains the agent handles Only answering questions about your product
Action Constraints What actions require human approval Sending emails needs confirmation

Tool Access Boundaries

The most fundamental boundary is controlling which tools your agent can access. Think of it like giving someone keys to a building — you wouldn't give a visitor the key to every room.


# Define available tools with clear boundaries
TOOLS = {
    "web_search": {
        "enabled": True,
        "max_results": 5,
        "allowed_domains": ["docs.python.org", "wikipedia.org"]
    },
    "file_read": {
        "enabled": True,
        "allowed_paths": ["/safe/directory/"]
    },
    "file_write": {
        "enabled": False,  # Disabled by default
        "requires_approval": True
    },
    "email_send": {
        "enabled": True,
        "requires_approval": True,
        "max_recipients": 1
    }
}

def execute_tool(tool_name, params):
    if tool_name not in TOOLS or not TOOLS[tool_name]["enabled"]:
        return f"Error: {tool_name} is not available"
    
    if TOOLS[tool_name].get("requires_approval"):
        if not get_human_approval(tool_name, params):
            return "Action cancelled by user"
    
    # Execute the tool...
    return perform_action(tool_name, params)

Scope and Domain Boundaries

Scope boundaries define what your agent should and shouldn't talk about. This is especially important for customer-facing agents.


# Define the agent's scope
AGENT_SCOPE = {
    "allowed_topics": [
        "product information",
        "order status",
        "return policy",
        "technical support"
    ],
    "disallowed_topics": [
        "competitor information",
        "internal company matters",
        "personal opinions"
    ],
    "fallback_response": "I'm sorry, I can't help with that. Is there something else I can assist you with?"
}

def handle_message(user_message):
    topic = classify_topic(user_message)
    
    if topic in AGENT_SCOPE["disallowed_topics"]:
        return AGENT_SCOPE["fallback_response"]
    
    if topic in AGENT_SCOPE["allowed_topics"]:
        return generate_response(user_message)
    
    return AGENT_SCOPE["fallback_response"]
Pro Tip: Always include a graceful fallback for out-of-scope queries. Never leave the user hanging or, worse, let the agent guess.

Implementing Action Constraints

Some actions are too important or risky to let an agent perform without human oversight. Let's look at how to implement approval workflows.

The Approval Queue Pattern

One effective approach is to queue risky actions for human review before execution.


class ActionQueue:
    def __init__(self):
        self.pending_actions = []
        self.approved_actions = []
    
    def request_action(self, action_type, details, risk_level):
        action = {
            "id": len(self.pending_actions) + 1,
            "type": action_type,
            "details": details,
            "risk_level": risk_level,
            "status": "pending"
        }
        
        # Auto-approve low-risk actions
        if risk_level == "low":
            action["status"] = "approved"
            self.approved_actions.append(action)
            return {"status": "approved", "auto": True}
        
        # Queue medium and high-risk actions
        self.pending_actions.append(action)
        return {"status": "pending", "action_id": action["id"]}
    
    def approve_action(self, action_id):
        for action in self.pending_actions:
            if action["id"] == action_id:
                action["status"] = "approved"
                self.pending_actions.remove(action)
                self.approved_actions.append(action)
                return True
        return False

# Usage
queue = ActionQueue()

# Low-risk: auto-approved
result = queue.request_action("read_file", {"path": "/data/report.txt"}, "low")
print(result)  # {'status': 'approved', 'auto': True}

# High-risk: needs approval
result = queue.request_action("send_email", {"to": "team@company.com"}, "high")
print(result)  # {'status': 'pending', 'action_id': 1}

Risk Levels Explained

Not all actions carry the same risk. Here's how to categorize them:

  • Low Risk: Read-only operations, searching information, generating reports
  • Medium Risk: Creating new files, updating non-critical data, sending internal notifications
  • High Risk: Deleting data, sending external communications, modifying permissions, financial transactions
Remember: When in doubt, set the risk level higher. It's easier to lower it later than to deal with the consequences of an unchecked action.

Building a Constraint System

Let's put it all together with a complete constraint system for an AI agent.


class AgentConstraints:
    def __init__(self):
        self.max_iterations = 10
        self.timeout_seconds = 30
        self.allowed_tools = ["search", "read_file", "calculate"]
        self.blocked_tools = ["delete_file", "send_email", "modify_settings"]
        self.require_approval_for = ["write_file", "api_call"]
        self.current_iteration = 0
        self.action_log = []
    
    def can_use_tool(self, tool_name):
        if tool_name in self.blocked_tools:
            return False, "Tool is blocked by policy"
        if tool_name not in self.allowed_tools:
            return False, "Tool not in allowed list"
        return True, "OK"
    
    def needs_approval(self, action_type):
        return action_type in self.require_approval_for
    
    def check_iteration_limit(self):
        self.current_iteration += 1
        if self.current_iteration > self.max_iterations:
            return False, "Maximum iterations reached"
        return True, "OK"
    
    def log_action(self, action, result):
        self.action_log.append({
            "action": action,
            "result": result,
            "timestamp": get_timestamp()
        })

# Initialize constraints
constraints = AgentConstraints()

# Check before using a tool
can_use, reason = constraints.can_use_tool("delete_file")
print(f"Can use delete_file: {can_use} - {reason}")
# Output: Can use delete_file: False - Tool is blocked by policy

can_use, reason = constraints.can_use_tool("search")
print(f"Can use search: {can_use} - {reason}")
# Output: Can use search: True - OK

Testing Your Boundaries

Setting boundaries is only half the battle — you need to test them thoroughly. Here are common test scenarios:

  1. Direct violation: Ask the agent to perform a blocked action
  2. Circumvention: Try to trick the agent into performing blocked actions indirectly
  3. Edge cases: Test with unusual inputs that might bypass constraints
  4. Boundary testing: Verify that allowed actions work correctly at the edges of their scope

# Test suite for agent constraints
def test_constraints():
    agent = AgentConstraints()
    
    # Test 1: Blocked tool should be rejected
    can_use, _ = agent.can_use_tool("delete_file")
    assert can_use == False, "delete_file should be blocked"
    
    # Test 2: Allowed tool should work
    can_use, _ = agent.can_use_tool("search")
    assert can_use == True, "search should be allowed"
    
    # Test 3: Unknown tool should be rejected
    can_use, _ = agent.can_use_tool("unknown_tool")
    assert can_use == False, "unknown tools should be blocked"
    
    # Test 4: Iteration limit
    agent.max_iterations = 2
    agent.current_iteration = 0
    ok, _ = agent.check_iteration_limit()  # iteration 1
    assert ok == True
    ok, _ = agent.check_iteration_limit()  # iteration 2
    assert ok == True
    ok, _ = agent.check_iteration_limit()  # iteration 3 - should fail
    assert ok == False
    
    print("All tests passed!")

test_constraints()
Exercise: Design Constraints for a Customer Support Agent

You're building a customer support agent for an online store. The agent should be able to:

  • Look up order information
  • Answer questions about products
  • Provide shipping status updates

But it should NOT be able to:

  • Process refunds (requires human approval)
  • Access customer payment information
  • Modify order details

Write a constraint configuration that implements these rules. Include tool definitions, risk levels, and any approval requirements.

Key Takeaways

  • Always define explicit boundaries — Never assume an agent will "figure out" what it shouldn't do
  • Use the principle of least privilege — Only grant access to tools and data that are absolutely necessary
  • Implement tiered risk levels — Not all actions require the same level of oversight
  • Test your constraints regularly — Boundaries can drift as you add new features
  • Log all actions — Keep records so you can audit what your agent has done
  • Plan for failure — Have a kill switch or emergency stop mechanism ready
