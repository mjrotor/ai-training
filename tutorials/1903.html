Intent Classification

Learn about intent classification.

What is Intent Classification?

Intent classification is one of the most fundamental tasks in building intelligent AI agents. At its core, it means figuring out what a user actually wants when they type or say something. When a user says "What's the weather like today?", the agent needs to recognize that the intent is get_weather — not book_flight or play_music.

Without intent classification, an AI agent would be like a librarian who hands you a random book no matter what you ask for. With it, the agent becomes a skilled assistant that routes your request to the right action.

Definition: Intent classification is a natural language processing (NLP) task that maps a user's input text to a predefined category (intent) that represents their goal or desired action.

Why Intent Classification Matters for AI Agents

AI agents interact with users through natural language, which is messy and ambiguous. The same request can be phrased in dozens of ways:

  • "Set a timer for 5 minutes"
  • "Can you start a 5-minute countdown?"
  • "I need a timer, five minutes please"
  • "Count down from 300 seconds"

All of these map to the same intent: set_timer. Your agent must be robust enough to recognize the underlying goal regardless of phrasing. Intent classification is the bridge between raw user text and the agent's action logic.

Pro Tip: A well-designed intent classifier is what separates a simple chatbot from a true AI agent. It enables the agent to dynamically choose tools, APIs, or response strategies based on what the user actually needs.

Approaches to Intent Classification

There are several approaches you can take, each with trade-offs:

Approach Pros Cons Best For
Keyword matching Simple, fast, no training needed Brittle, fails with paraphrasing Very small, fixed command sets
Traditional ML (SVM, Naive Bayes) Lightweight, interpretable Requires feature engineering Medium-sized datasets
Deep Learning (BERT, etc.) High accuracy, handles nuance Slower, needs more resources Complex, varied user inputs
LLM-based classification Zero-shot capable, flexible Latency, cost per call Dynamic or evolving intent sets

Building an Intent Classifier with Python

Let's start with a practical example using a traditional machine learning approach with scikit-learn. This gives you a solid foundation before moving to more advanced methods.

Step 1: Prepare Training Data

Every intent classifier needs labeled examples — pairs of text and their corresponding intent. Here's how you might structure your training data:

import json

# Training data: text-intent pairs
training_data = [
    {"text": "What's the weather like today?", "intent": "get_weather"},
    {"text": "Will it rain tomorrow?", "intent": "get_weather"},
    {"text": "Temperature in New York?", "intent": "get_weather"},
    {"text": "Set a timer for 5 minutes", "intent": "set_timer"},
    {"text": "Start a countdown timer", "intent": "set_timer"},
    {"text": "Remind me in 10 minutes", "intent": "set_timer"},
    {"text": "Play some music", "intent": "play_music"},
    {"text": "Start my playlist", "intent": "play_music"},
    {"text": "Skip this song", "intent": "play_music"},
    {"text": "What's on my calendar today?", "intent": "check_calendar"},
    {"text": "Do I have any meetings?", "intent": "check_calendar"},
    {"text": "Schedule a meeting for 3 PM", "intent": "check_calendar"},
    {"text": "Turn off the lights", "intent": "control_lights"},
    {"text": "Dim the bedroom lights", "intent": "control_lights"},
    {"text": "Make it brighter in here", "intent": "control_lights"},
]

texts = [item["text"] for item in training_data]
intents = [item["intent"] for item in training_data]

print(f"Loaded {len(texts)} training examples")
print(f"Unique intents: {set(intents)}")

Step 2: Train the Classifier

We'll use TF-IDF vectorization to convert text into numerical features, then train a Support Vector Machine (SVM) classifier:

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.svm import LinearSVC
from sklearn.pipeline import Pipeline
from sklearn.model_selection import cross_val_score
import numpy as np

# Build a pipeline: vectorizer + classifier
intent_pipeline = Pipeline([
    ("tfidf", TfidfVectorizer(
        ngram_range=(1, 2),    # Use unigrams and bigrams
        stop_words="english",
        max_features=5000
    )),
    ("classifier", LinearSVC(
        C=1.0,
        max_iter=10000
    ))
])

# Train on all data
intent_pipeline.fit(texts, intents)

# Evaluate with cross-validation
scores = cross_val_score(intent_pipeline, texts, intents, cv=3)
print(f"Cross-validation accuracy: {np.mean(scores):.2f} (+/- {np.std(scores):.2f})")

# Test with new inputs
test_inputs = [
    "Is it going to snow?",
    "Set timer for 2 minutes",
    "Play my favorite song",
    "What meetings do I have?",
    "Turn on the kitchen lights"
]

for user_input in test_inputs:
    predicted = intent_pipeline.predict([user_input])[0]
    print(f"'{user_input}' → {predicted}")

Step 3: Add Confidence Scoring

A production agent needs to know how confident the classifier is. If confidence is low, the agent can ask for clarification instead of guessing:

from sklearn.calibration import CalibratedClassifierCV

# Wrap the SVM with probability calibration
calibrated_clf = CalibratedClassifierCV(
    LinearSVC(C=1.0, max_iter=10000),
    cv=3
)

calibrated_pipeline = Pipeline([
    ("tfidf", TfidfVectorizer(
        ngram_range=(1, 2),
        stop_words="english",
        max_features=5000
    )),
    ("classifier", calibrated_clf)
])

calibrated_pipeline.fit(texts, intents)

def classify_with_confidence(pipeline, user_input, threshold=0.6):
    """Classify intent with confidence threshold."""
    proba = pipeline.predict_proba([user_input])[0]
    classes = pipeline.classes_
    
    # Get the top prediction and its confidence
    top_idx = np.argmax(proba)
    predicted_intent = classes[top_idx]
    confidence = proba[top_idx]
    
    if confidence < threshold:
        return {
            "intent": "unknown",
            "confidence": confidence,
            "message": "I'm not sure what you mean. Could you rephrase?"
        }
    
    return {
        "intent": predicted_intent,
        "confidence": confidence,
        "all_scores": dict(zip(classes, proba))
    }

# Test confidence scoring
result = classify_with_confidence(calibrated_pipeline, "What's the forecast?")
print(f"Intent: {result['intent']}")
print(f"Confidence: {result['confidence']:.2f}")
print(f"All scores: {result.get('all_scores', {})}")

result2 = classify_with_confidence(calibrated_pipeline, "asdfghjkl")
print(f"\nIntent: {result2['intent']}")
print(f"Message: {result2['message']}")
Warning: Always set a confidence threshold. Without one, your agent will confidently route "asdfghjkl" to some random intent. A threshold of 0.5–0.7 is a good starting point, but tune it based on your application's tolerance for errors.

LLM-Based Intent Classification

For more flexible and powerful classification, you can use a Large Language Model. This approach requires zero training data and handles novel phrasings naturally:

from openai import OpenAI

client = OpenAI()

INTENT_DEFINITIONS = """
You are an intent classifier for a smart home AI agent.
Classify the user's message into exactly one of these intents:

- get_weather: User asks about weather, temperature, or forecasts
- set_timer: User wants to set a timer, countdown, or alarm
- play_music: User wants to play, pause, skip, or control music
- check_calendar: User asks about schedule, meetings, or events
- control_lights: User wants to turn on/off or adjust lights
- unknown: The message doesn't match any known intent

Respond with ONLY the intent label, nothing else.
"""

def classify_with_llm(user_input):
    """Use an LLM to classify user intent."""
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": INTENT_DEFINITIONS},
            {"role": "user", "content": user_input}
        ],
        temperature=0,      # Deterministic output
        max_tokens=20       # We only need a short label
    )
    
    predicted_intent = response.choices[0].message.content.strip()
    return predicted_intent

# Test the LLM classifier
test_phrases = [
    "It looks cloudy outside, should I bring an umbrella?",
    "Can you count down from 60 seconds for me?",
    "Put on some jazz, I'm in the mood to relax",
    "Am I free this afternoon?",
    "The room is too dark, fix that"
]

for phrase in test_phrases:
    intent = classify_with_llm(phrase)
    print(f"'{phrase}' → {intent}")
Tip: LLM-based classification shines when your intents are nuanced or when you frequently add new intents. You simply update the prompt — no retraining needed. However, for latency-sensitive applications, a trained ML model is faster.

Integrating Intent Classification into an Agent

Now let's see how intent classification fits into a complete agent loop. The classifier acts as the "brain" that decides which tool or function to invoke:

class SmartHomeAgent:
    """A simple AI agent with intent classification."""
    
    def __init__(self, intent_pipeline, confidence_threshold=0.6):
        self.intent_pipeline = intent_pipeline
        self.threshold = confidence_threshold
        
        # Map intents to handler functions
        self.intent_handlers = {
            "get_weather": self._handle_weather,
            "set_timer": self._handle_timer,
            "play_music": self._handle_music,
            "check_calendar": self._handle_calendar,
            "control_lights": self._handle_lights,
        }
    
    def process(self, user_input):
        """Main entry point: classify intent and execute."""
        # Step 1: Classify
        proba = self.intent_pipeline.predict_proba([user_input])[0]
        classes = self.intent_pipeline.classes_
        top_idx = __import__('numpy').argmax(proba)
        
        intent = classes[top_idx]
        confidence = proba[top_idx]
        
        # Step 2: Check confidence
        if confidence < self.threshold:
            return {
                "response": "I'm not sure what you'd like me to do. "
                           "Could you try rephrasing that?",
                "intent": "unknown",
                "confidence": confidence
            }
        
        # Step 3: Execute the appropriate handler
        handler = self.intent_handlers.get(intent, self._handle_unknown)
        result = handler(user_input)
        
        return {
            "response": result,
            "intent": intent,
            "confidence": confidence
        }
    
    def _handle_weather(self, text):
        return "It's currently 72°F and partly cloudy. No rain expected today."
    
    def _handle_timer(self, text):
        return "Timer set! I'll let you know when time's up."
    
    def _handle_music(self, text):
        return "Playing your favorite playlist now 🎵"
    
    def _handle_calendar(self, text):
        return "You have 2 meetings today: a team standup at 10 AM and a review at 3 PM."
    
    def _handle_lights(self, text):
        return "Adjusting the lights for you."
    
    def _handle_unknown(self, text):
        return "I don't know how to help with that yet."

# Usage
agent = SmartHomeAgent(calibrated_pipeline)

interactions = [
    "What's the weather like?",
    "Set a timer for 10 minutes",
    "Play something relaxing",
    "Do I have meetings today?",
    "Make the lights dimmer"
]

for user_msg in interactions:
    result = agent.process(user_msg)
    print(f"User: {user_msg}")
    print(f"Agent ({result['intent']}, {result['confidence']:.2f}): {result['response']}\n")

Common Pitfalls and How to Avoid Them

When building intent classifiers, watch out for these common issues:

  1. Overlapping intents: "Set a reminder for my meeting" could be set_timer or check_calendar. Use more training examples at the boundaries and consider multi-label classification.
  2. Class imbalance: If you have 100 weather examples but only 10 for lights, the classifier will be biased. Use class weights or oversample minority classes.
  3. Out-of-scope inputs: Users will say things you never anticipated. Always include an unknown intent and set a confidence threshold.
  4. Stale training data: Language evolves and users find new phrasings. Regularly review misclassified examples and retrain.
Important: Never deploy an intent classifier without a fallback strategy. When the agent is confused, it should gracefully ask for clarification rather than silently failing or guessing wrong.
Exercise: Build Your Own Intent Classifier

You're building an agent for a restaurant. Create an intent classifier that recognizes at least 4 intents from user messages:

  • make_reservation — "Book a table for two at 7 PM"
  • check_menu — "What specials do you have today?"
  • order_takeout — "I'd like to place a pickup order"
  • ask_hours — "What time do you close?"

Write the training data (at least 5 examples per intent), build a scikit-learn pipeline, and test it with at least 3 new user messages. Add confidence scoring and a fallback for unknown intents.

Key Takeaways

  • Intent classification maps user text to a predefined goal, enabling AI agents to understand what users actually want.
  • Multiple approaches exist — from simple keyword matching to LLM-based classification. Choose based on your accuracy needs, latency budget, and how often your intents change.
  • Always use confidence thresholds to prevent the agent from confidently misclassifying ambiguous or out-of-scope inputs.
  • Training data quality matters more than quantity. Diverse phrasings per intent, clear boundaries between intents, and balanced classes lead to the best results.
  • LLM-based classification offers flexibility and zero-shot capability, while traditional ML models offer speed and lower cost. Many production systems use both.
  • Integrate classification into your agent loop as the routing layer that decides which tool, API, or response strategy to invoke.
  • Plan for failure. A good agent gracefully handles unknown intents by asking for clarification rather than guessing.
