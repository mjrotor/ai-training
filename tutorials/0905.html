Streaming + Tool Calls

Learn about streaming + tool calls.

What Is Streaming?

Imagine you're texting a friend, and instead of waiting for them to finish their entire paragraph before you see any words, you see each word appear as they type. That's streaming — delivering content piece by piece, in real time, rather than all at once.

In the world of AI agents, streaming means the model sends back its response token by token (little pieces of text), so the user sees the answer building up on screen almost instantly. This makes your agent feel fast, responsive, and alive.

Why Streaming Matters for Agents

Without streaming, the user stares at a blank screen while the AI thinks. With streaming, they watch the answer unfold. For agents that use tools (like searching the web or calling an API), streaming becomes even more important — you can show the agent's "thought process" as it happens.

Key idea: Streaming doesn't make the AI faster — it makes the experience feel faster because users see progress immediately.

What Are Tool Calls?

By now, your agents can chat. But real agents need to act — look up information, run calculations, send emails, query databases. Tool calls (also called function calling) let your agent decide to use a Python function mid-conversation.

Here's the flow:

  1. The user asks a question that requires external action (e.g., "What's the weather in Tokyo?").
  2. The AI decides which tool to call and with what arguments.
  3. Your code runs that tool and gets a result.
  4. The result is sent back to the AI, which uses it to craft a final answer.

Defining Tools for Your Agent

In practice, you describe each tool to the AI using a schema — a structured description of what the tool does, what inputs it needs, and what it returns. The AI reads these descriptions and picks the right tool when needed.

import json
from owl import Agent, tool

# Define a tool using the @tool decorator
@tool
def get_weather(city: str) -> str:
    """Get the current weather for a given city.
    
    Args:
        city: The name of the city to check weather for.
    """
    # In a real app, this would call a weather API
    weather_data = {
        "Tokyo": "Sunny, 22°C",
        "London": "Cloudy, 15°C",
        "New York": "Rainy, 18°C"
    }
    return weather_data.get(city, f"Weather data for {city} not available.")

# Define a calculator tool
@tool
def calculate(expression: str) -> str:
    """Evaluate a simple math expression.
    
    Args:
        expression: A math expression like '2 + 3 * 4'.
    """
    try:
        result = eval(expression)
        return str(result)
    except Exception as e:
        return f"Error: {e}"

# Create an agent with tools
agent = Agent(
    name="HelperBot",
    model="owl-3",
    tools=[get_weather, calculate],
    system_prompt="You are a helpful assistant with access to weather and math tools."
)

print("Agent is ready with tools!")
Tip: Write your tool descriptions clearly and specifically. The AI uses these descriptions to decide when and how to use each tool. A vague description leads to poor tool selection.

Combining Streaming + Tool Calls

This is where things get exciting. When you combine streaming with tool calls, you can build agents that:

  • Think out loud: Show the user what the agent is doing at each step.
  • Act in real time: Call tools, show the results, and continue the conversation seamlessly.
  • Feel conversational: No long pauses — the agent streams its reasoning and actions as they happen.

How the Combined Flow Works

Let's trace through what happens when a user asks "What's the weather in Tokyo, and what's 15% of 200?"

  1. User sends message: "What's the weather in Tokyo, and what's 15% of 200?"
  2. AI processes: Decides it needs to call two tools.
  3. Tool call 1: get_weather("Tokyo") → returns "Sunny, 22°C"
  4. Tool call 2: calculate("200 * 0.15") → returns "30.0"
  5. AI streams final response: "It's Sunny and 22°C in Tokyo! And 15% of 200 is 30."
import asyncio
from owl import Agent, tool, StreamEvent

@tool
def get_weather(city: str) -> str:
    """Get the current weather for a given city."""
    weather_data = {
        "Tokyo": "Sunny, 22°C",
        "London": "Cloudy, 15°C",
    }
    return weather_data.get(city, f"No data for {city}.")

@tool
def calculate(expression: str) -> str:
    """Evaluate a math expression."""
    return str(eval(expression))

agent = Agent(
    name="SmartBot",
    model="owl-3",
    tools=[get_weather, calculate],
)

async def run_agent_with_streaming():
    """Run the agent and stream all events."""
    
    messages = [
        {"role": "user", "content": "What's the weather in Tokyo and what's 15% of 200?"}
    ]
    
    async for event in agent.stream(messages):
        if event.type == StreamEvent.THINKING:
            # Agent is deciding what to do
            print(f"🤔 Agent thinking: {event.content}")
        
        elif event.type == StreamEvent.TOOL_CALL:
            # Agent is calling a tool
            print(f"🔧 Calling tool: {event.tool_name}({event.arguments})")
        
        elif event.type == StreamEvent.TOOL_RESULT:
            # Tool returned a result
            print(f"✅ Tool result: {event.result}")
        
        elif event.type == StreamEvent.RESPONSE:
            # Final streaming response
            print(event.chunk, end="", flush=True)
    
    print()  # newline at the end

# Run it
asyncio.run(run_agent_with_streaming())

# Expected output (approximately):
# 🤔 Agent thinking: I need to check the weather and do a calculation.
# 🔧 Calling tool: get_weather({"city": "Tokyo"})
# ✅ Tool result: Sunny, 22°C
# 🔧 Calling tool: calculate({"expression": "200 * 0.15"})
# ✅ Tool result: 30.0
# It's Sunny and 22°C in Tokyo! And 15% of 200 is 30.

Understanding Stream Events

When streaming with tool calls, your agent emits different types of events. Here's what each one means:

Event Type When It Fires What You Get Use Case
THINKING Agent is reasoning Internal thought text Show "thinking..." indicators
TOOL_CALL Agent invokes a tool Tool name + arguments Show "calling weather API..."
TOOL_RESULT Tool returns data Result value Display fetched data to user
RESPONSE Final answer chunks Text tokens Render streaming response
Watch out: Not all models support tool calling equally well. Always test your tools with the specific model you're using. If a model doesn't support native tool calling, you can use prompt-based workarounds (we'll cover this in Phase 2).

Building a Simple Streaming Chat Interface

Let's put it all together. Here's a complete example of a streaming agent with tool calls that you could integrate into a web app:

import asyncio
from owl import Agent, tool, StreamEvent

# --- Define Tools ---

@tool
def search_web(query: str) -> str:
    """Search the web for information.
    
    Args:
        query: The search query string.
    """
    # Simulated search results
    results = {
        "python latest version": "Python 3.12 was released in October 2023.",
        "owl ai framework": "OWL is a powerful framework for building AI agents.",
    }
    return results.get(query.lower(), f"No results found for '{query}'.")

@tool
def get_time(timezone: str) -> str:
    """Get the current time in a timezone.
    
    Args:
        timezone: Timezone name like 'UTC', 'EST', 'JST'.
    """
    from datetime import datetime
    times = {
        "UTC": "14:30 UTC",
        "EST": "09:30 EST",
        "JST": "23:30 JST",
    }
    return times.get(timezone.upper(), f"Unknown timezone: {timezone}")

# --- Create Agent ---

agent = Agent(
    name="ResearchBot",
    model="owl-3",
    tools=[search_web, get_time],
    system_prompt="""You are ResearchBot. You can search the web and check the time.
    Always use your tools when the user asks for factual information or current time.
    Be concise and friendly."""
)

# --- Streaming Chat Loop ---

async def chat():
    """Interactive streaming chat with tool call visibility."""
    messages = []
    
    print("🤖 ResearchBot is ready! Type 'quit' to exit.\n")
    
    while True:
        user_input = input("You: ").strip()
        
        if user_input.lower() == "quit":
            print("Goodbye! 👋")
            break
        
        messages.append({"role": "user", "content": user_input})
        
        print("\nBot: ", end="", flush=True)
        response_parts = []
        
        async for event in agent.stream(messages):
            if event.type == StreamEvent.TOOL_CALL:
                print(f"\n  🔧 [{event.tool_name}]", end="")
            
            elif event.type == StreamEvent.TOOL_RESULT:
                print(f" → {event.result}", end="")
            
            elif event.type == StreamEvent.RESPONSE:
                print(event.chunk, end="", flush=True)
                response_parts.append(event.chunk)
        
        print("\n")
        
        # Save the full response to message history
        full_response = "".join(response_parts)
        messages.append({"role": "assistant", "content": full_response})

# Run the chat
asyncio.run(chat())

Handling Errors Gracefully

Tools don't always work. APIs go down, inputs are invalid, things break. Your agent needs to handle this gracefully.

@tool
def get_weather(city: str) -> str:
    """Get the current weather for a given city."""
    if not city or not isinstance(city, str):
        return "Error: Please provide a valid city name."
    
    try:
        # Simulated API call that might fail
        weather_data = {
            "Tokyo": "Sunny, 22°C",
            "London": "Cloudy, 15°C",
        }
        result = weather_data.get(city)
        if result is None:
            return f"Sorry, I don't have weather data for '{city}'. Try Tokyo or London!"
        return result
    except Exception as e:
        return f"Error fetching weather: {str(e)}"

# The agent will see the error message and can respond naturally:
# "Sorry, I couldn't find weather for that city. Would you like to try another?"
Important: Always return a string from your tools — even on error. Never raise exceptions inside tool functions. The AI needs a string result to continue the conversation.
Exercise: Build a Note-Taking Agent

Create an agent with a save_note tool and a list_notes tool. The agent should be able to:

  1. Save a note with a title and content using save_note(title, content).
  2. List all saved notes using list_notes().
  3. Stream its response so the user sees the agent's actions in real time.

Use a simple Python list to store notes in memory. Make sure your tool descriptions are clear enough that the AI knows when to use each tool.

import asyncio
from owl import Agent, tool, StreamEvent

# In-memory storage
notes = []

@tool
def save_note(title: str, content: str) -> str:
    """Save a note with a title and content.
    
    Args:
        title: The title of the note.
        content: The body/content of the note.
    """
    note = {"title": title, "content": content}
    notes.append(note)
    return f"Note '{title}' saved successfully!"

@tool
def list_notes() -> str:
    """List all saved notes. Returns titles and content of all notes."""
    if not notes:
        return "No notes saved yet."
    
    result = []
    for i, note in enumerate(notes, 1):
        result.append(f"{i}. {note['title']}: {note['content']}")
    return "\n".join(result)

# Create the agent
agent = Agent(
    name="NoteBot",
    model="owl-3",
    tools=[save_note, list_notes],
    system_prompt="""You are NoteBot, a helpful note-taking assistant.
    Use save_note when the user wants to save information.
    Use list_notes when the user wants to see their notes.
    Always confirm actions with a friendly message."""
)

async def chat():
    messages = []
    print("📝 NoteBot ready! Type 'quit' to exit.\n")
    
    while True:
        user_input = input("You: ").strip()
        if user_input.lower() == "quit":
            break
        
        messages.append({"role": "user", "content": user_input})
        print("\nBot: ", end="", flush=True)
        
        response_parts = []
        async for event in agent.stream(messages):
            if event.type == StreamEvent.TOOL_CALL:
                print(f"\n  🔧 [{event.tool_name}]", end="")
            elif event.type == StreamEvent.TOOL_RESULT:
                print(f" → {event.result}", end="")
            elif event.type == StreamEvent.RESPONSE:
                print(event.chunk, end="", flush=True)
                response_parts.append(event.chunk)
        
        print("\n")
        messages.append({"role": "assistant", "content": "".join(response_parts)})

asyncio.run(chat())

Key Takeaways

  • Streaming delivers AI responses token by token, making your agent feel fast and responsive.
  • Tool calls let your agent take actions — query APIs, run calculations, save data — by invoking Python functions.
  • Combining streaming with tool calls lets you build agents that show their work in real time, creating a transparent and engaging user experience.
  • Use stream events (THINKING, TOOL_CALL, TOOL_RESULT, RESPONSE) to render different parts of the agent's process in your UI.
  • Always return strings from your tools, even on errors — the AI needs text to continue the conversation.
  • Write clear, specific tool descriptions so the AI knows exactly when and how to use each tool.
  • Test your tools thoroughly — the quality of your agent depends on the quality of its tools.
