Building a Multi-Agent Chat

Learn about building a multi-agent chat.

What Is a Multi-Agent System?

So far, you've built chatbots that use a single AI agent to handle user queries. But what happens when a task is too complex for one agent to handle alone? That's where multi-agent systems come in. A multi-agent system is a setup where multiple AI agents work together — each with a specialized role — to solve problems collaboratively. Think of it like a team of experts, each contributing their unique skill set.

In this lesson, you'll build a multi-agent chat system where a Router Agent decides which specialized agent should handle a given query, and then delegates the conversation accordingly.

Architecture Overview

Before writing code, let's understand the architecture of our multi-agent chat system. We'll have three main components:

  • Router Agent — Analyzes the user's message and decides which specialized agent should respond.
  • Specialized Agents — Each agent is an expert in a specific domain (e.g., math, general knowledge, creative writing).
  • Orchestrator — Manages the flow of messages between the router and the agents.
Why use multiple agents? Specialized agents produce higher-quality responses than a single general-purpose agent. By routing queries to the right expert, you get better answers across a wider range of topics.

Setting Up the Environment

First, make sure you have the required packages installed. You'll need an LLM API (we'll use OpenAI in this example) and the openai Python library:

pip install openai

Set your API key as an environment variable:

import os
os.environ["OPENAI_API_KEY"] = "your-api-key-here"

Defining Agent Roles

Each agent in our system has a system prompt that defines its personality and area of expertise. Let's define three specialized agents:

AGENT_PROMPTS = {
    "math_expert": """You are a math expert. You solve mathematical problems 
    step by step. Always show your work and explain your reasoning clearly.""",
    
    "creative_writer": """You are a creative writer. You help with storytelling, 
    poetry, and imaginative content. Be vivid and engaging in your responses.""",
    
    "general_assistant": """You are a helpful general assistant. You answer 
    questions on a wide range of topics in a friendly, concise manner."""
}

Building the Router Agent

The router agent is the brain of our multi-agent system. It reads the user's message and decides which specialized agent is best suited to respond. Here's how we implement it:

def router_agent(user_message):
    """Analyze the user message and route to the correct agent."""
    routing_prompt = f"""Given the following user message, decide which agent 
    should respond. Choose exactly one: 'math_expert', 'creative_writer', or 
    'general_assistant'.
    
    User message: {user_message}
    
    Respond with ONLY the agent name, nothing else."""
    
    response = openai.chat.completions.create(
        model="gpt-4",
        messages=[
            {"role": "system", "content": "You are a routing assistant."},
            {"role": "user", "content": routing_prompt}
        ],
        temperature=0
    )
    
    return response.choices[0].message.content.strip()
Pro tip: Setting temperature=0 for the router ensures consistent, deterministic routing decisions. You want the router to be predictable, not creative.

Building the Orchestrator

The orchestrator ties everything together. It takes a user message, routes it to the correct agent, and returns the response:

def orchestrator(user_message):
    """Main loop: route the message and get a response from the right agent."""
    
    # Step 1: Route the message
    agent_name = router_agent(user_message)
    print(f"[Router] Routing to: {agent_name}")
    
    # Step 2: Get the system prompt for the chosen agent
    system_prompt = AGENT_PROMPTS.get(agent_name, AGENT_PROMPTS["general_assistant"])
    
    # Step 3: Get the response from the specialized agent
    response = openai.chat.completions.create(
        model="gpt-4",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_message}
        ],
        temperature=0.7
    )
    
    return {
        "agent": agent_name,
        "response": response.choices[0].message.content
    }

Running a Multi-Agent Chat Session

Now let's put it all together in an interactive chat loop:

def run_multi_agent_chat():
    """Run an interactive multi-agent chat session."""
    print("=== Multi-Agent Chat System ===")
    print("Type 'quit' to exit.\n")
    
    while True:
        user_input = input("You: ")
        
        if user_input.lower() in ['quit', 'exit', 'q']:
            print("Goodbye!")
            break
        
        result = orchestrator(user_input)
        print(f"\n[{result['agent']}]: {result['response']}\n")

# Start the chat
run_multi_agent_chat()

Comparing Single-Agent vs. Multi-Agent Approaches

Let's look at how the two approaches compare across key dimensions:

Aspect Single Agent Multi-Agent System
Response Quality Good for general queries Higher quality in specialized domains
Complexity Low — one model call Higher — routing + agent calls
Cost Lower token usage Higher due to multiple LLM calls
Scalability Hard to specialize Easy to add new specialized agents
Latency Fast — single call Slower — sequential model calls
Watch out for routing loops! If the router agent is uncertain, it might misroute messages. Always include a fallback agent (like general_assistant) and consider adding a confidence threshold.

Adding Memory to Agents

For a more natural conversation, each agent should remember the context of the conversation. Let's add a simple conversation history:

def orchestrator_with_memory(user_message, conversation_history):
    """Orchestrator that maintains conversation context."""
    
    agent_name = router_agent(user_message)
    system_prompt = AGENT_PROMPTS.get(agent_name, AGENT_PROMPTS["general_assistant"])
    
    # Build the full message list with history
    messages = [{"role": "system", "content": system_prompt}]
    messages.extend(conversation_history)
    messages.append({"role": "user", "content": user_message})
    
    response = openai.chat.completions.create(
        model="gpt-4",
        messages=messages,
        temperature=0.7
    )
    
    reply = response.choices[0].message.content
    
    # Update conversation history
    conversation_history.append({"role": "user", "content": user_message})
    conversation_history.append({"role": "assistant", "content": reply})
    
    return {"agent": agent_name, "response": reply}

Handling Edge Cases

When building multi-agent systems, you need to handle several edge cases gracefully:

  1. Routing failures — The router might return an invalid agent name. Always validate the output.
  2. API errors — Network issues or rate limits can break your flow. Implement retry logic.
  3. Long conversations — Context windows are finite. Summarize or truncate old messages.
  4. Ambiguous queries — Some queries span multiple domains. Consider a "handoff" mechanism.
def safe_router(user_message):
    """Router with validation and fallback."""
    try:
        agent_name = router_agent(user_message)
        valid_agents = ["math_expert", "creative_writer", "general_assistant"]
        
        if agent_name not in valid_agents:
            print(f"[Warning] Invalid agent '{agent_name}', falling back to general_assistant")
            return "general_assistant"
        
        return agent_name
    except Exception as e:
        print(f"[Error] Routing failed: {e}")
        return "general_assistant"

Key Takeaways

  • Multi-agent systems use specialized agents, each with a defined role, to produce higher-quality responses than a single general-purpose agent.
  • The Router Agent is responsible for analyzing user input and delegating to the most appropriate specialized agent.
  • The Orchestrator manages the flow: routing → agent selection → response generation → output.
  • Setting temperature=0 for the router ensures consistent, predictable routing decisions.
  • Always include a fallback agent and validate router output to handle edge cases gracefully.
  • Adding conversation history to each agent enables more natural, context-aware multi-turn conversations.
  • Multi-agent systems trade higher cost and latency for better response quality and easier scalability.
  • You can extend the system by simply adding new entries to the AGENT_PROMPTS dictionary and updating the router prompt.
