Knowledge Base Integration

Learn about knowledge base integration.

What Is a Knowledge Base?

A knowledge base (KB) is a structured repository of information that an AI agent can query to retrieve accurate, domain-specific facts. Instead of relying solely on what the language model has memorized during training, a knowledge base allows your agent to pull in external data — documents, FAQs, product catalogs, policies, and more — at the moment it needs them. This approach is often called Retrieval-Augmented Generation, or RAG.

Think of it this way: the LLM is like a brilliant generalist, while the knowledge base is the specialist reference library it consults before answering. By combining both, you get responses that are both fluent and factually grounded.

What is R Retrieval-Augmented Generation is a technique where an AI system first searches a knowledge base for relevant documents, then feeds those documents into the language model along with the user's question. This dramatically reduces hallucinations and keeps answers up to date.

Why Integrate a Knowledge Base?

Large language models have a fixed training cutoff and no access to your private data. Here are the key reasons to connect your agent to a knowledge base:

  • Accuracy: Ground the agent's responses in verified, authoritative documents rather than the model's best guess.
  • Freshness: Update the knowledge base when new information is available — no retraining required.
  • Privacy & Specificity: Serve internal company documentation, proprietary processes, or customer-specific data without exposing it publicly.
  • Traceability: Include source citations so users can verify where an answer came from.
  • Cost Efficiency: Retrieving a few relevant snippets is cheaper than stuffing an entire document into the prompt every time.

Core Components of a RAG Pipeline

A typical knowledge base integration follows these stages. Understanding each step will help you design and debug your agent effectively.

1. Document Loading & Chunking

Raw documents come in many formats — PDFs, Markdown, HTML, Word files, and more. Before anything else, you need to load them and break them into smaller, meaningful pieces called chunks. Each chunk should be self-contained enough to make semantic sense on its own.


from langchain.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

# Load a document
loader = TextLoader("company_policy.md")
documents = loader.load()

# Split into overlapping chunks
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    length_function=len,
)

chunks = splitter.split_documents(documents)

print(f"Total chunks created: {len(chunks)}")
print(f"\nSample chunk:\n{chunks[0].page_content}")
Tip on Chunk Size: There is no universal sweet spot. Start with 500–1000 characters with 50–100 characters of overlap. Larger chunks preserve more context but cost more tokens; smaller chunks are cheaper but may lose meaning. Experiment with your specific documents.

2. Embedding Generation

An embedding is a numerical vector representation of text that captures its semantic meaning. Similar texts produce similar vectors. This is what enables semantic search — finding documents that are conceptually related to the user's query, not just keyword matches.


from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Chroma

# Initialize the embedding model
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# Create a vector store from the chunks
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db",
)

print("Vector store created and persisted!")
print(f"Total vectors stored: {vectorstore._collection.count()}")

3. Semantic Search (Retrieval)

When the agent receives a user question, it converts the question into an embedding and searches the vector store for the most similar chunks. This is the retrieval step.


# Perform a similarity search
query = "What is the remote work policy for full-time employees?"
results = vectorstore.similarity_search(query, k=3)

for i, doc in enumerate(results, 1):
    print(f"--- Result {i} ---")
    print(doc.page_content[:200])
    print(f"Source: {doc.metadata.get('source', 'unknown')}\n")

4. Augmented Generation

Finally, the retrieved chunks are injected into the prompt as context, and the language model generates a response using both the user's question and the retrieved information.


from langchain.chat_models import ChatOpenAI
from langchain.chains import RetrievalQA

# Build the retrieval-augmented chain
llm = ChatOpenAI(model="gpt-4", temperature=0)

qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",  # Stuff all retrieved docs into the prompt
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3}),
)

# Ask a question
response = qa_chain.run("What is the remote work policy for full-time employees?")
print(response)
Warning: If your retrieved chunks are too large or too numerous, you may exceed the model's context window. Use techniques like map-reduce or refine chain types to handle large result sets, or reduce the k parameter in your retriever.

Choosing a Vector Store

The vector store is the backbone of your knowledge base. Here is a comparison of popular options:

Vector Store Best For Deployment Scale Notes
Chroma Prototyping & small projects Embedded / Local Small to medium Simple API, great for development
FAISS In-memory Medium to large Facebook's library; fast but no persistence built in
Pinecone Production applications Managed cloud Large Fully managed, serverless, easy scaling
Weaviate Hybrid search (vector + keyword) Self-hosted / Cloud Medium to large Built-in modules for embedding generation
pgvector Existing PostgreSQL users Self-hosted Medium Extends Postgres; no extra infrastructure needed

Example: Using pgvector with Postgres


import psycopg2
from langchain.vectorstores import PGVector
from langchain.embeddings import OpenAIEmbeddings

# Connection string for a local Postgres with pgvector extension
CONNECTION_STRING = "postgresql://user:password@localhost:5432/kb_db"
COLLECTION_NAME = "policy_docs"

embeddings = OpenAIEmbeddings()

# Create or connect to an existing vector store
store = PGVector(
    collection_name=COLLECTION_NAME,
    connection_string=CONNECTION_STRING,
    embedding_function=embeddings,
)

# Add documents
store.add_documents(chunks)

# Search
results = store.similarity_search("remote work policy", k=3)
print(results[0].page_content)

Building a Complete Knowledge-Base Agent

Let's put everything together. Below is a complete, working example of an AI agent that answers questions using a knowledge base built from local Markdown files.


import os
from langchain.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Chroma
from langchain.chat_models import ChatOpenAI
from langchain.chains import RetrievalQA
from langchain.prompts import PromptTemplate

# ---------- Step 1: Load and chunk documents ----------

def load_documents(directory: str):
    """Load all .md files from a directory."""
    documents = []
    for filename in os.listdir(directory):
        if filename.endswith(".md"):
            loader = TextLoader(os.path.join(directory, filename))
            documents.extend(loader.load())
    return documents

raw_docs = load_documents("./knowledge_base")

splitter = RecursiveCharacterTextSplitter(
    chunk_size=800,
    chunk_overlap=80,
)

chunks = splitter.split_documents(raw_docs)
print(f"Loaded {len(raw_docs)} files → {len(chunks)} chunks")

# ---------- Step 2: Create embeddings and vector store ----------

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./agent_chroma_db",
)

# ---------- Step 3: Build the QA agent ----------

custom_prompt = PromptTemplate(
    template=(
        "You are a helpful assistant with access to a company knowledge base.\n"
        "Use the following context to answer the user's question.\n"
        "If you don't know the answer, say 'I could not find relevant information "
        "in the knowledge base.'\n\n"
        "Context:\n{context}\n\n"
        "Question: {question}\n"
        "Answer:"
    ),
    input_variables=["context", "question"],
)

llm = ChatOpenAI(model="gpt-4", temperature=0)

qa_agent = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=vectorstore.as_retriever(search_kwargs={"k": 4}),
    chain_type_kwargs={"prompt": custom_prompt},
)

# ---------- Step 4: Query the agent ----------

questions = [
    "What is the parental leave policy?",
    "How do I request a new laptop?",
    "What are the security guidelines for handling customer data?",
]

for q in questions:
    print(f"\nQ: {q}")
    answer = qa_agent.run(q)
    print(f"A: {answer}")
    print("-" * 60)

Advanced Techniques

Hybrid Search (Vector + Keyword)

Semantic search is powerful, but it can miss exact keyword matches — for example, searching for a specific product code or error number. Hybrid search combines vector similarity with traditional keyword matching (like BM25) for the best of both worlds.


from langchain.retrievers import BM25Retriever, EnsembleRetriever

# Vector retriever
vector_retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# Keyword retriever
bm25_retriever = BM25Retriever.from_documents(chunks)
bm25_retriever.k = 3

# Combine them
ensemble_retriever = EnsembleRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    weights=[0.6, 0.4],  # 60% vector, 40% keyword
)

results = ensemble_retriever.get_relevant_documents("error code E-1042")
for doc in results:
    print(doc.page_content[:150])
    print()

Re-ranking Retrieved Results

For even better accuracy, you can use a re-ranking model that scores each retrieved chunk more carefully after the initial search. This two-stage approach trades a small amount of latency for significantly improved relevance.


# Pseudo-code for a re-ranking pipeline
# (requires a cross-encoder model like 'cross-encoder/ms-marco-MiniLM-L-6-v2')

# Step 1: Retrieve top 20 candidates (broad recall)
candidates = vectorstore.similarity_search(query, k=20)

# Step 2: Re-rank with a cross-encoder (precise scoring)
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-12")

pairs = [(query, doc.page_content) for doc in candidates]
scores = reranker.predict(pairs)

# Sort by score
ranked = sorted(zip(scores, candidates), reverse=True)

# Use top 3 for the final prompt
final_docs = [doc for _, doc in ranked[:3]]

Metadata Filtering

Adding metadata to your chunks lets you filter results by category, date, department, or any other attribute. This is extremely useful in multi-tenant or multi-domain knowledge bases.


# Add metadata during chunk creation
for chunk in chunks:
    chunk.metadata["department"] = "engineering"
    chunk.metadata["doc_type"] = "policy"
    chunk.metadata["last_updated"] = "2025-01-15"

# Later, filter by metadata during retrieval
results = vectorstore.similarity_search(
    query="equipment request",
    filter={"department": "engineering"},
    k=3,
)
Pro Tip: Always store a source field in your metadata. This lets your agent cite where each piece of information came from, building trust with users and making it easy to verify answers.

  2. Chunks the documents with a chunk size of 500 characters and 50 characters of overlap.
  3. Generates embeddings and stores them in a Chroma vector store.
  4. Builds a RetrievalQA chain with a custom prompt that instructs the agent to say "I don't know" when the answer isn't in the knowledge base.
  5. Tests the agent with at least two questions — one that can be answered from the documents and one that cannot.

import os
from langchain.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Chroma
from langchain.chat_models import ChatOpenAI
from langchain.chains import RetrievalQA
from langchain.prompts import PromptTemplate

# --- Load documents ---
docs = []
for f in os.listdir("./my_kb"):
    if f.endswith(".txt"):
        loader = TextLoader(os.path.join("./my_kb", f))
        docs.extend(loader.load())

# --- Chunk ---
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)

# --- Embed & store ---
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(chunks, embeddings, persist_directory="./exercise_db")

# --- Custom prompt ---
prompt = PromptTemplate(
    template=(
        "Answer based ONLY on the provided context. "
        "If the context does not contain the answer, reply: "
        "'I don't know based on the available information.'\n\n"
        "Context: {context}\n\nQuestion: {question}\nAnswer:"
    ),
    input_variables=["context", "question"],
)

# --- Build agent ---
llm = ChatOpenAI(temperature=0)
agent = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3}),
    chain_type_kwargs={"prompt": prompt},
)

# --- Test ---
print(agent.run("What is the refund policy?"))
print(agent.run("What is the meaning of life?"))

Common Pitfalls and How to Avoid Them

  • Chunking too aggressively: Tiny chunks lose context. If your agent gives fragmented answers, increase chunk_size or add more overlap.
  • Retrieving too few or too many results: Start with k=3 to k=5. Too few may miss relevant info; too many introduce noise and inflate costs.
  • Ignoring relevance thresholds: Always check the similarity scores. If all scores are below a certain threshold (e.g., 0.5), fall back to a generic response rather than presenting irrelevant context.
  • Stale knowledge bases: Documents change over time. Set up a re-indexing schedule or trigger updates whenever source files are modified.
  • No source attribution: Users (and auditors) will want to know where answers came from. Always include source metadata in the agent's output.
Important: Never assume the knowledge base contains all relevant information for every query. Always design a graceful fallback — either directing the user to a human agent or clearly stating that the information is not available.

Key Takeaways

  • A knowledge base integration uses Retrieval-Augmented Generation (RAG) to ground AI agent responses in external, verifiable documents.
  • The four core pipeline steps are: document loading & chunking, embedding generation, semantic search, and augmented generation.
  • Vector stores like Chroma, FAISS, Weaviate, and pgvector enable fast similarity search over large document collections.
  • Chunk size and overlap are critical hyperparameters — there is no one-size-fits-all, so experiment with your specific content.
  • Hybrid search (vector + keyword) and re-ranking can significantly improve retrieval quality.
  • Metadata filtering lets you scope searches by department, document type, date, or any custom attribute.
  • Always include source attribution and a graceful fallback when the knowledge base doesn't contain the answer.
  • Keep your knowledge base fresh by re-indexing when source documents change.
