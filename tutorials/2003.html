LLM-as-Judge

Learn about llm-as-judge.

What Is an LLM-as-Judge?

As AI systems grow more sophisticated, evaluating their output becomes harder. You can't always rely on simple metrics like accuracy or BLEU scores — especially for open-ended tasks like creative writing, summarization, or reasoning. This is where the LLM-as-Judge pattern comes in.

The idea is simple yet powerful: use a large language model itself to evaluate and score the outputs of other models (or even its own outputs). Instead of writing complex rule-based evaluation pipelines, you leverage the LLM's natural language understanding to make nuanced judgments.

Key Concept: LLM-as-Judge is an agentic evaluation pattern where one LLM (the "judge") is prompted to assess the quality, correctness, or relevance of outputs produced by another model or pipeline.

Why Use an LLM Judge?

Traditional evaluation methods have real limitations. Here's why the LLM-as-Judge approach has become so popular:

  • Scalability: You can evaluate thousands of outputs without manually writing rules for each case.
  • Nuanced understanding: LLMs can judge tone, coherence, factual accuracy, and style — things regex and keyword matching can't catch.
  • Cost efficiency: Cheaper than hiring human annotators for every evaluation cycle.
  • Consistency: When properly configured, the judge applies the same criteria across all evaluations (unlike humans who may drift).
  • Flexibility: Swap in different rubrics or criteria by simply changing the prompt.
Watch out: LLM judges can exhibit biases — favoring longer responses, preferring their own style, or showing position bias. We'll cover how to mitigate these later.

Core Architecture

At its heart, an LLM-as-Judge system has three components:

  1. The Subject Model — the AI system whose output you want to evaluate.
  2. The Judge Prompt — a carefully crafted prompt that defines evaluation criteria.
  3. The Judge LLM — the model that reads the output and produces a score or verdict.
from openai import OpenAI

client = OpenAI()

def llm_as_judge(subject_output: str, original_input: str, rubric: str) -> str:
    """Use an LLM to judge the quality of a subject model's output."""
    
    judge_prompt = f"""You are an expert evaluator. Your task is to assess
the quality of an AI-generated response based on the provided rubric.

## Original Input
{original_input}

## AI-Generated Response
{subject_output}

## Evaluation Rubric
{rubric}

## Instructions
Score the response on a scale of 1-5 for each criterion in the rubric.
Provide a brief justification for each score.
End with an overall score as: OVERALL: """

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "You are a fair, thorough evaluator."},
            {"role": "user", "content": judge_prompt}
        ],
        temperature=0.1  # Low temperature for consistency
    )
    
    return response.choices[0].message.content

# Example usage
rubric = """- Accuracy: Is the information factually correct?
- Completeness: Does it address all parts of the question?
- Clarity: Is the response easy to understand?"""

result = llm_as_judge(
    subject_output="Photosynthesis converts sunlight into energy, occurring in chloroplasts.",
    original_input="Explain how photosynthesis works.",
    rubric=rubric
)
print(result)

Types of LLM Judges

There are several distinct patterns for using LLMs as judges. Choosing the right one depends on your use case.

1. Single Rating Judge

The simplest form. The judge reads the output and assigns a single score based on overall quality.

single_rating_prompt = """Rate the following response on a scale of 1 to 5,
where 1 is very poor and 5 is excellent.

Question: {question}
Response: {response}

Reply with ONLY a number (1-5)."""

2. Multi-Criteria Judge

The judge evaluates multiple dimensions independently. This gives you granular feedback.

multi_criteria_prompt = """Evaluate this response on the following criteria.
For each, give a score from 1-5 and a one-sentence explanation.

Criteria:
1. Factual Accuracy
2. Relevance to the Question
3. Depth of Explanation
4. Language Quality

Question: {question}
Response: {response}

Format your response as JSON:
{{"criteria": [{{"name": "...", "score": ..., "reason": "..."}}], "overall": ...}}"""

3. Pairwise Comparison Judge

Present two responses side by side and ask the judge to pick the winner. This is how Chatbot Arena rankings work.

pairwise_prompt = """You will see two responses to the same question.
Choose the better response.

Question: {question}

Response A: {response_a}

Response B: {response_b}

Which response is better? Reply with ONLY "A" or "B" and a brief reason."""

4. Reference-Based Judge

The judge compares the output against a known correct answer or gold standard.

Tip: Pairwise comparisons tend to be more reliable than absolute ratings because LLMs are generally better at relative judgments than assigning absolute scores.

Judge Comparison Table

Judge Type Best For Reliability Complexity
Single Rating Quick quality checks Medium Low
Multi-Criteria Detailed feedback High Medium
Pairwise Model comparison / ranking Very High Medium
Reference-Based Factual accuracy tasks High Low

Building a Robust Judge Agent

A naive judge prompt is a start, but production-grade LLM judges need careful engineering. Let's build one step by step.

Step 1: Define a Clear Rubric

The rubric is the most important part. Vague rubrics produce inconsistent results.

RUBRIC = """
Evaluate the AI assistant's response on these dimensions:

1. **Factual Accuracy** (1-5)
   - 5: All claims are verifiable and correct
   - 3: Mostly correct with minor inaccuracies
   - 1: Contains significant factual errors

2. **Helpfulness** (1-5)
   - 5: Fully addresses the user's need with actionable information
   - 3: Partially helpful but missing key details
   - 1: Does not address the user's question

3. **Safety** (1-5)
   - 5: No harmful, biased, or inappropriate content
   - 3: Minor concerns but nothing dangerous
   - 1: Contains harmful or dangerous content

4. **Conciseness** (1-5)
   - 5: Efficient and to the point
   - 3: Slightly verbose or terse
   - 1: Extremely wordy or too brief to be useful
"""

Step 2: Build the Judge Class

import json
from openai import OpenAI
from dataclasses import dataclass

client = OpenAI()

@dataclass
class JudgeResult:
    scores: dict
    overall_score: float
    reasoning: str
    confidence: str  # "high", "medium", "low"

class LLMAgentJudge:
    def __init__(self, model: str = "gpt-4o", temperature: float = 0.1):
        self.model = model
        self.temperature = temperature
        self.rubric = self._default_rubric()
    
    def _default_rubric(self) -> str:
        return """
        Evaluate on these criteria (1-5 each):
        - Accuracy: Is the information correct?
        - Helpfulness: Does it solve the user's problem?
        - Safety: Is it free from harmful content?
        - Clarity: Is it well-structured and easy to follow?
        """
    
    def evaluate(self, question: str, response: str) -> JudgeResult:
        prompt = f"""You are an impartial AI evaluator.

Question: {question}
Response: {response}

Rubric: {self.rubric}

Score each criterion 1-5. Provide brief reasoning.
Output valid JSON:
{{"scores": {{"accuracy": n, "helpfulness": n, "safety": n, "clarity": n}},
"overall": n, "reasoning": "...", "confidence": "high/medium/low"}}"""

        result = client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": "You are a precise, unbiased evaluator. Always output valid JSON."},
                {"role": "user", "content": prompt}
            ],
            temperature=self.temperature,
            response_format={"type": "json_object"}
        )
        
        parsed = json.loads(result.choices[0].message.content)
        
        return JudgeResult(
            scores=parsed["scores"],
            overall_score=parsed["overall"],
            reasoning=parsed["reasoning"],
            confidence=parsed["confidence"]
        )

# Usage
judge = LLMAgentJudge()
result = judge.evaluate(
    question="What is the capital of France and why is it important?",
    response="Paris is the capital of France. It's important as a major European cultural and economic center."
)

print(f"Overall Score: {result.overall_score}/5")
print(f"Confidence: {result.confidence}")
for criterion, score in result.scores.items():
    print(f"  {criterion}: {score}/5")

Step 3: Mitigate Bias

LLM judges are not perfect. Here are common biases and how to address them:

  • Position Bias: The judge prefers whichever response it sees first. Fix: Randomize the order of responses in pairwise comparisons.
  • Verbosity Bias: Longer responses get higher scores. Fix: Add a conciseness criterion to your rubric.
  • Self-Enhancement Bias: Models prefer outputs similar to their own style. Fix: Use a different model as the judge than the one being evaluated.
  • Halo Effect: One strong aspect inflates all scores. Fix: Use multi-criteria scoring with independent evaluations.
Important: Always run your judge multiple times and average the results. A single evaluation can be noisy. For critical applications, use at least 3 runs with majority voting. 
def evaluate_with_confidence(judge: LLMAgentJudge, question: str, 
                                response: str, runs: int = 3) -> dict:
    """Run the judge multiple times and aggregate results."""
    all_scores = []
    
    for i in range(runs):
        result = judge.evaluate(question, response)
        all_scores.append(result.overall_score)
    
    avg_score = sum(all_scores) / len(all_scores)
    
    # Check agreement — high variance means low confidence
    variance = sum((s - avg_score) ** 2 for s in all_scores) / len(all_scores)
    agreement = "high" if variance < 0.5 else "medium" if variance < 1.5 else "low"
    
    return {
        "average_score": round(avg_score, 2),
        "individual_scores": all_scores,
        "variance": round(variance, 2),
        "agreement": agreement
    }

# Example
result = evaluate_with_confidence(judge, 
    "Explain quantum entanglement", 
    "Quantum entanglement is when particles become correlated so that measuring one instantly affects the other.",
    runs=3
)
print(f"Average: {result['average_score']}, Agreement: {result['agreement']}")

Using LLM Judges in Agent Workflows

LLM-as-Judge shines when integrated into agentic pipelines. Here are three powerful patterns:

Pattern 1: Self-Refinement Loop

The agent evaluates its own output and iterates until it meets a quality threshold.

def self_refine(agent_response: str, question: str, 
                 judge: LLMAgentJudge, max_iterations: int = 3) -> str:
    """Agent refines its output based on judge feedback."""
    current_response = agent_response
    
    for iteration in range(max_iterations):
        result = judge.evaluate(question, current_response)
        
        if result.overall_score >= 4.0:
            print(f"✓ Passed evaluation on iteration {iteration + 1}")
            break
        
        # Ask the agent to improve based on judge feedback
        improvement_prompt = f"""Your previous response scored {result.overall_score}/5.
Judge feedback: {result.reasoning}

Improve your response to address the weaknesses.
Question: {question}
Previous response: {current_response}"""
        
        improved = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": improvement_prompt}]
        )
        current_response = improved.choices[0].message.content
    
    return current_response

Pattern 2: Multi-Agent Debate

Multiple agents generate responses, and the judge picks the best one.

Pattern 3: Quality Gate

The judge acts as a filter — only outputs above a threshold proceed to the next step in the pipeline.

Pro Tip: Combine LLM judges with traditional metrics. Use keyword matching or embedding similarity as a fast first pass, then apply the LLM judge only for borderline cases. This saves cost and latency.

Coding Exercise

Exercise: Build a Pairwise Comparison Judge

Write a function pairwise_judge that takes a question and two responses, uses an LLM to determine which is better, and returns the winner along with reasoning.

Requirements:

  • Accept a question, response_a, and response_b
  • Randomize the order (sometimes A first, sometimes B first) to reduce position bias
  • Return a dict with keys: winner ("A" or "B"), reasoning, and order (which order was presented)
  • Use response_format={"type": "json_object"} for reliable parsing

Bonus: Run the comparison twice with different orderings and check if the judge is consistent.

import random
import json
from openai import OpenAI

client = OpenAI()

def pairwise_judge(question: str, response_a: str, response_b: str) -> dict:
    """Compare two responses and return the winner, with bias mitigation."""
    
    # Randomize order to reduce position bias
    if random.random() > 0.5:
        first, second = response_a, response_b
        order = "AB"
    else:
        first, second = response_b, response_a
        order = "BA"
    
    prompt = f"""Compare these two responses to the same question.

Question: {question}

First Response:
{first}

Second Response:
{second}

Which response is better? Consider accuracy, helpfulness, and clarity.
Output JSON: {{"winner": "first" or "second", "reasoning": "..."}}"""

    result = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "You are an impartial evaluator."},
            {"role": "user", "content": prompt}
        ],
        temperature=0.1,
        response_format={"type": "json_object"}
    )
    
    parsed = json.loads(result.choices[0].message.content)
    
    # Map back to original labels
    if order == "AB":
        winner = "A" if parsed["winner"] == "first" else "B"
    else:
        winner = "B" if parsed["winner"] == "first" else "A"
    
    return {
        "winner": winner,
        "reasoning": parsed["reasoning"],
        "order": order
    }

# Bonus: Consistency check
def check_consistency(question: str, response_a: str, response_b: str, runs: int = 2):
    winners = []
    for _ in range(runs):
        result = pairwise_judge(question, response_a, response_b)
        winners.append(result["winner"])
    
    consistent = len(set(winners)) == 1
    return {"winners": winners, "consistent": consistent}

# Example
result = pairwise_judge(
    "What is machine learning?",
    "Machine learning is a subset of AI that uses algorithms to learn from data.",
    "Machine learning is when computers learn patterns from data to make predictions without being explicitly programmed."
)
print(f"Winner: {result['winner']}")
print(f"Reasoning: {result['reasoning']}")
print(f"Presentation order: {result['order']}")

Key Takeaways

  • LLM-as-Judge uses a language model to evaluate outputs, replacing or supplementing traditional metrics with nuanced, scalable assessment.
  • There are four main judge patterns: single rating, multi-criteria, pairwise comparison, and reference-based — each suited to different use cases.
  • A well-designed rubric is the foundation of reliable evaluation. Vague criteria lead to inconsistent scores.
  • Common biases include position bias, verbosity bias, and self-enhancement bias — all of which can be mitigated through careful design.
  • Running the judge multiple times and aggregating results significantly improves reliability.
  • LLM judges integrate naturally into agent workflows as self-refinement loops, multi-agent selectors, and quality gates.
  • For production systems, combine LLM judges with traditional metrics — use fast heuristics as a first pass and reserve LLM evaluation for nuanced or borderline cases.
