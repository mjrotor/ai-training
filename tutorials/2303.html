Tasks & Workflows

Learn about tasks & workflows.

What Are Tasks and Workflows?

So far, you've learned how to build a single AI agent that can use tools and respond to user input. But real-world applications rarely involve just one agent doing one thing. In practice, you'll need to orchestrate multiple agents working together, each handling a specific part of a larger job. This is where tasks and workflows come in.

A task is a discrete unit of work assigned to an agent. Think of it like a job description: "Research the latest news on AI regulation and write a 200-word summary." A workflow is the bigger picture — it's the sequence of tasks, the order they run in, and how they hand off results to one another.

Key Idea: A task is what an agent does. A workflow is how multiple tasks are organized and connected together.

Breaking Down a Task

Every task in a multi-agent system typically has a few core components. Let's look at what makes up a well-defined task:

  • Goal — A clear description of what the task should accomplish.
  • Agent — The specific agent responsible for completing the task.
  • Expected Output — What the task should produce (a summary, a file, a decision, etc.).
  • Context / Dependencies — Any information the task needs, including outputs from previous tasks.

Here's a simple Python class that represents a task:

class Task:
    def __init__(self, name, description, agent, expected_output, dependencies=None):
        self.name = name
        self.description = description
        self.agent = agent
        self.expected_output = expected_output
        self.dependencies = dependencies or []
        self.status = "pending"
        self.result = None

    def execute(self, context=None):
        """Run the task using the assigned agent."""
        print(f"Executing task: {self.name}")
        self.status = "in_progress"
        # The agent processes the task
        self.result = self.agent.run(self.description, context=context)
        self.status = "completed"
        return self.result

    def __repr__(self):
        return f"Task(name='{self.name}', status='{self.status}')"

Building a Sequential Workflow

The simplest kind of workflow is a sequential workflow, where tasks run one after another. The output of Task A becomes the input for Task B, and so on. This is like an assembly line in a factory.

Imagine you want to build a content pipeline that:

  1. Researches a topic and gathers key facts.
  2. Writes a blog post based on those facts.
  3. Proofreads and polishes the blog post.

Here's how you might implement this in Python:

class SequentialWorkflow:
    def __init__(self, name):
        self.name = name
        self.tasks = []

    def add_task(self, task):
        """Add a task to the end of the workflow."""
        self.tasks.append(task)
        return self  # allows chaining: workflow.add_task(t1).add_task(t2)

    def run(self):
        """Execute all tasks in order, passing results forward."""
        print(f"\n=== Starting Workflow: {self.name} ===\n")
        context = {}

        for i, task in enumerate(self.tasks):
            print(f"\n--- Step {i+1} ---")
            # Pass previous results as context
            result = task.execute(context=context)
            # Store result for downstream tasks
            context[task.name] = result
            print(f"Result: {result[:100]}..." if len(str(result)) > 100 else f"Result: {result}")

        print(f"\n=== Workflow Complete ===")
        return context

Now let's put it all together with some mock agents:

class MockAgent:
    """A simple mock agent for demonstration purposes."""
    def __init__(self, name, specialty):
        self.name = name
        self.specialty = specialty

    def run(self, description, context=None):
        # In a real system, this would call an LLM
        if "research" in self.specialty.lower():
            return f"[Research] Key facts about '{description}': Fact 1, Fact 2, Fact 3"
        elif "write" in self.specialty.lower():
            prev = context.get("research", "no prior info")
            return f"[Blog Post] Based on {prev[:30]}... — Here is a complete blog post."
        elif "proofread" in self.specialty.lower():
            return f"[Polished] {description[:50]}... (grammar fixed, tone improved)"
        return f"[{self.name}] Processed: {description}"

# Create agents
researcher = MockAgent("ResearchBot", "research")
writer = MockAgent("WriterBot", "write")
editor = MockAgent("EditorBot", "proofread")

# Create tasks
task1 = Task("research", "AI trends in 2025", researcher, "Key facts about AI trends")
task2 = Task("write", "Write a blog post", writer, "A 500-word blog post", dependencies=["research"])
task3 = Task("proofread", "Proofread the blog post", editor, "Polished blog post", dependencies=["write"])

# Build and run workflow
workflow = SequentialWorkflow("Content Pipeline")
workflow.add_task(task1).add_task(task2).add_task(task3)
results = workflow.run()
Pro Tip: Always store intermediate results in a shared context dictionary. This lets downstream tasks access what earlier tasks produced without tight coupling between agents.

Parallel Workflows: Running Tasks Simultaneously

Not every task depends on a previous one. Sometimes you can run multiple tasks at the same time to save time. This is a parallel workflow.

For example, if you're building a market analysis report, you might want to research three competitors simultaneously, then combine the results:

import threading
from concurrent.futures import ThreadPoolExecutor, as_completed

class ParallelWorkflow:
    def __init__(self, name):
        self.name = name
        self.tasks = []

    def add_task(self, task):
        self.tasks.append(task)
        return self

    def run(self):
        """Run all tasks in parallel and collect results."""
        print(f"\n=== Parallel Workflow: {self.name} ===\n")
        results = {}

        with ThreadPoolExecutor(max_workers=len(self.tasks)) as executor:
            # Submit all tasks
            future_to_task = {
                executor.submit(task.execute): task
                for task in self.tasks
            }

            # Collect results as they finish
            for future in as_completed(future_to_task):
                task = future_to_task[future]
                try:
                    results[task.name] = future.result()
                    print(f"✓ {task.name} completed")
                except Exception as e:
                    print(f"✗ {task.name} failed: {e}")
                    results[task.name] = None

        print(f"\n=== All Parallel Tasks Complete ===")
        return results

# Usage
agents = [MockAgent(f"Bot-{i}", "research") for i in range(3)]
topics = ["Company A financials", "Company B products", "Company C leadership"]

parallel_workflow = ParallelWorkflow("Competitor Analysis")
for agent, topic in zip(agents, topics):
    task = Task(f"research_{topic}", topic, agent, f"Facts about {topic}")
    parallel_workflow.add_task(task)

results = parallel_workflow.run()
Watch Out: Parallel workflows are faster, but they use more resources (API calls, memory). Make sure your rate limits and budget can handle multiple simultaneous agent executions.

Conditional Workflows: Branching Logic

Sometimes the next step depends on the result of a previous step. A conditional workflow uses if/else logic to decide which path to take.

class ConditionalWorkflow:
    def __init__(self, name):
        self.name = name
        self.steps = []  # list of (task, condition_func, next_step_if_true, next_step_if_false)

    def add_step(self, task, condition=None, on_true=None, on_false=None):
        """
        condition: a function that takes the task result and returns True/False
        on_true / on_false: the name of the next step to run
        """
        self.steps.append({
            "task": task,
            "condition": condition,
            "on_true": on_true,
            "on_false": on_false
        })
        return self

    def run(self):
        print(f"\n=== Conditional Workflow: {self.name} ===\n")
        context = {}
        step_index = 0

        while step_index < len(self.steps):
            step = self.steps[step_index]
            task = step["task"]

            print(f"\n→ Running: {task.name}")
            result = task.execute(context)
            context[task.name] = result

            if step["condition"]:
                condition_met = step["condition"](result)
                if condition_met:
                    print(f"  Condition met → going to '{step['on_true']}'")
                    next_name = step["on_true"]
                else:
                    print(f"  Condition NOT met → going to '{step['on_false']}'")
                    next_name = step["on_false"]

                # Find the next step by name
                step_index = next(
                    (i for i, s in enumerate(self.steps) if s["task"].name == next_name),
                    len(self.steps)  # if not found, end the workflow
                )
            else:
                step_index += 1

        print(f"\n=== Conditional Workflow Complete ===")
        return context

# Example: Check if research found enough info before writing
def has_sufficient_info(result):
    return len(str(result)) > 50  # simple heuristic

research_task = Task("deep_research", "Quantum computing advances", researcher, "Detailed findings")
write_task = Task("write_report", "Write a report", writer, "A formal report")
fallback_task = Task("request_more_info", "Ask for more details", researcher, "Clarification request")

cond_workflow = ConditionalWorkflow("Smart Research Pipeline")
cond_workflow.add_step(research_task)
cond_workflow.add_step(
    write_task,
    condition=has_sufficient_info,
    on_true="write_report",
    on_false="request_more_info"
)
cond_workflow.add_step(fallback_task)

results = cond_workflow.run()

Comparing Workflow Types

Here's a quick reference to help you choose the right workflow pattern for your use case:

Workflow Type When to Use Speed Complexity Example
Sequential Tasks depend on previous outputs Slower (one at a time) Low Research → Write → Edit
Parallel Tasks are independent of each other Faster (simultaneous) Medium Research 3 competitors at once
Conditional Next step depends on results Varies High Check quality → approve or retry
Hybrid Mix of the above patterns Varies Highest Parallel research → sequential editing with conditional review

Error Handling in Workflows

When you're chaining multiple agents together, things can go wrong. An API call might fail, an agent might return an unexpected format, or a task might take too long. Good workflows handle these gracefully.

import time

class RobustTask(Task):
    def __init__(self, *args, max_retries=3, timeout=30, **kwargs):
        super().__init__(*args, **kwargs)
        self.max_retries = max_retries
        self.timeout = timeout

    def execute(self, context=None):
        """Execute with retry logic and error handling."""
        for attempt in range(1, self.max_retries + 1):
            try:
                print(f"  Attempt {attempt}/{self.max_retries} for '{self.name}'")
                self.status = "in_progress"

                start = time.time()
                self.result = self.agent.run(self.description, context=context)
                elapsed = time.time() - start

                if elapsed > self.timeout:
                    raise TimeoutError(f"Task took {elapsed:.1f}s (limit: {self.timeout}s)")

                self.status = "completed"
                return self.result

            except Exception as e:
                print(f"  ✗ Error on attempt {attempt}: {e}")
                if attempt == self.max_retries:
                    self.status = "failed"
                    self.result = None
                    return None
                # Wait before retrying (exponential backoff)
                wait = 2 ** attempt
                print(f"  Retrying in {wait}s...")
                time.sleep(wait)
Best Practice: Use exponential backoff for retries. If the first retry waits 2 seconds, the second waits 4, the third waits 8, and so on. This prevents overwhelming a service that's already struggling.

Putting It All Together: A Complete Example

Let's build a realistic workflow that combines everything we've learned. We'll create a Customer Support Triage System that:

  1. Classifies the incoming message (billing, technical, or general).
  2. Routes it to the right specialist agent.
  3. Generates a response.
  4. Checks the response for quality before sending.
class SupportWorkflow:
    """A complete customer support triage workflow."""

    def __init__(self):
        self.classifier = MockAgent("Classifier", "classify")
        self.billing_agent = MockAgent("BillingBot", "billing")
        self.tech_agent = MockAgent("TechBot", "technical")
        self.general_agent = MockAgent("GeneralBot", "general")
        self.quality_checker = MockAgent("QABot", "quality_check")

    def classify_message(self, message):
        """Step 1: Determine the category of the message."""
        result = self.classifier.run(f"Classify this message: {message}")
        if "billing" in result.lower():
            return "billing"
        elif "technical" in result.lower() or "error" in result.lower():
            return "technical"
        return "general"

    def route_and_respond(self, message, category):
        """Step 2: Send to the right specialist."""
        agents = {
            "billing": self.billing_agent,
            "technical": self.tech_agent,
            "general": self.general_agent
        }
        agent = agents[category]
        return agent.run(f"Respond to: {message}")

    def quality_check(self, response):
        """Step 3: Verify the response is appropriate."""
        result = self.quality_checker.run(f"Review this response: {response}")
        return "approved" in result.lower() or "good" in result.lower()

    def process(self, message):
        """Run the full support pipeline."""
        print(f"\n{'='*50}")
        print(f"Processing: \"{message}\"")
        print(f"{'='*50}")

        # Step 1: Classify
        category = self.classify_message(message)
        print(f"  Category: {category}")

        # Step 2: Get response from specialist
        response = self.route_and_respond(message, category)
        print(f"  Response: {response[:80]}...")

        # Step 3: Quality check
        approved = self.quality_check(response)
        if approved:
            print(f"  ✓ Response approved!")
            return response
        else:
            print(f"  ✗ Response rejected — escalating to human agent")
            return "[ESCALATED TO HUMAN AGENT]"

# Run it
support = SupportWorkflow()
result = support.process("I was charged twice for my subscription last month")
print(f"\nFinal output: {result}")
Exercise: Build a Research Roundup Workflow

Create a workflow that takes a list of topics, researches each one in parallel, then combines the results into a single formatted report. Your workflow should:

  1. Accept a list of 3 topics.
  2. Research all 3 topics in parallel (use ParallelWorkflow or ThreadPoolExecutor).
  3. Pass all 3 research results to a "writer" agent that produces a combined report.
  4. Handle the case where one of the research tasks fails — the report should still be generated with a note like "Research unavailable for: [topic]".

Use the Task and agent classes from this lesson as your starting point.


from concurrent.futures import ThreadPoolExecutor, as_completed

def research_roundup(topics, researcher, writer):
    """Research multiple topics in parallel and combine into a report."""

    # Step 1: Research all topics in parallel
    research_results = {}

    with ThreadPoolExecutor(max_workers=len(topics)) as executor:
        future_to_topic = {}
        for topic in topics:
            task = Task(f"research_{topic}", topic, topic, f"Facts about {topic}")
            future = executor.submit(task.execute)
            future_to_topic[future] = topic

        for future in as_completed(future_to_topic):
            topic = future_to_topic[future]
            try:
                research_results[topic] = future.result()
                print(f"✓ Research complete: {topic}")
            except Exception as e:
                print(f"✗ Research failed: {topic} — {e}")
                research_results[topic] = None

    # Step 2: Build the combined report
    combined_context = "Research findings:\n"
    for topic, result in research_results.items():
        if result:
            combined_context += f"\n--- {topic} ---\n{result}\n"
        else:
            combined_context += f"\n--- {topic} ---\nResearch unavailable for: {topic}\n"

    report_task = Task(
        "write_report",
        combined_context,
        writer,
        "A formatted research roundup report"
    )
    report = report_task.execute()

    return report

# Usage
researcher = MockAgent("ResearchBot", "research")
writer = MockAgent("WriterBot", "write")

topics = ["AI in healthcare", "Quantum computing", "Sustainable energy"]
report = research_roundup(topics, researcher, writer)
print(f"\nFinal Report:\n{report}")

Key Takeaways

  • Tasks are individual units of work assigned to agents, each with a clear goal, owner, and expected output.
  • Workflows orchestrate multiple tasks — defining the order, dependencies, and handoff of results between agents.
  • Sequential workflows run tasks one after another, passing results forward. Best when each step depends on the previous one.
  • Parallel workflows run independent tasks simultaneously using ThreadPoolExecutor. Best for speed when tasks don't depend on each other.
  • Conditional workflows use branching logic to decide the next step based on the result of a previous task.
  • Always include error handling with retries and exponential backoff — multi-agent systems have more points of failure.
  • Use a shared context dictionary to pass information between tasks without tightly coupling your agents.
  • Start simple with sequential workflows, then add parallelism and conditional logic as your needs grow.
