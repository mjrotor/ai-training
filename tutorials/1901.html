Designing a Support Agent

Learn about designing a support agent.

What Is a Support Agent?

A support agent is an AI-powered assistant designed to help users by answering questions, troubleshooting issues, and guiding them through processes. Unlike a simple chatbot that responds with pre-written answers, a support agent can reason about context, access knowledge bases, and take actions on behalf of the user.

In this lesson, you will learn how to design a support agent from scratch using a modern AI framework. By the end, you will have a working prototype that can handle common customer inquiries.

Core Components of a Support Agent

Every support agent, no matter how simple or complex, is built from a few essential parts. Understanding these components will help you design agents for any domain.

1. The Language Model

The language model acts as the brain of your agent. It interprets user messages, decides what to do next, and generates natural-sounding responses. Modern models can follow instructions, reason through problems, and even decide when to call external tools.

2. The Knowledge Base

A knowledge base is a collection of documents, FAQs, or structured data that the agent can search when it needs to answer a question. Instead of relying only on what the language model memorized during training, the agent retrieves relevant information at runtime.

3. Tools and Actions

Tools let the agent do things beyond just replying with text. A support agent might look up an order status, reset a password, or escalate a ticket to a human. Each tool has a clear description so the language model knows when and how to use it.

4. Memory and Context

Good support agents remember what was said earlier in the conversation. This context allows the agent to handle follow-up questions, avoid asking for the same information twice, and provide a natural, continuous experience.

Why context matters: Without memory, every user message would be treated as the start of a brand-new conversation. The agent would forget names, issue details, and previous steps — leading to a frustrating experience.

Designing the Agent Workflow

Before writing any code, it helps to map out the flow of a typical support interaction. A well-designed workflow keeps the agent focused and predictable.

  1. Receive the user message — The agent listens for incoming text.
  2. Classify the intent — Is the user asking a general question, reporting a bug, or requesting a refund?
  3. Retrieve relevant information — Search the knowledge base for matching articles or policies.
  4. Decide on an action — Should the agent answer directly, call a tool, or escalate to a human?
  5. Generate a response — Craft a clear, empathetic reply and deliver it to the user.
  6. Log the interaction — Record the conversation for quality assurance and future improvement.
Design principle: Always plan for the case where the agent cannot help. A graceful handoff to a human agent builds trust and prevents user frustration.

Building the Knowledge Base

For this lesson, we will use a simple in-memory knowledge base. In a production system, you would use a vector database, but the concept is the same.

knowledge_base = {
    "refund policy": (
        "Our refund policy allows returns within 30 days of purchase. "
        "Please provide your order number to start the process."
    ),
    "shipping time": (
        "Standard shipping takes 5-7 business days. "
        "Express shipping takes 2-3 business days."
    ),
    "password reset": (
        "To reset your password, click 'Forgot Password' on the login page. "
        "A reset link will be sent to your registered email."
    ),
    "business hours": (
        "Our support team is available Monday through Friday, "
        "9:00 AM to 6:00 PM Eastern Time."
    ),
}

def search_knowledge(query: str) -> str:
    query_lower = query.lower()
    for key, value in knowledge_base.items():
        if key in query_lower:
            return value
    return "I'm not sure about that. Let me connect you with a human agent."

# Test it
print(search_knowledge("How do I get a refund?"))
# Output: Our refund policy allows returns within 30 days...

Defining Tools

Tools extend what your agent can do. Each tool is a plain Python function with a clear description that the language model can read.

tools = [
    {
        "type": "function",
        "function": {
            "name": "lookup_order",
            "description": "Look up the status of an order by order number.",
            "parameters": {
                "type": "object",
                "properties": {
                    "order_number": {
                        "type": "string",
                        "description": "The order number, e.g. ORD-12345"
                    }
                },
                "required": ["order_number"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "escalate_to_human",
            "description": "Transfer the conversation to a human support agent.",
            "parameters": {
                "type": "object",
                "properties": {
                    "reason": {
                        "type": "string",
                        "description": "Why the issue needs human attention"
                    }
                },
                "required": ["reason"]
            }
        }
    }
]

# Simulated tool implementations
def lookup_order(order_number: str) -> str:
    orders = {
        "ORD-12345": "Shipped — expected delivery June 14.",
        "ORD-67890": "Processing — will ship within 24 hours.",
    }
    return orders.get(order_number, "Order not found. Please verify the number.")

def escalate_to_human(reason: str) -> str:
    return f"Escalating to a human agent. Reason: {reason}"

Putting It All Together

Now let's wire everything into a single agent function that handles a full conversation turn.

SYSTEM_PROMPT = """
You are a friendly and helpful customer support agent for Acme Store.
Use the knowledge base tool to find answers. If you cannot help,
offer to escalate to a human agent. Always be concise and empathetic.
"""

def run_agent(user_message: str, history: list) -> str:
    messages = [{"role": "system", "content": SYSTEM_PROMPT}]
    messages.extend(history)
    messages.append({"role": "user", "content": user_message})

    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        tools=tools,
        temperature=0.3,
    )

    message = response.choices[0].message

    # If the model wants to call a tool
    if message.tool_calls:
        for call in message.tool_calls:
            func_name = call.function.name
            args = json.loads(call.function.arguments)

            if func_name == "lookup_order":
                result = lookup_order(args["order_number"])
            elif func_name == "escalate_to_human":
                result = escalate_to_human(args["reason"])
            else:
                result = "Unknown tool."

            messages.append(message)
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result,
            })

        # Get final response after tool use
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            temperature=0.3,
        )

    return response.choices[0].message.content

# Try it out
history = []
print(run_agent("Where is order ORD-12345?", history))
Error handling: In production, always wrap API calls in try/except blocks. Network issues, rate limits, and invalid responses can all cause failures. A good agent degrades gracefully.

Comparing Agent Architectures

There are several ways to architect a support agent. Here is a comparison of the most common approaches:

Architecture Best For Complexity Flexibility
Single-turn Q&A Simple FAQ bots Low Low
Multi-turn with tools Order support, account help Medium High
Multi-agent pipeline Complex workflows, routing High Very High
ReAct (Reason + Act) Research-heavy tasks High Very High

Key Takeaways

  • A support agent combines a language model, a knowledge base, tools, and memory to assist users effectively.
  • Designing a clear workflow before writing code keeps your agent focused and predictable.
  • Tools extend the agent's capabilities beyond text generation — they can look up data, trigger actions, and escalate issues.
  • A well-crafted system prompt sets the tone and boundaries for the agent's behavior.
  • Always plan for failure cases: network errors, unknown queries, and situations that require human intervention.
  • Start with a simple architecture and add complexity only as your use case demands it.
