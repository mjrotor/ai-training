Building the Full Research Agent

Learn about building the full research agent.

What Is a Full Research Agent?

So far, you have built individual pieces of an AI agent — a tool-calling function, a memory system, and a planning module. Now it is time to bring everything together into a full research agent: an AI system that can accept a research question, break it into sub-questions, search for information, synthesize findings, and present a coherent answer.

A full research agent is more than just a chatbot with a search bar. It follows a structured pipeline:

  1. Understand the user's question and identify what information is needed.
  2. Plan a sequence of searches or tool calls.
  3. Execute each step — querying APIs, reading documents, or calling tools.
  4. Synthesize the collected data into a clear, well-organized response.
  5. Present the answer with citations and confidence levels.

Designing the Agent Architecture

Before writing code, let's map out the components our research agent needs. Think of this as the blueprint — each component has a single responsibility, and they communicate through a central orchestrator.

Component Responsibility Input Output
Query Parser Extracts key entities and intent from the user's question Raw user question (string) Structured query object
Planner Decides which tools to call and in what order Structured query Ordered list of tool calls
Tool Executor Runs each tool call and collects results Tool name + parameters Raw tool output
Synthesizer Combines all tool outputs into a final answer List of tool outputs Formatted response with citations
Why separate components? By keeping each piece independent, you can test, debug, and swap out individual parts without rewriting the entire agent. This is the same principle behind modular software design.

Building the Query Parser

The query parser is the first component in the pipeline. Its job is to take a raw question like "What were the economic effects of the 2024 solar eclipse?" and turn it into a structured object the planner can work with.

# agent/query_parser.py

from dataclasses import dataclass, field
from typing import List

@dataclass
class ParsedQuery:
    original: str
    entities: List[str] = field(default_factory=list)
    intent: str = ""
    sub_questions: List[str] = field(default_factory=list)

def parse_query(user_question: str) -> ParsedQuery:
    """
    Analyze the user question and extract structured information.
    In production, you would use an LLM call here.
    """
    # Simple keyword-based parsing for demonstration
    question_lower = user_question.lower()

    # Detect intent
    if any(word in question_lower for word in ["compare", "difference", "versus", "vs"]):
        intent = "comparison"
    elif any(word in question_lower for word in ["effect", "impact", "cause", "result"]):
        intent = "causal_analysis"
    elif any(word in question_lower for word in ["what is", "define", "explain"]):
        intent = "definition"
    else:
        intent = "general_research"

    # Extract simple entities (capitalized words as a heuristic)
    import re
    entities = re.findall(r'\b[A-Z][a-z]+(?:\s[A-Z][a-z]+)*\b', user_question)

    # Generate sub-questions based on intent
    sub_questions = _generate_sub_questions(user_question, intent)

    return ParsedQuery(
        original=user_question,
        entities=entities,
        intent=intent,
        sub_questions=sub_questions
    )

def _generate_sub_questions(question: str, intent: str) -> List[str]:
    """Break a complex question into smaller, searchable pieces."""
    if intent == "comparison":
        return [
            f"What are the key characteristics of the first subject in: {question}",
            f"What are the key characteristics of the second subject in: {question}",
            f"How do these subjects differ or relate?"
        ]
    elif intent == "causal_analysis":
        return [
            f"What are the primary causes related to: {question}",
            f"What are the documented effects related to: {question}",
            f"What evidence supports these causal relationships?"
        ]
    else:
        return [question]
Pro tip: In a production system, you would replace the keyword-based parser with an LLM call. A model like GPT-4 or Claude can generate far more accurate sub-questions and entity extractions than hand-written rules.

Implementing the Planner

The planner decides which tools to invoke for each sub-question. It maps intents and entities to specific tool configurations.

# agent/planner.py

from typing import List, Dict, Any
from agent.query_parser import ParsedQuery

@dataclass
class ToolCall:
    tool_name: str
    parameters: Dict[str, Any]
    sub_question_index: int

def plan(query: ParsedQuery) -> List[ToolCall]:
    """
    Given a parsed query, generate an ordered list of tool calls.
    """
    tool_calls = []

    for i, sub_q in enumerate(query.sub_questions):
        # Every sub-question gets a web search
        tool_calls.append(ToolCall(
            tool_name="web_search",
            parameters={"query": sub_q, "max_results": 5},
            sub_question_index=i
        ))

        # If the query involves numbers, also use the calculator
        if query.intent == "causal_analysis":
            tool_calls.append(ToolCall(
                tool_name="document_reader",
                parameters={"path": f"data/research_{i}.txt"},
                sub_question_index=i
            ))

    return tool_calls

Writing the Tool Executor

The tool executor iterates through the planned tool calls and collects results. It also handles errors gracefully — a critical feature for any agent that depends on external services.

# agent/tool_executor.py

from typing import List, Any, Dict
import logging

logger = logging.getLogger(__name__)

class ToolExecutor:
    def __init__(self):
        self.tools = {}

    def register_tool(self, name: str, func):
        """Register a tool function by name."""
        self.tools[name] = func

    def execute(self, tool_call) -> Dict[str, Any]:
        """
        Execute a single tool call and return the result.
        Returns a dict with 'success', 'result', and optionally 'error'.
        """
        name = tool_call.tool_name
        params = tool_call.parameters

        if name not in self.tools:
            logger.error(f"Unknown tool: {name}")
            return {"success": False, "error": f"Tool '{name}' not found."}

        try:
            result = self.tools[name](**params)
            return {"success": True, "result": result}
        except Exception as e:
            logger.exception(f"Tool '{name}' failed with parameters {params}")
            return {"success": False, "error": str(e)}

    def execute_all(self, tool_calls: List) -> List[Dict[str, Any]]:
        """Execute all tool calls and return results in order."""
        results = []
        for call in tool_calls:
            result = self.execute(call)
            result["sub_question_index"] = call.sub_question_index
            results.append(result)
        return results
Error handling matters! External APIs fail, rate limits get hit, and network timeouts happen. Always wrap tool calls in try/except blocks and log errors. A good agent degrades gracefully — it reports what it could not find rather than crashing silently.

Creating the Synthesizer

The synthesizer is where raw tool outputs become a polished answer. It merges results from multiple sources, removes duplicates, and formats everything for the user.

# agent/synthesizer.py

from typing import List, Dict, Any

def synthesize(
    original_question: str,
    tool_results: List[Dict[str, Any]]
) -> str:
    """
    Combine all tool outputs into a well-structured response.
    """
    # Separate successful and failed results
    successes = [r for r in tool_results if r["success"]]
    failures = [r for r in tool_results if not r["success"]]

    if not successes:
        return (
            "I was unable to gather enough information to answer your question. "
            "Here are the errors encountered:\n" +
            "\n".join(f"- {r['error']}" for r in failures)
        )

    # Build the response
    sections = []
    sections.append(f"## Research Results for: {original_question}\n")

    # Group results by sub-question index
    from collections import defaultdict
    grouped = defaultdict(list)
    for result in successes:
        idx = result.get("sub_question_index", 0)
        grouped[idx].append(result["result"])

    for idx in sorted(grouped.keys()):
        sources = grouped[idx]
        combined = "\n".join(str(s) for s in sources)
        sections.append(f"### Finding {idx + 1}\n{combined}\n")

    # Add a note about any failures
    if failures:
        sections.append(
            "\n*Note: Some searches could not be completed due to errors. "
            "The results above reflect only the successful lookups.*"
        )

    return "\n".join(sections)

Wiring It All Together: The Orchestrator

The orchestrator is the heart of the agent. It calls each component in sequence and manages the overall flow.

# agent/orchestrator.py

from agent.query_parser import parse_query, ParsedQuery
from agent.planner import plan, ToolCall
from agent.tool_executor import ToolExecutor
from agent.synthesizer import synthesize
import logging

logger = logging.getLogger(__name__)

class ResearchAgent:
    def __init__(self, llm_client=None, config: dict = None):
        self.llm = llm_client
        self.config = config or {}
        self.executor = ToolExecutor()
        self.conversation_history = []

        # Register available tools
        self._register_default_tools()

    def _register_default_tools(self):
        """Register the built-in tool set."""
        from tools.web_search import web_search
        from tools.document_reader import read_document
        from tools.calculator import calculate

        self.executor.register_tool("web_search", web_search)
        self.executor.register_tool("document_reader", read_document)
        self.executor.register_tool("calculator", calculate)

    def run(self, user_question: str) -> str:
        """
        Execute the full research pipeline for a user question.
        """
        logger.info(f"Research agent received: {user_question}")

        # Step 1: Parse the question
        parsed = parse_query(user_question)
        logger.info(f"Intent: {parsed.intent}, Entities: {parsed.entities}")

        # Step 2: Plan tool calls
        tool_calls = plan(parsed)
        logger.info(f"Planned {len(tool_calls)} tool calls")

        # Step 3: Execute all tool calls
        results = self.executor.execute_all(tool_calls)
        successful = sum(1 for r in results if r["success"])
        logger.info(f"Completed {successful}/{len(results)} tool calls successfully")

        # Step 4: Synthesize the answer
        answer = synthesize(user_question, results)

        # Step 5: Store in conversation history
        self.conversation_history.append({
            "question": user_question,
            "answer": answer
        })

        return answer

Adding Memory for Multi-Turn Conversations

A research agent that forgets everything after each question is not very useful. Let's add short-term memory so the agent can reference earlier findings in a conversation.

# memory/short_term.py

from typing import List, Dict
from collections import deque

class ShortTermMemory:
    def __init__(self, max_turns: int = 10):
        self.max_turns = max_turns
        self.turns: deque = deque(maxlen=max_turns)

    def add_turn(self, question: str, answer: str):
        """Store a question-answer pair."""
        self.turns.append({"question": question, "answer": answer})

    def get_context(self) -> str:
        """
        Return a formatted string of recent conversation history.
        This gets injected into the system prompt.
        """
        if not self.turns:
            return "No prior conversation."

        lines = ["### Recent Conversation History ###"]
        for i, turn in enumerate(self.turns, 1):
            lines.append(f"Turn {i}:")
            lines.append(f"  Q: {turn['question']}")
            lines.append(f"  A: {turn['answer'][:200]}...")  # Truncate for brevity
        return "\n".join(lines)

    def clear(self):
        """Reset the conversation memory."""
        self.turns.clear()
Short-term vs. long-term memory: Short-term memory holds the current conversation. Long-term memory — which you will build in a later lesson — stores knowledge across sessions, such as previously researched topics or user preferences.
