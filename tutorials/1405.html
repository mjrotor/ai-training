Building a Hybrid Search Agent

Learn about building a hybrid search agent.

What Is a Hybrid Search Agent?

A Hybrid Search Agent is an AI agent that combines multiple search strategies — typically keyword-based search and semantic (vector) search — to retrieve more accurate and relevant information than either method could achieve alone. In this lesson, you'll learn why hybrid search matters, how it works under the hood, and how to build one from scratch using Python.

By the end of this lesson, you'll understand the strengths and weaknesses of different retrieval techniques, know how to fuse their results, and have a working hybrid search agent you can extend for your own projects.

Prerequisites: You should be familiar with basic Python, what a vector embedding is (Lesson 3), and how a simple RAG pipeline works (Lesson 4). If those terms are new to you, we recommend reviewing those lessons first.

Why Not Just Use One Search Method?

Before diving into hybrid search, it helps to understand why a single retrieval strategy often falls short. Let's look at the two most common approaches and where each one struggles.

Keyword (Lexical) Search

Keyword search — the kind used by traditional search engines and databases like Elasticsearch or SQLite FTS — matches documents based on the exact words in a query. Algorithms like BM25 rank documents by how frequently query terms appear, adjusted for document length and term rarity.

Strengths:

  • Excellent at matching precise terms, names, codes, and acronyms.
  • Fast and computationally cheap.
  • Interpretable — you can see why a document matched.

Weaknesses:

  • Cannot handle synonyms or paraphrases. A query about "automobiles" won't find documents that only mention "cars."
  • Struggles with typos and morphological variations (e.g., "running" vs. "run" is handled only with stemming).
  • Misses conceptual relevance when wording differs.

Semantic (Vector) Search

Semantic search converts both the query and documents into vector embeddings — dense numerical representations that capture meaning. Documents with similar meanings end up close together in vector space, even if they share no words. You measure proximity using cosine similarity or dot product.

Strengths:

  • Understands meaning beyond exact word overlap.
  • Handles synonyms, paraphrases, and cross-lingual matches.
  • Great for conceptual or open-ended queries.

Weaknesses:

  • Can miss exact keyword matches (e.g., product IDs, error codes).
  • Requires an embedding model and a vector store — more infrastructure.
  • Results can be harder to explain ("why was this document retrieved?").

Side-by-Side Comparison

Criteria Keyword Search (BM25) Semantic Search (Vector)
Exact term matching ✅ Excellent ⚠️ Can miss
Synonym / paraphrase handling ❌ Poor ✅ Excellent
Speed ✅ Very fast ⚠️ Moderate
Infrastructure needed Minimal Embedding model + vector DB
Interpretability ✅ High ⚠️ Lower
Typo tolerance ⚠️ Limited ✅ Good
Key Insight: Neither method is universally better. The best production retrieval systems combine both — that's exactly what a hybrid search agent does.

How Hybrid Search Works

A hybrid search agent runs both retrieval methods in parallel (or sequentially), then merges and re-ranks the results into a single, unified list. The magic is in the fusion strategy — the algorithm that decides how to combine scores from two very different systems.

The Basic Pipeline

  1. Receive the user query.
  2. Run keyword search → get a ranked list with BM25 scores.
  3. Run semantic search → get a ranked list with cosine similarity scores.
  4. Normalize scores from both lists to a common scale (e.g., 0–1).
  5. Merge and re-rank using a fusion formula.
  6. Return the top-k results to the user or pass them to an LLM.

Fusion Strategies

There are several ways to combine the two ranked lists. Here are the three most common:

  • Weighted Linear Combination (Reciprocal Rank Fusion): Each document's final score is a weighted sum of its normalized scores from both lists. Simple and effective.
    final_score = α × keyword_score + β × semantic_score
  • Reciprocal Rank Fusion (RRF): Instead of using raw scores, use each document's rank position. This avoids the problem of score scales being incomparable.
    RRF_score = Σ 1 / (k + rank) where k is a smoothing constant (typically 60).
  • Learned Re-ranking: Train a small model (e.g., a cross-encoder) to score each candidate document against the query. Most accurate but requires training data and more compute.
Watch out: Score normalization is critical. BM25 scores and cosine similarities live on completely different scales. Without normalization, one method will dominate the other. Always normalize before combining.

Building the Hybrid Search Agent in Python

Let's build a complete hybrid search agent step by step. We'll use:

  • rank_bm25 for keyword search
  • sentence-transformers for embeddings
  • NumPy for score normalization and fusion

Step 2: Prepare the Document Collection

import numpy as np
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer

# --- Sample document collection ---
documents = [
    "Python is a versatile programming language used in data science and web development.",
    "BM25 is a ranking function used by search engines to estimate document relevance.",
    "Vector embeddings capture the semantic meaning of text in numerical form.",
    "Hybrid search combines keyword and semantic retrieval for better results.",
    "Reciprocal Rank Fusion merges ranked lists from multiple retrieval systems.",
    "Sentence transformers convert sentences into dense vector representations.",
    "Cosine similarity measures the angle between two vectors in embedding space.",
    "An AI agent can use tools like search to answer complex questions.",
    "Tokenization splits text into individual words or subwords for processing.",
    "Retrieval-Augmented Generation improves LLM accuracy with external knowledge.",
]

# Tokenize documents for BM25 (simple whitespace tokenization for demo)
tokenized_docs = [doc.lower().split() for doc in documents]

# Initialize BM25
bm25 = BM25Okapi(tokenized_docs)

# Initialize embedding model
embedder = SentenceTransformer("all-MiniLM-L6-v2")

# Pre-compute document embeddings
doc_embeddings = embedder.encode(documents, convert_to_tensor=False)

print(f"Indexed {len(documents)} documents.")
print(f"Embedding dimension: {doc_embeddings.shape[1]}")

Step 3: Implement Keyword Search

def keyword_search(query, bm25_model, documents, top_k=5):
    """Retrieve top-k documents using BM25 keyword search."""
    tokenized_query = query.lower().split()
    scores = bm25_model.get_scores(tokenized_query)
    
    # Get top-k indices sorted by score (descending)
    top_indices = np.argsort(scores)[::-1][:top_k]
    
    results = []
    for idx in top_indices:
        results.append({
            "index": int(idx),
            "document": documents[idx],
            "keyword_score": float(scores[idx])
        })
    return results

# Example
query = "How does semantic search work?"
kw_results = keyword_search(query, bm25, documents)
for r in kw_results:
    print(f"  Score: {r['keyword_score']:.3f} | {r['document'][:60]}...")

Step 4: Implement Semantic Search

def semantic_search(query, embedder, doc_embeddings, documents, top_k=5):
    """Retrieve top-k documents using cosine similarity."""
    query_embedding = embedder.encode([query], convert_to_tensor=False)[0]
    
    # Compute cosine similarities
    similarities = np.dot(doc_embeddings, query_embedding) / (
        np.linalg.norm(doc_embeddings, axis=1) * np.linalg.norm(query_embedding)
    )
    
    top_indices = np.argsort(similarities)[::-1][:top_k]
    
    results = []
    for idx in top_indices:
        results.append({
            "index": int(idx),
            "document": documents[idx],
            "semantic_score": float(similarities[idx])
        })
    return results

# Example
sem_results = semantic_search(query, embedder, doc_embeddings, documents)
for r in sem_results:
    print(f"  Score: {r['semantic_score']:.3f} | {r['document'][:60]}...")

Step 5: Normalize and Fuse Results

def normalize_scores(results, score_key):
    """Min-max normalize scores to [0, 1]."""
    scores = [r[score_key] for r in results]
    min_s, max_s = min(scores), max(scores)
    if max_s - min_s == 0:
        for r in results:
            r[f"norm_{score_key}"] = 0.0
    else:
        for r in results:
            r[f"norm_{score_key}"] = (r[score_key] - min_s) / (max_s - min_s)
    return results

def hybrid_search(query, bm25_model, embedder, doc_embeddings, documents,
                  top_k=5, alpha=0.5):
    """
    Perform hybrid search combining BM25 and semantic search.
    
    Args:
        query: Search query string.
        bm25_model: Fitted BM25 model.
        embedder: SentenceTransformer model.
        doc_embeddings: Pre-computed document embeddings.
        documents: List of document strings.
        top_k: Number of results to return.
        alpha: Weight for keyword score (1-alpha for semantic).
    
    Returns:
        List of dicts with fused scores, sorted descending.
    """
    # Step A: Retrieve from both methods (get more than top_k for merging)
    kw_results = keyword_search(query, bm25_model, documents, top_k=len(documents))
    sem_results = semantic_search(query, embedder, doc_embeddings, documents,
                                  top_k=len(documents))
    
    # Step B: Normalize scores
    kw_results = normalize_scores(kw_results, "keyword_score")
    sem_results = normalize_scores(sem_results, "semantic_score")
    
    # Step C: Build a score dictionary keyed by document index
    fused = {}
    
    for r in kw_results:
        idx = r["index"]
        fused[idx] = {
            "index": idx,
            "document": documents[idx],
            "keyword_score": r["norm_keyword_score"],
            "semantic_score": 0.0,
        }
    
    for r in sem_results:
        idx = r["index"]
        if idx in fused:
            fused[idx]["semantic_score"] = r["norm_semantic_score"]
        else:
            fused[idx] = {
                "index": idx,
                "document": documents[idx],
                "keyword_score": 0.0,
                "semantic_score": r["norm_semantic_score"],
            }
    
    # Step D: Compute fused score
    for idx in fused:
        fused[idx]["fused_score"] = (
            alpha * fused[idx]["keyword_score"]
            + (1 - alpha) * fused[idx]["semantic_score"]
        )
    
    # Step E: Sort and return top-k
    ranked = sorted(fused.values(), key=lambda x: x["fused_score"], reverse=True)
    return ranked[:top_k]

# --- Run the hybrid search ---
query = "How does semantic search work?"
results = hybrid_search(query, bm25, embedder, doc_embeddings, documents,
                       top_k=5, alpha=0.4)

print(f"Query: '{query}'\n")
for i, r in enumerate(results, 1):
    print(f"  #{i} [fused={r['fused_score']:.3f} | kw={r['keyword_score']:.3f} | "
          f"sem={r['semantic_score']:.3f}]")
    print(f"      {r['document']}\n")
Try it yourself: Adjust the alpha parameter. Set it to 1.0 for pure keyword search and 0.0 for pure semantic search. Observe how the rankings change!

Turning It Into an Agent

A search function is useful, but an agent can decide when to search, how to refine queries, and what to do with the results. Let's wrap our hybrid search in a simple agent that uses an LLM to generate answers from retrieved context.

The Agent Loop

  1. User asks a question.
  2. The agent calls hybrid_search() to retrieve relevant documents.
  3. The retrieved documents are inserted into a prompt as context.
  4. The LLM generates a grounded answer.
  5. The agent returns the answer with source citations.
def build_context(results, max_docs=3):
    """Format top documents as context for an LLM prompt."""
    context_parts = []
    for i, r in enumerate(results[:max_docs], 1):
        context_parts.append(f"[Source {i}] {r['document']}")
    return "\n".join(context_parts)

def hybrid_search_agent(query, llm_client, bm25_model, embedder,
                        doc_embeddings, documents, alpha=0.4):
    """
    A simple hybrid search agent.
    
    Args:
        query: User's question.
        llm_client: Any callable that takes a prompt string and returns text.
        bm25_model, embedder, doc_embeddings, documents: Search components.
        alpha: Keyword weight for fusion.
    
    Returns:
        A dict with the answer and the sources used.
    """
    # 1. Retrieve
    results = hybrid_search(query, bm25_model, embedder, doc_embeddings,
                            documents, top_k=5, alpha=alpha)
    
    # 2. Build context
    context = build_context(results, max_docs=3)
    
    # 3. Construct prompt
    prompt = f"""You are a helpful assistant. Answer the question using ONLY the 
context below. If the context doesn't contain the answer, say "I don't know."

Context:
{context}

Question: {query}

Answer:"""
    
    # 4. Generate answer (replace with your LLM of choice)
    answer = llm_client(prompt)
    
    return {
        "query": query,
        "answer": answer,
        "sources": results[:3],
    }

Choosing the Right Alpha

The alpha parameter controls the balance between keyword and semantic search. Choosing the right value depends on your data and use case:

Use Case Recommended Alpha Reasoning
Technical documentation (APIs, error codes) 0.7 – 0.9 Exact terms matter most.
FAQ / help desk 0.4 – 0.6 Balance of exact matches and paraphrased questions.
General knowledge / open-domain QA 0.1 – 0.3 Semantic understanding is more important.
Legal / compliance documents 0.6 – 0.8 Precise language is critical, but synonyms exist.

In production, you'd tune alpha using a labeled evaluation set — queries paired with relevance judgments — and measure metrics like NDCG or Mean Reciprocal Rank (MRR).

Coding Exercise

Exercise: Implement Reciprocal Rank Fusion

The hybrid search agent we built uses a weighted linear combination of normalized scores. Another popular fusion method is Reciprocal Rank Fusion (RRF), which works with rank positions instead of raw scores.

Your task: Write a function reciprocal_rank_fusion(kw_results, sem_results, k=60, top_k=5) that:

  1. Takes the keyword search results and semantic search results (each a list of dicts with an "index" key).
  2. Computes the RRF score for each document using the formula: RRF_score = 1/(k + rank_kw) + 1/(k + rank_sem). If a document appears in only one list, use 0 for the missing rank's contribution.
  3. Returns the top-k documents sorted by RRF score in descending order.

Then, replace the fusion step in hybrid_search() with your RRF function and compare the results. 

def reciprocal_rank_fusion(kw_results, sem_results, k=60, top_k=5):
    """
    Merge two ranked lists using Reciprocal Rank Fusion.
    
    Args:
        kw_results: List of dicts from keyword search (ordered by rank).
        sem_results: List of dicts from semantic search (ordered by rank).
        k: Smoothing constant (default 60).
        top_k: Number of results to return.
    
    Returns:
        List of dicts with 'index', 'document', and 'rrf_score'.
    """
    # Build rank lookup: document_index -> rank_position (1-based)
    kw_ranks = {r["index"]: rank + 1 for rank, r in enumerate(kw_results)}
    sem_ranks = {r["index"]: rank + 1 for rank, r in enumerate(sem_results)}
    
    # Collect all unique document indices
    all_indices = set(kw_ranks.keys()) | set(sem_ranks.keys())
    
    # Compute RRF scores
    rrf_scores = {}
    for idx in all_indices:
        score = 0.0
        if idx in kw_ranks:
            score += 1.0 / (k + kw_ranks[idx])
        if idx in sem_ranks:
            score += 1.0 / (k + sem_ranks[idx])
        rrf_scores[idx] = score
    
    # Sort by RRF score descending
    sorted_indices = sorted(rrf_scores, key=rrf_scores.get, reverse=True)
    
    results = []
    for idx in sorted_indices[:top_k]:
        results.append({
            "index": idx,
            "document": documents[idx],
            "rrf_score": rrf_scores[idx],
        })
    
    return results

# --- Usage ---
query = "semantic search and embeddings"
kw_results = keyword_search(query, bm25, documents, top_k=len(documents))
sem_results = semantic_search(query, embedder, doc_embeddings, documents,
                              top_k=len(documents))

rrf_results = reciprocal_rank_fusion(kw_results, sem_results, k=60, top_k=5)

print(f"Query: '{query}'\n")
for i, r in enumerate(rrf_results, 1):
    print(f"  #{i} [RRF={r['rrf_score']:.4f}] {r['document']}")

What to notice: RRF doesn't require score normalization because it only uses rank positions. This makes it robust when the two retrieval methods produce scores on very different scales — which is almost always the case.

Key Takeaways

  • Hybrid search combines keyword and semantic retrieval to get the best of both worlds: exact term matching and conceptual understanding.
  • BM25 is the standard keyword ranking function; cosine similarity over embeddings is the standard semantic approach.
  • Score normalization is essential before fusing results from different retrieval methods — their raw scores are not comparable.
  • Weighted linear fusion (with an alpha parameter) is the simplest fusion strategy; Reciprocal Rank Fusion (RRF) is a robust alternative that uses rank positions instead of scores.
  • The alpha parameter should be tuned based on your data. Favor keyword search for technical/exact-match domains and semantic search for open-ended/conceptual queries.
  • Wrapping retrieval in an agent means the system can decide when to search, format context for an LLM, and return grounded, cited answers.
  • In production, evaluate your hybrid search with metrics like NDCG or MRR on a labeled test set, and tune alpha (or switch to a learned re-ranker) based on those metrics.
