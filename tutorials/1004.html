Memory & Context

Learn about memory & context.

What Is Memory in AI Agents?

Imagine you're having a conversation with a friend. They remember what you said five minutes ago, last week, and even last year. That's memory — and it's what makes conversations feel natural and continuous.

AI agents, by default, are like someone with short-term amnesia. Every time you send a new message, the agent has no idea what you talked about before. That's where memory comes in. Memory is the mechanism that allows an AI agent to store, retrieve, and use information from past interactions.

Without memory, an AI agent can't:

  • Remember your name or preferences from a previous conversation
  • Build on earlier steps in a multi-step task
  • Maintain context across a long document analysis
  • Learn from past mistakes or successful strategies
💡 Key Concept: Memory in AI agents is not the same as the model's training data. Training data is fixed and baked into the model. Memory is dynamic — it's information the agent collects and references during a specific session or across sessions.

Types of Memory

Not all memory is the same. AI agents use different types of memory depending on what they need to remember and for how long. Let's break down the main types.

Short-Term Memory (Working Memory)

Short-term memory is like a notepad the agent uses during a single conversation. It holds the most recent messages, the current task details, and any immediate context the agent needs to respond coherently.

This is the simplest form of memory — it's essentially the conversation history that gets passed along with each new request.

# Example: Short-term memory as a conversation history
conversation_history = [
    {"role": "user", "content": "My name is Alex."},
    {"role": "assistant", "content": "Nice to meet you, Alex!"},
    {"role": "user", "content": "What's my name?"},
    # The agent can answer correctly because the history is included
]

# When making a new request, we include the full history
response = agent.chat(
    message="What's my name?",
    history=conversation_history
)
# The agent sees "My name is Alex" in the history and responds correctly

Long-Term Memory

Long-term memory is like a filing cabinet. The agent stores important facts, user preferences, and learned patterns that persist across multiple sessions. This is what allows an AI agent to "remember" you from one conversation to the next.

# Example: Storing and retrieving long-term memory
memory_store = {}

# After a conversation, the agent saves key facts
def save_memory(user_id, key, value):
    if user_id not in memory_store:
        memory_store[user_id] = {}
    memory_store[user_id][key] = value

# Later, the agent retrieves stored facts
def get_memory(user_id, key):
    return memory_store.get(user_id, {}).get(key, None)

# Usage
save_memory("user_123", "name", "Alex")
save_memory("user_123", "preferred_language", "Python")

# In a future session:
name = get_memory("user_123", "name")
print(f"Welcome back, {name}!")  # "Welcome back, Alex!"

Episodic Memory

Episodic memory stores specific events or experiences — like a diary. The agent remembers what happened in past interactions, not just abstract facts. This helps the agent learn from experience and avoid repeating mistakes.

Semantic Memory

Semantic memory stores general knowledge and facts — like a textbook. It's the agent's understanding of concepts, relationships, and rules that apply broadly, not tied to any specific event.

Memory Type Analogy Duration Example
Short-Term Notepad Current session "What did I just say?"
Long-Term Filing cabinet Across sessions "Alex prefers Python"
Episodic Diary Across sessions "Last time we tried X, it failed"
Semantic Textbook Persistent "Python uses indentation for blocks"

Context Windows: The Agent's Attention Span

Every AI model has a context window — the maximum amount of text it can process in a single request. Think of it as the agent's attention span. If the conversation exceeds this limit, the oldest messages get cut off, and the agent "forgets" them.

⚠️ Important: Context windows are measured in tokens (roughly ¾ of a word). A model with a 128K token context window can process about 96,000 words at once. Long conversations, large documents, and extensive memory can quickly fill this space.

Here's why context windows matter for memory:

  1. Conversation history eats into the context window. Every past message you include takes up space.
  2. System prompts and instructions also count. Your agent's personality, rules, and tools all consume tokens.
  3. When the window is full, something has to go. Usually, the oldest messages are dropped first.
# Example: Managing context window limits
MAX_CONTEXT_TOKENS = 8000  # Our model's limit
SYSTEM_PROMPT_TOKENS = 500  # Reserved for instructions
RESPONSE_TOKENS = 1000  # Reserved for the agent's reply

# Available space for conversation history:
available = MAX_CONTEXT_TOKENS - SYSTEM_PROMPT_TOKENS - RESPONSE_TOKENS
print(f"Available for history: {available} tokens")
# Output: Available for history: 6500 tokens

# Strategy: Keep only the most recent messages that fit
def trim_history(messages, max_tokens):
    """Keep recent messages that fit within the token budget."""
    total_tokens = 0
    kept_messages = []
    
    # Iterate from newest to oldest
    for msg in reversed(messages):
        msg_tokens = estimate_tokens(msg["content"])
        if total_tokens + msg_tokens <= max_tokens:
            kept_messages.insert(0, msg)
            total_tokens += msg_tokens
        else:
            break  # Stop when we run out of space
    
    return kept_messages

def estimate_tokens(text):
    """Rough estimate: ~4 characters per token."""
    return len(text) // 4

Memory Management Strategies

Since context windows are finite, smart agents need strategies to manage what they remember. Here are the most common approaches.

Sliding Window

The simplest strategy: keep only the N most recent messages. Older messages are simply discarded. It's easy to implement but can lose important early context.

Summarization

Instead of keeping every message, the agent periodically summarizes older conversation into a compact summary. This preserves the key information while freeing up space.

# Example: Summarization-based memory management
def summarize_and_compress(messages, summary_model):
    """
    When conversation gets too long, summarize older messages
    into a compact form and keep recent messages intact.
    """
    if len(messages) <= 10:
        return messages  # No compression needed yet
    
    # Split: summarize the older half, keep the recent half
    midpoint = len(messages) // 2
    older_messages = messages[:midpoint]
    recent_messages = messages[midpoint:]
    
    # Create a summary of older messages
    summary_text = "\n".join(
        f"{m['role']}: {m['content']}" for m in older_messages
    )
    summary = summary_model.summarize(
        f"Summarize this conversation:\n{summary_text}"
    )
    
    # Return: summary + recent messages
    return [
        {"role": "system", "content": f"Previous conversation summary: {summary}"},
        *recent_messages
    ]

Selective Memory

The agent decides what's worth remembering. Important facts, decisions, and user preferences are stored; small talk and redundant information are discarded.

💡 Pro Tip: In practice, most production AI agents use a combination of these strategies. They might use a sliding window for recent messages, summarization for older context, and a separate long-term memory store for important facts.

Implementing a Simple Memory System

Let's build a basic memory system for an AI agent from scratch. This will tie together everything we've learned.

class SimpleAgentMemory:
    """A basic memory system for an AI agent."""
    
    def __init__(self, max_history=20):
        self.conversation_history = []  # Short-term memory
        self.long_term_facts = {}       # Long-term memory
        self.max_history = max_history
    
    def add_message(self, role, content):
        """Add a new message to conversation history."""
        self.conversation_history.append({
            "role": role,
            "content": content
        })
        
        # Enforce sliding window limit
        if len(self.conversation_history) > self.max_history:
            self.conversation_history = self.conversation_history[-self.max_history:]
    
    def remember_fact(self, key, value):
        """Store a fact in long-term memory."""
        self.long_term_facts[key] = value
        print(f"Remembered: {key} = {value}")
    
    def recall_fact(self, key):
        """Retrieve a fact from long-term memory."""
        return self.long_term_facts.get(key, None)
    
    def get_context(self):
        """Build the full context for the next agent request."""
        context = []
        
        # Add long-term facts as a system message
        if self.long_term_facts:
            facts = "\n".join(
                f"- {k}: {v}" for k, v in self.long_term_facts.items()
            )
            context.append({
                "role": "system",
                "content": f"Remember these facts:\n{facts}"
            })
        
        # Add conversation history
        context.extend(self.conversation_history)
        
        return context
    
    def display_memory(self):
        """Show what the agent currently remembers."""
        print("=== Agent Memory ===")
        print(f"\nLong-term facts ({len(self.long_term_facts)}):")
        for key, value in self.long_term_facts.items():
            print(f"  • {key}: {value}")
        print(f"\nRecent messages ({len(self.conversation_history)}):")
        for msg in self.conversation_history[-3:]:
            print(f"  [{msg['role']}]: {msg['content'][:50]}...")


# --- Using the memory system ---
agent_mem = SimpleAgentMemory(max_history=10)

# Simulate a conversation
agent_mem.add_message("user", "Hi, I'm Sarah and I love hiking.")
agent_mem.add_message("assistant", "Great to meet you, Sarah! Hiking is wonderful.")

# Agent extracts and stores a fact
agent_mem.remember_fact("user_name", "Sarah")
agent_mem.remember_fact("user_hobby", "hiking")

# Later in the conversation
agent_mem.add_message("user", "What should I do this weekend?")

# Build context for the AI model
context = agent_mem.get_context()
print("\nContext sent to AI model:")
for msg in context:
    print(f"  [{msg['role']}]: {msg['content'][:60]}")

Memory and Context in Multi-Step Tasks

Memory becomes especially critical when an agent is working on a multi-step task. Imagine an agent that needs to research a topic, draft a report, and then revise it. Each step depends on the results of the previous one.

# Example: Multi-step task with memory
def research_agent(task, memory):
    """An agent that performs research in steps, using memory."""
    
    # Step 1: Plan the research
    memory.add_message("user", f"Plan research for: {task}")
    plan = ai_model.generate(
        context=memory.get_context()
    )
    memory.add_message("assistant", plan)
    memory.remember_fact("research_plan", plan)
    
    # Step 2: Execute each research step
    steps = parse_steps(plan)
    results = []
    
    for i, step in enumerate(steps):
        memory.add_message("user", f"Execute step {i+1}: {step}")
        result = ai_model.generate(
            context=memory.get_context()
        )
        memory.add_message("assistant", result)
        results.append(result)
        memory.remember_fact(f"step_{i+1}_result", result)
    
    # Step 3: Synthesize findings
    memory.add_message("user", "Synthesize all findings into a report.")
    report = ai_model.generate(
        context=memory.get_context()
    )
    memory.add_message("assistant", report)
    
    return report
💡 Why This Matters: Without memory, the agent would start each step from scratch, forgetting what it planned and what it already discovered. Memory turns a series of disconnected requests into a coherent, multi-step workflow.

import re

class SupportAgent:
    def __init__(self):
        self.memory = {
            "customer_name": None,
            "issue_category": None,
            "messages": []
        }
    
    def handle_message(self, user_message):
        # 1. Extract name
        name_match = re.search(
            r"(?:my name is|i'm|i am)\s+(\w+)",
            user_message, re.IGNORECASE
        )
        if name_match:
            self.memory["customer_name"] = name_match.group(1)
        
        # 2. Detect issue category
        msg_lower = user_message.lower()
        if any(word in msg_lower for word in ["charge", "bill", "payment", "invoice"]):
            self.memory["issue_category"] = "billing"
        elif any(word in msg_lower for word in ["error", "bug", "not working", "crash"]):
            self.memory["issue_category"] = "technical"
        elif self.memory["issue_category"] is None:
            self.memory["issue_category"] = "general"
        
        # 3. Store message
        self.memory["messages"].append({
            "role": "user", "content": user_message
        })
        
        # 4. Build response using memory
        name = self.memory["customer_name"]
        category = self.memory["issue_category"]
        
        greeting = f"Hi {name}! " if name else "Hello! "
        
        if category == "billing":
            response = greeting + "I'll connect you with our billing department."
        elif category == "technical":
            response = greeting + "Let me help you troubleshoot that technical issue."
        else:
            response = greeting + "How can I assist you today?"
        
        self.memory["messages"].append({
            "role": "assistant", "content": response
        })
        
        return response

# Output: "Hi Jordan! I'll connect you with our billing department."

# Output: "Hi Jordan! I'll connect you with our billing department."

Common Pitfalls with Memory

As you start building memory into your agents, watch out for these common mistakes:

  • Memory bloat: Storing everything without filtering. Your context window fills up with irrelevant details, and the agent's responses become slower and less focused.
  • Forgetting to update memory: The agent stores a fact once but never updates it when circumstances change. "User prefers email" becomes outdated when the user switches to preferring chat.
  • Over-relying on conversation history: Simply passing the entire chat history isn't true memory. It's expensive, limited by context windows, and doesn't scale.
  • Not handling memory conflicts: What happens when the user says "Actually, my name is Sam" after previously saying "I'm Alex"? Your memory system needs conflict resolution.
⚠️ Watch Out: Always consider the cost of memory. More memory means more tokens per request, which means higher API costs and slower responses. Be intentional about what you store.

Key Takeaways

  • Memory is what makes AI agents conversational. Without it, every interaction starts from zero.
  • There are multiple types of memory: short-term (conversation history), long-term (stored facts), episodic (past events), and semantic (general knowledge).
  • Context windows are finite. Every token of memory competes with every token of your prompt and the model's response.
  • Use memory management strategies like sliding windows, summarization, and selective storage to stay within context limits.
  • Multi-step tasks depend on memory to maintain coherence across planning, execution, and synthesis phases.
  • Keep memory intentional. Store what matters, update when things change, and always be mindful of token costs.
