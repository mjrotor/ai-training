End-to-End RAG Pipeline

Learn about end-to-end rag pipeline.

What Is an End-to-End RAG Pipeline?

Retrieval-Augmented Generation (RAG) is a powerful technique that combines the strengths of information retrieval and large language models (LLMs). Instead of relying solely on a model's pre-trained knowledge, RAG retrieves relevant documents from an external knowledge base and uses them to generate more accurate, up-to-date, and context-aware responses.

An end-to-end RAG pipeline refers to the complete workflow—from ingesting raw data, indexing it, retrieving relevant chunks at query time, and finally generating a grounded response. In this lesson, we'll build one from scratch using Python.

💡 Why RAG? LLMs have a knowledge cutoff and can hallucinate. RAG grounds the model's output in real, verifiable data—making it ideal for enterprise search, customer support bots, and internal knowledge assistants.

Core Components of a RAG Pipeline

Every RAG system, regardless of complexity, consists of the following stages:

  1. Data Ingestion — Load raw documents (PDFs, web pages, text files, etc.).
  2. Chunking — Split documents into smaller, meaningful segments.
  3. Embedding — Convert each chunk into a numerical vector using an embedding model.
  4. Indexing & Storage — Store vectors in a vector database for fast similarity search.
  5. Retrieval — Given a user query, find the most relevant chunks.
  6. Generation — Feed the retrieved chunks + query into an LLM to produce a final answer.
🔧 Tip: The quality of your RAG system depends heavily on chunking strategy and embedding model choice. Poor chunking = poor retrieval = poor answers.

Step 1: Setting Up the Environment

We'll use langchain, chromadb, and openai for this tutorial. Install the required packages:

pip install langchain langchain-openai chromadb tiktoken

Set your OpenAI API key as an environment variable:

import os

Step 2: Loading and Chunking Documents

LangChain provides built-in document loaders and text splitters. Here's how to load a text file and split it into overlapping chunks:

from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

# Load a document
loader = TextLoader("company_handbook.txt", encoding="utf-8")
documents = loader.load()

# Split into chunks
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    length_function=len,
)
chunks = text_splitter.split_documents(documents)

print(f"Total chunks created: {len(chunks)}")
print(f"First chunk preview:\n{chunks[0].page_content[:200]}")

Why RecursiveCharacterTextSplitter?

This splitter tries to split on natural boundaries (paragraphs → sentences → words) before falling back to character count. This preserves semantic coherence better than a naive fixed-width split.

Splitter Best For Pros Cons
RecursiveCharacterTextSplitter General text documents Preserves structure, configurable overlap May split mid-sentence if no natural break
CharacterTextSplitter Simple, uniform text Fast and predictable Ignores document structure
TokenTextSplitter Token-aware splitting (for LLMs) Respects token limits Requires tokenizer, slightly slower

Step 3: Creating Embeddings and Storing in a Vector Database

We convert each chunk into a vector embedding and store it in ChromaDB—a lightweight, in-memory vector store perfect for prototyping.

from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Chroma

# Initialize the embedding model
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# Create a vector store from our chunks
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db"
)

print(f"Vector store created with {vectorstore._collection.count()} documents")
⚠️ Warning: For production systems, use a persistent vector database like Pinecone, Weaviate, or Qdrant instead of in-memory ChromaDB. In-memory stores lose data when the process exits.

Step 4: Retrieving Relevant Chunks

When a user asks a question, we embed the query and perform a similarity search against our vector store.

# Define a user query
query = "What is the company's remote work policy?"

# Retrieve the top 3 most relevant chunks
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 3}
)

relevant_docs = retriever.invoke(query)

for i, doc in enumerate(relevant_docs):
    print(f"--- Result {i+1} ---")
    print(doc.page_content[:300])
    print()

Retrieval Strategies

  • Similarity Search — Returns the k most similar vectors by cosine distance.
  • Maximal Marginal Relevance (MMR) — Balances relevance with diversity to avoid redundant results.
  • Similarity Score Threshold — Only returns results above a minimum similarity score.
# Using MMR for more diverse results
retriever_mmr = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 3, "fetch_k": 10, "lambda_mult": 0.5}
)

mmr_docs = retriever_mmr.invoke(query)

Step 5: Generating the Final Answer

Now we combine the retrieved context with the user's query and pass everything to an LLM using a prompt template.

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

# Define the prompt template
template = """You are a helpful assistant. Use the following context to answer the question.
If the answer is not in the context, say "I don't know based on the provided documents."

Context:
{context}

Question: {question}

Answer:"""

prompt = ChatPromptTemplate.from_template(template)

# Initialize the LLM
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# Format documents into a single string
def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

# Build the RAG chain
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)

# Run the full pipeline
answer = rag_chain.invoke("What is the company's remote work policy?")
print(answer)
🧠 How it works: The RunnablePassthrough passes the original question through unchanged, while the retriever fetches and formats context. Both are fed into the prompt, which the LLM uses to generate a grounded answer.

Putting It All Together: The Complete Pipeline

Here's the full end-to-end RAG pipeline in one cohesive script:

import os
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

os.environ["OPENAI_API_KEY"] = "sk-your-api-key-here"

# 1. Load documents
loader = TextLoader("company_handbook.txt", encoding="utf-8")
documents = loader.load()

# 2. Chunk documents
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(documents)

# 3. Embed and store
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(documents=chunks, embedding=embeddings)

# 4. Set up retriever
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 5. Define prompt and LLM
template = """Use the context below to answer the question. If unsure, say "I don't know."

Context: {context}
Question: {question}
Answer:"""
prompt = ChatPromptTemplate.from_template(template)
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 6. Build and run the chain
def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)

response = rag_chain.invoke("What is the company's remote work policy?")
print(response)

Common Pitfalls and How to Avoid Them

⚠️ Chunk Size Matters: Too small → loss of context. Too large → irrelevant information dilutes the signal. Start with 500–1000 characters and tune based on your data.
  • Garbage in, garbage out: Clean your source documents before ingestion. Remove headers, footers, and boilerplate text.
  • Stale embeddings: If your source data changes, you must re-index. Consider setting up a periodic refresh pipeline.
  • Over-reliance on top-1 result: Always retrieve multiple chunks (k=3 to k=5) to give the LLM enough context.
  • No source attribution: Modify your prompt to ask the LLM to cite which document or section it used. This builds trust and enables verification.

Key Takeaways

  • RAG combines retrieval (finding relevant documents) with generation (producing a natural language answer) to create more accurate and grounded AI responses.
  • The six stages of a RAG pipeline are: ingestion → chunking → embedding → indexing → retrieval → generation.
  • Chunking strategy directly impacts retrieval quality—use RecursiveCharacterTextSplitter for most text documents.
  • Vector databases like ChromaDB enable fast similarity search over embedded document chunks.
  • LangChain's Expression Language (LCEL) makes it easy to compose retrieval and generation into a single runnable chain.
  • Always retrieve multiple chunks (k=3–5) and consider using MMR for diverse results.
  • For production, replace in-memory ChromaDB with a persistent vector store and implement re-indexing for data freshness.
