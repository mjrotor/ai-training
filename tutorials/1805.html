Building the Full Code Review Agent

Learn about building the full code review agent.

What Is a Code Review Agent?

A code review agent is an AI-powered assistant that automatically analyzes source code for bugs, style violations, security issues, and opportunities for improvement. Instead of relying solely on human reviewers, we can build an intelligent agent that reads code, understands context, and provides meaningful feedback — just like a senior developer would.

In this lesson, we will build a full code review agent that takes a Python file as input, sends it to a language model, and returns structured feedback including issues found, severity levels, and suggested fixes.

Architecture Overview

Our code review agent will follow a pipeline architecture with four main stages:

  1. Input Parsing: Read the target source file and extract its contents.
  2. Prompt Construction: Build a detailed system prompt that instructs the model to act as a code reviewer.
  3. LLM Invocation: Send the prompt to the language model and capture the response.
  4. Output Parsing: Parse the model's response into a structured list of review comments.

Why a pipeline? Breaking the agent into discrete stages makes each piece easier to test, debug, and swap out. If you later want to change the model or add new review categories, you only modify the relevant stage.

Setting Up the Project

Create a new file called code_review_agent.py and install the required dependency:

pip install openai

We will use the OpenAI Python SDK to communicate with the language model. Make sure you have your API key set as an environment variable:

import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

Stage 1 — Reading the Source File

The first step is to read the file we want to review. We will write a helper function that safely opens the file and returns its contents as a string.

def read_source_file(filepath: str) -> str:
    """Read a source file and return its contents."""
    try:
        with open(filepath, "r", encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError:
        raise FileNotFoundError(f"File not found: {filepath}")
    except UnicodeDecodeError:
        raise ValueError(f"Cannot decode file: {filepath}")

Tip: Always specify encoding="utf-8" when opening files. Different operating systems use different default encodings, and explicit is better than implicit.

Stage 2 — Building the Review Prompt

The prompt is the most critical part of the agent. A well-crafted prompt determines the quality of the review. We want the model to:

  • Identify bugs and logic errors
  • Flag security vulnerabilities
  • Suggest performance improvements
  • Comment on code style and readability
  • Return results in a structured JSON format
REVIEW_SYSTEM_PROMPT = """
You are an expert code reviewer. Analyze the following Python code and return 
your findings as a JSON array. Each item in the array should have:
  - "line": the approximate line number of the issue (integer)
  - "severity": one of "low", "medium", "high", "critical"
  - "category": one of "bug", "security", "performance", "style"
  - "message": a clear description of the issue
  - "suggestion": how to fix it

Only return valid JSON. Do not include any extra text.
"""

def build_review_prompt(source_code: str) -> list[dict]:
    return [
        {"role": "system", "content": REVIEW_SYSTEM_PROMPT},
        {"role": "user", "content": f"Review this Python code:\n\n{source_code}"}
    ]

Stage 3 — Calling the Language Model

With the prompt ready, we invoke the model and handle potential errors gracefully.

def call_reviewer(messages: list[dict]) -> str:
    """Send messages to the LLM and return the raw response text."""
    try:
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            temperature=0.1,   # low temperature for consistent output
            max_tokens=2000,
        )
        return response.choices[0].message.content
    except Exception as e:
        raise RuntimeError(f"LLM call failed: {e}")

Warning: Always wrap API calls in error handling. Network issues, rate limits, and invalid responses can all cause exceptions in production.

Stage 4 — Parsing the Response

The model returns a JSON string. We need to parse it into a Python list of dictionaries that our application can work with.

import json

def parse_review_response(raw: str) -> list[dict]:
    """Parse the LLM's JSON response into a list of review items."""
    # Strip markdown code fences if present
    raw = raw.strip()
    if raw.startswith("```"):
        raw = raw.split("\n", 1)[1]            # remove first line (```json)
        raw = raw.rsplit("\n", 1)[0]            # remove last line (```)
        raw = raw.strip()

    try:
        findings = json.loads(raw)
        if not isinstance(findings, list):
            raise ValueError("Expected a JSON array")
        return findings
    except json.JSONDecodeError as e:
        raise ValueError(f"Failed to parse review JSON: {e}\nRaw: {raw[:200]}")

Putting It All Together

Now we combine every stage into a single review_code function:

def review_code(filepath: str) -> list[dict]:
    """End-to-end code review pipeline."""
    # Stage 1: Read the file
    source = read_source_file(filepath)

    # Stage 2: Build the prompt
    messages = build_review_prompt(source)

    # Stage 3: Call the LLM
    raw_response = call_reviewer(messages)

    # Stage 4: Parse and return structured findings
    findings = parse_review_response(raw_response)

    return findings


if __name__ == "__main__":
    import sys
    target = sys.argv[1] if len(sys.argv) > 1 else "example.py"
    results = review_code(target)

    for item in results:
        print(f"[{item['severity'].upper()}] Line {item['line']} "
              f"({item['category']}): {item['message']}")
        print(f"  Suggestion: {item['suggestion']}\n")

Comparing Review Strategies

Different review strategies trade off speed, cost, and depth. Here is a comparison:

Strategy Speed Cost Depth Best For
Single-pass review Fast Low Moderate Small files, quick checks
Multi-pass (file + function) Slow High Deep Large codebases, critical systems
Rule-based + LLM hybrid Medium Medium High Teams with strict style guides
Full agent with tool use Slowest Highest Very Deep Complex projects, CI/CD pipelines

Hybrid approach: For production systems, combine fast rule-based linters (like flake8 or ruff) with the LLM review. The linter catches obvious issues instantly, while the LLM handles nuanced logic and design problems.

Adding Severity-Based Filtering

Not every finding deserves the same attention. Let us add a filter so users can focus on what matters most.

SEVERITY_ORDER = {"low": 0, "medium": 1, "high": 2, "critical": 3}

def filter_findings(findings: list[dict], min_severity: str = "medium") -> list[dict]:
    """Return only findings at or above the given severity level."""
    min_level = SEVERITY_ORDER.get(min_severity, 0)
    return [f for f in findings if SEVERITY_ORDER.get(f["severity"], 0) >= min_level]


# Usage
results = review_code("app.py")
critical_issues = filter_findings(results, min_severity="high")
print(f"Found {len(critical_issues)} high/critical issues.")
Exercise

Your task: Add a new function called summarize_review that takes the list of findings and returns a summary dictionary with the following keys:

  • "total" — total number of findings
  • "by_severity" — a dict counting findings per severity level
  • "by_category" — a dict counting findings per category
  • "top_issue" — the finding with the highest severity (or None if empty)

Assume each finding dict has "severity" and "category" keys.

def summarize_review(findings: list[dict]) -> dict:
    """Produce a summary of code review findings."""
    if not findings:
        return {"total": 0, "by_severity": {}, "by_category": {}, "top_issue": None}

    by_severity: dict[str, int] = {}
    by_category: dict[str, int] = {}

    for f in findings:
        sev = f.get("severity", "low")
        cat = f.get("category", "style")
        by_severity[sev] = by_severity.get(sev, 0) + 1
        by_category[cat] = by_category.get(cat, 0) + 1

    top_issue = max(findings, key=lambda x: SEVERITY_ORDER.get(x["severity"], 0))

    return {
        "total": len(findings),
        "by_severity": by_severity,
        "by_category": by_category,
        "top_issue": top_issue,
    }

Key Takeaways

  • A code review agent follows a four-stage pipeline: read, prompt, call, and parse.
  • The system prompt is the most important component — it defines the agent's behavior and output format.
  • Always use low temperature (0.1–0.3) for review tasks to get consistent, reproducible results.
  • Structured JSON output makes it easy to filter, sort, and display findings programmatically.
  • Combining fast rule-based linters with LLM-based review gives the best balance of speed and depth.
  • Error handling around file I/O and API calls is essential for a production-ready agent.
  • Severity-based filtering helps developers focus on the most critical issues first.
