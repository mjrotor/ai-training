Understanding the Peer-to-Peer Pattern in AI Agents

Today, we're exploring the Peer-to-Peer Pattern, where multiple AI agents work together as equals to solve problems. Unlike hierarchical systems with a central boss agent, peer agents collaborate directly with each other.

What Makes Peer-to-Peer Different?

In this pattern:

  • All agents have equal status - no single leader
  • Agents communicate directly with each other
  • Each agent has its own specialized expertise
  • The system is decentralized and resilient
Why Use This Pattern? Peer-to-peer systems are more robust - if one agent fails, others continue working. They're perfect for distributed tasks where agents need to share information directly.

Basic Peer-to-Peer Architecture

Here's how a simple peer-to-peer agent system might look:

class PeerAgent:
    def __init__(self, name, specialty):
        self.name = name
        self.specialty = specialty
        self.knowledge = {}
    
    def receive_message(self, sender, message):

        print(f"{self.name} received from {sender}: {message}")
        # Process the message based on specialty
        return self.process_message(message)
    
    def process_message(self, message):
        """Process message using agent's specialty"""
        # Each agent has its own processing logic
        return f"{self.name} processed: {message}"
    
    def send_message(self, recipient, message):
        """Send message to another peer agent"""
        return recipient.receive_message(self.name, message)

Message Passing Between Peers

The core of peer-to-peer systems is message passing. Here's a practical example:

class MessageBus:
    """Simple message bus for peer communication"""
    def __init__(self):
        self.agents = {}
        self.message_log = []
    
    def register_agent(self, agent):
        """Register a new peer agent"""
        self.agents[agent.name] = agent
        print(f"Registered agent: {agent.name}")
    
    def broadcast(self, sender_name, message):
        """Send message to all peers except sender"""
        sender = self.agents.get(sender_name)
        if not sender:
            print(f"Agent {sender_name} not found!")
            return
        
        for name, agent in self.agents.items():
            if name != sender_name:
                response = agent.receive_message(sender_name, message)
                self.message_log.append({
                    'from': sender_name,
                    'to': name,
                    'message': message,
                    'response': response
                })
    
    def get_message_history(self):
        """Return all messages exchanged"""
        return self.message_log
Pro Tip: In real systems, you'd add message validation, error handling, and possibly encryption for security!

Specialized Peer Agents Working Together

Let's create a system with specialized agents for a research task:

class ResearchAgent(PeerAgent):
    """Agent specialized in research tasks"""
    def __init__(self, name, research_area):
        super().__init__(name, "research")
        self.research_area = research_area
        self.findings = []
    
    def conduct_research(self, topic):
        """Simulate research on a topic"""
        finding = f"Research on {topic} in {self.research_area}"
        self.findings.append(finding)
        return finding
    
    def share_findings(self, recipient):
        """Share research findings with another agent"""
        if self.findings:
            latest = self.findings[-1]
            return self.send_message(recipient, latest)
        return "No findings to share"

class AnalysisAgent(PeerAgent):
    """Agent specialized in data analysis"""
    def __init__(self, name):
        super().__init__(name, "analysis")
        self.analyses = []
    
    def analyze_data(self, data):
        """Analyze provided data"""
        analysis = f"Analysis of: {data[:50]}..."  # Truncate for display
        self.analyses.append(analysis)
        return analysis
    
    def request_analysis(self, data, analyst):
        """Request analysis from another agent"""
        return analyst.analyze_data(data)

Coordination Without a Central Controller

Peers need ways to coordinate. Here's a simple coordination protocol:

class PeerCoordinator:
    """Coordinates peer agents without being a central authority"""
    def __init__(self):
        self.peers = {}
        self.tasks = []
    
    def add_peer(self, peer):
        """Add a peer to the network"""
        self.peers[peer.name] = peer
        # Notify all existing peers about the new member
        for name, existing_peer in self.peers.items():
            if name != peer.name:
                existing_peer.receive_message("System", 
                    f"New peer joined: {peer.name}")
    
    def distribute_task(self, task):
        """Distribute task to appropriate peer"""
        # Simple round-robin assignment
        peer_names = list(self.peers.keys())
        if not peer_names:
            return "No peers available"
        
        # Assign to first available peer (simplified)
        assigned_peer = self.peers[peer_names[0]]
        result = assigned_peer.process_message(task)
        return {
            'assigned_to': assigned_peer.name,
            'result': result
        }
    
    def get_network_status(self):
        """Get status of all peers"""
        return {
            name: {
                'specialty': peer.specialty,
                'active': True  # Simplified - real systems would check
            }
            for name, peer in self.peers.items()
        }
Watch Out: Peer systems can become complex! Start simple and add coordination mechanisms only when needed.

Building a Complete Peer System

Here's a complete example of a peer-to-peer research system:

def create_research_network():
    """Create a network of research agents"""
    # Create specialized agents
    researcher1 = ResearchAgent("Alice", "Machine Learning")
    researcher2 = ResearchAgent("Bob", "Natural Language Processing")
    analyst = AnalysisAgent("Charlie")
    
    # Create message bus for communication
    bus = MessageBus()
    bus.register_agent(researcher1)
    bus.register_agent(resear2)
    bus.register_agent(analyst)
    
    # Simulate research collaboration
    print("=== Research Collaboration ===")
    
    # Alice conducts research
    finding = researcher1.conduct_research("Transformer architectures")
    print(f"Alice's finding: {finding}")
    
    # Alice shares with Bob
    response = researcher1.share_findings(researcher2)
    print(f"Bob's response: {response}")
    
    # Bob builds on Alice's work
    improved_finding = researcher2.conduct_research(
        "Improved transformers based on Alice's work"
    )
    print(f"Bob's improvement: {improved_finding}")
    
    # Charlie analyzes the combined findings
    combined_data = f"{finding} + {improved_finding}"
    analysis = analyst.analyze_data(combined_data)
    print(f"Charlie's analysis: {analysis}")
    
    # Broadcast final results
    bus.broadcast("Charlie", "Analysis complete!")
    
    return bus.get_message_history()

# Run the collaboration
history = create_research_network()
print(f"\nTotal messages exchanged: {len(history)}")
Exercise: Create a Peer Voting System

Create a simple peer voting system where agents can propose ideas and vote on them. Your system should:

  • Allow any agent to propose an idea
  • Let other agents vote (agree/disagree)
  • Determine if an idea passes based on majority vote
  • Track which agents voted for which ideas

Implement the VotingPeer class and a simple voting mechanism.

class VotingPeer:
    """Peer agent that can participate in voting"""
    def __init__(self, name, expertise):
        self.name = name
        self.expertise = expertise
        self.votes_cast = {}  # idea_id -> vote
        self.ideas_proposed = []
    
    def propose_idea(self, idea_id, idea_description):
        """Propose a new idea for voting"""
        idea = {
            'id': idea_id,
            'description': idea_description,
            'proposer': self.name,
            'votes': {self.name: 'agree'}  # Proposer auto-agrees
        }
        self.ideas_proposed.append(idea_id)
        return idea
    
    def vote(self, idea, vote_value):
        """Cast a vote on an idea"""
        if vote_value not in ['agree', 'disagree']:
            raise ValueError("Vote must be 'agree' or 'disagree'")
        
        idea['votes'][self.name] = vote_value
        self.votes_cast[idea['id']] = vote_value
        return f"{self.name} voted {vote_value} on {idea['id']}"
    
    def get_vote_result(self, idea):
        """Get the result of voting on an idea"""
        votes = idea['votes']
        agree = sum(1 for v in votes.values() if v == 'agree')
        disagree = sum(1 for v in votes.values() if v == 'disagree')
        
        return {
            'idea_id': idea['id'],
            'total_votes': len(votes),
            'agree': agree,
            'disagree': disagree,
            'passed': agree > disagree,
            'voters': dict(votes)
        }

class VotingSystem:
    """Manages peer voting across multiple agents"""
    def __init__(self):
        self.peers = {}
        self.ideas = {}
    
    def add_peer(self, peer):
        """Add a peer to the voting system"""
        self.peers[peer.name] = peer
    
    def propose_and_vote(self, proposer_name, idea_id, description):
        """Propose an idea and collect votes from all peers"""
        proposer = self.peers[proposer_name]
        idea = proposer.propose_idea(idea_id, description)
        self.ideas[idea_id] = idea
        
        # Collect votes from other peers
        for name, peer in self.peers.items():
            if name != proposer_name:
                # Simple voting logic - real system would be more complex
                vote = 'agree' if len(description) > 20 else 'disagree'
                peer.vote(idea, vote)
        
        return proposer.get_vote_result(idea)

Key Takeaways

  • Peer-to-peer means agents work as equals without a central controller
  • Agents communicate directly with each other through messages
  • Each peer has specialized expertise they contribute to the group
  • The pattern is resilient - if one agent fails, others continue
  • Message buses help coordinate communication between peers
  • Voting systems help resolve conflicts and make group decisions
  • Start simple and add coordination complexity only when needed
