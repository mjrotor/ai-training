Production Tool Agent Pattern

Learn about production tool agent pattern.

Introduction

Welcome to Day 5, Lesson 5! Today, we're diving into one of the most practical patterns in AI agent development: the Production Tool Agent Pattern. This pattern is all about giving your AI agents the ability to use real-world tools—like APIs, databases, and file systems—to accomplish tasks. By the end of this lesson, you'll understand how to build agents that can interact with external services, handle errors gracefully, and scale for production use.

What Is the Tool Agent Pattern?

The Tool Agent Pattern is an architectural approach where an AI agent is equipped with a set of predefined tools (functions or APIs) that it can call upon to complete tasks. Instead of trying to do everything itself, the agent intelligently selects and uses the right tool for the job—much like a human worker choosing between a calculator, a spreadsheet, or a database query.

💡 Key Idea: The agent doesn't need to know how each tool works internally—it just needs to know what each tool does and when to use it.

Why Use This Pattern?

  • Modularity: Tools can be developed, tested, and updated independently.
  • Scalability: Add new capabilities by simply adding new tools.
  • Reliability: Isolate failures—if one tool breaks, others keep working.
  • Security: Control exactly what actions the agent can perform.

Core Components

Every Tool Agent has three main parts:

  1. The Agent: The AI brain that decides which tool to use and when.
  2. The Tools: Functions or services the agent can call (e.g., search, calculate, send email).
  3. The Orchestrator: The logic that connects the agent to the tools and manages the workflow.

Tool Definition

Each tool should have a clear interface. In Python, we typically define tools as functions with descriptive names and docstrings. Here's an example:

def search_web(query: str) -> str:
    """
    Searches the web for the given query and returns a summary.
    
    Args:
        query: The search term or question.
    
    Returns:
        A string containing the search results summary.
    """
    # In production, this would call a real search API
    return f"Search results for '{query}': [summary of top 3 results]"

Building a Simple Tool Agent

Let's build a basic agent that can choose between two tools: a calculator and a web search. The agent will analyze the user's request and pick the right tool.

class SimpleToolAgent:
    def __init__(self):
        self.tools = {
            "calculator": self.calculate,
            "search": self.search_web
        }
    
    def calculate(self, expression: str) -> str:
        """Evaluates a mathematical expression safely."""
        try:
            # WARNING: eval() is dangerous in production!
            # Use a safe math parser instead.
            result = eval(expression, {"__builtins__": {}}, {})
            return f"Result: {result}"
        except Exception as e:
            return f"Error calculating: {e}"
    
    def search_web(self, query: str) -> str:
        """Simulates a web search."""
        return f"Search results for '{query}': [top 3 results]"
    
    def run(self, user_input: str) -> str:
        """Decides which tool to use based on user input."""
        # Simple keyword matching (in production, use LLM reasoning)
        if any(word in user_input.lower() for word in ["calculate", "math", "compute"]):
            return self.calculate(user_input)
        elif any(word in user_input.lower() for word in ["search", "find", "look up"]):
            return self.search_web(user_input)
        else:
            return "I'm not sure which tool to use. Try asking me to calculate or search something!"

# Usage
agent = SimpleToolAgent()
print(agent.run("Calculate 25 * 4"))  # Uses calculator
print(agent.run("Search for Python tutorials"))  # Uses search
⚠️ Security Note: Never use eval() with untrusted input in production! This example is simplified for learning. Always use safe parsing libraries like ast.literal_eval or dedicated math parsers.

Error Handling in Tool Agents

In production, things go wrong. APIs fail, inputs are malformed, and network connections drop. Your agent needs to handle these gracefully.

Common Error Scenarios

  • Tool not found: The agent tries to use a tool that doesn't exist.
  • Invalid input: The user provides data the tool can't process.
  • API failure: An external service is down or returns an error.
  • Timeout: A tool takes too long to respond.

Implementing Robust Error Handling

import time

Tool Selection Strategies

How does an agent decide which tool to use? Here are common approaches:

Strategy Description Best For Complexity
Keyword Matching Match user input keywords to tool names Simple agents with few tools Low
LLM Reasoning Use the AI to analyze intent and select tools Complex agents with many tools High
Rule-Based Predefined rules for tool selection Predictable workflows Medium
Hybrid Combine multiple strategies Production systems High
💡 Pro Tip: Start with keyword matching for prototyping, then upgrade to LLM reasoning as your agent grows. This keeps development fast while allowing for future sophistication.

Production Considerations

When deploying tool agents to production, keep these best practices in mind:

1. Input Validation

Always validate inputs before passing them to tools. This prevents crashes and security vulnerabilities.

def validate_search_query(query: str) -> Optional[str]:
    """Validates and sanitizes a search query."""
    if not query or not query.strip():
        return None
    
    # Remove potentially dangerous characters
    sanitized = "".join(c for c in query if c.isalnum() or c in " -_")
    
    # Limit length
    if len(sanitized) > 200:
        sanitized = sanitized[:200]
    
    return sanitized

2. Logging and Monitoring

Track which tools are being used, how often they succeed, and where failures occur.

import logging
from datetime import datetime

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("ToolAgent")

class MonitoredToolAgent:
    def __init__(self):
        self.tool_usage = {}
    
    def log_tool_call(self, tool_name: str, success: bool, duration: float):
        """Logs tool usage for monitoring."""
        if tool_name not in self.tool_usage:
            self.tool_usage[tool_name] = {"calls": 0, "successes": 0, "failures": 0}
        
        self.tool_usage[tool_name]["calls"] += 1
        if success:
            self.tool_usage[tool_name]["successes"] += 1
        else:
            self.tool_usage[tool_name]["failures"] += 1
        
        logger.info(f"Tool '{tool_name}' called. Success: {success}, Duration: {duration:.2f}s")
    
    def get_usage_stats(self) -> dict:
        """Returns usage statistics for all tools."""
        return self.tool_usage

3. Rate Limiting

Prevent abuse by limiting how often tools can be called.

import time
from collections import defaultdict

class RateLimitedAgent:
    def __init__(self, max_calls_per_minute: int = 10):
        self.max_calls = max_calls_per_minute
        self.call_times = defaultdict(list)
    
    def can_call_tool(self, tool_name: str) -> bool:
        """Checks if a tool can be called without exceeding rate limits."""
        now = time.time()
        minute_ago = now - 60
        
        # Remove old entries
        self.call_times[tool_name] = [
            t for t in self.call_times[tool_name] if t > minute_ago
        ]
        
        return len(self.call_times[tool_name]) < self.max_calls
    
    def record_call(self, tool_name: str):
        """Records a tool call for rate limiting."""
        self.call_times[tool_name].append(time.time())

Exercise: Build a Weather Tool Agent

Create a WeatherAgent class that can:

  1. Accept a user query about weather (e.g., "What's the weather in Paris?")
  2. Extract the city name from the query
  3. Call a simulated weather tool that returns a fake weather report
  4. Handle cases where no city is mentioned

Your agent should have at least two methods:

  • extract_city(query) - extracts city name from text
  • get_weather(city) - returns a simulated weather string

Test your agent with: "What's the weather in Tokyo?" and "Tell me the weather"

import random

class WeatherAgent:
    def __init__(self):
        self.weather_conditions = ["sunny", "cloudy", "rainy", "snowy", "windy"]
    
    def extract_city(self, query: str) -> str:
        """Extracts city name from a weather query."""
        # Simple extraction - look for "in" followed by a word
        words = query.lower().split()
        if "in" in words:
            city_index = words.index("in") + 1
            if city_index < len(words):
                return words[city_index].capitalize()
        return None
    
    def get_weather(self, city: str) -> str:
        """Returns a simulated weather report for the city."""
        condition = random.choice(self.weather_conditions)
        temp = random.randint(-10, 35)
        return f"Weather in {city}: {condition}, {temp}°C"
    
    def run(self, query: str) -> str:
        """Processes a weather query."""
        city = self.extract_city(query)
        
        if city is None:
            return "Please specify a city. Example: 'What's the weather in Paris?'"
        
        return self.get_weather(city)

# Test the agent
agent = WeatherAgent()
print(agent.run("What's the weather in Tokyo?"))
print(agent.run("Tell me the weather"))

Key Takeaways

  • The Tool Agent Pattern gives AI agents the ability to use external tools to accomplish tasks.
  • Tools should have clear interfaces with descriptive names and documentation.
  • Error handling is critical—always plan for tools to fail.
  • Use input validation to prevent crashes and security issues.
  • Logging and monitoring help you understand how your agent performs in production.
  • Rate limiting prevents abuse and manages resource usage.
  • Start simple with keyword matching, then upgrade to more sophisticated selection strategies as needed.
