Multi-Step Tool Workflows

Learn about multi-step tool workflows.

What Is a Multi-Step Tool Workflow?

So far, you've learned how to give an AI agent a single tool — like a calculator or a search function — and let it use that tool to answer a question. But real-world problems are rarely that simple. Most tasks require an agent to chain multiple tools together, using the output of one tool as the input to the next. This is what we call a multi-step tool workflow.

Think of it like cooking a meal. You don't just do one thing — you chop vegetables, heat a pan, combine ingredients, and plate the result. Each step builds on the last. Multi-step tool workflows work the same way: the agent decides which tools to use, in what order, and how to pass information between them.

Why Multi-Step Workflows Matter

Single-tool interactions are great for simple questions like "What's 15% of 200?" But consider a question like: "Find the population of France, convert it from millions to individual units, then calculate how many people that is per square kilometer." That requires at least three steps:

  1. Search for France's population.
  2. Convert the result into a raw number.
  3. Divide by France's land area.

A well-designed AI agent can plan and execute this chain automatically. That's the power of multi-step workflows.

Info: Multi-step workflows are the bridge between "smart assistants" and "autonomous agents." Without them, agents can only answer simple, one-shot questions.

How Agents Chain Tools Together

Under the hood, an AI agent follows a loop when executing multi-step workflows:

  1. Observe: The agent looks at the current state — the user's question and any results from previous steps.
  2. Think: The agent decides what tool to call next, if any.
  3. Act: The agent calls the chosen tool and records the result.
  4. Repeat: Steps 1–3 continue until the agent produces a final answer.

This cycle is sometimes called the ReAct loop (Reason + Act). Let's see it in action with a concrete code example.

Example: A Two-Step Math and Search Workflow

from openai import OpenAI

client = OpenAI()

def search_fact(query):
    """Simulated search tool that returns a fact string."""
    facts = {
        "france population": "France has 68 million people.",
        "france area": "France covers 643,801 square kilometers.",
    }
    return facts.get(query.lower(), "No data found.")

def calculate(expression):
    """Simple math evaluation tool."""
    try:
        result = eval(expression)
        return str(result)
    except Exception as e:
        return f"Error: {e}"

tools = [
    {
        "type": "function",
        "function": {
            "name": "search_fact",
            "description": "Look up a factual piece of information.",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "The fact to look up."}
                },
                "required": ["query"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "Evaluate a math expression.",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": "A valid Python math expression."}
                },
                "required": ["expression"]
            }
        }
    }
]

messages = [
    {"role": "system", "content": "You are an agent that can search facts and do math. Use tools step by step."},
    {"role": "user", "content": "What is the population density of France in people per square kilometer?"}
]

# Step 1: Agent decides to search for France's population
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools
)

# Suppose the model calls search_fact("france population")
# We simulate appending the tool result and calling again:
messages.append({
    "role": "assistant",
    "tool_calls": [{
        "id": "call_1",
        "type": "function",
        "function": {
            "name": "search_fact",
            "arguments": '{"query": "france population"}'
        }
    }]
})
messages.append({
    "role": "tool",
    "tool_call_id": "call_1",
    "content": search_fact("france population")
})

# Step 2: Agent searches for France's area
response2 = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools
)

messages.append({
    "role": "assistant",
    "tool_calls": [{
        "id": "call_2",
        "type": "function",
        "function": {
            "name": "search_fact",
            "arguments": '{"query": "france area"}'
        }
    }]
})
messages.append({
    "role": "tool",
    "tool_call_id": "call_2",
    "content": search_fact("france area")
})

# Step 3: Agent calculates the density
response3 = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools
)

messages.append({
    "role": "assistant",
    "tool_calls": [{
        "id": "call_3",
        "type": "function",
        "function": {
            "name": "calculate",
            "arguments": '{"expression": "68000000 / 643801"}'
        }
    }]
})
messages.append({
    "role": "tool",
    "tool_call_id": "call_3",
    "content": calculate("68000000 / 643801")
})

# Step 4: Final answer
final = client.chat.completions.create(
    model="gpt-4o",
    messages=messages
)

print(final.choices[0].message.content)
# Output: France's population density is approximately 105.6 people per square kilometer.

In this example, the agent made three separate tool calls, each one informed by the result of the previous call. The agent planned the sequence on its own — we just provided the tools.

Designing Effective Multi-Step Workflows

Not all tool chains are created equal. Here are the key design principles to keep in mind:

1. Tools Should Be Atomic

Each tool should do one thing well. A tool called get_weather_and_forecast_and_alerts is too broad. Instead, split it into get_current_weather, get_forecast, and get_weather_alerts. Atomic tools are easier for the agent to reason about and compose.

2. Tool Descriptions Are Critical

The agent chooses which tool to call based on the description field. If the description is vague or misleading, the agent will make bad choices. Be specific about what the tool does and what it returns.

3. Handle Errors Gracefully

Tools can fail. Network requests timeout, APIs return errors, and calculations can produce invalid results. Your tools should return clear error messages so the agent can decide what to do next — retry, try a different tool, or report the failure to the user.

Warning: Never let a tool crash silently. If a tool fails without returning useful feedback, the agent may loop endlessly or produce incorrect results. Always return a descriptive error string.

4. Set a Maximum Step Count

Without a limit, an agent might call tools in circles. Always define a maximum number of tool calls (commonly 5–10) to prevent runaway loops.

MAX_STEPS = 8
step_count = 0

while step_count < MAX_STEPS:
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=messages,
        tools=tools
    )
    msg = response.choices[0].message

    # If there are no tool calls, we have a final answer
    if not msg.tool_calls:
        print(msg.content)
        break

    # Execute each tool call and append results
    for tool_call in msg.tool_calls:
        result = execute_tool(tool_call)
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": result
        })

    step_count += 1
else:
    print("Reached maximum steps. Providing best available answer.")

Comparing Single-Step vs. Multi-Step Approaches

Aspect Single-Step Multi-Step
Complexity Simple — one tool call, one answer Complex — multiple calls chained together
Use Case Fact lookup, simple math Research, data pipelines, planning
Latency Low — single round-trip Higher — multiple round-trips
Error Risk Low Higher — errors can compound
Agent Autonomy Minimal — agent picks one tool High — agent plans a sequence
Tip: Start with single-step workflows when prototyping. Add multi-step capabilities only when the task genuinely requires it. This keeps your system simpler and easier to debug.

Common Patterns in Multi-Step Workflows

As you build more agents, you'll notice recurring patterns. Here are three of the most common:

Pattern 1: Search → Extract → Compute

The agent searches for information, extracts the relevant numbers or facts, and then performs a calculation. This is the pattern we used in the France population density example above.

Pattern 2: Plan → Execute → Verify

The agent first creates a plan (e.g., "I will first get the weather, then check flight prices, then recommend a destination"), executes each step, and finally verifies that the results are consistent before answering.

Pattern 3: Parallel Fetch → Merge

When multiple independent pieces of data are needed, the agent can request them all at once (in parallel tool calls) and then merge the results. Modern LLMs support parallel function calling, which speeds up workflows significantly.

Exercise: Build a Currency Converter Agent

Exercise

Create a multi-step agent that converts an amount from one currency to another. Your agent should:

  1. Use a get_exchange_rate(from_currency, to_currency) tool to look up the current exchange rate.
  2. Use a calculate(amount, rate) tool to multiply the amount by the rate.
  3. Return the converted amount to the user.

Write the Python code that sets up the tools and runs the agent loop. Assume the exchange rate tool returns a float like 1.087 for USD to EUR.

from openai import OpenAI

client = OpenAI()

def get_exchange_rate(from_currency, to_currency):
    rates = {
        ("USD", "EUR"): 0.92,
        ("EUR", "USD"): 1.09,
        ("USD", "JPY"): 149.50,
        ("JPY", "USD"): 0.0067,
    }
    key = (from_currency.upper(), to_currency.upper())
    if key in rates:
        return str(rates[key])
    return f"Error: No rate found for {from_currency} to {to_currency}."

def calculate(amount, rate):
    try:
        result = float(amount) * float(rate)
        return f"{result:.2f}"
    except ValueError:
        return "Error: Invalid number input."

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_exchange_rate",
            "description": "Get the exchange rate between two currencies.",
            "parameters": {
                "type": "object",
                "properties": {
                    "from_currency": {"type": "string"},
                    "to_currency": {"type": "string"}
                },
                "required": ["from_currency", "to_currency"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "Multiply two numbers together.",
            "parameters": {
                "type": "object",
                "properties": {
                    "amount": {"type": "string"},
                    "rate": {"type": "string"}
                },
                "required": ["amount", "rate"]
            }
        }
    }
]

messages = [
    {"role": "system", "content": "You are a currency converter agent. Use tools to convert amounts."},
    {"role": "user", "content": "Convert 100 USD to EUR."}
]

MAX_STEPS = 5
step = 0

while step < MAX_STEPS:
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=messages,
        tools=tools
    )
    msg = response.choices[0].message

    if not msg.tool_calls:
        print("Final answer:", msg.content)
        break

    messages.append(msg)
    for tc in msg.tool_calls:
        func_name = tc.function.name
        args = eval(tc.function.arguments)  # In production, use json.loads

        if func_name == "get_exchange_rate":
            result = get_exchange_rate(**args)
        elif func_name == "calculate":
            result = calculate(**args)
        else:
            result = "Unknown tool."

        messages.append({
            "role": "tool",
            "tool_call_id": tc.id,
            "content": result
        })

    step += 1

Key Takeaways

  • Multi-step tool workflows allow agents to solve complex problems by chaining multiple tool calls together, using the output of one as the input to the next.
  • The ReAct loop (Observe → Think → Act → Repeat) is the core pattern that drives multi-step agent behavior.
  • Tools should be atomic — each one does a single, well-defined job — and have clear descriptions so the agent can choose correctly.
  • Always set a maximum step count to prevent infinite loops, and handle errors gracefully with descriptive messages.
  • Common workflow patterns include Search → Extract → Compute, Plan → Execute → Verify, and Parallel Fetch → Merge.
  • Start simple with single-step workflows and add multi-step complexity only when the task demands it.
