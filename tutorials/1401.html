Beyond Pure Vector Search

Learn about beyond pure vector search.

Why Pure Vector Search Isn't Always Enough

So far, you've learned how vector search is a powerful way to find semantically similar content. You embed your query, compare it against a database of embeddings, and get back the closest matches. It's elegant, fast, and works incredibly well for many use cases.

But here's the problem: real-world retrieval is messy. Sometimes you need to find documents that contain a specific date range. Sometimes you need to filter by metadata like author, category, or publication year. Sometimes the user asks a question that requires combining semantic similarity with exact keyword matching. Pure vector search alone can't handle all of these scenarios gracefully.

This is where hybrid search comes in — combining the strengths of multiple retrieval strategies to build more robust, production-ready AI agents.

What you'll learn today: How to combine vector search with keyword search, metadata filtering, and reranking to build retrieval systems that actually work in production.

Understanding the Limitations of Pure Vector Search

Before we dive into solutions, let's clearly understand what pure vector search struggles with. This will help you recognize when you need to go beyond it.

1. Exact Match Queries

Vector search excels at finding semantically similar content. But what if a user asks: "Find me the document titled Q3 2024 Financial Report"? The embedding model might return documents about financial reports in general, but it won't reliably return the exact document with that title. Keyword search (like BM25) handles this much better.

2. Metadata and Structured Filtering

Imagine your agent needs to find "all support tickets from the last 7 days that mention billing issues." The "last 7 days" part is a structured filter on a date field. Vector search doesn't natively understand structured metadata — it only understands semantic similarity in embedding space.

3. Rare Terms and Proper Nouns

Embedding models are trained on general language patterns. They can struggle with rare technical terms, brand names, or very specific jargon. If a user searches for "Kubernetes pod autoscaling configuration," a keyword search might outperform vector search because it can match those exact terms.

4. The "Needle in a Haystack" Problem

When a user's query contains a very specific fact or number, vector search can get distracted by semantically related but irrelevant content. The specific detail gets "washed out" in the high-dimensional embedding.

Common mistake: Many developers build their first RAG system with pure vector search and are surprised when it fails on queries involving dates, names, exact phrases, or structured filters. Plan for hybrid search from the start.

Hybrid Search: Combining Vector and Keyword Search

The most common and impactful upgrade from pure vector search is hybrid search — combining dense vector retrieval with sparse keyword retrieval (typically BM25).

How BM25 Works (A Quick Refresher)

BM25 is a probabilistic ranking function that scores documents based on:

  • Term Frequency (TF): How often a query term appears in a document
  • Inverse Document Frequency (IDF): How rare or common a term is across all documents
  • Document Length Normalization: Prevents long documents from dominating just because they contain more words

Unlike vector search, BM25 doesn't understand meaning — it understands word overlap. That's exactly why the two approaches complement each other.

The Hybrid Approach

In hybrid search, you run both retrieval methods in parallel and then merge and rerank the results. Here's the basic flow:

  1. User submits a query
  2. Vector search retrieves top-K semantically similar documents
  3. BM25 retrieves top-K keyword-matching documents
  4. A fusion algorithm combines both result sets into a single ranked list
  5. The combined results are passed to the LLM for answer generation

Reciprocal Rank Fusion (RRF)

The most popular fusion algorithm is Reciprocal Rank Fusion. It's simple, effective, and doesn't require training. The formula for each document's RRF score is:

RRF_score(d) = Σ 1 / (k + rank_i(d))

Where k is a constant (typically 60) and rank_i(d) is the rank of document d in the i-th result list. Documents that appear high in both lists get the highest combined scores.

def reciprocal_rank_fusion(result_lists, k=60):
    """
    Combine multiple ranked lists using Reciprocal Rank Fusion.
    
    Args:
        result_lists: List of lists, where each inner list contains 
                      (doc_id, score) tuples sorted by relevance.
        k: Smoothing constant (default 60).
    
    Returns:
        List of (doc_id, rrf_score) sorted by descending RRF score.
    """
    from collections import defaultdict
    
    rrf_scores = defaultdict(float)
    
    for result_list in result_lists:
        for rank, (doc_id, _) in enumerate(result_list):
            rrf_scores[doc_id] += 1.0 / (k + rank + 1)  # rank is 0-indexed
    
    # Sort by RRF score descending
    fused = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)
    return fused


# Example usage
vector_results = [("doc_5", 0.92), ("doc_2", 0.88), ("doc_8", 0.85)]
bm25_results = [("doc_2", 12.4), ("doc_5", 10.1), ("doc_1", 9.8)]

fused_results = reciprocal_rank_fusion([vector_results, bm25_results])
print("Fused ranking:")
for doc_id, score in fused_results:
    print(f"  {doc_id}: RRF score = {score:.4f}")
Pro tip: Many vector databases like Pinecone, Weaviate, and Qdrant now support hybrid search natively. You don't always need to implement RRF yourself — check your database's documentation first.

Metadata Filtering

Beyond combining search types, production AI agents almost always need to filter results by metadata. This is where you narrow down the search space before (or after) retrieval.

Pre-Filtering vs. Post-Filtering

Approach How It Works Pros Cons
Pre-filtering Apply metadata filter before vector search Faster search, smaller search space May miss relevant docs near filter boundaries
Post-filtering Retrieve top-K results, then apply metadata filter More accurate semantic matches May return fewer results than requested; slower
Hybrid filtering Pre-filter to a reasonable subset, then post-filter Balances speed and accuracy More complex to implement

Implementing Metadata Filters

Here's how you might implement metadata filtering with a vector database client:

from datetime import datetime, timedelta

def search_with_metadata_filter(
    query: str,
    vector_db,
    category: str = None,
    date_after: datetime = None,
    min_score: float = 0.7,
    top_k: int = 10
):
    """
    Search with optional metadata filters applied before vector search.
    """
    # Build the metadata filter
    filters = {}
    
    if category:
        filters["category"] = {"$eq": category}
    
    if date_after:
        filters["published_date"] = {"$gte": date_after.isoformat()}
    
    # Embed the query
    query_embedding = embed_text(query)
    
    # Search with pre-filtering
    results = vector_db.query(
        vector=query_embedding,
        top_k=top_k,
        filter=filters if filters else None,
        include_metadata=True
    )
    
    # Post-filter by minimum similarity score
    filtered_results = [
        r for r in results 
        if r.score >= min_score
    ]
    
    return filtered_results


# Example: Find recent articles about machine learning
one_week_ago = datetime.now() - timedelta(days=7)

results = search_with_metadata_filter(
    query="transformer architecture improvements",
    vector_db=my_database,
    category="research_papers",
    date_after=one_week_ago,
    min_score=0.75,
    top_k=5
)

for r in results:
    print(f"Score: {r.score:.3f} | Title: {r.metadata['title']}")
    print(f"  Published: {r.metadata['published_date']}")
    print()

Reranking: The Final Polish

Even after hybrid search and metadata filtering, your results might not be in the ideal order. A reranker is a specialized model that takes the initial set of retrieved documents and re-scores them for relevance to the original query.

Why Rerank?

Think of it this way:

  • First-stage retrieval (vector + BM25) is about recall — finding all potentially relevant documents quickly from a large corpus.
  • Reranking is about precision — carefully evaluating each candidate and putting the best ones on top.

Rerankers are typically cross-encoder models that take the query and a candidate document as input and output a relevance score. They're more accurate than embedding-based similarity but also more computationally expensive — which is why you only use them on a small set of candidates (e.g., the top 20 from hybrid search).

Using a Reranker in Python


# Using the sentence-transformers cross-encoder for reranking
from sentence_transformers import CrossEncoder

# Load a pretrained cross-encoder reranker
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

def rerank_results(query: str, candidate_docs: list[str], top_n: int = 5):
    """
    Rerank candidate documents using a cross-encoder model.
    
    Args:
        query: The user's original query
        candidate_docs: List of document texts from initial retrieval
        top_n: Number of top results to return
    
    Returns:
        List of (doc_text, score) tuples, sorted by relevance
    """
    # Create query-document pairs
    pairs = [(query, doc) for doc in candidate_docs]
    
    # Score each pair
    scores = reranker.predict(pairs)
    
    # Combine and sort by score
    scored_docs = list(zip(candidate_docs, scores))
    scored_docs.sort(key=lambda x: x[1], reverse=True)
    
    return scored_docs[:top_n]


# Full pipeline: hybrid search + reranking
def full_retrieval_pipeline(query: str, vector_db, bm25_index, top_k: int = 5):
    """Complete retrieval pipeline with hybrid search and reranking."""
    
    # Step 1: Vector search (get top 20 candidates)
    query_embedding = embed_text(query)
    vector_results = vector_db.query(vector=query_embedding, top_k=20)
    
    # Step 2: BM25 keyword search (get top 20 candidates)
    bm25_results = bm25_index.search(query, top_k=20)
    
    # Step 3: Fuse results using RRF
    fused = reciprocal_rank_fusion([vector_results, bm25_results])
    
    # Step 4: Get the top 20 fused candidates for reranking
    candidate_ids = [doc_id for doc_id, _ in fused[:20]]
    candidate_docs = [fetch_document(doc_id) for doc_id in candidate_ids]
    
    # Step 5: Rerank the candidates
    final_results = rerank_results(query, candidate_docs, top_n=top_k)
    
    return final_results
Cross-encoder vs. Bi-encoder: A bi-encoder (used in vector search) encodes the query and document independently into embeddings, then compares them. A cross-encoder processes the query and document together, allowing deeper interaction between tokens. This makes cross-encoders more accurate but slower — perfect for reranking a small candidate set.

Putting It All Together: Architecture Overview

Here's what a production-ready retrieval pipeline looks like when you combine all these techniques:


class HybridRetrievalAgent:
    """
    An AI agent that uses hybrid search, metadata filtering,
    and reranking for high-quality retrieval.
    """
    
    def __init__(self, vector_db, bm25_index, reranker_model):
        self.vector_db = vector_db
        self.bm25_index = bm25_index
        self.reranker = CrossEncoder(reranker_model)
        self.embedder = SentenceTransformer("all-MiniLM-L6-v2")
    
    def embed(self, text: str) -> list[float]:
        return self.embedder.encode(text).tolist()
    
    def retrieve(
        self,
        query: str,
        filters: dict = None,
        top_k: int = 5,
        candidate_pool: int = 30
    ) -> list[dict]:
        """
        Full retrieval pipeline.
        
        Args:
            query: User's search query
            filters: Optional metadata filters
            top_k: Number of final results to return
            candidate_pool: Number of candidates to gather before reranking
        """
        # Phase 1: Parallel retrieval
        query_embedding = self.embed(query)
        
        vector_results = self.vector_db.query(
            vector=query_embedding,
            top_k=candidate_pool,
            filter=filters
        )
        
        bm25_results = self.bm25_index.search(
            query, 
            top_k=candidate_pool
        )
        
        # Phase 2: Fusion
        fused = reciprocal_rank_fusion(
            [vector_results, bm25_results]
        )
        
        # Phase 3: Reranking
        top_candidates = fused[:min(20, len(fused))]
        candidate_texts = [
            fetch_document(doc_id) for doc_id, _ in top_candidates
        ]
        
        pairs = [(query, text) for text in candidate_texts]
        scores = self.reranker.predict(pairs)
        
        # Sort by reranker score
        ranked = sorted(
            zip(candidate_texts, scores),
            key=lambda x: x[1],
            reverse=True
        )
        
        return [
            {"text": text, "score": float(score)}
            for text, score in ranked[:top_k]
        ]
    
    def answer(self, query: str, filters: dict = None) -> str:
        """Retrieve relevant context and generate an answer."""
        results = self.retrieve(query, filters=filters)
        
        context = "\n\n".join([r["text"] for r in results])
        
        prompt = f"""Based on the following context, answer the question.
If the context doesn't contain enough information, say so.

Context:
{context}

Question: {query}

Answer:"""
        
        return llm.generate(prompt)

When to Use What

Not every application needs the full hybrid + filter + rerank pipeline. Here's a guide to help you decide:

Scenario Recommended Approach Why
Simple FAQ bot Pure vector search Queries are semantic; speed matters more than precision
Enterprise document search Hybrid search + metadata filters Users search by topic AND need to filter by department, date, etc.
Legal/medical research Hybrid + reranking + filters Precision is critical; users need exact clause/term matches
E-commerce product search Hybrid + filters + reranking Combines "I want something like..." with structured filters (price, brand)
Real-time chat assistant Vector search only (for speed) Latency is critical; semantic similarity is usually sufficient
Start simple, then add complexity: Begin with pure vector search. Add hybrid search when you notice keyword-heavy queries failing. Add reranking when you need better precision on the top results. Add metadata filters when your data has structured attributes. Each layer adds latency and complexity — only add what you need.

Given the following results:

  • Vector search returned: [("doc_a", 0.95), ("doc_b", 0.91), ("doc_c", 0.87), ("doc_d", 0.82)]
  • BM25 returned: [("doc_b", 15.3), ("doc_d", 12.1), ("doc_a", 10.5), ("doc_e", 8.7)]

Write a function that takes these two result lists and returns the fused ranking using RRF with k=60. Which document ends up at the top? Why?

from collections import defaultdict

def reciprocal_rank_fusion(result_lists, k=60):
    rrf_scores = defaultdict(float)
    
    for result_list in result_lists:
        for rank, (doc_id, score) in enumerate(result_list):
            rrf_scores[doc_id] += 1.0 / (k + rank + 1)
    
    return sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)


vector_results = [("doc_a", 0.95), ("doc_b", 0.91), ("doc_c", 0.87), ("doc_d", 0.82)]
bm25_results = [("doc_b", 15.3), ("doc_d", 12.1), ("doc_a", 10.5), ("doc_e", 8.7)]

# Expected output (approximately):
# doc_b: 0.032787  (rank 1 in vector, rank 0 in BM25 → highest combined)
# doc_a: 0.032514  (rank 0 in vector, rank 2 in BM25)
# doc_d: 0.031963  (rank 3 in vector, rank 1 in BM25)
# doc_c: 0.016129  (rank 2 in vector only)
# doc_e: 0.015873  (rank 3 in BM25 only)

# doc_b wins because it appears near the top of BOTH lists.
# RRF rewards documents that are consistently ranked highly
# across multiple retrieval methods.

Key insight: doc_b ends up at the top because it was ranked #2 in vector search and #1 in BM25. Even though doc_a was #1 in vector search, it was only #3 in BM25. RRF rewards consistent high ranking across methods, which is exactly what we want — documents that are both semantically relevant AND keyword-relevant.

Key Takeaways

  • Pure vector search has real limitations — it struggles with exact matches, metadata filtering, rare terms, and specific factual queries.
  • Hybrid search combines vector (dense) and BM25 (sparse) retrieval to get the best of both worlds: semantic understanding and keyword precision.
  • Reciprocal Rank Fusion (RRF) is a simple, effective way to merge results from multiple retrieval methods without requiring training.
  • Metadata filtering lets you narrow results by structured attributes like dates, categories, or authors — essential for production systems.
  • Reranking with cross-encoders significantly improves precision by carefully re-evaluating the top candidates from initial retrieval.
  • Choose your architecture based on your needs — not every application requires the full pipeline. Start simple and add complexity only when metrics show it's needed.
  • Pre-filtering vs. post-filtering involves a trade-off between speed and accuracy. Consider your latency requirements when deciding.
