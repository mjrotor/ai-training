Building the Core Loop

Learn about building the core loop.

Understanding the Core Loop

At the heart of every AI agent lies a simple but powerful pattern: the core loop. This is the repeating cycle that allows an agent to perceive its environment, reason about what to do, take action, and then observe the results — over and over again until a goal is achieved.

Think of it like a chef in a kitchen: they look at the recipe (perception), decide what step to take next (reasoning), perform the action (chopping, stirring), and then check if it looks right (observation). Then they repeat.

The Four Stages of the Core Loop

  1. Perceive: Gather input from the environment — user messages, tool outputs, sensor data, etc.
  2. Reason: Use an LLM or logic engine to decide what action to take next.
  3. Act: Execute the chosen action — call a tool, send a message, update state.
  4. Observe: Collect the result of the action and feed it back into the next cycle.
💡 Did you know? The core loop is inspired by the OODA Loop (Observe, Orient, Decide, Act) used in military strategy and decision-making theory. AI agents adapt this into a computational cycle.

Implementing the Core Loop in Python

Let's build a minimal but functional core loop from scratch. We'll use a simple agent that can search the web and answer questions.

import json
from typing import Callable

class SimpleAgent:
    def __init__(self, llm_call: Callable, tools: dict):
        self.llm_call = llm_call
        self.tools = tools
        self.memory = []

    def run(self, user_input: str, max_steps: int = 5):
        self.memory.append({"role": "user", "content": user_input})

        for step in range(max_steps):
            # REASON: Ask the LLM what to do next
            response = self.llm_call(self.memory)
            self.memory.append({"role": "assistant", "content": response})

            # ACT: If the response is a tool call, execute it
            if response.startswith("TOOL:"):
                tool_name, args = self._parse_tool_call(response)
                result = self.tools[tool_name](**args)

                # OBSERVE: Feed the result back into memory
                self.memory.append({
                    "role": "tool",
                    "content": f"Result from {tool_name}: {result}"
                })
            else:
                # The agent has a final answer
                return response

        return "Max steps reached without a final answer."

    def _parse_tool_call(self, response: str):
        # Expected format: "TOOL: tool_name {"arg": "value"}"
        parts = response[5:].split(" ", 1)
        tool_name = parts[0]
        args = json.loads(parts[1]) if len(parts) > 1 else {}
        return tool_name, args
🔧 Pro tip: Always set a max_steps limit. Without it, an agent could loop forever if it keeps calling tools without reaching a conclusion. This is called an infinite loop guard.

Connecting Tools to the Agent

Tools are the agent's hands — they let it interact with the outside world. Here's how we define and register them:

def search_web(query: str) -> str:
    """Simulates a web search tool."""
    # In a real agent, you'd call an API like SerpAPI or Brave Search
    return f"Search results for '{query}': Python is a popular programming language..."

def calculate(expression: str) -> str:
    """Evaluates a simple math expression."""
    try:
        result = eval(expression)
        return str(result)
    except Exception as e:
        return f"Error: {e}"

# Register tools
tools = {
    "search_web": search_web,
    "calculate": calculate
}

# Mock LLM call (replace with real API in production)
def mock_llm(messages):
    last_msg = messages[-1]["content"]
    if "search" in last_msg.lower():
        return 'TOOL: search_web {"query": "Python programming"}'
    elif "calculate" in last_msg.lower() or "math" in last_msg.lower():
        return 'TOOL: calculate {"expression": "2 + 2"}'
    else:
        return "I don't have enough information to answer that."

# Run the agent
agent = SimpleAgent(llm_call=mock_llm, tools=tools)
result = agent.run("What is Python?")
print(result)

Agent Architectures: A Comparison

Not all agents use the same loop structure. Here's how the most common architectures compare:

Architecture Loop Type Best For Complexity
ReAct Reason → Act → Observe General-purpose tasks Low
Plan-and-Execute Plan → Execute steps → Replan Multi-step complex tasks Medium
Reflexion Act → Self-critique → Retry Tasks requiring high accuracy High
LATS Tree search over actions Exploratory problem solving Very High
⚠️ Common mistake: Beginners often skip the observation step and feed raw tool output directly into the next reasoning step without formatting. Always wrap tool results in a structured message (like {"role": "tool", "content": ...}) so the LLM can distinguish between its own thoughts and external data.

Managing Agent State

The agent's memory (or state) is what makes the loop work across multiple turns. Without it, the agent would be stateless and forgetful — like having amnesia after every action.

Types of Agent Memory

  • Short-term memory: The conversation history within a single session. This is what we store in self.memory.
  • Long-term memory: Persistent storage (e.g., a vector database) that the agent can search across sessions.
  • Working memory: A scratchpad the agent uses to track intermediate steps and sub-goals.
class StatefulAgent:
    def __init__(self):
        self.short_term = []      # Current conversation
        self.working = {}          # Scratchpad for sub-goals
        self.completed_steps = []  # Track what's done

    def add_to_working_memory(self, key: str, value):
        self.working[key] = value

    def mark_step_complete(self, step: str):
        self.completed_steps.append(step)

    def get_progress(self):
        return {
            "completed": self.completed_steps,
            "pending": self.working
        }

Handling Errors in the Loop

Real-world agents fail. Tools return errors, APIs go down, and LLMs hallucinate. A robust core loop must handle these gracefully.

def safe_tool_call(tool_func, **kwargs):
    """Wrapper that catches and formats tool errors."""
    try:
        result = tool_func(**kwargs)
        return {"status": "success", "data": result}
    except Exception as e:
        return {"status": "error", "message": str(e)}

# Usage inside the loop
tool_result = safe_tool_call(self.tools[tool_name], **args)
if tool_result["status"] == "error":
    self.memory.append({
        "role": "tool",
        "content": f"Error: {tool_result['message']}. Try a different approach."
    })
else:
    self.memory.append({
        "role": "tool",
        "content": tool_result["data"]
    })
🔧 Pro tip: When a tool fails, don't just pass the raw error to the LLM. Wrap it in a helpful message that suggests what the agent should try next. This dramatically improves recovery rates.

class SimpleAgent:

        self._step_count = 0

        for step in range(max_steps):
            self._step_count += 1
            response = self.llm_call(self.memory)
            self.memory.append({"role": "assistant", "content": response})

            if response.startswith("TOOL:"):

                })
            else:
                return response  # Early exit

        return "Max steps reached without a final answer."

        return self._step_count

Key Takeaways

  • The core loop (Perceive → Reason → Act → Observe) is the fundamental pattern behind all AI agents.
  • Always set a max steps limit to prevent infinite loops.
  • Tools are functions the agent calls to interact with the outside world — they should be registered in a dictionary for easy lookup.
  • Memory management is critical: use structured messages to keep the LLM aware of conversation history and tool results.
  • Error handling should wrap tool outputs in helpful messages, not raw exceptions.
  • Different agent architectures (ReAct, Plan-and-Execute, Reflexion, LATS) build on the same core loop but add different layers of sophistication.
