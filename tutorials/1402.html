BM25 Keyword Search

Learn about bm25 keyword search.

What Is BM25 Keyword Search?

BM25 stands for Best Matching 25 — it's a ranking function used by search engines and retrieval systems to estimate how relevant a document is to a given search query. It's one of the most widely used algorithms in information retrieval, and it forms the backbone of systems like Elasticsearch and Lucene.

Unlike semantic search (which uses embeddings and vector similarity), BM25 is a keyword-based approach. It works by matching exact or partial words in a query against words in a document, then scoring each document based on several statistical factors.

BM25 vs. TF-IDF: BM25 is essentially an evolution of the classic TF-IDF algorithm. While TF-IDF only considers term frequency and inverse document frequency, BM25 adds document length normalization and saturation controls, making it more robust and accurate in practice.

The BM25 Formula Explained

The BM25 score for a document D given a query Q containing terms q₁, q₂, ..., qₙ is calculated as:

BM25(D, Q) = Σ IDF(qi) · [f(qi, D) · (k1 + 1)] / [f(qi, D) + k1 · (1 - b + b · |D| / avgdl)]

Let's break down each component:

Component Meaning
f(qi, D) Term frequency — how many times query term qi appears in document D
|D| Length of the document (number of words)
avgdl Average document length across the entire corpus
k1 Tuning parameter that controls term frequency saturation (typically 1.2–2.0)
b Tuning parameter that controls document length normalization (typically 0.75)
IDF(qi) Inverse document frequency — how rare the term qi is across all documents

Understanding IDF (Inverse Document Frequency)

IDF rewards rare terms and penalizes common ones. If the word "the" appears in almost every document, it gets a very low IDF score. If "quantum" appears in only a few documents, it gets a high IDF score. The formula is:

IDF(qi) = ln[(N - n(qi) + 0.5) / (n(qi) + 0.5) + 1]

# Where:
#   N  = total number of documents in the corpus
#   n(qi) = number of documents containing the term qi
Why does IDF matter? Without IDF, common words like "the" or "is" would dominate search results. IDF ensures that matching on rare, meaningful terms contributes more to the relevance score than matching on common filler words.

Term Frequency Saturation

One of BM25's key improvements over TF-IDF is saturation. In raw TF-IDF, a word appearing 100 times in a document scores 10× more than a word appearing 10 times. But in reality, the 100th occurrence of a word doesn't add much more relevance than the 10th. BM25 handles this with the k1 parameter:

# With k1 = 1.5, the contribution of term frequency saturates:

# Term appears 1 time:   score contribution ≈ 1.00
# Term appears 5 times:   score contribution ≈ 2.73
# Term appears 10 times:  score contribution ≈ 3.10
# Term appears 50 times:  score contribution ≈ 3.48  (diminishing returns!)

# Compare with raw TF-IDF (no saturation):
# Term appears 1 time:   score contribution = 1
# Term appears 5 times:   score contribution = 5
# Term appears 10 times:  score contribution = 10
# Term appears 50 times:  score contribution = 50  (unbounded!)

Implementing BM25 in Python

Let's build a BM25 implementation from scratch to understand how it works, and then use a production-ready library.

From-Scratch Implementation


import math
from collections import Counter, defaultdict

class BM25:
    def __init__(self, corpus, k1=1.5, b=0.75):
        self.k1 = k1
        self.b = b
        self.corpus = corpus
        self.doc_count = len(corpus)
        self.doc_lengths = []
        self.term_freqs = []
        self.doc_freq = defaultdict(int)
        self.idf = {}
        self.avgdl = 0

        self._build_index()

    def _tokenize(self, text):
        return text.lower().split()

    def _build_index(self):
        total_length = 0

        for doc in self.corpus:
            tokens = self._tokenize(doc)
            self.doc_lengths.append(len(tokens))
            total_length += len(tokens)

            tf = Counter(tokens)
            self.term_freqs.append(tf)

            for term in set(tokens):
                self.doc_freq[term] += 1

        self.avgdl = total_length / self.doc_count

        # Compute IDF for each term
        for term, df in self.doc_freq.items():
            self.idf[term] = math.log(
                (self.doc_count - df + 0.5) / (df + 0.5) + 1
            )

    def score(self, query, doc_index):
        query_terms = self._tokenize(query)
        score = 0.0
        doc_tf = self.term_freqs[doc_index]
        doc_len = self.doc_lengths[doc_index]

        for term in query_terms:
            if term not in self.idf:
                continue

            tf = doc_tf.get(term, 0)
            numerator = tf * (self.k1 + 1)
            denominator = tf + self.k1 * (1 - self.b + self.b * doc_len / self.avgdl)
            score += self.idf[term] * (numerator / denominator)

        return score

    def search(self, query, top_k=5):
        scores = []
        for i in range(self.doc_count):
            score = self.score(query, i)
            scores.append((i, score))

        scores.sort(key=lambda x: x[1], reverse=True)
        return scores[:top_k]


# Example usage
corpus = [
    "The cat sat on the mat and looked at the bird.",
    "Machine learning algorithms process data to find patterns.",
    "The dog chased the cat around the garden.",
    "Natural language processing helps computers understand text.",
    "BM25 is a ranking function used in information retrieval.",
    "Cats and dogs are popular pets around the world.",
    "Deep learning models can learn complex patterns from data.",
    "The quick brown fox jumps over the lazy dog.",
    "Information retrieval systems help users find relevant documents.",
    "Python is a popular programming language for data science.",
]

bm25 = BM25(corpus)
results = bm25.search("cat dog pets", top_k=3)

for doc_idx, score in results:
    print(f"Doc {doc_idx} (score: {score:.4f}): {corpus[doc_idx]}")

BM25Okapi vs BM25L, BM25Plus: The rank_bm25 library offers three variants. BM25Okapi is the classic version. BM25L uses a different saturation formula. BM25Plus adds a small correction to prevent negative scores for very long documents. For most use cases, BM25Okapi works great.

BM25 in RAG Pipelines

BM25 is often used as the first-stage retriever in Retrieval-Augmented Generation (RAG) systems. It quickly narrows down thousands of documents to a small set of candidates, which can then be re-ranked using more expensive methods like cross-encoders or vector search.

Hybrid Search: Combining BM25 with Vector Search

Modern RAG systems often combine BM25 (keyword matching) with dense vector search (semantic matching) for the best of both worlds:


from rank_bm25 import BM25Okapi
import numpy as np

class HybridSearch:
    def __init__(self, documents, embeddings, bm25_weight=0.5):
        self.documents = documents
        self.embeddings = embeddings  # Pre-computed vector embeddings
        self.bm25_weight = bm25_weight
        self.vector_weight = 1 - bm25_weight

        # Build BM25 index
        tokenized = [doc.lower().split() for doc in documents]
        self.bm25 = BM25Okapi(tokenized)

    def search(self, query, query_embedding, top_k=5):
        # BM25 scores
        bm25_scores = self.bm25.get_scores(query.lower().split())
        bm25_scores = bm25_scores / (bm25_scores.max() + 1e-8)  # Normalize

        # Vector similarity scores
        similarities = np.dot(self.embeddings, query_embedding)
        similarities = similarities / (similarities.max() + 1e-8)  # Normalize

        # Combine scores
        combined = (self.bm25_weight * bm25_scores +
                    self.vector_weight * similarities)

        top_indices = np.argsort(combined)[::-1][:top_k]
        return [(self.documents[i], combined[i]) for i in top_indices]


# Example usage
documents = [
    "Python is a versatile programming language.",
    "BM25 ranks documents based on keyword relevance.",
    "Vector embeddings capture semantic meaning.",
    "Hybrid search combines keyword and semantic methods.",
]

# Simulated embeddings (in practice, use sentence-transformers)
embeddings = np.random.rand(4, 384)  # 4 docs, 384-dim vectors
query_embedding = np.random.rand(384)

searcher = HybridSearch(documents, embeddings, bm25_weight=0.4)
results = searcher.search("keyword search ranking", query_embedding)

for doc, score in results:
    print(f"  [{score:.4f}] {doc}")
Normalization is critical! When combining BM25 and vector scores, you must normalize both to the same scale (e.g., 0–1). Otherwise, one scoring method will dominate the combined results. Min-max normalization or rank-based fusion are common approaches.

When to Use BM25

Scenario BM25 Works Well? Notes
Exact keyword matching ✅ Excellent BM25's core strength
Technical terms / acronyms ✅ Excellent Precise term matching
Synonym handling ❌ Poor "car" won't match "automobile"
Semantic similarity ❌ Poor Use vector search instead
Large-scale filtering ✅ Excellent Very fast even on millions of docs
Multilingual search ⚠️ Limited Needs language-specific tokenizers
Pro tip: In AI agent systems, BM25 is often used to retrieve relevant tools, API documentation, or knowledge base entries based on the user's query keywords. It's fast, interpretable, and doesn't require GPU resources — making it ideal for the first stage of a multi-step retrieval pipeline.

]

# Build the index
tokenized_corpus = [doc.lower().split() for doc in faq_corpus]
bm25 = BM25Okapi(tokenized_corpus)

def faq_search(query, top_k=3):
    if not query or not query.strip():
        return []

    tokenized_query = query.lower().split()
    scores = bm25.get_scores(tokenized_query)

    # Get top-k indices
    import numpy as np
    top_indices = np.argsort(scores)[::-1][:top_k]

    results = []
    for idx in top_indices:
        if scores[idx] > 0:  # Only include documents with non-zero scores
            results.append({
                "document": faq_corpus[idx],
                "score": round(float(scores[idx]), 4)
            })

    return results

# Test it
query = "How do I get my money back?"
results = faq_search(query)

print(f"Query: '{query}'\n")
for i, r in enumerate(results, 1):
    print(f"  {i}. [{r['score']}] {r['document']}")

Key points in this solution:

  • We tokenize both the corpus and the query in the same way (lowercase + split)
  • We filter out documents with a score of 0 (no matching terms)
  • We use np.argsort to efficiently get the top-k results
  • The function handles edge cases like empty queries

Key Takeaways

  • BM25 is a keyword-based ranking function that scores documents based on term frequency, inverse document frequency, and document length normalization.
  • Term frequency saturation (controlled by k1) prevents documents with extremely high keyword counts from dominating results — a key improvement over raw TF-IDF.
  • Document length normalization (controlled by b) prevents longer documents from having an unfair advantage simply because they contain more words.
  • IDF rewards rare terms — matching on uncommon, meaningful words contributes more to the score than matching on common words like "the" or "is".
  • BM25 does not handle synonyms or semantics — "car" won't match "automobile". For semantic matching, use vector search or combine BM25 with embeddings in a hybrid approach.
  • Hybrid search (BM25 + vector search) is the recommended approach for production RAG systems, combining the precision of keyword matching with the flexibility of semantic search.
  • Normalization is essential when combining BM25 scores with other scoring methods to ensure fair weighting.
  • The rank_bm25 library provides a fast, production-ready implementation that's easy to integrate into Python projects.
