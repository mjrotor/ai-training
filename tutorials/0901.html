Why Stream?

Learn about why stream?.

What Is Streaming?

When you ask a large language model (LLM) a question, the model doesn't produce its entire answer all at once. Instead, it generates text one token at a time — a token being roughly a word or sub-word piece. Streaming is the technique of sending each of those tokens to the user as soon as they're generated, rather than waiting for the full response to finish before showing anything.

Think of it like watching a live sports broadcast versus waiting for a recorded highlight reel. With streaming, you see the action unfold in real time. Without it, you stare at a loading spinner until the entire game is over.

Key term: A token is the basic unit an LLM works with. One token might be a common word like "the", a piece of a longer word like "ing", or even a single punctuation mark. On average, one token is about ¾ of an English word.

Why Does Streaming Matter for AI Agents?

AI agents often need to interact with users in real time — answering questions, summarizing documents, writing code, or making decisions. If the agent waits until the entire response is ready before showing anything, the user experiences a long, frustrating pause followed by a wall of text all at once.

Streaming solves three critical problems:

  1. Perceived latency. The user sees the first word in milliseconds instead of waiting 10–30 seconds for a complete answer. Even though the total time is the same, the experience feels dramatically faster.
  2. User engagement. A response that appears gradually keeps the user's attention. A blank screen does not.
  3. Early cancellation. If the user realizes mid-response that the answer is going in the wrong direction, they can stop the generation early — saving compute cost and time.
Pro tip: In production AI applications, streaming isn't just a nice-to-have — it's expected. Users of ChatGPT, Claude, and similar tools are accustomed to seeing text appear token by token. A non-streaming interface feels broken by comparison.

How Streaming Works Under the Hood

At a technical level, streaming relies on Server-Sent Events (SSE) or WebSockets — protocols that let a server push data to a client over a single, long-lived HTTP connection. Here's the simplified flow:

  1. The client sends a request to the server (e.g., "Explain quantum computing").
  2. The server forwards the request to the LLM API.
  3. The LLM API begins generating tokens and sends them back one at a time through the streaming endpoint.
  4. The server relays each token to the client immediately.
  5. The client appends each token to the displayed text in the user's browser.
  6. This continues until the LLM signals that generation is complete.

Non-Streaming vs. Streaming: A Comparison

Aspect Non-Streaming Streaming
User sees first output After full response is ready Within ~100–300 ms
Total response time Same Same
Perceived speed Slow Fast
Can cancel early? No Yes
Implementation complexity Simple Moderate
Network protocol Standard HTTP request/response SSE or WebSocket

Streaming with the OpenAI Python SDK

Let's see how to implement streaming in Python using the OpenAI SDK. The key difference is adding stream=True to your API call and then iterating over the response chunks.

Non-Streaming Example (What You've Seen Before)

import openai

client = openai.OpenAI()

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Explain streaming in one sentence."}
    ]
)

# The entire answer arrives at once
full_text = response.choices[0].message.content
print(full_text)

Streaming Example

import openai

client = openai.OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Explain streaming in one sentence."}
    ],
    stream=True  # ← This is the only change to the API call
)

# Tokens arrive one at a time — print each as it comes
for chunk in stream:
    token = chunk.choices[0].delta.content
    if token is not None:
        print(token, end="", flush=True)

print()  # Final newline

Notice the flush=True argument in print(). Without it, Python buffers the output and you might not see tokens appear immediately. flush=True forces each token to the terminal the instant it arrives.

Watch out: Each chunk in the stream is a small object. The actual text content lives in chunk.choices[0].delta.content. Some chunks may have None as the content (for example, the final "done" signal), so always check before using the value.

Collecting the Full Response While Streaming

Sometimes you want to display tokens in real time and save the complete response for later use. Here's how:

import openai

client = openai.OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "List three benefits of exercise."}
    ],
    stream=True
)

full_response = ""

for chunk in stream:
    token = chunk.choices[0].delta.content
    if token is not None:
        print(token, end="", flush=True)
        full_response += token

print("\n---")
print(f"Total characters received: {len(full_response)}")

Streaming with System Prompts and Agent Context

In a real AI agent, you'll almost always include a system prompt to set the agent's behavior. Streaming works identically — you just add the system message to the messages list:

import openai

client = openai.OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {
            "role": "system",
            "content": "You are a helpful coding tutor. Explain concepts simply."
        },
        {
            "role": "user",
            "content": "What is a Python list comprehension?"
        }
    ],
    stream=True
)

for chunk in stream:
    token = chunk.choices[0].delta.content
    if token is not None:
        print(token, end="", flush=True)

print()

Streaming Multiple Messages in a Conversation

Agents maintain conversation history. Here's how to stream a response while preserving context from previous turns:

import openai

client = openai.OpenAI()

conversation = [
    {"role": "system", "content": "You are a concise assistant."},
    {"role": "user", "content": "What is 2 + 2?"},
    {"role": "assistant", "content": "2 + 2 = 4."},
    {"role": "user", "content": "Now multiply that by 3."}
]

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=conversation,
    stream=True
)

response_text = ""
for chunk in stream:
    token = chunk.choices[0].delta.content
    if token is not None:
        print(token, end="", flush=True)
        response_text += token

# Add the assistant's reply to the conversation history
conversation.append({"role": "assistant", "content": response_text})
print()
Remember: Always append the assistant's full response to your conversation history after streaming completes. If you only append partial tokens, your conversation context will be corrupted.

Handling Errors During Streaming

Network issues can interrupt a stream mid-response. Good agent code handles this gracefully:

import openai

client = openai.OpenAI()

try:
    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "user", "content": "Write a haiku about Python."}
        ],
        stream=True
    )

    full_response = ""
    for chunk in stream:
        token = chunk.choices[0].delta.content
        if token is not None:
            print(token, end="", flush=True)
            full_response += token

    print(f"\n\n[Complete response: {len(full_response)} chars]")

except openai.APIConnectionError:
    print("\n[Error: Could not connect to the API. Check your network.]")
except openai.RateLimitError:
    print("\n[Error: Rate limit exceeded. Wait and try again.]")
except openai.APIError as e:
    print(f"\n[Error: API returned an error: {e}]")

Streaming in a Web Application Context

In a real web app, you wouldn't just print to the terminal. You'd send each token to the browser. Here's a minimal Flask example using Server-Sent Events:

from flask import Flask, Response, request, jsonify
import openai

app = Flask(__name__)
client = openai.OpenAI()

@app.route("/chat", methods=["POST"])
def chat():
    user_message = request.json.get("message", "")

    def generate():
        stream = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": "You are a helpful assistant."},
                {"role": "user", "content": user_message}
            ],
            stream=True
        )
        for chunk in stream:
            token = chunk.choices[0].delta.content
            if token is not None:
                yield f"data: {token}\n\n"

    return Response(generate(), mimetype="text/event-stream")

On the frontend, you'd use the EventSource API to listen for incoming tokens and append them to the page in real time.

Architecture note: In production, you'd typically put a queue (like Redis or RabbitMQ) between your web server and the LLM API to handle multiple concurrent users and manage rate limits. But the streaming pattern remains the same.

When NOT to Stream

Streaming is the right choice for most interactive applications, but there are cases where it's not ideal:

  • Batch processing. If you're generating 10,000 responses overnight and saving them to a database, streaming adds unnecessary complexity. A simple request/response is cleaner.
  • Tool-use agents. If your agent needs to call a function (like searching a database or calling another API) before responding, you typically wait for the tool result first, then stream the final answer.
  • Structured output. When you need the complete JSON response to parse it (e.g., with response_format={"type": "json_object"}), you may prefer to wait for the full response to ensure valid JSON.
Exercise: Build a Streaming Echo Agent

Write a Python script that:

  1. Asks the user for input in a loop (type "quit" to exit).
  2. Sends each user message to the OpenAI API with stream=True.
  3. Prints each token as it arrives.
  4. Tracks and displays the total number of tokens received for each response.

Use the gpt-4o-mini model and a system prompt that says: "You are a friendly echo agent. Repeat the user's message back to them, but add one interesting fact related to their message."

import openai

client = openai.OpenAI()

SYSTEM_PROMPT = (
    "You are a friendly echo agent. Repeat the user's message "
    "back to them, but add one interesting fact related to their message."
)

print("Streaming Echo Agent (type 'quit' to exit)\n")

while True:
    user_input = input("You: ").strip()

    if user_input.lower() == "quit":
        print("Goodbye!")
        break

    if not user_input:
        print("Please enter a message.\n")
        continue

    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_input}
        ],
        stream=True
    )

    print("Agent: ", end="", flush=True)
    token_count = 0

    for chunk in stream:
        token = chunk.choices[0].delta.content
        if token is not None:
            print(token, end="", flush=True)
            token_count += 1

    print(f"\n[Tokens received: {token_count}]\n")

Key Takeaways

  • Streaming sends tokens to the user as they're generated, rather than waiting for the complete response — dramatically improving perceived performance.
  • Enable streaming by adding stream=True to your API call and iterating over the response chunks.
  • Each chunk contains a delta.content field with the next token (or None for control signals). Always check for None before using the value.
  • Use flush=True in print() to ensure tokens appear immediately in the terminal.
  • Collect the full response by concatenating tokens as they arrive, so you can store the complete answer in your conversation history.
  • Handle errors gracefully — network interruptions can break a stream mid-response.
  • Streaming is ideal for interactive applications but may be unnecessary for batch processing or structured output tasks.
