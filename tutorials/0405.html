Error Handling for Tools

Learn about error handling for tools.

Why Error Handling Matters for AI Agent Tools

When your AI agent calls external tools—APIs, databases, file systems, or web scrapers—things will go wrong. Networks drop. APIs return unexpected formats. Rate limits get hit. Files go missing. If your agent doesn't handle these failures gracefully, the entire workflow collapses.

Error handling is what separates a fragile prototype from a production-ready agent. In this lesson, you'll learn how to anticipate failures, catch them cleanly, and give your agent the ability to recover or fail informatively.

Common Types of Tool Errors

Before writing error handling code, you need to understand what can go wrong. Here are the most common categories of errors your agent's tools will encounter:

Error Type Example Typical Cause
Network Errors ConnectionError, Timeout Server down, DNS failure, slow response
API Errors 401 Unauthorized, 429 Too Many Requests Bad credentials, rate limiting, invalid parameters
Data Errors KeyError, JSONDecodeError Unexpected response schema, malformed data
Resource Errors FileNotFoundError, PermissionError Missing files, insufficient permissions
Logic Errors ValueError, TypeError Wrong input types, out-of-range values
Warning: Never assume a tool call will succeed. Every external interaction is a potential failure point. Always wrap tool calls in try/except blocks.

Basic Try/Except Patterns for Tools

The foundation of error handling in Python is the try/except block. For AI agent tools, you want to be specific about which exceptions you catch so you can respond appropriately.

Catching Specific Exceptions

Always prefer catching specific exceptions over a bare except: clause. A bare except catches everything, including SystemExit and KeyboardInterrupt, which makes debugging a nightmare.

import requests

def fetch_weather(city: str) -> dict:
    """Fetch weather data for a given city."""
    url = f"https://api.weather.com/v1/current?city={city}"
    
    try:
        response = requests.get(url, timeout=10)
        response.raise_for_status()  # Raises HTTPError for 4xx/5xx
        return response.json()
    except requests.exceptions.Timeout:
        return {"error": "Request timed out. The weather service may be slow."}
    except requests.exceptions.ConnectionError:
        return {"error": "Could not connect to the weather service."}
    except requests.exceptions.HTTPError as e:
        return {"error": f"HTTP error: {e.response.status_code}"}
    except requests.exceptions.JSONDecodeError:
        return {"error": "Received invalid data from the weather service."}
Tip: Notice how each except block returns a dictionary with an "error" key. This gives the AI agent a structured way to understand what went wrong and potentially retry or choose a different tool.

Using Finally for Cleanup

Sometimes you need to clean up resources regardless of whether an error occurred—closing files, releasing locks, or logging the attempt. The finally block runs no matter what.

def read_config_file(path: str) -> dict:

Building a Robust Tool Wrapper

Instead of scattering try/except blocks inside every tool function, you can create a decorator that wraps all your tools with consistent error handling. This is a powerful pattern for AI agent development.

The Safe Tool Decorator

import functools
import traceback
import time

def safe_tool(func):
    """Decorator that wraps any tool function with error handling."""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        tool_name = func.__name__
        try:
            start = time.time()
            result = func(*args, **kwargs)
            elapsed = time.time() - start
            return {
                "success": True,
                "tool": tool_name,
                "result": result,
                "duration_seconds": round(elapsed, 3)
            }
        except Exception as e:
            return {
                "success": False,
                "tool": tool_name,
                "error_type": type(e).__name__,
                "error_message": str(e),
                "traceback": traceback.format_exc()
            }
    return wrapper

@safe_tool
def search_web(query: str) -> list:
    """Search the web for information."""
    # Simulated search that might fail
    if not query.strip():
        raise ValueError("Search query cannot be empty")
    return [f"Result 1 for '{query}'", f"Result 2 for '{query}'"]

@safe_tool
def calculate(expression: str) -> float:
    """Safely evaluate a math expression."""
    allowed = set("0123456789+-*/(). ")
    if not all(c in allowed for c in expression):
        raise ValueError("Expression contains invalid characters")
    return eval(expression)

# Usage
print(search_web("AI agents"))
# {'success': True, 'tool': 'search_web', 'result': [...], 'duration_seconds': 0.001}

print(search_web(""))
# {'success': False, 'tool': 'search_web', 'error_type': 'ValueError', ...}
Info: The decorator pattern keeps your tool functions clean and focused on their core logic. All error handling, timing, and response formatting happens in one place. This is especially useful when you have dozens of tools in your agent's toolkit.

Retry Logic with Exponential Backoff

Some errors are temporary—a brief network hiccup, a rate limit that resets in seconds. For these cases, retrying with increasing delays (exponential backoff) is the standard approach.

import time
import random

def retry_with_backoff(func, max_retries=3, base_delay=1.0):
    """Retry a function with exponential backoff."""
    last_exception = None
    
    for attempt in range(max_retries + 1):
        try:
            return func()
        except (ConnectionError, TimeoutError) as e:
            last_exception = e
            if attempt < max_retries:
                # Exponential backoff with jitter
                delay = base_delay * (2 ** attempt) + random.uniform(0, 0.5)
                print(f"Attempt {attempt + 1} failed: {e}. "
                      f"Retrying in {delay:.1f}s...")
                time.sleep(delay)
            else:
                print(f"All {max_retries + 1} attempts failed.")
                raise last_exception

# Example usage
def unreliable_api_call():
    """Simulates an API that fails 60% of the time."""
    if random.random() < 0.6:
        raise ConnectionError("API temporarily unavailable")
    return {"data": "Success!"}

result = retry_with_backoff(unreliable_api_call, max_retries=3)
print(result)

When to Retry vs. When to Fail

Not all errors should be retried. Use this decision framework:

  • Retry: Network timeouts, 429 Too Many Requests, 503 Service Unavailable, 502 Bad Gateway
  • Fail immediately: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found
  • Fail after one retry: 500 Internal Server Error (might be a transient issue)
Warning: Never retry operations that have side effects (like sending an email or charging a credit card) unless you're certain the operation is idempotent. Retrying a payment tool could charge the user twice.

Returning Structured Error Responses

Your AI agent needs to understand what went wrong to decide what to do next. Raw Python exceptions are meaningless to an LLM. Instead, return structured error responses that the agent can reason about.

from dataclasses import dataclass
from typing import Optional, Any

@dataclass
class ToolResult:
    """Standardized result from any tool call."""
    success: bool
    data: Optional[Any] = None
    error_code: Optional[str] = None
    error_message: Optional[str] = None
    suggestion: Optional[str] = None  # Hint for the agent on what to do next

def divide(a: float, b: float) -> ToolResult:
    try:
        result = a / b
        return ToolResult(success=True, data=result)
    except ZeroDivisionError:
        return ToolResult(
            success=False,
            error_code="DIVISION_BY_ZERO",
            error_message=f"Cannot divide {a} by zero.",
            suggestion="Try using a non-zero denominator, or use the "
                       "'safe_divide' tool which returns 0 for division by zero."
        )
    except TypeError as e:
        return ToolResult(
            success=False,
            error_code="INVALID_INPUT_TYPE",
            error_message=str(e),
            suggestion="Ensure both inputs are numbers (int or float)."
        )

# The agent receives a clear, actionable response
result = divide(10, 0)
if not result.success:
    print(f"Error: {result.error_message}")
    print(f"Suggestion: {result.suggestion}")
# Error: Cannot divide 10 by zero.
# Suggestion: Try using a non-zero denominator, or use the
# 'safe_divide' tool which returns 0 for division by zero.

Logging Errors for Debugging

In production, you need to know when and why tools fail. Python's built-in logging module is your best friend here.

import logging

# Configure logging
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    handlers=[
        logging.FileHandler("agent_tools.log"),
        logging.StreamHandler()
    ]
)

logger = logging.getLogger("agent.tools")

def call_external_api(endpoint: str, payload: dict) -> dict:
    logger.info(f"Calling API: {endpoint}")
    try:
        response = requests.post(endpoint, json=payload, timeout=15)
        response.raise_for_status()
        logger.info(f"API call succeeded: {endpoint}")
        return response.json()
    except requests.exceptions.Timeout:
        logger.error(f"API timeout: {endpoint} (payload: {payload})")
        return {"error": "timeout", "endpoint": endpoint}
    except requests.exceptions.HTTPError as e:
        logger.error(
            f"API HTTP error: {endpoint} | "
            f"Status: {e.response.status_code} | "
            f"Body: {e.response.text[:200]}"
        )
        return {"error": "http_error", "status": e.response.status_code}
    except Exception as e:
        logger.critical(f"Unexpected error calling {endpoint}: {e}", exc_info=True)
        return {"error": "unexpected", "details": str(e)}
Tip: Use logger.critical() with exc_info=True for unexpected errors. This captures the full stack trace in your logs, which is invaluable for debugging issues you didn't anticipate.

Putting It All Together: A Resilient Tool

Let's combine everything—the decorator, retry logic, structured responses, and logging—into a single, production-quality tool.

import functools
import logging
import time
import random
import requests

logger = logging.getLogger("agent.tools")

def resilient_tool(max_retries=2, timeout=10):
    """Decorator combining retry logic, error handling, and logging."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            tool_name = func.__name__
            last_error = None
            
            for attempt in range(max_retries + 1):
                try:
                    logger.info(
                        f"[{tool_name}] Attempt {attempt + 1}/{max_retries + 1}"
                    )
                    start = time.time()
                    result = func(*args, **kwargs, timeout=timeout)
                    elapsed = time.time() - start
                    logger.info(f"[{tool_name}] Success in {elapsed:.2f}s")
                    return ToolResult(success=True, data=result)
                    
                except (ConnectionError, TimeoutError) as e:
                    last_error = e
                    logger.warning(
                        f"[{tool_name}] Attempt {attempt + 1} failed: {e}"
                    )
                    if attempt < max_retries:
                        delay = (2 ** attempt) + random.uniform(0, 0.5)
                        time.sleep(delay)
                        
                except ValueError as e:
                    logger.error(f"[{tool_name}] Invalid input: {e}")
                    return ToolResult(
                        success=False,
                        error_code="INVALID_INPUT",
                        error_message=str(e),
                        suggestion="Check the input parameters and try again."
                    )
                    
                except Exception as e:
                    logger.critical(
                        f"[{tool_name}] Unexpected error: {e}", exc_info=True
                    )
                    return ToolResult(
                        success=False,
                        error_code="UNEXPECTED_ERROR",
                        error_message=str(e),
                        suggestion="This is an unexpected error. "
                                   "Please report this issue."
                    )
            
            logger.error(f"[{tool_name}] All {max_retries + 1} attempts failed")
            return ToolResult(
                success=False,
                error_code="MAX_RETRIES_EXCEEDED",
                error_message=str(last_error),
                suggestion="The service appears to be down. "
                           "Try again in a few minutes."
            )
        return wrapper
    return decorator

@resilient_tool(max_retries=2, timeout=10)
def get_stock_price(symbol: str, timeout: int = 10) -> dict:
    """Fetch the current stock price for a given symbol."""
    url = f"https://api.stocks.example.com/quote/{symbol}"
    response = requests.get(url, timeout=timeout)
    response.raise_for_status()
    data = response.json()
    return {"symbol": symbol, "price": data["price"], "currency": "USD"}

# The agent can now handle failures gracefully
result = get_stock_price("AAPL")
if result.success:
    print(f"AAPL is trading at ${result.data['price']}")
else:
    print(f"Could not fetch price: {result.error_message}")
    print(f"Suggestion: {result.suggestion}")
Info: This pattern—decorator + retry + structured response + logging—is the gold standard for AI agent tools. As you build more tools, you'll reuse this exact structure over and over.
Exercise: Build a Safe File Reader Tool

Create a tool called safe_read_file that reads a text file and returns its contents. Your tool should:

  1. Use the @safe_tool decorator pattern (or write your own error handling)
  2. Handle FileNotFoundError with a clear error message
  3. Handle PermissionError with a clear error message
  4. Handle UnicodeDecodeError (for binary files) with a clear error message
  5. Return a ToolResult with appropriate error_code and suggestion fields for each error case
  6. Log each error using the logging module

Test your tool with: a valid text file, a nonexistent path, and a file you don't have permission to read.

import logging
import functools
from dataclasses import dataclass
from typing import Optional, Any

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("agent.tools")

@dataclass
class ToolResult:
    success: bool
    data: Optional[Any] = None
    error_code: Optional[str] = None
    error_message: Optional[str] = None
    suggestion: Optional[str] = None

def safe_tool(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        try:
            result = func(*args, **kwargs)
            return result
        except Exception as e:
            logger.critical(f"Unhandled error in {func.__name__}: {e}", exc_info=True)
            return ToolResult(
                success=False,
                error_code="UNHANDLED_ERROR",
                error_message=str(e),
                suggestion="An unexpected error occurred. Please report this."
            )
    return wrapper

@safe_tool
def safe_read_file(file_path: str) -> ToolResult:
    """Safely read a text file with comprehensive error handling."""
    logger.info(f"Attempting to read file: {file_path}")
    try:
        with open(file_path, "r", encoding="utf-8") as f:
            contents = f.read()
        logger.info(f"Successfully read file: {file_path} ({len(contents)} chars)")
        return ToolResult(success=True, data=contents)
    except FileNotFoundError:
        logger.error(f"File not found: {file_path}")
        return ToolResult(
            success=False,
            error_code="FILE_NOT_FOUND",
            error_message=f"The file '{file_path}' does not exist.",
            suggestion="Check the file path for typos, or use the "
                       "'list_files' tool to see available files."
        )
    except PermissionError:
        logger.error(f"Permission denied: {file_path}")
        return ToolResult(
            success=False,
            error_code="PERMISSION_DENIED",
            error_message=f"You don't have permission to read '{file_path}'.",
            suggestion="Try a different file, or check the file's permissions."
        )
    except UnicodeDecodeError:
        logger.error(f"Cannot decode file as text: {file_path}")
        return ToolResult(
            success=False,
            error_code="DECODE_ERROR",
            error_message=f"The file '{file_path}' appears to be a binary file.",
            suggestion="This tool only reads text files. Try a different file "
                       "or use a binary file reader."
        )

# Test cases
print(safe_read_file("existing_file.txt"))   # Should succeed
print(safe_read_file("nonexistent.txt"))      # FILE_NOT_FOUND
print(safe_read_file("/etc/shadow"))          # PERMISSION_DENIED
print(safe_read_file("image.png"))            # DECODE_ERROR

Key Takeaways

  • Always wrap tool calls in try/except blocks. External services fail—your agent must be prepared.
  • Catch specific exceptions rather than using bare except: clauses. This lets you respond appropriately to each failure type.
  • Use a decorator pattern to apply consistent error handling across all your tools without repeating code.
  • Implement retry logic with exponential backoff for transient errors like network timeouts and rate limits.
  • Return structured error responses (like ToolResult) so your AI agent can understand and react to failures.
  • Log everything. Use Python's logging module to capture errors with context for debugging.
  • Never retry non-idempotent operations. Be careful with tools that have side effects like payments or emails.
  • Provide actionable suggestions in error responses so the agent knows what to try next.
