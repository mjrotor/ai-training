Designing a Code Review Agent

Learn about designing a code review agent.

What Is a Code Review Agent?

A Code Review Agent is an AI-powered assistant that automatically analyzes source code and provides feedback — just like a human reviewer would. It checks for bugs, style violations, security issues, and suggests improvements. By combining a large language model (LLM) with well-crafted prompts and structured workflows, you can build an agent that catches common mistakes before they reach production.

Why build one? Code review is one of the most time-consuming parts of software development. An AI code review agent doesn't replace human reviewers — it augments them by catching low-level issues so people can focus on architecture and logic.

The Architecture of a Code Review Agent

Before we write any code, let's understand the pieces that make up a simple but effective code review agent:

  1. Input Layer — Receives the code snippet or full file to review.
  2. Analysis Engine — An LLM that reads the code and applies review criteria.
  3. Prompt Template — A structured prompt that guides the LLM on what to look for.
  4. Output Formatter — Structures the LLM's response into a readable, actionable report.

Writing the Review Prompt Template

The prompt is the heart of your agent. A good prompt tells the model exactly what categories to check and how to format its response.

Pro tip: Use a system prompt to define the agent's role and a user prompt for the actual code. This two-prompt pattern keeps instructions clean and reusable. 
SYSTEM_PROMPT = """
You are an expert code reviewer. When given a code snippet, analyze it and provide feedback in the following categories:

1. **Bugs & Logic Errors** — Any mistakes that will cause incorrect behavior.
2. **Security Issues** — Vulnerabilities such as injection, hardcoded secrets, etc.
3. **Code Quality** — Readability, naming conventions, dead code.
4. **Performance** — Inefficient patterns that could be improved.

For each issue found, provide:
- The line or section where it occurs
- A brief explanation of the problem
- A suggested fix

If the code is clean, say so! Be concise and constructive.
"""

def build_review_prompt(code_snippet: str) -> list[dict]:
    return [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": f"Please review the following Python code:\n\n```python\n{code_snippet}\n```"}
    ]

Building the Agent Class

Now let's wrap everything into a reusable CodeReviewAgent class:

import openai
import os

class CodeReviewAgent:
    """A simple AI agent that reviews code snippets."""

    def __init__(self, model: str = "gpt-4o"):
        self.client = openai.OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))
        self.model = model
        self.system_prompt = """
You are an expert code reviewer. Analyze code for bugs, security issues,
code quality problems, and performance concerns. Provide actionable feedback
with line references and suggested fixes. Be concise.
"""

    def review(self, code: str, language: str = "python") -> str:
        """Review a code snippet and return feedback."""
        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": f"Review this {language} code:\n\n```{language}\n{code}\n```"}
        ]

        response = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            temperature=0.3,  # Lower temp for more consistent reviews
            max_tokens=1024
        )

        return response.choices[0].message.content

    def review_with_category(self, code: str, category: str) -> str:
        """Review code focusing on a specific category."""
        focused_prompt = f"""
You are an expert code reviewer. Focus ONLY on **{category}** issues.
Analyze the code below and report any problems in that area.

```python
{code}
```
"""
        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": focused_prompt}
        ]

        response = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            temperature=0.3,
            max_tokens=800
        )

        return response.choices[0].message.content

Running Your First Code Review

agent = CodeReviewAgent()

import os

def get_user_data(username):
    query = f"SELECT * FROM users WHERE name = '{username}'"
    result = execute(query)
    
    password = "admin123"
    
    if result == None:
        print("No user found" + username)
    
    for i in range(1000000):
        data = result[i]
    
    return data
"""

# Run the review
feedback = agent.review(bad_code)
print(feedback)
Expected issues the agent should catch:
  • SQL injection vulnerability (string interpolation in query)
  • Hardcoded password/secret
  • Use of == None instead of is None
  • String concatenation instead of f-string
  • Potential IndexError — no bounds check on result
  • Unnecessary million-iteration loop

Comparing Review Approaches

There are several strategies for building code review agents. Here's a comparison:

Approach Pros Cons Best For
Single Prompt Simple to implement, fast May miss nuanced issues Quick checks, small snippets
Multi-Category (Focused) Thorough, catches more issues Multiple API calls, slower Full-file reviews
Agent with Tools Can run linters, execute tests Complex to build and maintain CI/CD pipeline integration
Multi-Model Pipeline Different models for different tasks Expensive, high latency Enterprise-grade review systems

Adding Structured Output

Raw text feedback is useful, but structured JSON output makes it easier to integrate with dashboards, CI tools, or IDEs. Let's enhance our agent to return structured results:

import json

class StructuredCodeReviewAgent(CodeReviewAgent):
    """Extended agent that returns structured JSON output."""

    def review_structured(self, code: str) -> list[dict]:
        """Return review findings as a list of structured dicts."""
        structured_system = """
You are an expert code reviewer. Analyze the code and return your findings
as a JSON array. Each object should have:
  - "severity": "critical" | "warning" | "suggestion"
  - "line": the approximate line number
  - "category": "bug" | "security" | "quality" | "performance"
  - "description": brief explanation of the issue
  - "fix": suggested fix

Return ONLY valid JSON, no markdown fences.
"""
        messages = [
            {"role": "system", "content": structured_system},
            {"role": "user", "content": f"Review this Python code:\n\n```python\n{code}\n```"}
        ]

        response = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            temperature=0.1,
            max_tokens=1500,
            response_format={"type": "json_object"}
        )

        result = json.loads(response.choices[0].message.content)
        return result.get("findings", result) if isinstance(result, dict) else result
Note: The response_format={"type": "json_object"} parameter tells the model to output valid JSON. Always validate the output before using it in production — LLMs can occasionally produce malformed JSON.

Building a Batch Review Tool

In real projects, you often need to review multiple files. Let's add batch processing:

def review_multiple_files(agent: CodeReviewAgent, files: dict[str, str]) -> dict:
    """
    Review multiple files and return a report.
    
    Args:
        agent: The CodeReviewAgent instance
        files: A dict mapping filename to code content
    
    Returns:
        A dict mapping filename to review feedback
    """
    report = {}
    
    for filename, code in files.items():
        print(f"Reviewing {filename}...")
        
        # Skip empty files
        if not code.strip():
            report[filename] = "Skipped (empty file)"
            continue
        
        try:
            feedback = agent.review(code)
            report[filename] = feedback
        except Exception as e:
            report[filename] = f"Error: {str(e)}"
    
    return report

def review_file(self, file_path: str) -> str:
    """
    Read a file from disk and review its contents.
    
    Args:
        file_path: Path to the source code file
    
    Returns:
        Formatted review string with filename, language, and feedback
    
    Raises:
        FileNotFoundError: If the file doesn't exist (handled gracefully)
    """
    # Map extensions to language names
    extension_map = {
        ".py": "python",
        ".js": "javascript",
        ".ts": "typescript",
        ".java": "java",
        ".go": "go",
        ".rs": "rust",
        ".rb": "ruby",
        ".cpp": "cpp",
        ".c": "c",
    }
    
    # Check if file exists
    if not os.path.exists(file_path):
        return f"Error: File '{file_path}' not found."
    
    # Detect language from extension
    _, ext = os.path.splitext(file_path)
    language = extension_map.get(ext.lower(), "unknown")
    
    # Read file content
    with open(file_path, "r", encoding="utf-8") as f:
        code = f.read()
    
    # Skip empty files
    if not code.strip():
        return f"[{file_path}] Language: {language}\nSkipped: empty file."
    
    # Run the review
    feedback = self.review(code, language=language)
    
    return (
        f"{'='*60}\n"
        f"FILE: {file_path}\n"
        f"LANGUAGE: {language}\n"
        f"{'='*60}\n"
        f"{feedback}"
    )

Handling Large Files

Most LLMs have context window limits (e.g., 128K tokens). If a file is too large, you need to chunk it and review each part separately:

def chunk_code(code: str, max_chars: int = 10000) -> list[str]:
    """Split code into chunks at logical break points."""
    chunks = []
    current_chunk = ""
    
    for line in code.split("\n"):
        if len(current_chunk) + len(line) + 1 > max_chars and current_chunk:
            chunks.append(current_chunk)
            current_chunk = line + "\n"
        else:
            current_chunk += line + "\n"
    
    if current_chunk:
        chunks.append(current_chunk)
    
    return chunks


def review_large_file(agent: CodeReviewAgent, code: str) -> str:
    """Review a large file by chunking and aggregating results."""
    chunks = chunk_code(code)
    all_feedback = []
    
    for i, chunk in enumerate(chunks):
        feedback = agent.review(
            chunk,
            # Tell the model which chunk it's reviewing
        )
        all_feedback.append(f"--- Chunk {i+1} of {len(chunks)} ---\n{feedback}")
    
    return "\n\n".join(all_feedback)
Best practice: When chunking code, try to split at function or class boundaries rather than mid-function. This gives the LLM better context for each chunk.

Key Takeaways

  • A Code Review Agent uses an LLM with a well-crafted prompt to automatically analyze source code for bugs, security issues, quality problems, and performance concerns.
  • The prompt template is the most important part — it defines what the agent looks for and how it formats its output.
  • Use lower temperature values (0.1–0.3) for code review to get more consistent, deterministic feedback.
  • Structured JSON output makes it easy to integrate review results with CI/CD pipelines, dashboards, and IDEs.
  • For large files, use chunking strategies to stay within context window limits while maintaining review quality.
  • Always include error handling for missing files, empty files, and API failures in production agents.
  • AI code review agents augment human reviewers — they don't replace them. Use them to catch low-level issues so humans can focus on architecture and design.
