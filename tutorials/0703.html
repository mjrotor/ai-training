Conditional Chains

Learn about conditional chains.

What Are Conditional Chains?

So far, you've learned how AI agents can follow simple sequences of steps — doing one thing, then another, then another. But real-world problems aren't always that straightforward. Sometimes an agent needs to make decisions along the way: "If this happens, do X; otherwise, do Y." This is where conditional chains come in.

A conditional chain is simply a sequence of steps where the agent chooses which path to follow based on certain conditions — much like a flowchart with yes/no branches.

Think of it like this: Imagine you're making breakfast. If you have eggs, you scramble them. If you don't, you grab cereal. That's a conditional chain — your actions depend on a condition.

Why Do Agents Need Conditional Logic?

Without conditional logic, an AI agent would follow the same steps every single time, no matter what. That works fine for simple, predictable tasks. But most real-world scenarios involve:

  • Uncertain inputs — the agent doesn't know in advance what data it will receive
  • Multiple possible outcomes — different situations require different responses
  • Error handling — what happens when something goes wrong?
  • User preferences — different users may want different things

Conditional chains give agents the flexibility to handle all of these cases gracefully.

Basic If/Else in Python

Let's start with the most fundamental building block: the if/else statement. Here's a simple example:

temperature = 32

if temperature > 30:
    print("It's hot outside! Stay hydrated.")
else:
    print("The weather is comfortable.")

Python checks the condition temperature > 30. If it's True, it runs the first block. If it's False, it runs the else block. Simple!

Adding More Branches with Elif

What if you have more than two possibilities? Use elif (short for "else if"):

temperature = 22

if temperature > 30:
    print("It's hot! 🔥")
elif temperature > 20:
    print("It's warm. Enjoy! ☀️")
elif temperature > 10:
    print("It's cool. Grab a jacket. 🧥")
else:
    print("It's cold! Bundle up! ❄️")

Python evaluates each condition from top to bottom. As soon as it finds one that's True, it runs that block and skips the rest.

Order matters! If you put temperature > 10 before temperature > 20, a temperature of 25 would match the first condition and never reach the more specific one. Always put the most specific conditions first.

Building a Conditional Chain for an Agent

Now let's see how this applies to an AI agent. Imagine an agent that processes customer support tickets and routes them to the right department:

def route_ticket(ticket):
    """Route a support ticket to the correct department."""
    
    issue_type = ticket["category"]
    priority = ticket["priority"]
    
    if priority == "urgent":
        if issue_type == "billing":
            return "Route to Billing — Priority Escalation Team"
        elif issue_type == "technical":
            return "Route to Engineering — On-Call Team"
        else:
            return "Route to General Support — Urgent Queue"
    
    elif priority == "high":
        if issue_type == "billing":
            return "Route to Billing Team"
        elif issue_type == "technical":
            return "Route to Engineering Team"
        else:
            return "Route to General Support"
    
    else:
        return "Route to General Support — Standard Queue"


# Test it out
ticket_1 = {"category": "billing", "priority": "urgent"}
ticket_2 = {"category": "technical", "priority": "low"}

print(route_ticket(ticket_1))
print(route_ticket(ticket_2))

This is a nested conditional chain — conditions inside conditions. The agent first checks the priority, then within each priority level, it checks the issue type. This creates a decision tree with multiple possible paths.

Comparison: Linear Chains vs. Conditional Chains

Feature Linear Chain Conditional Chain
Steps Always the same order Varies based on conditions
Flexibility Low — rigid sequence High — adapts to inputs
Complexity Simple to build and debug More complex, but more powerful
Best for Predictable, repeatable tasks Tasks with multiple scenarios
Example Fetch data → format → display Check input type → process accordingly → handle errors

Using Logical Operators

Sometimes a single condition isn't enough. Python lets you combine conditions using and, or, and not:

def can_access_feature(user):
    """Check if a user can access a premium feature."""
    
    is_subscribed = user["subscription"] == "premium"
    is_admin = user["role"] == "admin"
    account_age_days = user["account_age_days"]
    
    # Must be premium OR admin, AND account must be older than 7 days
    if (is_subscribed or is_admin) and account_age_days > 7:
        return True
    else:
        return False


# Test cases
user_1 = {"subscription": "premium", "role": "member", "account_age_days": 30}
user_2 = {"subscription": "free", "role": "admin", "account_age_days": 3}
user_3 = {"subscription": "free", "role": "member", "account_age_days": 100}

print(can_access_feature(user_1))  # True (premium + old enough)
print(can_access_feature(user_2))  # False (admin but too new)
print(can_access_feature(user_3))  # False (not premium, not admin)
Pro tip: Use parentheses () to make complex conditions readable. (A or B) and C is much clearer than figuring out what A or B and C means based on Python's operator precedence rules.

Handling Edge Cases

One of the most important skills in building conditional chains is thinking about what could go wrong. What if a required field is missing? What if the input is the wrong type?

def process_agent_command(command, context):
    """Process a command with proper error handling."""
    
    # Guard clause: check if command exists
    if command is None or command.strip() == "":
        return {"status": "error", "message": "No command provided."}
    
    # Guard clause: check if context is valid
    if not isinstance(context, dict):
        return {"status": "error", "message": "Invalid context format."}
    
    # Main logic
    action = command.lower().strip()
    
    if action == "summarize":
        if "text" in context:
            return {"status": "success", "result": "Summary: " + context["text"][:50] + "..."}
        else:
            return {"status": "error", "message": "No text found in context to summarize."}
    
    elif action == "search":
        if "query" in context:
            return {"status": "success", "result": f"Searching for: {context['query']}"}
        else:
            return {"status": "error", "message": "No search query provided."}
    
    else:
        return {"status": "error", "message": f"Unknown command: '{action}'"}


# Test it
print(process_agent_command("summarize", {"text": "This is a long article about AI agents..."}))
print(process_agent_command("search", {}))
print(process_agent_command("", {"query": "test"}))
print(process_agent_command("dance", {"text": "hello"}))

Notice the pattern at the top: we check for problems first and return early. These are called guard clauses, and they keep your main logic clean and easy to read.

Putting It All Together

A well-designed conditional chain follows this general structure:

  1. Validate inputs — check for missing or invalid data (guard clauses)
  2. Identify the primary condition — what's the main decision point?
  3. Handle each branch — define what happens in each scenario
  4. Include a fallback — always have an else for unexpected cases
  5. Return consistent outputs — every branch should return the same type of result
Remember: Conditional chains are the foundation of agent decision-making. As you progress through this course, you'll build more sophisticated agents that use these same patterns — just with more complex conditions and more powerful tools.
🧩 Exercise: Build a Smart Router

Write a function called smart_router that takes a dictionary called request and returns a string indicating where to send the request. The dictionary will have these keys:

  • "type" — one of: "question", "complaint", "feedback", or "other"
  • "sentiment" — one of: "positive", "negative", or "neutral"

Your routing rules should be:

  • If type is "complaint" and sentiment is "negative" → return "Escalate to Manager"
  • If type is "complaint" → return "Route to Support Team"
  • "question" → return "Route to FAQ Bot"
  • If type is "feedback" and sentiment is "positive" → return "Send to Marketing Team"
  • If type is "feedback" → return "Log for Review"
  • For everything else → return "Route to General Inbox"

Make sure to handle edge cases where keys might be missing!

def smart_router(request):
    """Route a request based on type and sentiment."""
    
    # Guard clauses for missing keys
    if not isinstance(request, dict):
        return "Route to General Inbox"
    
    req_type = request.get("type", "other")
    sentiment = request.get("sentiment", "neutral")
    
    # Primary routing logic — most specific first
    if req_type == "complaint" and sentiment == "negative":
        return "Escalate to Manager"
    elif req_type == "complaint":
        return "Route to Support Team"
    elif req_type == "question":
        return "Route to FAQ Bot"
    elif req_type == "feedback" and sentiment == "positive":
        return "Send to Marketing Team"
    elif req_type == "feedback":
        return "Log for Review"
    else:
        return "Route to General Inbox"


# Test it out
print(smart_router({"type": "complaint", "sentiment": "negative"}))
print(smart_router({"type": "complaint", "sentiment": "neutral"}))
print(smart_router({"type": "question", "sentiment": "neutral"}))
print(smart_router({"type": "feedback", "sentiment": "positive"}))
print(smart_router({"type": "feedback", "sentiment": "negative"}))
print(smart_router({"type": "other", "sentiment": "neutral"}))
print(smart_router({}))
print(smart_router(None))

Key Takeaways

  • Conditional chains allow AI agents to make decisions based on input data, rather than following a fixed sequence every time.
  • Use if/elif/else to handle multiple possible paths, evaluating conditions from top to bottom.
  • Nested conditionals let you create decision trees for complex routing logic.
  • Logical operators (and, or, not) let you combine multiple conditions into a single check.
  • Guard clauses at the top of your function handle edge cases and keep your main logic clean.
  • Always include a fallback (else) for unexpected inputs — agents should never crash silently.
  • Order your conditions from most specific to least specific to avoid logic bugs.
