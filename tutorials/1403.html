Hybrid Search

Learn about hybrid search.

What Is Hybrid Search?

In the previous lessons, you learned about keyword-based search (like BM25) and semantic search (using embeddings). Each has its strengths — and its blind spots. Hybrid search combines both approaches to deliver results that are more accurate and more robust than either method alone.

Think of it like this: keyword search is great when the user knows exactly what they're looking for (e.g., "error code 404"), while semantic search shines when the intent matters more than exact words (e.g., "why isn't my page loading"). Hybrid search gives you the best of both worlds.

Definition: Hybrid search is a retrieval strategy that combines lexical (keyword) matching and semantic (embedding-based) matching, then intelligently merges the results to produce a single, ranked list.

Why Not Just Use One?

Let's break down why relying on a single search strategy can fall short in real-world AI agent scenarios.

Limitations of Keyword Search (BM25)

  • Cannot understand meaning — "car" and "automobile" are treated as completely unrelated tokens.
  • Misses relevant documents that use synonyms or paraphrases.
  • Struggles with multilingual or domain-specific jargon.

Limitations of Semantic Search (Dense Retrieval)

  • Can miss exact keyword matches that are critical (e.g., product IDs, error codes, legal terms).
  • Embedding models may not capture rare or highly specific terminology well.
  • Computationally more expensive at scale.

Comparison: Keyword vs. Semantic vs. Hybrid

Feature Keyword (BM25) Semantic (Dense) Hybrid
Exact match strength ✅ Excellent ❌ Weak ✅ Excellent
Synonym & paraphrase handling ❌ Weak ✅ Excellent ✅ Excellent
Handles rare terms ✅ Good ❌ Often poor ✅ Good
Computational cost ✅ Low ❌ Higher ⚠️ Moderate
Overall robustness ⚠️ Limited ⚠️ Limited ✅ Strong

How Hybrid Search Works

At a high level, hybrid search follows a three-step pipeline:

  1. Parallel Retrieval: Run both a keyword search and a semantic search on the same query.
  2. Score Normalization: Bring both result sets onto a common scale (e.g., 0 to 1) so they can be fairly compared.
  3. Score Fusion: Combine the normalized scores using a weighted formula or a learned ranking model.
Tip: The most common fusion method is Reciprocal Rank Fusion (RRF), which doesn't require score normalization at all — it works purely on rank positions. We'll cover this below.

Step 1: Parallel Retrieval

Given a user query, we retrieve the top-k results from both systems simultaneously.

# Example: Parallel retrieval with both BM25 and dense embeddings

from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer
import numpy as np

# --- Setup (done once at index time) ---
documents = [
    "Python is a popular programming language for data science.",
    "BM25 is a keyword-based ranking function used in search engines.",
    "Embeddings capture semantic meaning of text.",
    "Hybrid search combines keyword and semantic approaches.",
    "JavaScript is widely used for web development."
]

# BM25 index
tokenized_docs = [doc.lower().split() for doc in documents]
bm25 = BM25Okapi(tokenized_docs)

# Dense index
model = SentenceTransformer('all-MiniLM-L6-v2')
doc_embeddings = model.encode(documents)

# --- Retrieval ---
query = "how does semantic search work?"

# BM25 results
tokenized_query = query.lower().split()
bm25_scores = bm25.get_scores(tokenized_query)
bm25_ranking = np.argsort(bm25_scores)[::-1][:3]
print("BM25 top-3:", [documents[i] for i in bm25_ranking])

# Dense results
query_embedding = model.encode([query])
similarities = np.dot(doc_embeddings, query_embedding.T).flatten()
dense_ranking = np.argsort(similarities)[::-1][:3]
print("Dense top-3:", [documents[i] for i in dense_ranking])

Step 2: Score Normalization

To fairly combine scores from two different systems, we normalize them to a common range:

def min_max_normalize(scores):
    """Normalize scores to [0, 1] range."""
    min_s = min(scores)
    max_s = max(scores)
    if max_s == min_s:
        return [0.0] * len(scores)
    return [(s - min_s) / (max_s - min_s) for s in scores]

bm25_normalized = min_max_normalize(bm25_scores.tolist())
dense_normalized = min_max_normalize(similarities.tolist())

print("BM25 normalized:", [round(s, 3) for s in bm25_normalized])
print("Dense normalized:", [round(s, 3) for s in dense_normalized])

Step 3: Score Fusion

The simplest fusion approach is a weighted linear combination:

def weighted_fusion(bm25_scores, dense_scores, alpha=0.5):
    """
    Combine BM25 and dense scores using a weighted average.
    alpha: weight for BM25 (1-alpha for dense).
    """
    return [
        alpha * bm25 + (1 - alpha) * dense
        for bm25, dense in zip(bm25_scores, dense_scores)
    ]

# Alpha = 0.5 gives equal weight to both methods
combined_scores = weighted_fusion(bm25_normalized, dense_normalized, alpha=0.5)

# Rank documents by combined score
final_ranking = np.argsort(combined_scores)[::-1]

print("\nHybrid Search Results:")
for rank, idx in enumerate(final_ranking, 1):
    print(f"  {rank}. [{combined_scores[idx]:.3f}] {documents[idx]}")
Warning: Choosing the right alpha value is crucial. If your domain relies heavily on exact matches (e.g., legal documents), use a higher alpha. For conversational or exploratory queries, favor the dense component (lower alpha). In practice, tune alpha on a validation set.

Reciprocal Rank Fusion (RRF)

Instead of normalizing raw scores, Reciprocal Rank Fusion works purely on the rank positions of results. This avoids the tricky problem of aligning score distributions from different systems.

def reciprocal_rank_fusion(rankings_list, k=60):
    """
    Combine multiple ranked lists using Reciprocal Rank Fusion.
    
    rankings_list: list of lists, each containing document indices in ranked order.
    k: constant to dampen the impact of low-ranked documents (default 60).
    
    Returns: list of (doc_id, rrf_score) tuples sorted by score descending.
    """
    rrf_scores = {}
    
    for ranking in rankings_list:
        for rank, doc_id in enumerate(ranking):
            if doc_id not in rrf_scores:
                rrf_scores[doc_id] = 0.0
            rrf_scores[doc_id] += 1.0 / (k + rank + 1)
    
    # Sort by RRF score descending
    sorted_results = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)
    return sorted_results

# Convert top-k rankings from BM25 and Dense
bm25_top_k = list(np.argsort(bm25_scores)[::-1])
dense_top_k = list(np.argsort(similarities)[::-1])

# Fuse
results = reciprocal_rank_fusion([bm25_top_k, dense_top_k])

print("RRF Results:")
for rank, (doc_id, score) in enumerate(results, 1):
    print(f"  {rank}. [RRF: {score:.4f}] {documents[doc_id]}")
Why RRF works well: RRF doesn't require score normalization, making it simple and robust. The constant k prevents very low-ranked documents from having outsized influence. It's production-proven — used by major search engines and RAG pipelines alike.

Implementing Hybrid Search with LangChain

In practice, you'll often use a framework like LangChain that provides built-in support for hybrid search via its EnsembleRetriever. Here's how to set it up:

from langchain.retrievers import BM25Retriever, EnsembleRetriever
from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings

# Assume 'chunks' is a list of Document objects loaded from your data source

# 1. Set up BM25 retriever (keyword-based)
bm25_retriever = BM25Retriever.from_documents(chunks)
bm25_retriever.k = 5  # Return top 5 results

# 2. Set up dense retriever (semantic-based)
vectorstore = FAISS.from_documents(chunks, OpenAIEmbeddings())
dense_retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

# 3. Combine into an EnsembleRetriever
ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, dense_retriever],
    weights=[0.5, 0.5]  # Equal weight to both
)

# 4. Query!
results = ensemble_retriever.invoke("How does hybrid search improve RAG?")

for i, doc in enumerate(results):
    print(f"{i+1}. {doc.page_content[:100]}...")
Note: LangChain's EnsembleRetriever uses Reciprocal Rank Fusion under the hood by default. You can also configure it to use weighted score fusion if your retrievers return compatible score types.

When to Use Hybrid Search in AI Agents

Hybrid search is especially powerful in RAG (Retrieval-Augmented Generation) pipelines, which are the backbone of most AI agents today. Here are common use cases:

  • Customer support agents: Users ask questions using varied phrasing — semantic search handles the diversity, while keyword search catches product names and error codes.
  • Enterprise knowledge bases: Employees search for documents that may contain exact terminology (legal clauses, technical specs) as well as conceptual topics.
  • Code assistants: Developers might search for a function name (keyword) or describe what they want to do (semantic).
  • Medical or scientific agents: Exact terms like drug names or gene identifiers must match precisely, while broader queries benefit from semantic understanding.

Common Pitfalls and How to Avoid Them

  1. Choosing weights arbitrarily: Don't just use 50/50. Evaluate on real queries from your domain and tune alpha or weights accordingly.
  2. Ignoring index freshness: If your dense index and keyword index are out of sync, you'll get inconsistent results. Keep both updated simultaneously.
  3. Over-retrieving: Don't set k too high — retrieving too many documents wastes tokens and can confuse your LLM. Start with k=5 and adjust.
  4. Forgetting query preprocessing: Both BM25 and embedding models benefit from clean, well-formatted queries. Strip noise, expand abbreviations when possible.

Exercise

Coding Exercise: Build a Hybrid Search Function

Write a Python function called hybrid_search that takes a query, a list of documents, a BM25 model, a sentence transformer model, and pre-computed document embeddings. The function should:

  1. Retrieve scores from both BM25 and the dense model.
  2. Min-max normalize both score arrays.
  3. Combine them using a weighted average (default alpha=0.6 favoring BM25).
  4. Return a list of (document_index, combined_score) tuples sorted by score descending.

Test it with the following documents and query:

documents = [
    "RAG stands for Retrieval-Augmented Generation.",
    "Large language models can hallucinate without grounding.",
    "Vector databases store embeddings for fast similarity search.",
    "Hybrid search combines sparse and dense retrieval methods.",
    "Prompt engineering improves LLM output quality."
]
query = "how do RAG systems work with search?"

import numpy as np
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer

def hybrid_search(query, documents, bm25, model, doc_embeddings, alpha=0.6):
    """
    Perform hybrid search combining BM25 and dense retrieval.
    
    Returns: list of (doc_index, combined_score) sorted by score descending.
    """
    # Step 1: BM25 scores
    tokenized_query = query.lower().split()
    bm25_scores = np.array(bm25.get_scores(tokenized_query), dtype=float)
    
    # Step 2: Dense scores (cosine similarity)
    query_embedding = model.encode([query])
    dense_scores = np.dot(doc_embeddings, query_embedding.T).flatten()
    
    # Step 3: Min-max normalize both
    def normalize(arr):
        min_val, max_val = arr.min(), arr.max()
        if max_val == min_val:
            return np.zeros_like(arr)
        return (arr - min_val) / (max_val - min_val)
    
    bm25_norm = normalize(bm25_scores)
    dense_norm = normalize(dense_scores)
    
    # Step 4: Weighted fusion
    combined = alpha * bm25_norm + (1 - alpha) * dense_norm
    
    # Step 5: Sort and return
    ranked_indices = np.argsort(combined)[::-1]
    return [(int(idx), float(combined[idx])) for idx in ranked_indices]


# --- Test ---
documents = [
    "RAG stands for Retrieval-Augmented Generation.",
    "Large language models can hallucinate without grounding.",
    "Vector databases store embeddings for fast similarity search.",
    "Hybrid search combines sparse and dense retrieval methods.",
    "Prompt engineering improves LLM output quality."
]

# Build indices
tokenized = [doc.lower().split() for doc in documents]
bm25 = BM25Okapi(tokenized)
model = SentenceTransformer('all-MiniLM-L6-v2')
embeddings = model.encode(documents)

# Run hybrid search
query = "how do RAG systems work with search?"
results = hybrid_search(query, documents, bm25, model, embeddings, alpha=0.6)

print("Hybrid Search Results (alpha=0.6):")
for rank, (idx, score) in enumerate(results, 1):
    print(f"  {rank}. [{score:.4f}] {documents[idx]}")

Key Takeaways

  • Hybrid search combines keyword (BM25) and semantic (dense embedding) retrieval to overcome the weaknesses of each individual approach.
  • Parallel retrieval runs both methods simultaneously, then normalizes scores to a common scale before fusion.
  • Weighted linear fusion is intuitive and easy to implement; Reciprocal Rank Fusion (RRF) is more robust and doesn't require score normalization.
  • The alpha parameter (or weights) should be tuned on real data from your domain — there's no universal best value.
  • Frameworks like LangChain's EnsembleRetriever make hybrid search easy to set up in production RAG pipelines.
  • Hybrid search is essential for AI agents that rely on RAG, especially in domains with exact terminology and varied user phrasing.
  • Avoid common pitfalls: arbitrary weights, stale indices, over-retrieval, and poor query preprocessing.
