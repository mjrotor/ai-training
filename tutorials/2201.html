LlamaIndex Overview

Learn about llamaindex overview.

What is LlamaIndex?

If you've been following along through Phase 2, you've already learned the fundamentals of building with large language models. Now it's time to level up. LlamaIndex is one of the most popular frameworks for building AI agents and RAG (Retrieval-Augmented Generation) applications. Think of it as the connective tissue between your data and your LLM.

At its core, LlamaIndex gives you the tools to:

  • Ingest data from virtually anywhere — PDFs, databases, APIs, Notion, Google Docs, and more
  • Structure that data into formats LLMs can reason over efficiently
  • Build indexes that allow fast, relevant retrieval of information
  • Create query engines and chat agents that combine retrieval with LLM generation

Instead of manually chunking documents, writing embedding code, and orchestrating prompt calls yourself, LlamaIndex provides a clean, high-level abstraction for all of it.

Note: LlamaIndex was originally built for Llama models, but it now supports virtually every major LLM provider including OpenAI, Anthropic, Google, Mistral, and more. The name is historical at this point.

Installing LlamaIndex

Before we dive into code, let's get LlamaIndex installed. You can install the core package with pip:

pip install llama-index

If you want to use a specific LLM provider, you'll also install the corresponding integration package. For example, with OpenAI:

pip install llama-index-llms-openai

Or with a local model via Ollama:

pip install llama-index-llms-ollama
Tip: If you're experimenting and want to try multiple providers, you can install several integration packages at once. LlamaIndex will automatically detect which one to use based on your configuration.

Core Concepts: Indexes, Engines, and Agents

LlamaIndex has a layered architecture. Understanding the three main layers will help you design effective systems.

1. Indexes

An index is a data structure built on top of your documents. It's the foundation of everything in LlamaIndex. When you create an index, LlamaIndex:

  1. Loads your raw documents (called Documents)
  2. Splits them into smaller pieces (called Nodes)
  3. Optionally generates embeddings for each node
  4. Stores everything in a structured format for fast retrieval

The most common index type is the VectorStoreIndex, which creates embeddings and allows semantic search over your data.

from llama_index.core import VectorStoreIndex, SimpleDirectoryReader

# Load documents from a directory
documents = SimpleDirectoryReader("data").load_data()

# Build a vector index
index = VectorStoreIndex.from_documents(documents)

print(f"Index created with {len(documents)} documents")
print(f"Total nodes in index: {index.index_struct.num_nodes}")

2. Engines

An engine is an interface that lets you interact with your index (or directly with an LLM). Think of engines as the "query layer." There are several types:

  • QueryEngine — Send a question, get a response based on your indexed data
  • ChatEngine — Same as QueryEngine but maintains conversation history
  • Retriever — Retrieve relevant nodes without LLM generation (useful for inspection)
# Create a query engine from the index
query_engine = index.as_query_engine()

# Ask a question
response = query_engine.query("What is the main topic of the documents?")
print(response)

# Or create a chat engine for multi-turn conversations
chat_engine = index.as_chat_engine()
response = chat_engine.chat("Tell me about the project")
print(response)

3. Agents

An agent goes beyond simple Q&A. It can reason about which tools to use, call external APIs, run computations, and make decisions — all powered by an LLM. LlamaIndex agents can use your query engines as tools, along with any custom tools you define.

from llama_index.core.tools import QueryEngineTool, ToolMetadata
from llama_index.core.agent import ReActAgent

# Create a tool from your query engine
query_tool = QueryEngineTool(
    query_engine=query_engine,
    metadata=ToolMetadata(
        name="document_search",
        description="Search the document knowledge base for answers"
    )
)

# Build an agent with tools
agent = ReActAgent.from_tools(
    tools=[query_tool],
    llm=your_llm,
    verbose=True
)

# The agent decides when to use the tool
response = agent.chat("Summarize the key findings and list action items")
print(response)

Data Ingestion: Reading Your Documents

One of LlamaIndex's biggest strengths is its Readers ecosystem. It supports over 100 data sources out of the box. Let's look at the most common patterns.

Reading from a Directory

The simplest way to get started is loading all files from a folder:

from llama_index.core import SimpleDirectoryReader

# Reads all supported files in the "data/" directory
documents = SimpleDirectoryReader("data").load_data()

# You can also filter by file extension
documents = SimpleDirectoryReader(
    "data",
    required_exts=[".pdf", ".md", ".txt"]
).load_data()

# Access metadata
for doc in documents[:3]:
    print(f"File: {doc.metadata.get('file_name', 'unknown')}")
    print(f"Length: {len(doc.text)} characters")
    print("---")

Reading from Specific Sources

For databases, APIs, and cloud services, LlamaIndex has dedicated readers:

# Example: Reading from a SQL database
from llama_index.readers.database import DatabaseReader

reader = DatabaseReader(
    scheme="postgresql",
    host="localhost",
    port=5432,
    user="admin",
    password="secret",
    dbname="mydb"
)

# Query specific data into Documents
documents = reader.load_data(
    query="SELECT * FROM knowledge_base WHERE category = 'research'"
)
Warning: When loading from large databases or APIs, be mindful of token limits. Consider filtering and paginating your queries to avoid overwhelming your LLM's context window.

Index Types: Choosing the Right One

Not all indexes are the same. The right choice depends on your use case. Here's a comparison of the most common types:

Index Type Best For Requires Embeddings Speed
VectorStoreIndex Semantic search, RAG Yes Fast (with vector DB)
SummaryIndex Sequential/hierarchical summaries No Moderate
KeywordTableIndex Exact keyword matching No Very fast
TreeIndex Hierarchical document structure Yes Moderate
KnowledgeGraphIndex Entity relationships, graph queries Yes Slower

For most RAG applications, VectorStoreIndex is the right starting point. You can always experiment with other index types later.

Query Engines in Depth

Query engines are where the magic happens. Let's explore the different configurations and modes available.

Synchronous vs. Asynchronous Queries

LlamaIndex supports both sync and async patterns:

# Synchronous query
response = query_engine.query("What are the key benefits?")
print(response)

# Asynchronous query (great for web applications)
import asyncio

async def main():
    response = await query_engine.aquery("What are the key benefits?")
    print(response)

asyncio.run(main())

Streaming Responses

For chat interfaces, streaming provides a much better user experience:

# Streaming query
query_engine = index.as_query_engine(streaming=True)
response = query_engine.query("Explain the architecture")

# Print tokens as they arrive
response.print_response_stream()

Customizing the Prompt

You can customize the system prompt and context template:

from llama_index.core import PromptTemplate

custom_qa_template = PromptTemplate(
    "You are a helpful research assistant.\n"
    "Context information is below:\n"
    "---------------------\n"
    "{context_str}\n"
    "---------------------\n"
    "Given this context, answer: {query_str}\n"
    "If you don't know, say 'I don't have enough information.'"
)

query_engine = index.as_query_engine(text_qa_template=custom_qa_template)
response = query_engine.query("What methodology was used?")
print(response)

Building a RAG Pipeline: Full Example

Let's put everything together into a complete RAG pipeline. This example demonstrates the full workflow from document loading to query answering.

import os
from llama_index.core import (
    VectorStoreIndex,
    SimpleDirectoryReader,
    Settings
)
from llama_index.llms.openai import OpenAI
from llama_index.embeddings.openai import OpenAIEmbedding

# Step 1: Configure global settings
Settings.llm = OpenAI(model="gpt-4", temperature=0)
Settings.embed_model = OpenAIEmbedding(model="text-embedding-3-small")

# Step 2: Load documents
print("Loading documents...")
documents = SimpleDirectoryReader("data/reports").load_data()
print(f"Loaded {len(documents)} documents")

# Step 3: Build the index
print("Building index...")
index = VectorStoreIndex.from_documents(
    documents,
    show_progress=True
)

# Step 4: Persist the index (save to disk)
index.storage_context.persist(persist_dir="./storage")
print("Index saved to ./storage")

# Step 5: Create a query engine
query_engine = index.as_query_engine(
    similarity_top_k=3,
    streaming=True
)

# Step 6: Query
print("\nQuerying...")
response = query_engine.query(
    "What were the three most significant findings in the reports?"
)
response.print_response_stream()

# Step 7: Inspect what was retrieved
print("\n--- Source Nodes ---")
for node in response.source_nodes:
    print(f"Score: {node.score:.3f}")
    print(f"Source: {node.metadata.get('file_name', 'unknown')}")
    print(f"Text: {node.text[:100]}...")
    print("---")

Storing Indexes: In-Memory vs. Persistent

By default, LlamaIndex stores indexes in memory. When your Python process ends, the index is gone. For production applications, you'll want persistent storage.

Using Built-in Vector Stores

# ChromaDB (great for development)
# pip install llama-index-vector-stores-chroma
from llama_index.vector_stores.chroma import ChromaVectorStore
import chromadb

chroma_client = chromadb.PersistentClient(path="./chroma_db")
chroma_collection = chroma_client.get_or_create_collection("my_collection")
vector_store = ChromaVectorStore(chroma_collection=chroma_collection)

index = VectorStoreIndex.from_documents(
    documents,
    vector_store=vector_store
)

# The index is now persisted in ChromaDB
# To reload later:
# index = VectorStoreIndex.from_vector_store(vector_store)

Using Remote Vector Databases

For production deployments, consider dedicated vector databases:

  • Qdrant — High performance, supports filtering
  • Pinecone — Fully managed, serverless option
  • Weaviate — Built-in vectorization modules
  • pgvector — Extend your existing PostgreSQL database
Tip: Start with an in-memory index for prototyping. Switch to a persistent vector store only when you need to serve multiple users or restart your application without rebuilding the index.

# Your code here...

# 2. Build index
# 3. Create query engine with top_k=5

# 5. Print response and source files
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader, Settings

Key Takeaways

  • LlamaIndex is a data framework for LLM applications — it bridges the gap between your data and language models, handling ingestion, structuring, indexing, and querying.
  • The three core layers are Indexes, Engines, and Agents — indexes store your structured data, engines provide query interfaces, and agents add reasoning and tool-use capabilities.
  • VectorStoreIndex is the most common index type — it creates embeddings for semantic search and powers most RAG applications.
  • LlamaIndex supports 100+ data sources — from local files to databases, APIs, and cloud services, making it easy to bring your existing data into L>
  • Query engines are highly configurable — you can customize prompts, enable streaming, adjust retrieval parameters, and choose sync or async execution.
  • Persistent storage is essential for production — use vector databases like ChromaDB, Qdrant, or Pinecone to avoid rebuilding indexes on every restart.
  • Agents combine query engines with tool use — they can decide when to search your data, when to call external APIs, and when to reason independently.
